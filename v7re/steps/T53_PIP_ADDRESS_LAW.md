# T53：PIP 地址编码规律 —— 列 = 线长类别，行 = 角色

日期：2026-11-08
数据：`law.cells`(INT_L, sense=1) × `routing/out_routing/templates/INT_L.json` 的 `wire_defs`

## 1. 决定性的不变式：列码 ↔ 线长类别

把 48 个 IMUX 族全部 768 个布线源（4 行 × 4 列 × 48 族）按「列码 × wire kind」统计：

| 列码 | wire kind | 条目数 |
|---|---|---|
| 1 | DOUBLE | 192 |
| 2 | DOUBLE | 192 |
| 7 | SINGLE | 192 |
| 11 | SINGLE | 192 |

**0 例外。** 即：

```
列码 ∈ {0001, 0010}  ⇔  线长类别 DOUBLE（跨两个 tile 的长线）
列码 ∈ {0111, 1011}  ⇔  线长类别 SINGLE（单 tile 内的短线）
```

这解释了列码为什么恰好是这四个值：**它不是任意编码，是按线长分两大类、每类再分两列。**

## 2. 行 = 角色

| 行 | 内容 | kind |
|---|---|---|
| 0–3 | 16 条方向线 | DOUBLE 或 SINGLE |
| 4 | `LOGIC_OUTS_L*` ×3 + `GFAN0` | OUTBOUND / BOUNCEIN |
| 5 | `BYP_BOUNCE* ×2` + `FAN_BOUNCE* ×2` | BOUNCEACROSS |

所以 24 = **4 行布线源（每列 4 个）× 4 列 + 4 个逻辑源 + 4 个 bounce 源**。

## 3. 为什么是 6×4（回答提示词里的 C）

- **6 行** = 4 行布线源 + 1 行逻辑输出 + 1 行 bounce 源；
  前 4 行是同一个「方向类」的 4 个成员，第 5/6 行是另外两类完全不同的源。
- **4 列** = 每个方向类的 4 个成员位置；列码本身按线长分成 2+2。

即 6×4 不是任意的网格：**行是"源的类别"，列是"类别内的成员序"**。

## 4. 方向类的可推导性

同一个族里，16 条方向线可归成 4 个名字类：

```
对角线类 {NE2, SE2, NW2, SW2}
直角类   {NN2, EE2, WW2, SS2}
R 后缀类 {NR1, SR1, ER1, WR1}
L 后缀类 {NL1, SL1, EL1, WL1}
```

每类 4 条线，正好占满某一列的 4 行。**类内的行顺序**是固定置换的组合
（例：对角线类在 `IMUX_L0` 里是 NE→r0, SE→r1, NW→r2, SW→r3，
即 `row = (竖向为 N ? 0 : 1) + (横向为 E ? 0 : 2)`），但**类落到哪一列**随族而变。

## 5. 现在能算的和不能算的

| 量 | 可算？ | 依据 |
|---|---|---|
| 列 → 线长类别 | ✅ 恒定 | 768/768 无例外 |
| 位对 / parity | ✅ 闭式 | 48/48 |
| 行类别（布线/逻辑/bounce） | ✅ | 恒定 |
| LOGIC/BOUNCE 谁在 r4 | ✅ | 8 段规则，64/64 |
| 类内行顺序 | 🟡 部分（对角线类有闭式，其余待查） | 样例 |
| 方向类 → 列 | ❌ per-mux | 12 种序列 |
| 源 → 成员序号 | ❌ per-mux | — |

## 6. 结论

**PIP 地址编码 = 「线长类别（列）」×「角色（行）」×「族编号（位对/parity）」。**

前两项里，线长与角色的映射已经证明是器件级的固定规则；
只有「哪条具体线落在哪个格」是布线图事实（等价于 tileconn 邻接表）。
这已经是位流层面能推到的边界——再往下就是布线图本身。


## 7. 「方向类 → 列」是可预测的（2 种，按 8 段交替）

| 族段 | 列 1 | 列 2 | 列 7 | 列 11 |
|---|---|---|---|---|
| L0–L7 | 对角线 | 直角 | R 后缀 | L 后缀 |
| L8–L15 | 直角 | 对角线 | L 后缀 | R 后缀 |
| L16–L23 | 对角线 | 直角 | R 后缀 | L 后缀 |
| L24–L31 | 直角 | 对角线 | L 后缀 | R 后缀 |
| L32–L39 | 对角线 | 直角 | R 后缀 | L 后缀 |
| L40–L47 | 直角 | 对角线 | L 后缀 | R 后缀 |

即：

```
(i // 8) 为偶数 → {1:对角, 2:直角, 7:R, 11:L}
(i // 8) 为奇数 → {1:直角, 2:对角, 7:L, 11:R}
```

**48 个 IMUX 全部命中，0 例外**（全器件只有 2 种签名）。

## 8. 剩下的唯一 per-mux：类内行序

同一方向类内部的 4 条线谁在哪一行，仍有多种变体：
DIAG/ORTH 各 8 种、R/L 各 24 种（每种被 3–8 个族使用）。

这与「列」不同：列完全由 (i//8) 的奇偶决定，行序则没有找到同级别的规则。

## 9. 更新后的完整编码律

```
给定 IMUX_L<i> 与源 wire S：
  class(S) ∈ {DIAG, ORTH, R, L} 或 {LOGIC, BOUNCE}        # 由名字直接判定
  col = 由 (i//8)%2 与 class 决定的固定映射                # 已证，48/48
  row = 类内成员序                                          # per-mux，唯一残余
  bitpair/parity = 由 i 的闭式公式                          # 已证，48/48
  列帧 = col 对应的 1 或 3 帧；行帧 = 16 + row
```


## 10. 类内行序：不是按段变化的（负结果）

分别按「8 段」和「半段（i%8<4 与 >=4）」分组检验行序是否一致：

| 分组 | DIAG | ORTH | R | L |
|---|---|---|---|---|
| 按 8 段 | 2 种 | 2 种 | 4 种 | 4 种 |
| 按半段 | 2/2 | 2/2 | 4/2 | 2/4 |

**即使把粒度压到 4 个族，段内仍有 2 种变体。** 说明类内行序的最小变化单位是
「族本身（或相邻的一对族）」，不再由任何段号决定。

各段的首族行序（供参考，互不相同）：

```
段0 DIAG (NE2, SE2, NW2, SW2)     段3 DIAG (NW2, SE2, NE2, SW2)
段1 DIAG (SW2, NE2, SE2, NW2)     段4 DIAG (NE2, SW2, NW2, SE2)
段2 DIAG (SE2, NW2, SW2, NE2)     段5 DIAG (SE2, NE2, SW2, NW2)
```

既不是循环移位，也不是常数置换 —— 属布线邻接事实。

## 11. 最终编码律（本轮定稿）

```
输入：IMUX_L<i>，源 wire S
1. class(S)：由线名直接判定
     DIAG = NE/SE/NW/SW + 数字
     ORTH = NN/SS/EE/WW + 数字
     R    = NR/SR/ER/WR + 数字
     L    = NL/SL/EL/WL + 数字
     LOGIC/BOUNCE = 其余
2. 列：(i//8) 偶 → DIAG:1 ORTH:2 R:7 L:11 ；(i//8) 奇 → DIAG:2 ORTH:1 R:11 L:7
       （LOGIC 恒在 r4 或 r5，BOUNCE 在另一行，由 (i//8) 奇偶决定）
3. 行：类内成员序 —— per-family 数据（唯一残余）
4. 位对：minbit = 8*(i%4) + 2*(i//16) + 2*((i//8)%2)，parity = (i%8)>=4
5. 行帧 = 16+row；列帧 = col 码对应的 1 或 3 帧（25 / 24 / 23,24,25 / 22,24,25）
6. 位：列帧用 P，行 16/17/20/21 用 P，行 18/19 用 S（S = P±1）
```

**可计算部分**：第 1、2、4、5、6 步全部是固定规则，48/48 验证。
**不可计算部分**：第 3 步（类内成员序），它是布线图邻接关系的直接映射。


## 12. 追加：类内行序其实只有 8 种，且与「i 的奇偶」相关

按「同类行序序列」把 48 个族分组，结果极其规整（以 DIAG 为例）：

| 行序 | 族编号 |
|---|---|
| (NE2,SE2,NW2,SW2) | 0,2,4,6 |
| (SW2,NW2,SE2,NE2) | 1,3,5,7 |
| (SW2,NE2,SE2,NW2) | 8,10,12,14, 33,35,37,39 |
| (NE2,SW2,NW2,SE2) | 9,11,13,15, 32,34,36,38 |
| (SE2,NW2,SW2,NE2) | 16,18,20,22, 25,27,29,31 |
| (NW2,SE2,NE2,SW2) | 17,19,21,23, 24,26,28,30 |
| (SE2,NE2,SW2,NW2) | 40,42,44,46 |
| (NW2,SW2,NE2,SE2) | 41,43,45,47 |

两条规律：

1. **行序只与 `i` 的奇偶有关**：偶数族一套、奇数族一套（48 个族严格按奇偶二分）；
2. **块类只有 4 个**：块 1 与块 4 相同、块 2 与块 3 相同。

即 48 族的行序 = **4 个块类 × 2 个奇偶 = 8 种**（不是 48 种，也不是 8/24 种）。

ORTH 类完全平行的 8 组（`NN2/EE2/WW2/SS2` 及其排列），说明这是结构性的，不是巧合。

### 12.1 用 8 个代表族预测整表的检验

取每个 (块类, 奇偶) 的最小族作代表，学「(类, 方向) → 行」，再预测其余 40 个族：

- **整表预测 20/48 完全命中**，其余 28 族各错 0–16 条；
- 错得最多的族集中在块 3（L24/L25 全错）→ 块类到块号的映射还没定对；
- 其余多错 1 条/族（某个方向标签与代表族不同名）。

**结论**：8 种行序这个结构成立；但「块类」的正确编号法尚未确定，
所以现在还**不能**宣称整表可算。


## 13. 更正：§12 的「8 种行序」只对单类成立，整表实为 36 种

§12 是按 DIAG 一个类的序列分的组。把**四类合起来**（(类, 方向) → 行）重新分组：

```
按「行映射」分组：36 组 / 48 族
  2 族一组：{0,4} {3,7} {8,12} {11,15} {16,20} {19,23} {24,28} {27,31}
            {32,36} {35,39} {40,44} {43,47}
  其余 24 族各自独立
```

即：只有 `i % 8 ∈ {0,3}` 的族与 `i+4` 共用行映射，其余每族一套。
**行映射不是 8 种，而是 36 种**——§12 的结论作废。

## 14. 列码规则：744/744 零例外（本轮独立复核）

把「列」单独拿出来，用 `(i//8) 奇偶` 的规则预测 48 族 × 16 条布线源的列码：

```
列码命中：744 / 744
```

**列是完全可算的，行不是。** 这就是最终边界。

## 15. RapidWright 几何路线：不可行

- `routing/out_routing/templates/INT_L.json` 的 `pip_defs` 只有 4 个字段
  （dst, src, 常量 0, 布尔），不含任何几何/顺序信息，第 3 字段 3737 条全是 0；
- RapidWright 的 `Wire` / `PIP` 没有坐标 API（只有所属 `Tile` 的 XY），
  mux 内部 24 个源的行序无法从器件数据读出。

因此「块类 = 物理坐标函数」这条无法验证，行序只能作为表固化。
