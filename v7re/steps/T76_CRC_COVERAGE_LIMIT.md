# T76：CRC 全位置覆盖 —— 用现有语料做不到（定量结论）

日期：2026-11-10　脚本 `v7re/scripts/crc_solve_all.py`　日志 `_crc_all.log` / `_crc_s8.log`

## 1. 目标

把 T60 的 CRC 学习（231 个位置、留一法 4/4）扩到 INT 全部 3,634 个位置，
使「位流 → 改 FASM → 位流」能真正产出**可加载**的位流（当前缺 CRC 重算）。

## 2. 做法

- 本地 **967 份 `.bit`**，按目录分 30+ 组；
- 每组选「置位格最少」的文件作基准（即最接近空白设计的那个）；
- 每份非基准文件产生一条方程 `XOR_{p∈A△B} c(p) = CRC(A)^CRC(B)`；
- 对 32 个位平面分别做 GF(2) 高斯消元。

## 3. 结果：系统严重欠定

```
equations: 895
positions: 44867
rank: 760
contradicted: False
learned nonzero signatures: 31 of 44867
holdout(last5): 0/5
```

- **无矛盾**（说明 CRC 确实对数据位线性，模型没写错）；
- 但 895 条方程对 44,867 个未知位置 → 秩 760，只能定出 31 个位置；
- 留出验证 0/5 —— 解出来的东西不能预测新文件。

## 4. 根因：语料里没有「只差 1 位」的成对位流

统计每组最小差分：

| 目录 | 文件数 | 与基准的最小差分（格）|
|---|---|---|
| `_sb`（单最小项）| 65 | **22** |
| `_clbll` | 65 | 16 |
| `_t24` | 65 | 20 |
| `_initbits` | 112 | 48 |
| 全体 | 967 | **14** |

即：**没有任何一对位流只差 1 个数据位**。每条方程同时引入十几个到上千个未知量，
方程组自然解不动。

对比：T60 能得到 231 个位置，是因为当时专门挑了「差分 = 1 个位置」的成对文件
（`_sb` 的 `s_base` 与 `s0k` 在**当时那批构建**里确实只差 1 格）。现在本地这批
`_sb` 文件与 `s_base` 差 22–26 格 —— 说明这批文件不是当时那批（或经历过重构建）。

## 5. 结论与所需成本

**用现有语料无法把 CRC 覆盖推到 3,634 个位置。** 硬需求是：

- 需要 **每对只差 1 个数据位** 的位流，数量级 ≈ 3,634 对；
- 单次构建 84 s，32 路并发 → 3,634 个构建 ≈ **2.7 小时机时**；
- 前提是 `LOCK_PINS` + 固定 LOC/BEL + 显式 `-part`，保证「只有 1 格变」。

这是**工程可做、但需要专门排产**的任务，不是「再跑一下脚本」能拿到的。

## 6. 对主线的影响

- 「位流 ↔ FASM 双向」在**数据字层面**已闭环（幂等、跨设计复现）；
- 但产出的位流**不可加载**（CRC 不重算，BootROM 会校验失败）；
- 或者：保持原 CRC 不动的做法——只改数据位并**从原始位流继承 CRC**，适用于
  「改一处、且改后 CRC 恰好不变」的场合，不通用。

## 7. 复现

```bash
MAXDIFF=8 python v7re/scripts/crc_solve_all.py
```
