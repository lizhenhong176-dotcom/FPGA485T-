# T40：A 类 tile（一条 PIP 一位）验证 —— 协议与首批实测

日期：2026-11-08

## 1. 结论先说

**受控协议成立，但「一条 PIP 一位」尚未直接验证。** 本轮拿到的是：
- ✅ 同引脚重跑的负对照 **0 差**（构建确定性已证）；
- ✅ 「只改一个 IO 属性、引脚全固定」的干净差分：**7 个位、2 个帧，PIP 列表逐行相同**；
- ❌ 「换引脚」的差分仍是 85 格 / 49 帧（因为布线路径整体变了，不是单纯 IO 配置）。

## 2. 三组实测（`/opt/lzh/v7re/work/ioif2`、`ioif3`、`clsa`）

| 对比 | 变量 | 数据差格 | 帧数 | PIP 列表 |
|---|---|---|---|---|
| `p1b` vs `p2a` | 无（同引脚 AN33） | **0** | 0 | 相同 |
| `c1` vs `c2` | 输入脚 AF25 → AN33 | 85 | 49 | 不同（走线换了） |
| `t18` vs `t15` | `IOSTANDARD` LVCMOS18 → 15（引脚全固定） | **7 位** | 2 | **完全相同（61 行逐行同）** |

`t18` vs `t15` 的 7 个位，全在 IO 行（配置行 6）：

```
帧 27360 word 96 bit 16
帧 27361 word 95 bits 23, 31
帧 27361 word 96 bits 1, 3, 15, 17
```

## 3. 这组数据说明了什么

1. **协议可行**：只要保证「PIP 列表逐行相同」，差分里就只剩真正的配置位。
   这一条可作为所有 A 类测试的前置断言（比只看 `SITE/BEL` 更强）。
2. **IOSTANDARD 编码是 7 位/2 帧**，不是 1 位——说明 IO 属性本身是多位编码，
   「一条 PIP 一位」若成立，只可能对**布线 PIP** 而言，而不是 IO 属性。
3. **换引脚不能用来测 interface PIP**：换脚会同时改 IOB 位、ILOGIC 位、LIOI 与
   `IO_INT_INTERFACE` 的 PIP、以及到 LUT 的整条 INT 路径。

## 4. 下一步的正确设计（未做）

要单独测 `INT_INTERFACE_LOGIC_OUTS_L_B18 ->> INT_INTERFACE_LOGIC_OUTS_L18`
这条 PIP，必须让「同一引脚、同一 IOB、同一 LIOI」下只改变该 PIP 的使能。
可行做法：

- 使用 ILOGIC 的 `IDDR`/`IDELAY` 组合，让信号走 ILOGIC0 vs ILOGIC1 → 接口源索引变化而引脚不变；
- 或把同一引脚接到两个不同 LUT 输入（一个走 B18、一个走别的接口位），
  两设计只差「接哪个」。

## 5. 判据备忘

- 前置断言：`pips_a == pips_b`（逐行）；
- 后置断言：差格数应为个位数，且全部落在目标 tile 的帧内；
- 若差格横跨 >10 帧，说明混入了布线变化，必须重设设计。
