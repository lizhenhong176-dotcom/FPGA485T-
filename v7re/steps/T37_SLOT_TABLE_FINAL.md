# T37：槽位表能否由 mux 位置推导 —— 判定否

日期：2026-11-07
问题：`(family, source) → (row, colcode)` 这张表，是不是 `f(source)` 或 `f(mux 位置)` 的产物？

## 1. 已排除的四条路

| 假设 | 检验方式 | 结果 |
|---|---|---|
| 槽位 = routing 模板顺序 | `templates/INT_L.json` 的源列表顺序 vs 实测槽位 | 模板严格字典序，完全对齐 **0/64 族** |
| 槽位 = 方向 + 最近端线 | 按方向前缀归类统计槽位 | 同一方向横跨 **4–8** 个槽位 |
| 槽位 = `f(source)` | 同一导线跨 mux 的槽位 | 122 个源名中**始终同槽 0 个** |
| 槽位 = `f(源集合)` | 源集合完全相同的族之间比表 | 16 组、每组 3 族，组内槽位表**全部不同**（0/32 相同） |

## 2. 本轮新增：同源集合族之间的置换不成立

48 个 mux 族按源集合分成 **16 组 × 3 族**（例如 `IMUX_L0/L8/L16` 共用同一套 24 源）。
组内三族的槽位表比较：

```
IMUX_L0  row0 = NE2END0  NN2END0  NR1END0   SL1END0
IMUX_L16 row0 = SE2END0  EE2END0  WR1END0   EL1END0
```

行映射出现 **10 种对应**、列映射 4 种 —— 既不是整表平移，也不是行列独立置换。

用「槽位序列 → 源编号」做指纹：

```
48 个 mux 族的不同指纹数：42
每个指纹对应族数：36 个指纹各 1 族，6 个指纹各 2 族
16 组的指纹三元组种类：14（若只有少数几种置换模式，这个数应接近 1）
```

即：**几乎每个 mux 都有自己的槽位表**，不存在「少数几张表轮换」的压缩空间。

## 3. 结论

1. 槽位表 = `f(mux 实例, source)`，随 mux 实例变化；
2. 变化方式不是平移、不是行列独立置换、也不是有限几种模式；
3. 与「每个 mux 在其 tile 内的物理位置决定引脚到导线的映射」一致 —— 这是**器件布线事实**。

因此这张表应当像布线图一样**固化存储**，而不是继续找闭式解。
`law_cells` 已经提供了它（1,536/1,536 反证过），无需再测。

## 4. 「PIP 复用」问题的完整答案

| 问题 | 答案 | 证据 |
|---|---|---|
| 复用在哪一层 | **族内、格级**：同一 family 的多个源共用同一批 cell | 跨族零共享；族内每 cell 被 1–18 源共用，均值 5.56 |
| 复用的结构 | 三类：6×4 网格（mux）/ 完全二分 K(4,5)·K(5,4)（BEG）/ 组-核心-附加位（时钟控制） | 1,536 + 1,920 + 96 条逐条精确 |
| 位坐标怎么来 | 几何公式（行帧、列码、位对、parity、phase） | 3,634/3,634 精确、0 不符 |
| 源集合怎么来 | routing 模板离线可得（去 VCC/GND 后 166/172 精确，余 6 族只差时钟树常量线） | T36 |
| 哪个源占哪个引脚 | **per-mux 数据**，42/48 个 mux 的表互不相同 | 本文 |

一句话：**复用是"多个源共用同一批配置位"的必然结果；共用哪些位由几何决定，谁跟谁共用由布线决定。**
