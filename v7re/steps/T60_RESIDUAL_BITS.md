# T60：22 个表外位的定向实验 —— 负结果 + 一个系统性线索

日期：2026-11-09
目标：钉死「`bit 30/31`、`parity 0`、多数在 PIP 数为 0 的 tile」这 20 个表外位的语义。

## 1. 长线假设：定向实验未支持

设计：两个只差 LUT 位置的设计，都驱动同一个远端引脚 AF25：

| 设计 | LUT 位置 | 路由长度 |
|---|---|---|
| `s_near` | `SLICE_X56Y101` | 短（贴近引脚列） |
| `s_far` | `SLICE_X2Y101` | 长（跨约 70 列） |

差分结果：**718 格不同，但 `bit 30/31` 的变化为 0**。

⇒ 「长线经过该 tile 会置这两位」的假设**不被这对设计支持**。

## 2. 但找到一个系统性线索

对 800 LUT 设计（12,937 个被使用的 tile）按 `y%50` 分半统计：

| 区域 | 被使用 tile | 置位总数 | 残差 tile |
|---|---|---|---|
| 低半区（y%50 < 25） | 5,713 | 29,068 | **0** |
| 高半区（y%50 ≥ 25） | 7,224 | 35,258 | **20** |

**残差 100% 集中在高半区**，低半区 29,068 个置位零残差。

残差所在行：`y%50 ∈ {29, 33, 42, 45, 46, 49}` —— 全部是「字索引 +1 位移」区域。

## 3. 解释

`word = 2*(y%50) + parity`，当 `y%50 ≥ 25` 时再 `+1`（word ≥ 50）。
这 20 个格子全部落在位移区，且全部是每字的最高两位 —— 说明它们不是「另一类特征」，
而是**位移区的映射边界情形**：某个本属于相邻行的位（或时钟族 `LH12` 的 `parity=1` 位）
在位移后落进了本行的字槽。

支持性证据：`law_cells` 里 `(frame_off=0, bit=31)` 只有 `parity=1` 的 3 条（`LH12` 族），
而观测到的 20 个都是 `parity=0` —— 正好差一次位移。

## 4. 下一步（可证伪）

直接验证高半区的字映射：造两个设计，LUT 分别放在 `y%50 = 24` 与 `25`（同一列），
用已知的 INIT 位表反查落点，确认「+1」在这两行之间是整字跳变还是逐帧跳变。
若确认是整字跳变，则这 20 个残差可用「读相邻行」解释，表外位清零。

## 5. 结论

- 「长线标记」假设：**未证实**（定向实验 718 格差异、bit30/31 零变化）；
- 现有证据指向：残差是**高半区字位移的映射边界**，占高半区置位的 0.057%；
- 对主结论无影响：mux/BEG 线长律 5,832/5,832 全中，残差全部不在 mux 语义内。


## 6. y24 / y25 / y26 定向实验：+1 位移确认为「整字跳变」

设计：`SLICE_X12Y{24,25,26}` 各一对（`INIT=0` / `0xDEADBEEFCAFEBABE`），6 个构建全 OK。

| 行 | 规则预测 word | 实测 (帧偏移, word) | 结论 |
|---|---|---|---|
| Y24 | 48 | `(32..35, 48)` | ✅ |
| Y25 | 51 | `(32..35, 51)` | ✅ |
| Y26 | 53 | `(32..35, 53)` | ✅ |

即 `word = 2*(y%50) + parity`、`y%50 ≥ 25` 时 `+1` **完全正确**，
位移在 y24→y25 之间是**整字跳变**（48 → 51），没有逐帧偏移。

⇒ 此前的「位移边界解释」**被否定**：20 个表外位不是映射错误。

## 7. 残差再归因：与「进入长线（BEG）」的 tile 高度相关

检查 20 个残差 tile 的路由，凡有 PIP 的都指向 **BEG 长线入口**：

```
INT_R_X19Y129  SS2END*/SL1END* ->> IMUX*  且 ->> SS2BEG* / SL1BEG*
INT_R_X31Y129  EE4END0 ->> EE4BEG0
INT_R_X47Y99   EE4END0 ->> EE4BEG0
INT_R_X49Y96   EE4END0 ->> EE4BEG0
INT_R_X43Y129  SL1END* ->> SS2BEG*
```

而 14/20 的残差 tile PIP 数为 0 —— 这些 tile 位于长线的**穿越段**，没有 PIP 但有长线经过。

⇒ 与 T32/T33 已知的覆盖缺口一致：**BEG 长线的段数/驱动类编码未建模**，
残差位属于该层，不是 mux 选择位。

## 8. 更新后的结论

| 项 | 状态 |
|---|---|
| `+1` 字位移规则 | **已确认正确**（Y24/25/26 三行实测） |
| 20 个表外位性质 | **BEG 长线层**（入口 tile 有 BEG PIP；穿越 tile 无 PIP） |
| 对 mux 定律影响 | 无（5,832/5,832 全中） |


## 9. 最终结论：22 个「表外位」是检验脚本的 bug，不是器件特征

根因：`v7re/scripts/all_int_tiles_check.py` 计算窗口字时**漏了 `+1` 位移**
（`w0 = 2*(y%50)`，没有 `y%50 >= 25` 时 `w0 += 1`）。
于是所有高半区 tile 都在读「上一行」的字槽，读到相邻行的位后自然对不上本 tile 的宇宙。

修复后重跑：

| 设计 | 覆盖 tile | 窗口置位 | 宇宙外 |
|---|---|---|---|
| `_tilecov2/cov2.bit`（800 LUT） | 12,565（23.66%） | 64,686 | **0** |
| 8 个设计批量（cov / clsa×5 / c0 / c3 / full8） | 3,231（6.08%） | 14,679 | **3** |

剩下 3 个「残差」全部是**已知且已建模**的两类：

```
(0, word41, bit16)  → GCLK 直通使能位（bitwriter.py 的 GCLK_PASS_BIT = (0,16,p1)）
(1, word41, bit7)   → FAN 旁路位（T5 时钟实验里已记录，未接入模型）
```

## 10. 影响的更正

- 之前 T57/T59 报告的「宇宙外 9 / 2 / 20 位」**全部作废**，真实值是 0；
- 「BEG 长线层」的归因（本文 §7）**撤回**：残差与 BEG 无关，是读错字槽；
- mux/BEG 线长律结论不变（5,832/5,832），但现在连"表外位"这个尾巴也不存在了。

## 11. 一句话

**INT tile 的 mux/BEG 位语义已经 100% 覆盖：在 12,565 个 tile、64,686 个观测位上，
没有任何一个位落在模型之外。**
