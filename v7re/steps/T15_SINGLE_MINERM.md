# T15：单最小项法 —— INIT 位映摆脱位平面的坑

日期：2026-11-06

## 1. 为什么要换方法

位平面法（6 个设计、每设计一个 0/1 图案平面）在 y=20 那次成功，但在 row 3 失败：
用它建的 row-3 表去解随机值 `0xA5A5F0F01234ABCD`，得到 `0x5A5AF0F0213857CE`。
即使加了 SITE/BEL 回读、加了掩码重跑，仍不通过 —— 说明**方法本身有系统性缺陷**
（某些平面被 Vivado 优化成非 LUT6 或极性反相）。

## 2. 单最小项法

对每个 truth-table 索引 k 单独造一个设计：`INIT = 1 << k`（其余为 0）。
与全零基线差分，**出现的那一格就是索引 k 的位**。

- 每个构建都回读 `SITE` / `BEL` / `INIT`，不一致即作废；
- 单个设计只放一个 LUT，无合并、无优化空间。

## 3. 结果（row 3，SLICE_X2Y3/A6LUT）

65 个构建（1 基线 + 64 最小项），全部 `SITE=SLICE_X2Y3 BEL=SLICEM.A6LUT`。

| 检查 | 结果 |
|---|---|
| 每次构建产生的新格数 | **恰好 1 个**（64/64） |
| 64 个格是否互不相同 | **是，64 个** |
| 用该表反读 `0xA5A5F0F01234ABCD` | **精确命中** |
| 反读全零设计 | `0x0` ✔ |

同一份 `hv.bit` 在位平面表下解错、在单最小项表下解对 —— **方法差异被干净地隔离出来**。

## 4. 结构：帧组随行变化

| 位置 | INIT 所在帧 | 字 |
|---|---|---|
| row 3（`SLICE_X2Y3`） | base + 0 … 3 | `2*(3%50)+parity` = 6 |
| row 20（`SLICE_X12Y20`） | base + 68 … 71 | 40 |

帧组不同（+0..3 vs +68..71），字按 `2*(y%50)+parity` 各自取值。

## 5. 关键发现：行间差异是**纯位序置换**

把两张已通过随机验证的表按「索引 → 归一化后的 (帧偏移, 位)」对齐，
求 row3 → row20 的索引映射 `perm`：

```
perm(0)=0
perm(1)=16, perm(2)=4, perm(3)=20, perm(4)=2, perm(5)=18, perm(6)=6, perm(7)=22 …
```

验证：`perm` 在全部 64×64 组合上满足 `perm(x^y) = perm(x)^perm(y)`，且 `perm(0)=0`
→ **它是一个 GF(2) 上的纯位置换**（无仿射常数）：

```
索引位 0 → 位 4
索引位 1 → 位 2
索引位 2 → 位 1
索引位 3 → 位 5
索引位 4 → 位 0
索引位 5 → 位 3
即置换 (0 4)(1 2)(3 5)
```

两者的 64 个物理格集合**完全相同**，只有「哪个索引落在哪一格」不同。

## 6. 含义

- 同一块芯片里，LUT 的 INIT 位**物理排布是同一套 64 格**，行与行之间只是
  **地址位与物理位序的对应关系被置换**；
- 若这个置换随行有规律（例如与 y 的二进制位、或与帧组号有关），
  就能用「一张基准表 + 一个置换规则」覆盖整片，而不必逐行重建；
- 现在手上的两个数据点（row 3、row 20）对应置换 (0 4)(1 2)(3 5)。

## 7. 正在验证

已启动 row 4 与 row 8 的同样扫描（每设计 16 个 LUT = 2 行 × 2 slice × 4 BEL，
65 个构建）：若 row4 与 row3 置换相同，则置换只随「帧组/区块」变化而非逐行变化。

## 8. 教训

前几轮把「位平面法」当通用工具，导致 T13/T14 的排列结论不可靠。
今后强制：**每个新表必须用随机值反读自校验**，且构建必须回读 SITE/BEL/INIT。
单最小项法虽然贵 64 倍构建，但它是「一次做对」的方法。


## 9. 两行 16 个 LUT 的合并扫描（row 4 / row 8）

设计：`SLICE_X12Y{4,8}` 与 `SLICE_X13Y{4,8}` 各放 A6/B6/C6/D6 四个 LUT6（共 16 个），
`INIT = 1<<k` 逐轮替换，65 个构建（1 基线 + 64 最小项）。

结果：

| 检查 | 结果 |
|---|---|
| 每次构建新增格数 | **恰好 16 个**（16 个 LUT 各 1 个，64/64 轮都是 16） |
| 涉及 word | 8 / 9（row 4）、16 / 17（row 8） |
| 每个 word 的格数 | 256（= 4 个 LUT × 64） |
| 每个 word 涉及的帧 | 31778…31781 与 31784…31787（8 帧，每帧 32 格） |

**重要发现：四个 word 的 (帧, 位) 位置集合完全相同** ——
`word8 == word9 == word16 == word17`（32 位/帧 × 8 帧 = 256 格）。
即同一 block 内，不同行、不同 parity 的 INIT 只改 **word**，不改**帧与位**。

单最小项的样例（word 8，minterm 0）：4 个格分别落在
`(31778,15) (31778,31) (31786,15) (31786,31)` —— 位总是成对出现（`b` 与 `b+16`）。

仍未解决：这 16 个 LUT 之间的格分配（哪个格属于哪个 LUT）需要额外约束，
已启动 **单 LUT 对照实验**（`SLICE_X12Y4`/A6LUT 单独，65 个构建）来取得一张无歧义的表，
再与 row 3（`SLICE_X2Y3`/A6LUT）的表比较置换。
