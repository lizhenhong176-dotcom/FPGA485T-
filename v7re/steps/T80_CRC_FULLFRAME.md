# T80 全帧 CRC 签名语料：3,200 位一次测齐

日期：2026-11-11
数据：`/opt/lzh/v7re/work/crcfull2`（远端）、`_crcfull2_all.csv`（本地）

## 1. 目的
验证 T79 留下的最后一个前提：**所有位置的 CRC 增量是否落在同一个 31 维子空间**，
并把 `crc_table.json` 从 64 条扩到“一帧全部 3,200 个数据位”。

## 2. 语料构造
- 站点固定 `SLICE_X12Y20`，行 `Y = 0..49`（`SLICE_X12Y<Y>`，同列同 block），
  四个 BEL 各 16 个单最小项。
- `k = 16a + 2b`（a,b ∈ 0..3）⇒ 16 个 k 值 `0 2 4 6 16 18 … 54`，
  由 `bit = 15 - 4*(k>>4) - ((k>>1)&3)` 正好覆盖 bit 15..0 各一次。
- 每行 4 BEL × 16 = 64 个构建，50 行 = 3,200；**基线按 (Y, BEL) 各一份，共 200**。

第一次尝试的错：基线只按 Y 一份（BEL 用 A6LUT）。不同 BEL 的 `LOCK_PINS` 引脚位置不同，
输入布线整体变化，每份差分含约 100 格噪声，无法得到单格。改为 **per-(Y,BEL) 基线**后
每份差分严格 1 格。

## 3. 结果（三项验证）

### V1 位置域完整性
| 项 | 值 |
|---|---|
| 设计数 | 3,200 |
| 每份差分 | `add=1, rem=0`（3,200/3,200） |
| (word,bit) 唯一 | 3,200，重复 0 |
| word 覆盖 | 0..100 共 100 个（word 50 = ECC，按设计排除） |
| bit 覆盖 | 0..31 共 32 个 |
| 缺失 | 仅 `(50, 0..31)` 32 个，即 ECC 字 |
| 落帧 | **全部在 frame 31786 单帧** |
| 签名互异性 | 3,200 个全互异，零签名 0 |

⇒ **一帧的全部 3,200 个数据位已在同一帧测齐**，且位域完整（只有 ECC 字不在内）。

### V2 子空间闭合
旧语料（`_crc` A6LUT bit 0–15、`_crcb` B6LUT bit 16–31，各 4 帧）给出 64 个签名。
| 项 | 值 |
|---|---|
| rank(旧 64 个) | **31** |
| rank(新 3,200 个) | **31** |
| 新签名不在 span(旧) 内的 | **0** |

⇒ 3,200 个位置的 CRC 增量**全部落在同一个 31 维空间**，T79 的前提成立。
这也说明：表中的 3,200 条在信息上是冗余的（31 维即可张成），但作为“查表”仍然实用。

### V3 跨帧预测（补满秩后，满分）
在 word 40 的 32 个位置之外，追加 **word 41**（C6LUT/D6LUT）32 个位置、各两帧：
64 个构建（`k` 取偶数 → frame 31786；取奇数 → frame 31787），**64/64 全部单格差分**。

| 项 | 值 |
|---|---|
| 训练对 | **64**（word 40 位 0–31 + word 41 位 0–31，各 31786→31787） |
| 训练张成维数 | **31（饱和，与 3,200 个签名的秩相同）** |
| 留一法 | **64 / 64 精确命中，0 错，0 不可表达** |

留一法含义：每次剔除一个 (word,bit) 的训练对，用剩下 63 对拟合张成关系，
再预测被剔除那一位在 31787 的签名 —— **65 次预测（含首次的 16/16 检查）零错误**。

⇒ 跨帧映射与 **word 无关、与行无关、与 BEL 无关**，只与帧序号有关；
补上 word 41 后张成空间满秩，任何位置的第二帧签名都可精确算出。

## 4. 结论与边界
- **可确立**：CRC 增量对 3,200 个数据位是线性的；全部落在同一 31 维空间；
  跨帧映射在可表达方向上零错误、跨 word 跨行通用。
- **未覆盖**：训练集只到 30 维，6 个方向需补 ~64 个构建（word 41 的 32 位 × 2 帧）才能满分。
- **仍未知**：硬件是否校验该 CRC（从未验证）。
