## 一、先划清证据等级

`law_cells` 只有 `INT_L` / `INT_R` 两个 tile_type（各 8,900 条 sense=1）。
BRAM/DSP/CLB 的族形状来自 **prjxray 的 Artix-7 segbits**（`tile_pip_lawscan.json`），
不是 V7 实测位；只能用于「有没有复用」的筛选，不能用于判定 V7 的行序。

## 二、族规模普查（【数据事实】，A7 segbits）

| tile_type | 族数/侧 | 源数 min | max | mean | 源数 ≥8 的族 |
|---|---|---|---|---|---|
| INT_L/R | 172 | 12 | 24 | 21.14 | **172** |
| BRAM_L/R | 63 | 2 | 111 | 5.56 | **3** |
| DSP_L/R | 79 | 2 | 280 | 5.52 | **1**（其余 78 为 2 源 one-hot） |
| CLBLL/CLBLM | 2 | 338 | 358 | 348 | 2（全部是 ppip，无可配置位） |

结论：非 INT 类型里，真正存在「多源共享一组位」的族只有 **BRAM 3 族/侧、DSP 1 族/侧、CLK_HROW 时钟族**。

## 三、CLK_HROW：键形状相同、映射代数不同（【数据事实】+【推断】）

§164 的 62 源族 `CLK_HROW_CK_MUX_OUT_L8` 实测 19 个 GCLK 源，槽位公式：

```
p = k // 16      （组位，0/1）
s = k % 16       （16 位组内位置）
frame = 2589 - floor(s / 8)
word  = 24 + floor((s % 8) / 2)
half  = s % 2
标记值 = 0x800a >> p
```

- **19/19 成立**；§165 的全库普查又在 k=2 上独立复现（(2589,25) 低半），合计 **20/20**。
- 与 INT 的共同点：**键都是「组内位置（mod 16）+ 一个组位」**，与 INT 的
  `j = (pair//2) % 8`（16 位半区内的位对序号）同形。
- 与 INT 的差异：CLK_HROW 的映射是 **16 槽位的表**（帧 × 字 × 半区），
  不是 INT 的「4 成员置换 + 步进律」。因此「同类映射、不同基置换」这句预言**只对键成立，对映射代数不成立**。
- 【推断】两者共享的是 CRAM 的 16 位半区布局；这点只有分布证据，没有位布局级证据。

**可证伪预测（未做）**：按上式，k=0、18..23、25..30 的槽位可直接给出；
造 2 个受控位流（k=18、k=25）即可检验。若任一不符，则「mod-16 键」在时钟区不成立。

## 四、BRAM / DSP：本轮无法判定

- BRAM 每侧只有 3 个族源数 ≥8，DSP 只有 1 个；其余都是一次性 one-hot 或 2 源。
- 判定行序律是否同形，需要 V7 实测位表（`law_cells` 现在没有这两个类型）；
  A7 segbits 的位号不能借用（项目禁区第 1 条）。
- 最小可行动作：选 BRAM 的 3 个族之一，照 T62/T64 的方法各造 8–12 个受控差分位流，
  得到 (family, source) → cell 后，再套「键 = 组内位置 + 组位」判据。
