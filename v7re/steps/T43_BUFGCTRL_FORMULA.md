## 2. 公式

```
f0 = 7834 + 5246 * (Y // 16)          # 5246 = 每配置行的帧数
w  = (93 + Y // 2) mod 101            # 101 = 每帧字数

偶数 Y：(f0, w, 11)  和 (f0+1, w,  3)
奇数 Y：(f0, w, 27)  和 (f0+1, w, 19)
```

校验：Y=16 → f0=13080、w=(93+8) mod 101 = **0** ✓；Y=24 → w=(93+12) mod 101 = **4** ✓；
Y=8 → w=97（不跨行）✓。11 个 site 全部吻合。

## 3. 结构解读

- 每个 BUFGCTRL site 的「选择」= **2 位**，一位在帧 f0、一位在 f0+1；
- 同一个字里按奇偶占不同的位对：偶数 site 用 `{11, 3}`、奇数 site 用 `{27, 19}`；
- 一个字因此能容纳 **2 个 site × 2 位 = 4 位**；`w` 每 2 个 site 前进 1；
- 一行 101 个字，足够排下 16 个 site，跨行时 `f0` 加 5246。

## 4. 附带：IGNORE0 是独立位

`BUFGCTRL_X0Y16` 的 `IGNORE0` 从 0 改 1：**1 位**，位置 `(13080, 0, **1**)`，
与选择位同在 word 0 上，但不同位。

即：BUFGCTRL 的功能位是「按字分块」的——一个 site 的控制字里，选择占 2 位，其余功能位（IGNORE/CE 等）各占独立位。

## 5. 失败与修正

- `BUFGCTRL_X0Y40` / `X0Y48` **不存在**（器件只有 `X0Y0..X0Y31` + 第二列）；
- `BUFHCE_X0Y8` 在综合阶段被优化掉（`set_property` 找不到 cell）——BUFHCE 的 CE 若为常量，整个 cell 会被裁掉，需要接真实信号才能保留。

## 6. 结论

时钟 mux 的第一层（BUFGCTRL 输入选择）已经**完全公式化**：
11 个 site、每 site 2 位、位置由 `Y` 唯一决定。这已经可以直接写进解码器/写入器。

## 8. BUFHCE 的失败与原因

4 个 site × 2 变体共 8 个构建全部失败：

| 现象 | 原因 |
|---|---|
| `set_property ... expects at least one object` | `BUFHCE` 在综合阶段被整体优化掉（`CE` 为常量时输出恒定，即使实例带 `DONT_TOUCH` 也没保住） |
| `'BUFHCE_X0Y84' is not a valid site name` | 该 site 不存在 |

**教训**：`DONT_TOUCH` 只保护“不被合并/重命名”，不保证“不被常量传播删除”。
要测 BUFHCE 的 CE 位，必须让 CE 来自真实信号（输入脚或 LUT 输出），
而那样布线就变了——需要另设对照组（CE 来自两个不同但等价的信号）。
