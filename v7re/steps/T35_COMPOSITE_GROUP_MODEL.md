# T35：复合族做成「组模型」——96 条 feature 由 24 组核心 + 12 个附加位重建

日期：2026-11-07
对象：`CLK_L0/L1`、`CTRL_L0/L1`、`GFAN0/1`

## 1. 组模型

每个复合族 = **4 个组**，每组 = 一个 3 格 core + 两个附加位；组内 4 个源：

```
core C = {c1, c2, c3}
  src_a = C \ {c1}       2 格
  src_b = C \ {c2}       2 格
  src_c = C ∪ {e1}        4 格
  src_d = C ∪ {e2}        4 格
```

其中 `e1, e2` **在整族内共享**（同一族的所有组用同样两个附加位）。

## 2. 验证：组模型重建全部 feature

用组模型（不含逐源位列表）重新生成每条的位集合并与 `law_cells` 比对：

```
复合族组模型：重建 feature 96 条，不符 0
组数：CLK_L0 4 / CLK_L1 4 / CTRL_L0 4 / CTRL_L1 4 / GFAN0 4 / GFAN1 4
未进任何组的源：无
```

产物 `v7re/steps/composite_groups.json`（每族 4 组：core + drops + extras）。

**模型体积对比**：原表 96 条 × 2–4 格 ≈ 290 个格记录；
组模型 24 个 core（72 格）+ 12 个附加位 + 96 条「源→槽位」映射。

## 3. 槽位映射到底能不能推

尝试用命名规则推断「源 → 组」：

| 族 | 组 0 | 组 1 | 组 2 | 组 3 |
|---|---|---|---|---|
| `CLK_L0` | B0,B1,B2 + FAN_BOUNCE5 | B3,B4,B5,B6_WEST | B7_WEST..B10_WEST | B11_WEST + SR/WR/ER1END1 |
| `GFAN0` | B0..B3 | B4..B7_WEST | B8_WEST..B11_WEST | GND_WIRE, WW4END1, BYP_BOUNCE1, NR1END1 |
| `CTRL_L0` | BYP_BOUNCE4, FAN_BOUNCE1, GFAN0, GFAN1 | EE4END2, SE6END2, SR1END2, SS6END2 | ER1END2, WW4END2, NE6END2, NN6END2 | SW6END1, WR1END2, NR1END2, NW6END2 |

三者都是「每 4 个源一组」，但**组的划分边界不同**：
`GFAN0` 是 B0–B3 / B4–B7 / B8–B11 的整齐四分组，
`CLK_L0` 却把 B11 与三条 end 线放在一组，把 `FAN_BOUNCE5` 塞进第一组。

这正是「组的划分来自物理邻接」的迹象：GCLK 线沿 tile 四周排布，
每侧的可用线数不同，缺位时由相邻的端线（`SR1END1`、`WR1END1`）或 bounce 线补上。
**所以「源→组」是布线图事实，不是位流规律。**

## 4. 结论

| 层 | 是否可生成 | 依据 |
|---|---|---|
| 位的位置（core 与附加位在帧/字/位上的坐标） | ✅ 可生成 | 组模型 24 组，96/96 复现 |
| 组内 4 个源的编码（2 格掉落位 / 4 格附加位） | ✅ 可生成 | 2 位子选择，规律统一 |
| 源名 → 组 / 槽位 | ❌ 不可生成 | 依赖物理邻接；三族分组边界互不相同 |

这与 BEG 的结论完全一致：**几何可推导，邻接是器件事实**。
把「邻接」当作待解的谜是方向错误 —— 它在布线数据库里本来就有。

## 6. 口径硬规则：比对必须先过滤 `sense=1`

`law_cells` 同时存两类行：`sense=1`（该位必须置 1）与 `sense=0`（该位必须为 0）。
INT_L 侧 8,900 条 `sense=1` + 3,264 条 `sense=0`，后者覆盖 1,632 个 `(family, src)`、70/172 族。

本次复核在此踩过一次坑：把两类行并进观测集后，`CLK_L0` 的 96 条全部「不等」，
再人为补上「族内恒定 3–4 格」才凑平——那是**假象**。过滤 `sense=1` 后：

```
组模型重建：96 条 精确命中 96  不符 0  恒定格 0
（实例 GCLK_L_B1：core {(0,0,25),(0,0,26),(1,0,24)} 去 (0,0,25) = {(0,0,26),(1,0,24)}，
 即 law_cells 里唯一的 2 条 sense=1 行；另外 3 行是 sense=0 的约束位，不进置位集。）
```

**引用任何复用/命中数字时必须写明口径**：`sense=1` = 置位事实；`全部行` = 置位 + 清零约束。

## 7. `LV_L0` 的归属（T33 遗留项归档）
