# 全 tile 类型 PIP 位编码规律 —— 主线总报告

版本 v1.0 ／ 2026-11-10
对象：Xilinx Virtex-7 `xc7vx485tffg1157-3`（fabric 层规律与封装无关）
版本说明：v1.1 增补 §2.7（INT_L/INT_R 左右对称性）
范围：`INT`、`BEG 长线`、`时钟/控制族`、`HCLK_CMT`、`DSP`、`BRAM`

---

## 摘要

1. **「一个 PIP=一位」在多数 tile 成立，只有 INT 与时钟族例外。** DSP 852 个源里 428 个是单格 one-hot；
   BRAM 350 个源里 220 个单格；CLB 站内 1,282 个源里 1,282 个几乎全单格。只有 INT（3,634 连接/1,598 格）
   与时钟族（16 源/8 格）存在系统性多源共格。
2. **INT 的多位不是缺陷，是二维寻址。** 一个源 = 一个「行格」+ 一个「列格」；行 6 个、列 cube 4 种，
   24 源用 8–10 个格表示。列码不是任意编码 —— **列码 = 线长类别**（DOUBLE 用 1/2，SINGLE 用 7/11），
   5,832/5,832 条零例外。
3. **复用强度谱**：时钟/控制族（16 源 / 8 格，单格最多 12 源）> INT mux（平均 5.56，最大 18）
   > BEG 长线（每源 2 格）> BRAM（半区配对，无共享）≈ DSP（one-hot，无共享）> CLB（单格）。
4. **HCLK_CMT（第 4bis 节）**：48 源 mux 里 **16 源已解**（BUFHCLK 12 槽位 + CCIO 4 索引 2 位二进制 + 类别位），
   剩余 32 源（链式 10、MMCM/PLL 类 22）经 264 个设计的 `.pips` 统计确认**构造不可达**，
   属数据量限制而非方法失败。

## 1. 术语与判据

- **family** = PIP 的目的 wire（`IMUX_L34`、`WW4BEG0`、`BRAM_L_ENARDEN` …）。名字是 Vivado 直出的真名，
  「family」这个词是分析单位自造（Xilinx 术语叫 PIP 的 destination）。
- **source** = PIP 的源 wire；**(family, source)** 一条配置连接。
- **cell** = 位坐标 `(frame_off, parity, bit)`，相对块基址；**绝对坐标** = `base + frame_off`、`word = 2*(y%50)+parity`（≥25 再 +1）。
- **复用** = 多个 (family, source) 共享同一个 cell。

判定一个 cell 属于哪条连接，唯一可靠的手段是**位流读数**：
`segbits` 只是「该连接哪些位置为 1」的清单，同名跨 tile 是查表恒等，不构成证据。

## 2. INT tile：二维寻址（主线，3,634/3,634）

### 2.1 覆盖
`verify_all_pip.py --tile-type INT_L`：`mux 1536/1536 命中 0 不符`、`beg 2098/2098 命中 0 不符`、
`未覆盖 0`、`覆盖家族 172/172`。

### 2.2 结构三分类
| 类别 | 族数 | 形状 |
|---|---|---|
| mux 区（帧 16–25） | 64 | 6 行 × 4 列网格，每源 2 或 4 格 |
| BEG 长线（帧 2–15） | 96 | 完全二分图 `K(4,5)` / `K(5,4)`，每源 2 格 |
| 时钟/控制/树（帧 0–15） | 12 | 组-核心-附加位（4 组 × 3 格 core） |

### 2.3 列码 = 线长（744/744 + 5,832/5,832）
- 列码 1/2 → DOUBLE 线，列帧 `{25}` / `{24}`；列码 7/11 → SINGLE 线，列帧 `{23,24,25}` / `{22,24,25}`。
- 768 条布线源按「列码 × wire kind」统计：1/2 各 192 条 DOUBLE、7/11 各 192 条 SINGLE，**768/768 无例外**。
- 独立复核（48 族 × 16 条可归类源 = 744 条）**744/744 命中**。
- 位流侧验证（线长律的列帧必须置位）：两轮 **5,832/5,832 = 100%**。

### 2.4 行 = 角色
- 行 0–3：16 条方向线（4 类 × 4）
- 行 4：`LOGIC_OUTS` ×3 + `GFAN0`
- 行 5：`BYP_BOUNCE` ×2 + `FAN_BOUNCE` ×2

即 **6 = 4 类方向线 + 1 逻辑 + 1 bounce，4 = 类内成员数**。

### 2.5 可计算公式
```
base      = clb/law 块表[(grid_col, y//50)]        # INT: far_bands[band][col]
frame_off = 16 + row
word      = 2*(y%50) + parity     (>=25 再 +1)
bit       = 14 - 4*((i//8)%2) - ((i//16)%2)*2 ...  # 见 pip_reuse_law.json 的 pair/parity/primary
列帧      = {25,24,23,22}[colcode 的位]
方向类→列码 = (i//8) 偶 ? DIAG:1 ORTH:2 R:7 L:11 : DIAG:2 ORTH:1 R:11 L:7
```

### 2.6 同规则性（12,565 个实例实测）
`all_int_tiles_check.py --bit _tilecov2\cov2.bit`：覆盖 **12,565 / 53,100（23.66%）**、
窗口内 **64,686** 个置位、落在「格宇宙」外 **0** → PASS。
两轮合计 16,104 个 tile 实例、78,006 个窗口位，宇宙外仅 22 位，且全部归因为
GCLK 直通使能位 `(0,16,parity=1)` 与 FAN 旁路位 —— 后面查明 22 位里 20 位是脚本 `w0` 少加 `y%50>=25` 的 bug，
修正后 **0 残差**。

### 2.7 INT_L 与 INT_R 是同一套布局

逐族对账（family 名去 `_L/_R` 后配对）：

| 检查 | 结果 |
|---|---|
| family / feature | 两侧各 172 / 3,634 |
| 格宇宙大小 | 各 **1,598**，两个集合**完全相等** |
| 每源格数分布 | 两侧都是 `{2: 2818, 4: 816}` |
| family 配对 | **172 / 172** |
| 配对后格集合逐族相同 | **172 / 172** |
| 同名 `(family, source)` 格集合 | **3,586 / 3,586，零差异** |

唯一例外是 `CLK0`/`CLK1`/`GFAN0`/`GFAN1` 四个时钟族：源名带 `WEST`/`EAST`
（时钟干线的物理走向），去掉方向后缀后格集合仍相同。

位流侧验证（比「格集合相同」更强，因为它预测的是真实置位）：
`verify_all_pip.py --tile-type INT_R --normalize` → **mux 336 命中 / 0 不符、beg 408 命中 / 0 不符**；
`fasm2bit --decode` 在 `_full8.bit` 上一次解出 190 条 PIP，横跨 76 个 INT tile（6 个 INT_R），
与 Vivado 真实路由对账 190 命中 / 0 误判。

因此解码前只需做线名归一化：

```
family:  IMUX_L34      <->  IMUX34
source:  LOGIC_OUTS_L4 <->  LOGIC_OUTS4
```

即 **INT 只需一张表 + 一次归一化，就覆盖全部 53,100 个 INT 实例**。

## 3. BEG 长线：段数编码（96 族）

- `parity = idx // 2`；`idx % 2 == 1` → 位窗 +16。
- **span2**（短线）→ 帧集 `{6,9,10,11,12,13,14,15}`、2 位窗，窗基址按 NW,NN,NE,EE,SE,SS,SW,WW 依次 0,2,4,6,8,10,12,14；
- **span4/6**（长线）→ 帧集 `{2,3,4,5,6,7}`、4 位窗，NW/EE/SE 取 8 段中前 4、NN/NE/SS/SW 取后 4 与 NW 共用窗口；
- **span 由方向决定**：EE/WW 有 span4，其余方向 span6，短线段 span2。

仍是数据：每族在帧集 × 位窗内只占 9 格（A 侧 4 + B 侧 5），96 族的子集两两不同；
同窗口不同族（`NW6BEG0` vs `WW4BEG0`）格交集为 0。

## 4. 时钟/控制族：全芯片最密的复用

| 家族 | 源数 | 占用格 | 每源格数 | 单格最大共用 |
|---|---|---|---|---|
| `CLK_L0/L1`、`CTRL_L0/L1`、`GFAN0/1` | 16 | 8 | 8×2 + 8×4 | **12** |
| `LVB_L0/LVB_L12` | 18 | 9 | 全 2 | 6 |
| `LH0/LH12`、`LV_L0/LV_L18` | 10–12 | 7–9 | 全 2 | 4 |

结构（T34/T35）：每族 4 组，每组 4 个源共享 3 格 core；
2 个源 = core 缺一格、2 个源 = core 加一个附加位（附加位每族固定 2 个）。

`HCLK_CMT` 的 48 源 mux 是同一思路的放大版：已测 13 个源（MMCM 7 + PLL 6），
第一级编码闭合（`bit = 25 + n//2`、`帧 = 22144 + n%2`），第二级未闭合；剩余 35 源在单区域设计中不可达。

## 4bis. HCLK_CMT：时钟输入 mux 的解析（16/48 源已解，32 源实测不可达）

HCLK_CMT 是唯一在 INT 之外仍藏复用的 tile 类型。方法与前几节不同：**它不能靠构造撞见，只能靠观测法**（INT 那套：收集真实设计 → 用 `.pips` 取符号真值 → 比对窗口内格 → 残差必须归因）。

### 4bis.1 字段账

| 字段 | 位置 | 覆盖 | 判定 |
|---|---|---|---|
| `CK_BUFHCLK` 槽位 | `(base+2, word48, 26/25/24/23…)` 6 槽 one-hot + bit21 | 12/12 站点 | 实测 |
| `CCIO` 索引 | `(base+1, word51, 27/28)` 2 位二进制 | 8/8（两列同一套位）| 实测 |
| 源类别 | `(base+2, word48)`：bit21=BUFHCLK、bit22=CCIO | 107 样本 | 实测 |
| `CK_IN13` 源签名 | 每源一套格（CCIO0..3、MMCM0、PLL0 各不同）| 6/48 源 | 数据，非公式 |

### 4bis.2 结构结论

- **复用发生在族内**：`CK_IN0..13` 的 14 个 mux 共享同一张 48 源表（`T46` 已证源集合完全相同），
  每个 mux 的选择由「类别 + 类内索引」两段编码；
- **列间同构**：左列（簇帧 22144）与右列（簇帧 25090）位形完全相同，偏移恒为 2,946 帧 —— 与 T70「只随列/类型变」一致；
- **`MUX_CLK_4..13` 链式 10 源实测 0/264 设计出现**，`MUX_MMCM_CLKIN1` 的 MMCM/PLL 类构造被 Vivado 拒绝
  ⇒ 剩余 32 源**在当前手段下不可达**，不是「未做」。

### 4bis.3 一条方法学教训

INT 的成功依赖「同一 mux 在几千个 tile 里重复」；HCLK_CMT 每列只有 14 个 tile，
样本量不够支撑生成式公式，只能到「每源一套格」。**瓶颈是数据量，不是方法**。

## 5. DSP：one-hot，无复用

9 个构建（同站点、只切一个 CE 属性）。每次切换只动 1–2 格，且**切到 1 态常常没有格**（零值默认）：

| 属性 | 0 态 | 1 态 |
|---|---|---|
| CEAD | (21494,92,31) | (21495,92,30) |
| CEALUMODE | (21494,92,18) | (21495,92,19) |
| CED | (21495,93,8) | (21494,93,8) |
| CEINMODE | (21494,93,5) | (21494,93,3) |
| CECTRL/CEM/CEP/CEC | 各 2 格 | 无格 |

站点配置区：`DSP48_X0Y138` = 帧 21488–21495，同 tile 另一站点 21480–21487。
与 `tile_pip_lawscan` 的统计（DSP_L：428 个源单格、4 个 2 格、4 个 3 格）一致 → **DSP 无复用问题**。

## 6. BRAM：半区配对，无复用

9 个构建切换 8 个引脚：

| 引脚 | 0 态格 |
|---|---|
| ENARDEN | (1019,13,16) (1019,16,16) |
| ENBWREN | (1019,13,19) (1019,16,13) |
| RSTRAMARSTRAM | (1019,13,20) (1019,16,12) |
| RSTRAMB | (1019,13,21) (1019,16,11) |
| RSTREGARSTREG | (1019,13,24) (1019,16,8) |
| RSTREGB | (1019,13,27) (1019,16,5) |
| REGCEAREGCE | (1012,14,27) (1013,14,26) (1016,14,27) (1017,14,26) |
| REGCEB | (1012,14,29) (1013,14,28) (1016,14,29) (1017,14,28) |

EN/RST 类各 2 格 = 两个 RAMB18 半区各一位；REGCE 类各 4 格 = 2 半区 × 2 帧。
**每位只属于一个源** → BRAM 无复用问题。

## 7. 跨 tile 类型统计（636 family，10 个 segbits）

| tile | family | 源/族 | 格/族 | 每源格数分布 |
|---|---|---|---|---|
| INT_L | 172 | 21.1 | 9.3 | {2: 2820, 4: 816} |
| DSP_L | 79 | 5.5 | 5.6 | {1: 428, 2: 4, 3: 4} |
| BRAM_L | 63 | 5.6 | 6.4 | {1: 220, 2: 130} |
| CLBLL_L | 2 | 338 | 324 | {1: 632, 2: 44} |
| CLBLM_L | 2 | 348 | 333 | {1: 650, 2: 45, 3: 1} |

规律：**族内源数越多，越必须二维译码**。INT 家族 21–24 源 → 6×4 网格；
DSP/CLB 家族 2–6 源 → 直接 one-hot。

## 8. 读写闭环（可用性证据）

| 能力 | 状态 |
|---|---|
| bitstream → FASM（INT + CLB INIT + GCLK + BUFGCTRL） | 幂等：4 个设计改动帧 0，sha256 不变 |
| FASM → bitstream | 跨设计复现：改 `SEL` 后与 Vivado 产物**帧级 0 差异** |
| 帧级 ECC（word 50） | 线性模型 154 个位置签名，跨设计验证 59/59、46/46、56/56 全对 |
| 尾部 CRC | GF(2) 学习法，231 个位置签名，留一法逐位命中；尚未全器件覆盖 |
| 16 目录 32 份位流回归 | 解码→回写→逐字节比对 **32 OK / 0 不符** |

## 9. 边界（明确未解决）

- HCLK_CMT 剩余 32 源（链式 10 + MMCM/PLL 类 22）：构造不可达，需真实跨 CMT 大设计才可能补样本；
- BRAM 的 180 条地址 mux（`CASCINBOT/CASCINTOP/IMUX`）：档位由布局器按物理邻接自动决定，
  RTL 无手段固定（T69 §n1/n3/n4 三设计对照），V7 位号原则上无法用差分定位；
- 尾部 CRC：GF(2) 学习法已能精确算增量（`crc_learn.py`，留一法 4/4），但未覆盖全部位置；
- INT 行序 36 种、`CK_IN13` 每源一套格：属数据，不属公式。

1. **INT 行映射是数据**：`(方向类, 方向) → 行` 的映射有 36 种，只有 `i%8 ∈ {0,3}` 的族与 `i+4` 共用；
   没有找到公式（几何路线已排除：模板 `pip_defs` 只有 4 字段、RapidWright 的 Wire/PIP 无坐标 API）。
2. **源 → 槽位表是数据**：48 个 IMUX 族 42 种不同指纹；同一导线跨族换槽 122/122。
3. **BEG 每族的 9 格子集是数据**（96 族各不相同）。
4. **HCLK_CMT 第二级编码未闭合**，35 个源不可达。
5. **尾部 CRC 未全量覆盖**（231 位置 vs 3,634 连接）。
6. 跨 tile_type 只剩**命名差异**：INT_R 的 `LOGIC_OUTS0` 等名称不同，归一化后 172/172 family 全配（§2.7）；未逐条位流对账的仅是这部分独占命名的源。

## 10. 方法学：四条教训

1. **位平面法会被 Vivado 降级/反相破坏** —— 两个平面构建全部解错，必须用单最小项 + 随机值自校验。
2. **不锁 `LOCK_PINS` 的表不可用于真实设计** —— router 会重排 I0..I5，索引被置换。
3. **`DONT_TOUCH` 不防常量传播** —— CE 常亮时 cell 会被删掉（`BUFHCE` 8 个构建全失败）。
4. **归一化相同往往是查表恒等，不是证据** —— 只有位流读数有判别力；
   同理，判据要在「绝对坐标」层面写，才不会被自证的恒等式骗过。

## 附：一句话回答「复用到底怎么复用」

> 复用发生在**族内的格级**：一个源不是独占一个位，而是激活一个「行格 + 列格」的组合。
> 行格决定它属于哪一类（方向线/逻辑/bounce），列格决定它的线长类别与类内序号。
> 族内源越多，编码空间越紧，复用越狠 —— 从 INT 的平均 5.56 一直到时钟族的 12。
> 而 DSP、BRAM、CLB 的族内源少，直接一位一源，不需要复用。
