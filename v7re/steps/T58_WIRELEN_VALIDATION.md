# T58：用「线长编码律」在 237 个新 tile 上做独立检验

日期：2026-11-08
脚本：`v7re/scripts/wirelen_check.py`

## 1. 被检验的定律（T53）

48 个 IMUX 族的列码由两件事决定：

```
段 = (i // 8) % 2                    # i = 族编号
源名方向类别：DIAG(NE/SE/NW/SW) ORTH(NN/SS/EE/WW) R(NR/SR/ER/WR) L(NL/SL/EL/WL)

段偶 → DIAG:1  ORTH:2  R:7   L:11
段奇 → DIAG:2  ORTH:1  R:11  L:7

列码 → 帧：1→{25}  2→{24}  7→{23,24,25}  11→{22,24,25}
```

而源名里的数字给出线长类别（`1=SINGLE 2=DOUBLE 4=QUAD 6=SIX`），
定律要求：**列码 1/2 的族只接 DOUBLE 线，列码 7/11 的族只接 SINGLE 线**。

## 2. 检验用什么数据

- 路由与位流来自**完全没参与定律推导的设计**：`_tilecov/`（200 个 LUT6，16 列 × 14 行）；
- 该项设计覆盖 **3,167 个 INT tile 实例**；
- 从 `cov.pips`（Vivado 直出）取 `(tile, src, dst)`，dst 即 family。

规模：**1,440 个 PIP 实例、237 个 tile、43 个 family**（其中 SINGLE 399、DOUBLE 262，其余为无方向类别名）。

## 3. 两项检验与结果

### A) 名字一致性：预测列码的线长类别 == 源名的线长类别

```
一致 661，不一致 0
```

零反例。

### B) 位一致性：预测的列帧格在真实位流里必须为 1

```
命中 648 / 648 = 100.00%
```

（用 `pip_reuse_law.json` 的 `pair/parity/primary` 只定位「用哪一位」，列码完全由名字算。）

## 4. 结论

**线长编码律在新 tile、新设计上 100% 成立**：

- 名字层面 661/661 一致（说明「DIAG/ORTH → 双长线、R/L → 单长线」的映射不是训练集巧合）；
- 位层面 648/648 命中（说明列帧位置可直接由名字算出来，不需要查表）。

这是对「所有 INT tile 同一套规则」的**独立第二证据链**：前一轮是「格宇宙残差 11/25,000」，
这一轮是「按名字算出来的列帧逐位命中 648/648」。

## 5. 边界

- 覆盖 237 / 53,100 个 tile（0.45%），仍非穷尽；
- 只检验 43 / 48 个 IMUX 族（其余族在该设计里没被用到）；
- `BYP_ALT`/`FAN_ALT`/BEG 族不适用本律（它们的列不是线长编码）；
- A 项 661 条里含 43 个族，B 项 648 条略少 13 条，是族参数表里缺该族的 `primary` 记录所致。
