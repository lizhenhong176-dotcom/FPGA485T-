# T11：CLB INIT 位映射重建（位平面法）与逐字节对账

日期：2026-11-04
产物：`v7re/steps/clb_init_map_x12y20.json`（64 条：INIT 索引 → 绝对位）

## 1. 方法：6 个位平面设计，而不是 64 个单点设计

原本打算造 64 个 `INIT=2^k` 的设计。更好的办法是用**位平面编码**：只造 6 个，
第 k 个设计的 INIT 让「索引 i 的第 k 位为 1」的那些位置为 1：

| k | INIT 值 |
|---|---|
| 0 | `0x5555555555555555` |
| 1 | `0xCCCCCCCCCCCCCCCC` |
| 2 | `0xF0F0F0F0F0F0F0F0` |
| 3 | `0xFF00FF00FF00FF00` |
| 4 | `0xFFFF0000FFFF0000` |
| 5 | `0xFFFFFFFF00000000` |

每个设计与基线 `_full8.bit`（INIT=1）逐位差分，得到该设计的置位格集合。
对任意一个格，`索引 = Σ_k (该格在第 k 个差分中出现) << k`。

**6 次综合实现了 64 次的效果**（约 20 分钟 vs 约 80 分钟）。

## 2. 结果：64 个 INIT 位落位

数据格共 64 个（排除 word 50 的 ECC 变化），映射完整无重（`clb_init_map_x12y20.json`）：

```
INIT[00] -> (31786, 40, 15)      INIT[01] -> (31786, 40, 7)
INIT[02] -> (31784, 40, 15)      INIT[03] -> (31784, 40, 7)
INIT[04] -> (31786, 40, 11)      INIT[05] -> (31786, 40, 3)
INIT[06] -> (31784, 40, 11)      INIT[07] -> (31784, 40, 3)
INIT[08] -> (31786, 40, 13)      INIT[09] -> (31786, 40, 5)
...
```

结构：所有 INIT 位都在 **word 40（= 2*(20%50) + 0，y=20 的 parity 0 字）**，
分布在 **frame 31784 / 31785 / 31786**（= block base 31716 + 68/69/70）三个帧上。
而旧表（`site_frames`）说 INIT 在 frame 31786/31787 且 64 位分散在 4 个帧 —— **旧表是错的**。

## 3. 验收：随机 INIT 预测

造 `INIT=0xDEADBEEFCAFEBABE` 的设计，用新映射预测置位格：

```
预测格数 46，实际数据格数 47
预测但未变: 0     ← 零误报
变了但未预测: 1   ← (31786,40,15) = INIT[00]，因基线 INIT=1 而新值 bit0=0，是被清掉的那一位
```

46 置位 + 1 清零 = 47，**完全吻合**。

## 4. 逐字节对账：payload 与 Vivado 完全一致

用 `bitgen.py` 在 `_full8.bit` 上只置 `(31786,40,7)`（即把 INIT 从 1 改成 3），
与 Vivado 重新实现出的 `full8_i3.bit` 比较：

```
帧级差异：0 格 / 50,176 帧
字节级差异：11 个字节
```

11 个字节分别是：

* **7 个字节在头部**：文件日期 `2026/11/02` → `2026/11/04`、时间 `18:43:26` → `21:02:34`
  （Vivado 写入的构建时间戳，与设计内容无关）；
* **4 个字节在后部**：`0x30000001 <CRC>` 包里的 CRC 值（我们写的是旧值 `0x4e6c4350`，
  Vivado 写的是 `0xb3b04c17`）。

即：**配置数据 100% 一致**，剩下的是时间戳与 CRC 校验字。

## 5. 还没解决：尾部 CRC 算法

试过的组合（20 MB 数据 × 3 个起始点 × 2 种字节序 × 2 种位序 × 2 个初值 × 2 种终值
× zlib）全部不匹配 `0xb3b04c17`。说明 Xilinx 的 CRC 不是对整段字节流的常规 CRC，
可能按帧（3232 位）为单位、或另有位序约定。

两条可行路径：
1. **把 CRC 也当线性函数学**：CRC 是 GF(2) 线性的，可以用与 ECC 相同的方法
   （收集成对位流、求解每个数据位对 CRC 的贡献）求出；
2. **省略 CRC 包**：很多情况下 CRC 校验不是强制的，删掉该包可能仍可加载（需硬件验证）。
