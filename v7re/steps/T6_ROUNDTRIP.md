# T6：端到端闭环——位流 → PIP 列表 → 重写 → 逐位比对

日期：2026-11-02
脚本：`v7re/scripts/roundtrip.py`
与前几步的区别：**不喂 Vivado 的路由结果**。PIP 列表完全由位流自身解码得到
（mux 区用 T3 定律，帧 0–15 的族用 `law_cells` 查表），再用同一套规则重写回去。

```bash
python v7re/scripts/roundtrip.py --bit _full8.bit --min-cells 2
```

## 1. 位级结果：往返精确

| 设计 | 解码出的 PIP | 重写后位差 |
|---|---|---|
| c0（单时钟 + FF） | 31 条 | **漏 0 / 多 0** |
| full8（48 个 LUT 输入） | 282 条 | **漏 0 / 多 0** |
| c3（CE 经 FAN） | 45 条 | 漏 1 / 多 0 —— 已知的表外旁路位 |
| c4（D 经两跳 BYP） | 48 条 | 漏 1 / 多 0 —— 同上 |

结论：**`位流 → PIP 列表 → 位流` 在真实设计上逐位还原**（c0/full8 零差异）。
GCLK 使能位 `(frame_0, bit16, par1)` 也已被解码器识别并写回（c0/c3/c4 各 1 个 tile）。

## 2. 符号级结果：2 格 pattern 的歧义是真的

把解码出的 `(tile, src, family)` 与 Vivado 真实路由（只取 INT tile）对账：

| 设计 | 解码 | 真值 | 命中 | 多（误判） | 漏 |
|---|---|---|---|---|---|
| c0 | 31 | 27 | 24 | 7 | 3 |
| full8 | 282 | 198 | 190 | 92 | 8 |
| c3 | 45 | 39 | 35 | 10 | 4 |

**误判的预测格数分布：full8 全部 92 条都是 2 格；c0 是 6 条 2 格 + 1 条 4 格。**

即：

- **4 格及以上 pattern：整芯片尺度 0 误判**（c0 那条 4 格是 `GCLK_B11 -> CLK1` 的族名歧义，非位判断错误）；
- **2 格 pattern：误判率约 1/3**（full8：92 误判 / 274 条 2 格候选 ≈ 34%）。

这与 T4 的负对照（4 格 0/546、2 格 60/558）方向一致，但整芯片真实设计上的数字更严重，
因为设计越密，2 格组合撞车的概率越高。

## 3. 为什么“位级完美、符号级有歧义”可以并存

PIP 的位是**线性叠加**的（T4 已证），一条 2 格 PIP 的位很可能被同 tile 内别的 PIP 顺带点亮。
于是：

- **重写方向**：写多了相同的位 ⇒ 位图不变 ⇒ 逐位比对仍然 0 差异；
- **解读方向**：看到那 2 位为 1，无法断定是哪条 PIP 点亮的 ⇒ 误判。

这不是实现缺陷，是信息不足：2 格 pattern 提供的信息量小于候选空间。

## 4. 消歧的三条可行路径

1. **按 net 链联合判定**：一条 net 的 PIP 链必须首尾相接（`A->>B` 后必须存在 `B->>C`），
   孤立的多余 PIP 会破坏链的连通性，可直接剪掉。这是最有效的一条。
2. **提高格数门槛**：只信 4 格及以上（会丢掉约一半 2 格 PIP 的解，full8 漏 8 条里的主体）。
3. **引入占用约束**：一个 IMUX 同时只能选一个源，一族内互斥——把候选集合做成
   精确覆盖问题（set cover / exact cover），用互斥性剪枝。

## 6. 还缺的一块：帧级 ECC

第 50 字是帧级 ECC（13 位有效，见 SITE_FRAMES_STATUS §4.1）。当前往返是在**位图层面**比对，
不重算 ECC；若要生成真正可加载的 bitstream，必须根据改动后的数据字重算该字。
候选实现方向：按 (帧内数据位 → ECC 位) 的线性方程组求解（已知若干单点样本，
如 `a.bit` 帧 31750 相对全零基线只有 INIT[00] 一位，可得到一个列向量）。
