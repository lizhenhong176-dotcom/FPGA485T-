## 一、结论

**旧结论（PIP_ADDRESS_ENCODING_LAW v1.1 §5.1 / T53 §13）**：类内成员序不可导出，
「(类, 方向) → 行」在 48 族里有 **36 种**映射，只能作为表数据固化。

**本轮结论（【数据事实】）**：在本机 `v7_law.sqlite` 的当前数据上，这个数字不成立。

1. **64 个 mux family（每侧）的「(类, 方向) → 行」只有 16 种**，并且
   **16 个键 → 16 个编码是双射**。键是 `(pair // 2) % 8, primary`，即
   「位对序号在 16 位半区内的位置」与「primary 位」。族名、parity、L/R 侧都不进入键。
2. **INT_L 与 INT_R 逐键完全相同**（0 个键不同）；用 INT_L 建表预测 INT_R：
   **1,024/1,024，0 不符**（跨侧留出，非训练集自证）。
3. **primary=S 的行号 = primary=P 的行号 XOR 2**（行号 +2 mod 4），
   16 张表因此只剩 **8 张基础表**。
4. **族名 → (pair, parity, primary) 有闭式**（H4，128 族 0 不符）。
5. **全量再生 2,048/2,048 条方向线 feature**（64 族 × 16 条 × 2 侧），
   `(row, colcode)` 逐条与 `law_cells` 相等，`missing=0`、`extra=0`。
6. `LOGIC_OUTS/GFAN` 与 `BOUNCE` 落在第 4/5 行，由全局 mux 序号 `g = i//8` 的奇偶决定
   （`g` 偶 → LOGIC 行 4 / BOUNCE 行 5），**64/64 族 0 反例**。
7. 48 个 IMUX 族的等价类实为 **12 组 × 4 族**：`{0,2,4,6} {1,3,5,7} {8,10,12,14} …`，
   即行序只依赖 `(i 的奇偶, i//8)`。

**判定**：行序**不是**每族自由数据。它由「位对在 32 位字里的位置（半区内序号）」唯一决定；
可导出的部分是 8 张基础表 + 1 条镜像律 + 分配闭式，不可导出的只剩这 8 张表本身。

## 二、口径与定义（先把话说死）

| 项 | 定义 |
|---|---|
| 方向线 | 前缀 `NE/NW/SE/SW`（DIAG）、`NN/SS/EE/WW`（ORTH）、`NR/SR/ER/WR`（R）、`NL/SL/EL/WL`（L），每族每类恰 1 条、共 16 条 |
| 行 | `row = frame_off - 16 ∈ 0..3`（第 4/5 行是 LOGIC/GFAN 与 BOUNCE，不参与本表） |
| 编码 | 按固定成员序把每类的 4 个行号拼成 4 位串：`DIAG[NE,NW,SE,SW]`、`ORTH[NN,EE,WW,SS]`、`R[NR,ER,WR,SR]`、`L[NL,EL,WL,SL]`；四类以空格分隔 |
| 键 | `j = (pair // 2) % 8`（`pair ∈ {0,2,…,30}`，即 16 个偶数位对）与 `primary ∈ {P,S}` |
| 范围 | `IMUX*` 48 族 + `BYP_ALT0..7` + `FAN_ALT0..7` = 64 族/侧 |

例：`j=0, P → 2031 2301 2013 3102` 读作 DIAG 的 NE→2、NW→0、SE→3、SW→1；
ORTH 的 NN→2、EE→3、WW→0、SS→1；R 的 NR→2、ER→0、WR→1、SR→3；
L 的 NL→3、EL→1、WL→0、SL→2。

## 三、16 张表（完整枚举，供解码器直接使用）

| j | primary=P | primary=S |
|---|---|---|
| 0 | `2031 2301 2013 3102` | `0213 0123 0231 1320` |
| 1 | `1320 1230 3120 0213` | `3102 3012 1302 2031` |
| 2 | `2013 2103 0213 3120` | `0231 0321 2031 1302` |
| 3 | `1302 1032 1320 0231` | `3120 3210 3102 2013` |
| 4 | `1302 1032 2103 3012` | `3120 3210 0321 1230` |
| 5 | `0231 0321 3210 0123` | `2013 2103 1032 2301` |
| 6 | `3102 3012 0123 3210` | `1320 1230 2301 1032` |
| 7 | `2031 2301 1230 0321` | `0213 0123 3012 2103` |

S 列逐条 = P 列逐位 `+2 mod 4`（H3），故实现时只需存 P 列 8 行。

## 四、分配闭式（族名 → 位对/奇偶/primary）

```
全局 mux 序号：IMUX_L<i> → i；BYP_ALT<k> → 48+k；FAN_ALT<k> → 56+k
g = 全局序号 // 8

IMUX：pair  = [0,2,2,4,4,6][g] + 8 * (i % 4)
      parity = (i // 4) % 2
      primary = "S" if g 为偶 else "P"
BYP： pair  = [6,14,6,14,22,30,22,30][k]
      parity = (k // 2) % 2
      primary = "S"
FAN： pair  = [0,16,16,24,8,8,24,0][k]
      parity = k % 2
      primary = "P"
```

## 五、列码（与行并用，构成 mux 区的完整坐标）

```
g = 全局序号 // 8
g 偶：DIAG=1  ORTH=2  R=7   L=11
g 奇：DIAG=2  ORTH=1  R=11  L=7
```

## 七、与旧结论的差异（如实记录）

- 旧文写「48 族 36 种」，本轮用当前 `law_cells` 得到的等价类有 12 组（IMUX 48 族），
  加上 BYP/FAN 为 16 种。**三种口径都复现不出 36**：
  ① 只比方向线（按前缀）→ 12 组；
  ② 比全部 24 条源的**具体线名** → 48 组（族族不同）；
  ③ 比含 LOGIC/BOUNCE 的完整 24 源签名 → 48 组。
  旧数字可能来自更早的 `law_cells` 版本或另一种分组口径；本轮不复用该数字。
- 旧文「`i%8 ∈ {0,3}` 的族与 `i+4` 共用」与当前数据不符：当前是 `i` 与 `i+2`（同奇偶同块）共用。
- 本节的结论**不否定**「源→槽位不是线名的函数」这一条：同一线名（如 `NE2END0`）
  在不同族仍可落到不同行；被确定为函数的是**键**，不是线名。

## 八、边界与未测

- **未测**：这 8 张基础表能否再用更小的结构生成（如按 j 的循环/反射序列）。
  已试「相邻 j 是行旋转」只在 j=0→1、1→2 成立，j 更大时出现反射，未找到统一生成元。
- **未测**：`primary` 的物理含义（列帧用 pair 的哪一位）与行表为何以半区为周期，
  两者是否同一硬件机制（16 位半区）——需要 CRAM 位布局层面的证据。
- **边界**：本结论只在 `law_cells` 覆盖的 `INT_L/INT_R` 类型级成立；
  实例级（12,565 个 INT tile）已由 `verify_all_pip.py --normalize` 另行对账（3,634/3,634）。
- **未覆盖**：第 4/5 行内 8 条源的**成员选择**（LOGIC_OUTS_L22 等具体线名）仍是数据，
  与方向线行序是两件事。
