# T3：PIP 复用规律的生成式表述（mux 区）

日期：2026-11-02
器件：xc7vx485tffg1761-2
脚本：`v7re/scripts/pip_reuse_law.py`（`--build` / `--verify`）
参数：`v7re/steps/pip_reuse_law.json`

## 0. 一句话结论

在 mux 区（帧 16–25），**地址与位平面可以用公式算出来，不需要查表**：

> 一个 family 有 24 个源，落在固定的 6×4 网格上；源 `(row, colcode)` 决定它占哪些帧，
> family 的「位对 + parity + phase」决定用哪一位。
> 16 个位对 × 2 个 parity × 2 个 phase = **恰好 64 个 family，一一对应**。

`--verify` 结果：**1,536 / 1,536** 条 `(family, src)` 的 cell 集合精确命中，0 不符。

**唯一仍是数据的部分**：源 → 网格槽位的排列（每 family 24 条）。它是器件布线邻接关系
决定的顺序，不能由线名推出（见 §4）。

## 1. 网格：所有 mux 区 family 共用同一个 6×4

* 行 `row ∈ 0..5`，列码 `colcode ∈ {0b0001, 0b0010, 0b0111, 0b1011}`。
* 24 = 6 行 × 4 列码，每个源恰好占一个槽位。
* 48 个 IMUX + 8 个 BYP_ALT + 8 个 FAN_ALT = 64 个 family，全部使用这一张网格，
  **只有一种网格模式**（不是每族自定）。

## 2. 地址：源占哪些帧

```
frame_row = 16 + row                    # row ∈ 0..5  →  帧 16..21
frame_col = { 25 - i | colcode 的第 i 位(LSB=0) 为 1 }
                                        # 0001→{25}  0010→{24}  0111→{25,24,23}  1011→{25,24,22}
```

一条 PIP 的 cell 数 = 1（行帧）+ popcount(colcode)（列帧），与实测的
`每 feature 2.45 位`、`每个源 1–4 格` 一致。

## 3. 位平面：用哪一位

* 每个 family 拥有一对**相邻位** `(B, B+1)`，`B` 为偶数，16 对覆盖 0..31；
* 每个 family 有一个字 `parity p ∈ {0,1}`；
* **列帧永远落在 primary 位 `P` 上**；
* **行帧**：`row ∈ {0,1,4,5}` 用 `P`，`row ∈ {2,3}` 用另一相位 `S`（`S` 是 `P` 的配对位）。

`P` 取 `B` 还是 `B+1` 称为该 family 的 **phase**。于是：

| 维度 | 取值数 |
|---|---|
| 位对 `(B,B+1)` | 16 |
| parity | 2 |
| phase（primary = 低位 / 高位） | 2 |
| 合计 | **64** |

`--build` 的 `combo_check`：`families=64, distinct_combos=64, max_per_combo=1`
—— 64 个 family 与 64 个组合**一一对应，没有重复也没有空缺**。

举例（同一对位 6/7、同一 parity 0，靠 phase 区分）：

| family | 位对 | parity | phase | 行帧用位 | 列帧用位 |
|---|---|---|---|---|---|
| `BYP_ALT0` | (6,7) | 0 | primary = 7 | row 0,1,4,5→7；2,3→6 | 7 |
| `IMUX_L40` | (6,7) | 0 | primary = 6 | row 0,1,4,5→6；2,3→7 | 6 |

两者源集合相同、cell 集合互斥 —— 这正是「复用」的几何本质。

## 4. 仍是数据的部分：源 → 槽位

* 每 family 24 条、64 族共 1,536 条 `src → (row, colcode)`。
* 已排除的猜想：
  * **名称字典序**：48 个 mux 全部不符合（`IMUX_L0` 实序为
    `NE2END0, NN2END0, SL1END0, NR1END0, SE2END0, EE2END0, NL1END, SR1END…`）；
  * **按基名归类**：22 个基名（`NE2END`、`SW2END`、`LOGIC_OUTS_L`…）在不同 family
    落在不同槽位，同一基名可占多个槽位；
  * 每族的基名组合只有 3 种，但组合内顺序仍不一致。
* 结论：槽位顺序 = 器件布线图中「该 mux 的 24 个扇入在网表中的枚举顺序」，
  即物理邻接，属路由数据；要压掉它必须用 `v7_routing.db` 的邻接关系重建，
  而不是从 bit 位置反推。

## 5. 跨类型：INT_L 与 INT_R

用 INT_L 的定律去预测 INT_R 的 `law_cells`：

* 直接预测：336 / 1,536 命中，其余多为**线名缺 `_L` 后缀**（`LOGIC_OUTS0` vs `LOGIC_OUTS_L0`）；
* 归一化名称后：**384 / 1,536 命中，且「名字能对上时算错 = 0」**；
* 剩下的 1,152 条是 INT_R 独有的源（`GFAN0/GFAN1`、`BYP_BOUNCE_N3_6`…），
  INT_L 里根本不存在这些线。

即：**几何定律（网格 + 帧 + 位对/parity/phase）在两类 INT 上通用，差别只在源集合**。
与 `REUSE_RULES.md §1.1`「INT_L 与 INT_R 完全相同」的块内分区结论一致。

## 6. 对 L1–L4 的定位

| 级别 | 状态 |
|---|---|
| L1 可查表 | 已有（`all_cells.json` / `law_cells`） |
| L2 可预测 | **达成（mux 区）**：给 family 与源即可算出全部 cell，无需查表 |

把同一套分析（`law_cells`，INT_L，`sense=1`，共 **172 个 family**）跑遍非 mux 区：

| 帧窗 | family 数 | 每源格数 | 结构 |
|---|---|---|---|
| 0–1 | 12（`CLK_L0/1`、`CTRL_L0/1`、`GFAN0/1`、`LH0/12`、`LV*`） | 2 或 4 | 位池 6–8 位，**不是**网格；待单独处理 |
| 2–7 | 32（`*6BEG*`、`*4BEG*`） | 2 | 位池 4 位（两个位对），**不是**简单网格；待单独处理 |
| 6–15 | 64（`*2BEG*`、`*1BEG*`） | 2 | **5×4 网格，已完全生成化** |
| 16–25 | 64（IMUX/BYP_ALT/FAN_ALT） | 2–4 | 6×4 网格，已完全生成化（§1–§3） |

### 8.1 帧 6–15 窗口：第二个完整定律

64 个 family，每个都是 **5×4 = 20 个源的网格**（与 20 个源数完全吻合，0 例外）：

* **axis1（4 个成员）**：帧 12–15，固定用位对中的一位；
* **axis0（5 个槽）**：帧 6–11，用位对中的两位组合；
* 每个源的 cell = (axis0 的 frame/bit) + (axis1 的 frame/bit)，2 格，唯一可逆。

组合自检（和 mux 区完全同构）：

```
位对：16 个，覆盖 0..31 的偶数对
parity：2 个
phase（axis1 取低位还是高位）：2 个
16 × 2 × 2 = 64  ←→  64 个 family，一一对应，最大重复 = 1
```

即 **帧 6–15 窗口与 mux 区共用同一套 (位对, parity, phase) 编址体制**，只是网格尺寸不同
（5×4 vs 6×4）、帧窗不同。这把「mux 区特例」升级为「INT tile 的通用编址体制」。

### 8.2 全域可逆性

172 个 family 全部满足：**同一 family 内没有任何两个源的 cell 集合相同**
（`唯一=True` 计 172/172）。所以 L4（差分反解 PIP）在整个 INT tile 上成立，
不只是 mux 区。

### 8.3 仍未生成化的部分

* 帧 0–1 的 12 族（时钟/控制）与帧 2–7 的 32 族（`*6/4BEG*`）：每源 2–4 格，
  位池 4–8 位，**不符合 5×4/6×4 网格判定**。它们更像「多节点图上的路径」编码
  （样例 `EE4BEG0`：`EE2END0=(3,8)+(3,9)` 同帧两位、`SS2END0=(3,8)+(5,11)` 跨帧跨位），
  需要专门分析。
* 所有族的 **源 → 槽位** 排列仍是数据（同 §4）。

## 9. 收尾：帧 2–7 与帧 0–1 的 44 个 family（2026-11-02 追加）

### 9.1 帧 2–7 的 32 个 BEG 族：**4×5 完全二分图，已定性**

用图论重做判定（每源 2 格 = 一条边，格 = 节点）：

| 指标 | 值（32/32 族一致） |
|---|---|
| 节点（位池） | 9 |
| 边（源） | 20 |
| 形状 | **完全二分图 K(4,5)**：4 节点 × 5 节点，20 条边全用满 |
| 度 | A 侧 4 个各连 5，B 侧 5 个各连 4 |
| 三角形 / 直径 / 二分 | 0 / 2 / 是 |

即 **每个源 = 一个 A 格 + 一个 B 格**，20 = 4 × 5，和帧 6–15 窗口的 5×4 网格同构。
之前 `--stats` 判为「非网格」，是因为按 `(frame,bit)` 字典序切两轴，
同帧两位的源（如 `EE2END0=(3,8)+(3,9)`）会被切错；按二分集切就完全规整。

几何签名（相对位偏移，减最小位）：

| 组 | 族数 | A（4 格） | B（5 格） | 例 |
|---|---|---|---|---|
| 1 | 16 | `(2,+1) (3,0) (5,0) (6,0)` | `(3,+1) (4,+1) (4,+2) (5,+3) (7,+1)` | `EE4BEG*`、`NE6BEG*` |
| 2 | 16 | `(2,+3) (3,+2) (4,+3) (7,+3)` | `(2,+2) (4,0) (5,+1) (5,+2) (6,+2)` | `NN6BEG*`、`NW6BEG*` |

两组互为镜像（帧序与位序反向）。族编号规律：**编号奇偶选位窗**（偶数 → 位基 8，奇数 → 位基 24），
**parity = 编号 div 2**。

### 9.2 帧 0–1 的 12 个时钟/控制族：**复合码，未闭合**

以 `CLK_L0` / `CTRL_L0` / `GFAN0/1` 为样本（每族 16 源、8 个位池格、48 个 cell）：

* **8 个源 = 2 格**（一条"选择"码，2-of-8）
* **8 个源 = 4 格**，且 8/8 都**包含**某个 2 格码 → 4 格 = 主码 + 附码
* 附码只有 4 种，各被 4 个源使用（`CLK_L0`：`{(0,25),(1,21)}`、`{(1,21),(1,24)}`、
  `{(0,25),(1,20)}`、`{(1,20),(1,24)}`）
* 4 格源**不等于**任意两个 2 格源之并（已测：0/8），所以附码不是独立可选项

`LH*`、`LV*`、`LVB*` 族更杂：12–18 个源、7–9 个位池格，**同时跨 parity 0 与 parity 1**，
即它们的 cell 落在 4 个不同的字上，不符合"一族一字 parity"的体制。

`--stats` 的网格判定对其中 3 族给出 `(4,3)`/`(6,3)`/`(3,6)`，但它们的边集**不连通**
（NetworkX `AmbiguousSolution: Disconnected graph`），所以不构成单一网格，只能算分量内的局部二分。

结论：这 12 族是**时钟/控制类的复合编码**（选择码 + 附码，可能对应时钟使能/旁路），
靠纯表分析到此为止，需要**仪器化实验**（在 Vivado 里逐一切换时钟源/BUFG/CE 组合，
看哪些位成组翻转）才能定出语义。已登记为开放项。

### 9.3 对「INT tile 通用编址体制」的修正

至此 INT_L 的 172 个 family 分成三类：

| 类 | 族数 | 结构 | 状态 |
|---|---|---|---|
| 网格族（6×4 / 5×4 / 4×5） | 160（64 mux + 64 BEG2/1 + 32 BEG6/4） | 源 = 行坐标 × 列坐标的全组合 | **生成化**（位对 × parity × phase 编址） |
| 复合码族 | 12（时钟/控制） | 主码 + 附码，跨 parity | 未闭合，待实验 |
| 源→槽位排列 | 全部 | 布线邻接顺序 | 数据（160 族各自一张） |
