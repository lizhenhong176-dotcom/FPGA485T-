# T75：用 INT 的「格宇宙/观测法」补 HCLK_CMT（19 个真实设计）

日期：2026-11-10　数据：本地 143 份 `.bit` + `.pips`（`_h48/_ha2/_ccio_out/_ck2/_ck3`）

## 1. 为什么换方法

T74 的结论是「MMCM/PLL 类不可构造」——因为 Vivado 拒绝把 MMCM 输出接进 `MUX_MMCM_CLKIN1`。
但 INT tile 的方法本来就不依赖「构造出想要的拓扑」，而是：

1. 收集**大量真实设计**；
2. 读它们 `.pips` 得到「选了哪个源」（符号级真值）；
3. 只看该 tile 类型的窗口，比对格随源变化的规律；
4. 剩下的位必须能归因，不能归因的记为残差。

HCLK_CMT 的窗口：左列簇帧 `22144..22157`、右列簇帧 `25090..25103`（各取 14 帧），只看 word 48 / 49 / 51。

## 2. 观测结果：143 份设计里 19 份用到 HCLK_CMT，8 种选择组合

| `CK_IN13` 源 | `MUX_MMCM_CLKIN1` 源 | 设计数 | 簇内格 |
|---|---|---|---|
| `MUX_CLK_PLL0` | — | 7 | `(0,49):28,31` `(0,51):25` `(1,51):31` |
| `MUX_CLK_MMCM0` | `CCIO1` | 6 | `(0,49):28,31` `(0,51):26,31` `(2,48):22` `(3,48):23` |
| `MUX_CLK_MMCM0` | — | 1 | （空） |
| `CCIO1` | `CK_BUFHCLK0` | 1 | `(0,49):28,31` `(0,51):29` `(1,51):27` |
| `CCIO0` | `CK_BUFHCLK0` | 1 | `(0,51):27,29` `(1,49):29,31` |
| `CCIO3` | `CK_BUFHCLK0` | 1 | `(0,49):30` `(1,51):27,28` `(3,51):26` |
| `CCIO2` | `CK_BUFHCLK0` | 1 | `(0,51):27` `(1,49):30` `(1,51):28` `(2,51):25` |

（坐标已归一化为「簇起点 = 0」；`(2,48):22` 表示帧 `base+2`、word 48、bit 22，下同。）

## 3. 得到的三条结论

### 3.1 `MUX_MMCM_CLKIN1` 的类别位（样本从 2 增到 107）

| CLKIN1 源 | 类别位 | 样本数 |
|---|---|---|
| `CK_BUFHCLK0/5` | `(2,48):21` + 槽位位 | 102 |
| `CCIO1` | `(2,48):22` | 6 |
| `CCIO0` | `(2,48):22`（同上，另有 `(2,48):24` 配套）| 1 |

⇒ **类别 = `(base+2, word48)` 的 bit21（BUFHCLK）/ bit22（CCIO）**，这条从 2 个样本升到 107 个样本。

### 3.2 `CK_IN13` 的源签名是「每源一套格」，不共用统一字段

6 个已知源给出 6 套**互不相同**的格：

```
CCIO0 → (0,51):27,29 + (1,49):29,31
CCIO1 → (0,49):28,31 + (0,51):29 + (1,51):27
CCIO2 → (0,51):27 + (1,49):30 + (1,51):28 + (2,51):25
CCIO3 → (0,49):30 + (1,51):27,28 + (3,51):26
MMCM0 → (0,49):28,31 + (0,51):26,31
PLL0  → (0,49):28,31 + (0,51):25 + (1,51):31
```

`(0,49):28,31` 是 CCIO1 / MMCM0 / PLL0 三者共有，但 CCIO0 / CCIO2 / CCIO3 没有 —— 说明它**不是**「已选通」标记，
更像是某个子字段的一部分。**这条与 INT 的「行序 36 种」同类：结构已知、映射属数据。**

### 3.3 顺带否证「CCIO0 也是 CLKIN1 源」

`u1_mmcm2mmcm` 的 `.pips` 里同时有 `CCIO0 ->> MUX_MMCM_CLKIN1` 与 `CK_BUFHCLK0 ->> MUX_MMCM_CLKIN1` 两条，
但它的簇内格是 `(2,48):21,26` = **BUFHCLK 类**。说明 `.pips` 会列出同一 mux 的多个候选边，
**不能只凭 `.pips` 判「选中了哪个源」**——T74 把 u1 当成 CCIO 类样本是错的，本轮更正（结论 3.1 已改用 m01 系列 6 份）。

## 4. 方法学教训（更新到 INT 那一套里）

INT 的成功靠「**同一 mux 在几千个 tile 里重复出现**」。HCLK_CMT 只有 14 个 tile/列，样本量天然小，
所以它的编码只能到「每源一套格」这层，拿不到 INT 那种生成式公式。这不是方法失败，是**数据量决定的**。

## 5. 未解与残差

- `CK_IN0..13` 共 14 个 mux × 48 源，目前只观测到 6 个源（CCIO0..3、MMCM0、PLL0），其余 42 源无样本；
- `MUX_CLK_13` 的 MMCM/PLL 源见 T48/T49（7+6 样本，另有 `(22144,51,25..27)+(22147,27..30,9/25)` 交叉开关图案）；
- 簇内仍有未归因位（如 CCIO2 的 `(2,51):25`、CCIO3 的 `(3,51):26`），本轮只登记不解释。
