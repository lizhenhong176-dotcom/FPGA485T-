## 2. 闭式公式（64/64 全对）

令块基址 `B = 31716`（本例 B = 块起点），则

```
frame = B + 70 + (k & 1) - 2 * ((k >> 3) & 1)
word  = 40
bit   = 15 - 4 * (k >> 4) - ((k >> 1) & 3)
```

64 个 `k` 全部吻合，零例外。

## 4. 与 T13 那张表的关系（收回一句错话）

T18 里我用错期望值（把 `L20_k2` 的 INIT 当成 `0x2`，实际是 `0x4`）描述过跨构建结果，这里更正：

- 结论：**索引空间必须锁引脚才能确定**，T13 表作废，以本表为准。

## 5. 对解码真实设计的意义

真实设计里，LUT 输入由 placer 分配到 `A1..A6` 的某一个。本表给的是**物理真值表**（索引位 = `A1..A6` 的组合）。
所以要得到逻辑函数，还需结合布线信息（哪条 net 进了哪个 `A` 脚）做一次置换：

```
逻辑 INIT[i] = 物理表[j]，其中 j 由 (I0..I5) → (A1..A6) 的实际分配决定
```

布线信息在 `v7_model.sqlite` 的 `site_pins` / PIP 里已有，所以解码链可以正确闭合。
