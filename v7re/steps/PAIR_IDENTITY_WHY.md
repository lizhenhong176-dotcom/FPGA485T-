## 0. 一句话结论（验收 A1）

> **「两个一样的」是同一张不含 tile 坐标的 `(tile_type, family, src)` 格表，被同一个解码循环套用到两个 tile 实例上得到的结果**：
> 编码层上，CRAM 地址 = 块基址 + 块内偏移，块内偏移由表直接给出、表里没有任何 `col/y/base` 列；
> 口径层上，解码器只在「表预测集合 **严格等于** 窗口实测集合」时输出该源（`v == obs`），
> 所以输出格集合按定义就等于实测格集合，`missing` 与 `extra` 两边由同一个集合构造。
> **`missing=0 且 extra=0` 因此是构造性恒真，不是两次独立观测吻合。**

三句可直接引用的版本：

1. 「一样」不是巧合：`law_cells` 的列是 `(tile_type, family, src_wire, frame_off, bit, sense, parity, src_index)`，**没有 col / y / base**（`v7re/scripts/fasm2bit.py:94-98` 载入；列名由本轮 `PRAGMA table_info` 复核，见 `t5_recheck.log`）。
2. 「零差」不是测量：`obs` 由域内实测位构造（`v7re/scripts/fasm2bit.py:270-271`），解码只输出 `pats[s] == obs` 的源（`:274`），故 `missing = extra = ∅` 恒成立，实测 **190/190** 实例满足（`t3_probe_out.txt:127`）。
3. 「两个」不是上限：30 个多实例组、**240 对**候选（`t3_probe_out.txt:8-10`），任取一对都是其中一条；本文件的主实例是 `NW6BEG0.WW4END0`（col12 vs col14）。

## 1. 对象锁定：「两个一样的」到底指哪一处（本任务的主要矛盾）

待验证提案原句（只读锚点 `STATUS.md:3557-3558`，即本条待办在 STATUS 中的原文记录）同时给了四个限定词：**同一个 family**、**相隔很远的两个列各构一个设计**、
**归一化后比格集合**、**判据仍是 missing=0 且 extra=0**。这四个词唯一指向表中的 ①。

| # | 「两个」指什么 | 判据实测 | 机制 | 证据 |
|---|---|---|---|---|
| **① 单 family 的归一化格集合**（本文件主答案） | 两个 tile 上同一 `(tt, family, src)` 的 L2 集合 `(frame_off, parity, bit)` | **31/31 全等**（其中 29 对同 tile_type、2 对跨 tile_type） | 表无坐标 + 解码恒等 → **构造性相同** | `pair_identity_check.md:70-78`；`t5_recheck.log` [1] 段（第 5 行） |
| ② 整窗（该 tile 全部 PIP 的位集合） | 两个 tile 的整个 26 帧窗口归一化后 | **6/30 组**全等；跨列仅 **1 对**（Δcol=2） | 两端被编入**同一 PIP 签名** | `t3_probe_out.txt:129-138,144` |
| ③ c08/c20 镜像表的两行 | CLB `INIT` 的帧行 | 镜像下 **2 行相同 / 2 行不同** | 索引→帧映射 σ（4-循环），**不是镜像** | `T55_OBJECT_JUDGMENT_INIT_VS_PIP.md:19`；`T1_REFERENT_RESOLUTION.md` §3-B |
| ④ 同一位被两条 PIP 重复计入 | 计数记录 | 设计级 **0 格**；模型级 5.57 条/格 | mux 互斥：一个 mux 只有一个源点亮 | `t3_probe_out.txt:91-93`；`pair_identity_check.md:165-168` |

**判定**：① 是唯一同时满足四个限定词的对象，因此是本文件解释的现象。
② 是**另一个对象**（整窗含该 tile 上其它 PIP 的位，不进入单 family 的 `cells_of`），其 6/30 与 ① 的 31/31 不可互相引用。
③ 属 CLB 配置位，与 PIP 无共同帧、无共同编码（`T55:19` 的 4 帧全部落在 `base+32..35`，无任何 INT 帧）。
④ 在 law 表层面成立、在本 artifact 的观测层被排除——两者必须分开写。

**关于「远列设计从未构建」这一事实**（不能含糊）：提案所述「`IMUX_L34` 在两个远距列上各构一个」**没有做过**。
现有数据里 `IMUX_L34` 共 9 个 tile / 5 个源（2+2+2+2+1），同源跨列组合 **0**（`t3_probe_out.txt:153-177`：四组全在 col32、同 base 32568、Δy=4；`WR1END1` 只有 col8 一个实例，n=1，无配对）。
但这**不改变本文件的答案**：①的相同在 L2 口径下是**结构性的**，换到任意两个远列（只要同 tile_type、同 `(family,src)`）结果只会相同——这恰恰是 §8 要说的问题（该实验无法失败）。

## 2. 编码层机制：为什么「本来就该一样」（预期相同）

【数据事实】三要素，逐条有代码位置：

| 要素 | 内容 | 位置 |
|---|---|---|
| 表键 | `(tile_type, family, src_wire, frame_off, bit, sense, parity, src_index)`——**无 col / y / base** | `v7re/scripts/fasm2bit.py:94-98`（`self.cells[(tt,fam,src)]`）；列名本轮 `PRAGMA` 复核 |
| 地址公式 | `frame = tile_base(col,band,y) + frame_off`；`word = 2*(y%50) + parity`；`bit = bit` | `fasm2bit.py:100-111`（`tile_base` / `word_of`） |
| 取格入口 | `cells_of(ttype, family, src)`——**三个入参都不含 tile 名/列/行** | `fasm2bit.py:113` |

归一化恰好减掉的就是那两个实例项（`pair_identity_check.py:121-134`）：

```
L1（去列）  : (frame - base, word, bit)
L2（去列+去行）: (frame - base, parity, bit)      # word 被压成 parity
```

于是对同一 `(tt, family, src)` 的任意两个 tile，L2 集合在代码层面**就是同一个对象**（`pair_identity_check.py:127-134` 的 docstring 已注明）。
**这不是拟合出来的规律，是表的形状决定的。**

【数据事实】独立于上述恒等的硬件证据（用来证明「表里确实没有列相关项」）：
`_full8.bit` 的 76 个 INT tile、**17 个列**、458 个置位格，窗口（26 帧 × 2 word）残差 **0 位**
（`t3_probe_out.txt:61-79`，逐列列出，合计残差 0）。若表里存在任何列相关项，远端列必然出现未建模的残余位。

反向读法同样成立：**L0 绝对位 0/31 对相同**（`t5_recheck.log` [1] 段（第 5 行））。即两个实例的绝对落点没有一对重合，
「一样」只发生在剥掉 `base` 与 `2*(y%50)` 之后——这正好是 §2 公式预测的方向。

## 3. 口径层机制：为什么 `missing=0 且 extra=0` 必然成立（表示层恒真）

三段推导，每段可对代码：

```
① obs   = { c ∈ domain(family) : bit(base+c.fo, word(y,c.parity), c.bit) = 1 }     # fasm2bit.py:270-271
② 输出  = [ s | cells_of(tt,family,s) == obs ]                                     # fasm2bit.py:274  （严格相等）
③ 故    extra = obs − cells_of(...) = ∅ 且 missing = cells_of(...) − obs = ∅       # 由 ② 直接推出
```

【数据事实】190 个 PIP 实例全部满足 `E == rel ∩ family域` 且 `E ⊆ rel`（`t3_probe_out.txt:127`）。

这解释了上游 T2 那条最关键的统计量为什么不可用作证据：
`t2b_pair_detail.py:80-81` 先取表常量 `E`（无 tile 坐标），再求 `E & rel` 放进 `pair[...]`；
而 `E ⊆ rel` 由 ② 保证，所以「每个组合内相对格集合种类 = 1」**不可能取到第 2 种**。
同一文件 `:87` 的 `assert rel == U`（窗口实测 == 各 PIP 格并集）才是独立校验——本轮把它扩到**全窗口、不预限域**后仍为残差 0（`t3_probe_out.txt:61-79`）。

**判据的证明力边界（本文件最重要的一句话）**：
`missing=0 且 extra=0` 证明「law 表与该位流自洽」，**不证明**「两个 tile 的两次独立观测吻合」。
把它当成后者，就会得到「同类型 tile 可移植已被证实」这种**超出证据**的结论。

## 4. 因果链（一段话，五个可复核环节）

```
① CRAM 布局：块基址 + 块内偏移；law 表无 col/y/base                     → 同一 feature 在同类型实例上块内地址相同
② 归一化：减 base、word→parity                                          → 剥掉的恰好是仅有的两个实例项
③ 解码：pats[s] == obs 严格相等                                          → 输出格集合 ≡ 域内实测集合（190/190）
④ 判据：missing/extra 两边由同一集合构造                                  → 恒为 0
⑤ 「两个」：一次 decode 遍历 76 个 tile，同一张表在两个窗口各命中一次       → 同一常量被打印两次
```

①② 是「预期相同」（编码层），③④ 是「口径必真」（表示层）。**二者同时成立**，这才是「为什么会同时出现两个一样的」的完整答案：
它是同一个必然性的两种表述，**不是两个独立证据互相印证**。

## 7. 为什么是「两个」而不是「N 个」

【数据事实】30 个多实例组，组大小 `{2:20, 3:2, 4:3, 5:1, 6:2, 13:2}`，组内对总数 **240**（`t3:8-10`）；
13-tile 组单独就有 `C(13,2)=78` 对（`t3:98-99`）。

所以「两个一样的」里的「两个」是**措辞/抽样**，不是结构上限：同一张表在 76 个 tile 上各命中一次，
打印出来是一串相同记录，任取两条就是「两个」。这也解释了为什么换个 family 再问一次，还会看到「两个一样的」。

## 8. 这条结论对实验设计的含义（比结论本身更重要）

**按原句设计的实验（远列各构一个 → 归一化 → 比格集合 → 判据 missing=0 且 extra=0）无法失败**：
只要两端的 `(family,src)` 相同、tile_type 相同，L2 就恒等（§2），`missing/extra` 就恒 0（§3）。
一个恒真的判据不构成对「可移植性」的检验。

有判别力的判据（现有数据已能给出读数，建议后续实验直接报这五项）：

| # | 判据 | 现有读数 | 它能证伪什么 |
|---|---|---|---|
| D1 | **L0 绝对位**必须全不同 | 0/31 相同（`t5_recheck.log`） | 若出现相同 ⇒ 两端真的同址（同 base 同 y），归一化叙事不成立 |
| D2 | **L1 只去列**：跨列同 y 时应相同 | 4/31 相同，且 4 对全部 `Δy=0/Δcol≠0`、签名 `frame`（`pair_identity_check.md:84-91`） | 检验「列只进块基址」这一条 |
| D3 | **全窗口残差**（26 帧 × 2 word，不预限 family 域） | 17 列 **0 位**（`t3:61-79`） | 若表缺列相关项，远端列必出残余位 |
| D4 | **错误归一化对照** | 0/30、0/30 vs 6/30（`t3:80-87`） | 若相同与公式无关，三档应同值 |
| D5 | **跨 tile_type** 同 key 比较 | 107/107 一致、0 不一致（`pair_identity_check.md:185`） | 这是唯一不是构造性的同 key 比较 |

## 11. 附录：三处口径更正（都附本轮复算，供主 Agent 决定是否回写）

### B.1 `1602` 与 `1598` 不是「一个对一个错」，是两种口径

- `1598` = INT_L 内去重后的 **格坐标** 数 `(frame_off, bit, parity)`（同一坐标被两个 family 共用只算一次）。
- `1602` = **`(family, cell)` 对** 数（跨 family 共用就重复计）。
- 差 **4** 可完全解释：INT_L 内有 3 个格被多个 family 共用 —— `(0,2,0)` 被 2 family、`(0,9,0)` 被 2 family、`(1,6,0)` 被 3 family，
  多计 `1+1+2 = 4`（本轮 sqlite 查询，见 `t5_recheck.log` [3]）。
- `8900` = `(family, src)` → 格 的**引用条数**。

建议统一写：**1598 个格坐标 / 1602 个 `(family,cell)` 对 / 8900 条 `(family,src)` 引用**
（`8900/1602 = 5.56`，`8900/1598 = 5.57`——§105 的 5.56× 与 T4 的 5.57× 是同一比值的两个分母，不是矛盾）。
`STATUS.md:3612`（§105 表内「1602 格」）与 `pair_identity_check.md:198`（「1602 应为 1598」）各自的说法都只说对了一半。

### B.2 T4 §5.1 的 INT_R 行（1118 / 5444）不是「law 全量」

- 直接查库：INT_R `sense=1` 共 **8900** 条引用、**1598** 个格——与 INT_L 完全相同（`t5_recheck.log` [2]）。
- 脚本里 `ref_stats` 只给 INT_L 补了 `fams |= set(m.law)`；而 `cells_of` 对 `MUX_PREFIX`（`fasm2bit.py:38`）开头、但不在 `m.law` 里的 family **返回 None**（`fasm2bit.py:115-118`），循环里 `if not cs: continue` 跳过。
- INT_R 有 **48** 个独占的 mux family（名为 `IMUX0`…`IMUX47`，连续无缺号；INT_L 侧为 `IMUX_L0`…`IMUX_L47`；`BYP_ALT*`/`FAN_ALT*` 两侧同名、不在此列），合计 **3456** 条引用 / **480** 个格（每 family 72 引用 / 10 格）。
  INT_R 另有 8 个非 mux 的独占 family（`CLK0`/`CLK1`/`CTRL0`/`CTRL1`/`LV0`/`LV18`/`LVB0`/`LVB12`，INT_L 侧带 `_L` 后缀），不属于本行的跳过口径。
- 算术吻合：`8900 − 3456 = 5444`，`1598 − 480 = 1118`——正是 T4 表的 INT_R 行。
- 结论：该行是「**非 mux family 子集**」，不是 law 全量。引用位复用结论时**只用 INT_L 行**（已与 DB 逐值吻合）。

### B.3 计数惯例：190/191 与 76/77

`t2b_full8_decode.fasm` 的非空行 **191 = 190 条 PIP + 1 条 CLB INIT**（`SLICE_X12Y20.ALUT=0x…01`，`t3:4`、`pair_identity_check.md:17`）；
tile 数 **76** 个 INT tile（INT_L 70 / INT_R 6）+ 1 个 SLICE = **77**。
`STATUS.md:3550`、`:3582` 的「191 条 PIP / 76 个 INT tile」把两种外形相同的行按同一口径数成一批，应统一写
**190 条 PIP / 76 个 INT tile**，CLB INIT 行单列。本文件不改那两行原文，仅在此登记。
