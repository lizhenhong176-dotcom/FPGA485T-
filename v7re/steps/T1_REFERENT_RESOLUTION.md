# T1 · 指代解析：「两个一样的」是哪一处成对相同

> 本文只做一件事：把用户原句里的「两个一样的」落成 **A / B / C 三条互斥候选**，给每条写出
> ①可执行判定条件 ②现有数据中的具体记录位置 ③若成立应观测到什么 ④一行机制（口径层 / 编码层）
> ⑤证伪依据。**不代替用户选定**——选定只需一句话（§5 问题单，每问一词可答）。
> 用户不答时，按 §6 的默认口径按 A 解读，并在引用本文的文档里显式标注。

【数据事实】本文所有数字均来自 `v7re/scripts/t1_referent_probe.py` 一次运行（exit 0），
输入为仓库内既有产物：`_xcheck_local/*.bit`、`v7re/steps/clb_init_locked_map.json`、
`v7re/steps/t2b_full8_decode.fasm`、law 库 `law_cells` 表。复算命令见 §7。

---

## 1. 先把原句的限定词拆开（歧义是从哪里长出来的）

| 原句限定词 | 约束 | 它排除了什么 |
|---|---|---|
| 同一个 family（比如 IMUX_L34） | 比较对象是 **family**，不是 tile、不是网线 | 「同一个 tile 的两个构建」 |
| 在相隔很远的两个列上各构一个设计 | **两份独立 bitstream**，绝对坐标不同 | 同一列、同一次构建内的两个 tile |
| 归一化后 | 先消去绝对坐标再比 | 「绝对落点相同」这种平凡相同 |
| 比格集合 | 比的是 features → 格集合 | 比字数、比行数、比 bit 向量 |
| 判据仍是 missing=0 且 extra=0 | 双向零差 | 「包含 / 超集」式的相同 |
| **为什么会同时出现两个一样的** | 一次观测里出现 **两份相同的东西** | — |

前三行把对象钉在「两份设计产物的归一化格集合」上，**唯独最后半句没有钉住「两个」的量词所指**：
「两个」既可以是两份设计产物，也可以是镜像对照表里的两行，也可以是同一批位在计数时被算了两遍。
这三种「两个」的机制互不相同，**锁错则整份解释作废**——这就是本任务的主要矛盾。

---

## 2. 三条候选总览

| 候选 | 「两个」指什么 | 相同的层面 | 现有数据能否直接观测 | 现状 |
|---|---|---|---|---|
| **A** | 两份设计的归一化格集合 | 位级（编码） | 否（该 two-column 设计尚未构建）；但同构现象有现成实例 | 待产生，实例已成立 |
| **B** | c08/c20 镜像对照表里的**两行** | 帧序 + 位集合 | 是 | 已观测：2 行相同 / 2 行不同 |
| **C** | 同一位被两条 PIP **重复计入** | 计数口径 | 是 | 已观测：按源累加膨胀 5.56×，物理位不重复 |

三者互斥性：A 的「两个」是**产物**，B 的「两个」是**表行**，C 的「两个」是**计数项**。
判别只需一问（§4），不必三条都做。

## 3. 逐条候选

### 候选 A：两份设计的归一化格集合相同

**现象定义**：在 col c₁ 与 col c₂（相隔很远）各构一个设计，两份产物各自 decode 出 IMUX_L34 的
feature → 相对格集合；归一化（减去各自 tile 基址、把行折成行内偏移）后两份集合逐元素相等，
missing=0 且 extra=0。

**判定条件（可执行）**

1. 两份产物各跑 `fasm2bit --decode`，只保留 `INT_*` 行，按 `(family, src)` 分组，
   取格集合 `(frame_off, parity, bit)`；
2. 对每个同时出现在两份产物里的 `(family, src)` 键，算 `missing = |S₁−S₂|`、`extra = |S₂−S₁|`；
3. 判据：**所有共有键** 的 missing=0 且 extra=0，且**共有键数 > 0**（无共有键时判据空洞）。

**现有记录位置**

- 提出该实验的原句在 `STATUS.md:3557-3558`（「下一步若要更硬的同类-tile PIP 证据：选同一 family
  （如 IMUX_L34）在两个远距列上各构一个设计，比对归一化后的格集合（判据仍是 missing=0 且 extra=0）」）；
  支撑句在 `STATUS.md:3550`、`STATUS.md:3554`。
- 同构现象（A 的 CLB 版本）已实测：`v7re/steps/T54_INIT_TILE_TYPE_CHECK.md:19`
  「CLBLM_R（col 33）与训练用的 CLBLM_L（col 20）归一化后完全一致」；
  两列块基址见同文件 `:14`（col33→31924、col16→31680、col20→31752）。
- A 的 PIP 版本已实测（跨 14 个 tile）：`v7re/steps/T56_SAME_TYPE_TILE_PIP.md:152-157`
  （`WW4BEG0/WW4END0`：14 个 tile 有 **14 种绝对落点**，归一化后 **只有 1 种相对格集合**）。

**若成立应观测到什么（【数据事实】层）**

- 两份产物里同一 `(family, src)` 的 `(frame_off, parity, bit)` 集合逐元素相等；
- 而**绝对**位 `(tile_base(col,y)+frame_off, 2*(y%50)+parity, bit)` 在两列不同（基址不同）；
- 即「同一批相对格、两套绝对坐标」——两侧同时成立才算 A 成立。

**一行直接机制**

- **口径层**：归一化 = 减去 `tile_base(col, y)`、行号折成 `y % 50`；这一步把 col 与 y 的绝对值全部消掉，
  只留下「块内第几帧 / 行内第几个 word / 第几位」三个局部量。
- **编码层**：CRAM 地址 = 块基址 + 块内相对帧，`word = 2*(y%50) + parity`；PIP 的格只由
  `(tile_type, family, src)` 决定，编码里**没有 col 分量**——列信息只进块基址。
  两条合起来：任何两个同 tile_type 的块，只要基址不同，同 family 同源的格必然「相对相同、绝对不同」。

**证伪 / 排除依据（必须一起看，否则 A 会被误判成立）**

- 【数据事实】现有数据里 **IMUX_L34 没有跨两个远列的同源实例**：`BYP_BOUNCE0 {X32Y10, X32Y6}`、
  `FAN_BOUNCE7 {X32Y12, X32Y8}`、`SL1END1 {X32Y11, X32Y7}`、`SR1BEG_S0 {X32Y13, X32Y9}` 都在 col 32；
  `WR1END1 {X8Y20}` 在 col 8 且源线不同。IMUX_L34 共 **9 tile / 5 源，同源跨列组合数 = 0**
  （复算：`t1_referent_probe.py` §5；来源 `v7re/steps/T56_SAME_TYPE_TILE_PIP.md:188-198`、
  `v7re/steps/t2b_pair_table.md:21-24`）。
- 因此**按 (family, src) 口径，IMUX_L34 的两列实验会得到「共有键 = 0」，判据空洞**；
  按 **family 口径**（把同 family 所有源的格并起来）则实测**两列不同**：
  col 8 并集 4 格 vs col 32 并集 7 格，`missing 1 / extra 4`（同上 §5）。两种口径都**不会**给出
  missing=0 / extra=0——除非构建设计时把两列的 IMUX_L34 绑到**同一条源线**上。
  【推断】这是 A 能否被判定的前置条件，不是 A 的反例。
- 若 A 被解读为 family 口径，则「归一化后相同」必须证明同一 family 的两列**源线集合也相同**，否则比的是不同的 mux 输入。

### 候选 B：c08/c20 镜像对照里的两行相同

**现象定义**：在做 c08（CLBLL_L/SLICEL）与 c20（CLBLM_R/SLICEM）的帧序对照时，
镜像映射（rel → 67−rel）表里出现**两行逐位相同**，另两行不同（于是「看起来像镜像、又不像镜像」）。

**判定条件（可执行）**

1. 取两个构建在 word 40 的逐帧位集合 `S₀₈[rel]`、`S₂₀[rel]`（rel ∈ 32..35）；
2. 对给定映射 μ 算 `missing = |{(μ(f), b)} − {(g, b)}|`、`extra` 反之；
3. 判据：**某映射下 missing=0 且 extra=0 才算相同**；「有几行相同」= 满足 `S₀₈[f] == S₂₀[μ(f)]` 的帧数。

**现有记录位置**

- 逐帧位数与集合：`v7re/steps/T55_OBJECT_JUDGMENT_INIT_VS_PIP.md:19`（c20 为 7/14/10/15、c08 为 10/15/14/7，均 46）；
  `v7re/steps/T54_INIT_TILE_TYPE_CHECK.md:28-31`（c08 实测位）。
- 两次被否掉的映射：`T54_INIT_TILE_TYPE_CHECK.md:37`（帧序号 XOR 2：missing 9 / extra 9 → FAIL）、
  `:38`（帧镜像 rel→67−rel：missing 7 / extra 7 → FAIL）。
- 本轮复算：`t1_referent_probe.py` §2 枚举全部 24 种双射，唯一零差的是
  `μ = {32:34, 33:35, 34:33, 35:32}`（4-循环 0→2→1→3→0）；identity 13/13、XOR2 9/9、mirror 7/7，
  与 T54 两个数字**逐位吻合**。

**若成立应观测到什么**

- 镜像表里恰好 **2 行**逐位相等、2 行不等（即「两个一样的」= 这两行）；
- 相等的是 `c08 rel34 vs c20 rel33` 与 `c08 rel35 vs c20 rel32`（【数据事实】已复算成立）。

**一行直接机制**

- **口径层**：镜像 `67−rel` 把 rel 34 映到 33、35 映到 32，恰好与真映射 σ 在这两帧上重合，
  所以这两行「看起来一样」；而 σ 在另两帧（32→34、33→35）与镜像相反，于是另两行不等。
- **编码层**：真映射不是镜像而是**帧表置换 σ = {0:2, 1:3, 2:1, 3:0}**，即 4-循环
  `0→2→1→3→0`（绝对帧 `32→34→33→35→32`），由两张 INIT 表的 64 个索引逐位相同、仅帧号不同所决定
  （`clb_init_locked_map.json` 的 `orders.SLICEM` / `orders.SLICEL`；复算：bit 差异索引 **0** 个）。

**证伪 / 排除依据**

- 换成 σ 后 46/46 位相等（missing 0 / extra 0）→「镜像是正确映射」被**直接否证**；
- XOR2 与 σ 只在帧 {32,33} 重合、镜像与 σ 只在帧 {34,35} 重合 → 两次 FAIL 的 9/9 与 7/7 是同一种
  「部分重合」的算术后果，不是两个独立缺陷；
- 因此 B 若成立，其机制**不是**「帧被镜像」，而是「σ 是 4-循环、镜像只是它的两条对角线」。

### 候选 C：同一批位被两条 PIP 重复计入

**现象定义**：统计格数时，同一物理格被算进多个 `(family, src)` 条目，于是「同一批位出现两次」，
两份统计看起来「一样」（同一批位、两个条目）。

**判定条件（可执行）**

1. 取 law 库 `law_cells`（`tile_type='INT_L'`、`sense=1`），分别算
   `|∪(family,cell)|` 与 `Σ_(family,src) |cells|`；
2. 判据：`Σ > |∪|` ⇒ 存在按源重复计数；再看同一 `(family, cell)` 被几条 src 共用；
3. 若要判「同一 tile 内两条 PIP 共用同一位」，则在**同一 tile** 内比较两条 PIP 的绝对位是否相同
   （不是比较相对格）。

**现有记录位置**

- 表结构无 tile 坐标：`v7re/steps/T56_SAME_TYPE_TILE_PIP.md:24`（键 = `(tile_type, family, src_wire,
  frame_off, bit) + sense/parity/src_index`，**无 tile 坐标**）。
- 按 (family, src) 累加的跨 tile 统计：`T56_SAME_TYPE_TILE_PIP.md:136-146`
  （去重键 117 个、≥2 tile 的组合 31 个、220 格、不一致 0、**族内 src 撞车 0**）。
- 本轮复算（law 库）：不同 `(family, cell)` **1602** 个；按 `(family, src)` 累加得 **8900** 个格
  → **膨胀 5.56 倍**；每格被 N 条源共用：`{1:4, 2:5, 3:26, 4:909, 5:384, 6:134, 12:12, 18:128}`。

**若成立应观测到什么**

- 同一 `(family, cell)` 出现在多条 src 的格集合里（已观测：8900/1602，绝大多格被 4–6 条源共用）；
- 但**同一 tile 内**两条不同 src 的格集合不相交（族内撞车 0）→ 物理位不重复，重复只发生在
  「把一个 tile 的 1602 个格按源展开成 8900 条」的**计数口径**上。

**一行直接机制**

- **口径层**：mux 的格是**共享**的（一个格参与多条源的选择），按「源」展开必然把共享格重复计入；
  正确口径是「先按 tile 取并集、再跨 tile 比」。
- **编码层**：PIP 的 sense 位分两类（sense=1 参与译码、sense=0 为清零位），
  `law_cells` 每行是一个 `(family, src, 格)` 三元组，**同一格可对应多行**——表本身不保证格唯一。

**证伪 / 排除依据**

- 若 C 的「重复」是指同一 tile 内两条 PIP 落在同一物理位，则被 **族内 src 撞车 = 0** 否证；
- 若指跨 tile 的「同一格」，那不是重复计数，而是同一相对坐标对应不同物理位（块基址不同）——
  这正是 A 成立的原因，两件事不能混。

## 4. 判别树（一步分辨，不用三条都做）

```
问：「两个一样的」说的是哪两个？
├─ 两份设计产物之间            → A（再问口径：family 级 / (family,src) 级）
├─ 一张对照表里的两行          → B（再问：哪两行 / 哪两帧）
└─ 同一批位被算了两遍          → C（再问：Σ 还是 ∪）
```

三条候选各自的最小可执行检验（任一即可把候选钉死或排除）：

| 候选 | 一条命令/一次观测 | 期望 |
|---|---|---|
| A | 对两份 fasm 按 `(family,src)` 求格集合差 | 共有键 > 0 且 missing=extra=0 |
| B | `python v7re/scripts/t1_referent_probe.py` §2 | 唯一零差映射 μ={32:34,33:35,34:33,35:32}；镜像仅 2 行相同 |
| C | 同一脚本 §4 的 law 库统计 | 1602 vs 8900，膨胀 5.56×；族内撞车 0 |

## 8. 顺带发现：「191 条 / 77 tile」的算术来源已被定位（与 C 同型的计数口径错）

【数据事实】`STATUS.md:3550` 与 `:3582` 写「191 条 PIP 横跨 **77 个 INT_L tile**」，同一文件
`:3598` 写「76 tile」，`T56:60/:68` 实测 76 tile = INT_L 70 + INT_R 6。三处不一致，本轮把行构成拆开：

```
非注释行 191 = PIP 行 190 + 非 PIP 行 1
非 PIP 行：SLICE_X12Y20.ALUT=0x0000000000000001      ← CLB INIT，不是 PIP
PIP 行 tile：76 {'INT_L': 70, 'INT_R': 6}
全部行 tile：77（多出的 ['SLICE_X12Y20']）
```

- **191** = 190 条 PIP **+ 1 条 CLB INIT**（`SLICE_X12Y20.ALUT=…`）；
- **77** = 76 个 INT tile **+ 1 个 SLICE tile**（`SLICE_X12Y20`），且 76 里 INT_L 只有 70，另有 6 个 INT_R；
- 两个数字来自「把整份解码文件的行都当作 PIP 行来数」这一个口径。【推断】这是两个数字的直接来源；
  【数据事实】支撑它的是行构成的整数关系 `191=190+1`、`77=76+1` 与唯一那条非 PIP 行的实测内容。
- 这正是候选 C 的同一错误形状：**同一文件里两种对象（PIP 行 / CLB INIT 行）外形相同（`tile.x=v`），
  不声明口径就会把两类东西数成一批**——「两个一样的」若指这类记录，机制就在这一行。

修正建议：统一写「190 条 PIP / 76 tile（INT_L 70、INT_R 6）」，CLB INIT 行单独列。
