# T64：BRAM PIP 编码实测 —— 成对位（两半区各一位）

日期：2026-11-09
实验：`/opt/lzh/v7re/work/bram4`（9 个构建，同一 RAMB36E1 站点，`-part xc7vx485tffg1157-3`）
对照：`b_base`（EN/RST/REGCE 全接 0）vs 各 `b_<pin>`（对应引脚接 1），其余逐字相同。

## 1. 结果

| 切换 | 方向 | 格（frame, word, bit） | 格数 |
|---|---|---|---|
| ENARDEN | 新增 | (1019,13,16) + (1019,16,16) | 2 |
| ENBWREN | 新增 | (1019,13,19) + (1019,16,13) | 2 |
| REGCEAREGCE | **移除** | (1012,14,27)+(1013,14,26)+(1016,14,27)+(1017,14,26) | 4 |
| REGCEB | **移除** | (1012,14,29)+(1013,14,28)+(1016,14,29)+(1017,14,28) | 4 |
| RSTRAMARSTRAM | 新增 | (1019,13,20) + (1019,16,12) | 2 |
| RSTRAMB | 新增 | (1019,13,21) + (1019,16,11) | 2 |
| RSTREGARSTREG | 新增 | (1019,13,24) + (1019,16,8) | 2 |
| RSTREGB | 新增 | (1019,13,27) + (1019,16,5) | 2 |

**没有任何一族是 1 格；最少 2 格，REGCE 类 4 格。**

## 2. 结构解读

- EN/RST 族：两个格在**同一帧（1019）的两个 word（13 与 16）**上 —— 一个 RAMB36 由两个 RAMB18 半区组成，
  同一控制信号在两个半区各占一位，这与"成对位"一致；
- REGCE 族：4 格 = 2 个半区 × 2 个帧（1012/1013 一对、1016/1017 一对），
  且方向**反了**（REGCE=1 时格消失 = 缺省态表示 1）。

## 3. 与离线形状预测的对照

`tile_pip_lawscan` 对 BRAM_L 的预测：每源格数 `{1: 220, 2: 130}`（共 63 族 / 5.6 源每族）。
实测 8 族全部 ≥2 格（2 或 4），**落在预测的 2 格档**；1 格档应为 GND/常量绑定的 always 类，本次未触及。

## 4. 与 INT / DSP 的三方对照

| tile | 一条 PIP 几位 | 寻址方式 | 复用（多源共格） |
|---|---|---|---|
| INT | 2 或 4 | 6×4 二维（行+列码） | 有，平均 5.56 源/格 |
| DSP | 1（少数 2） | one-hot | 无 |
| **BRAM** | **2（REGCE 类 4）** | **半区配对 one-hot** | 无（每源独占自己的位对） |

结论：**BRAM 也没有"复用"问题** —— 它的多位不是因为多源共用，而是因为一个 RAMB36 物理上由两个半区组成。
这与 INT 的多位成因（多源共享）在机制上完全不同。
