# T77：清除位（sense=0）与 4 个「异常族」的定案

日期：2026-11-10　离线分析为主，含 1 次（失败的）构建尝试

## 1. 结论先说

| 项 | 结论 |
|---|---|
| 4 个「异常族」（`LH0`/`LVB_L0`/`LV_L0`/`LV_L18`）| **不是异常**，是 prjxray 真实声明的跨时钟树源，routing 模板里没有 |
| `sense=0` 清除位 | 6,528 行（INT_L/INT_R 各 3,264），但去重后 **280 个格全部 ⊂ sense=1 格集**，无需单独的清除知识 |
| 清除是否已被写入器处理 | 是 —— `fasm2bit.py` 按「族内互斥先清全部候选源再点亮」实现 |

## 2. 4 个「异常族」的定案

之前记的是「4 族各多一条常量线，根因未定」。查 `prjxray_ref/artix7/segbits_int_l.db` 原文：

```
INT_L.LH0.LH12      01_54 01_56
INT_L.LV_L0.LH12    00_05 01_06
INT_L.LV_L18.LH0    00_01 01_02
INT_L.LV_L18.LH12   01_02 01_08
INT_L.LVB_L0.LVB_L12 00_51 00_54
```

即 prjxray **本身就声明**这些跨时钟树源。routing 模板（Vivado `get_pips` 导出）里没有这些边，
所以「law 比模板多」是 prjxray 与 Vivado 的口径差，不是导入错误、也不是数据异常。

- 172 族里 **168 族**与模板完全一致（含 6 个时钟族 `CLK_L0`/`GFAN0` 等全等）；
- 剩下 4 族的差集恰好是上表 5 条跨树源。

**定案：无需构建验证，撤掉「异常」这个标签。**

## 3. `sense=0` 清除位的真实含义

```
总量        : 6,528 行（INT_L 3,264 + INT_R 3,264）
INT_L 去重格: 280
与 sense=1 交集: 280 / 280   ← 全部重合
```

分布：`BYP_ALT0..7` 与 `FAN_ALT0..7` 各 48 行最集中（16 族共 768 行），
它们是「该族各源必须置 0 的伴随位」，其格本身属于**同一族其他源的置位格**。

因此：

- 不存在「只清不置」的独立位；
- 写 FASM 时只需 **把该族全部候选源的格清 0，再置目标源** —— 这已覆盖 280 个清除格；
- `fasm2bit.py` 现状正是如此（族内互斥清空）。

## 4. 一次失败的「干净切换」构建（如实记录）

想用「同一 LUT 的同一输入脚，改由引脚 vs 改由另一 LUT 驱动」来观察清除行为：

- `_sw1`：`SLICE_X12Y20/A6LUT`，`I1 = a`（引脚 AF25）
- `_sw2`：同 LUT，`I1 = w`（`SLICE_X12Y21/A6LUT` 的输出）
- 两构建均成功（`/opt/lzh/v7re/work/sw01`）

差分：**移除 28 格 / 新增 110 格**，涉及帧 31784–31787（16 格/帧）加多帧 INT 位。

**这不能作为清除测试**：`_sw2` 多了整个 LUT 和它的走线，变量不唯一。
要干净测清除，需要「同一 mux 家族内换源、且不增删逻辑」，那属于 M2 语料的做法
（一次只差一条 PIP），现有 `_m2` 目录最小差分也有 16 格，同样不满足。

**判断：清除正确性由 T8b 已有证据覆盖** —— `_c0` 改写 78 位后与 Vivado 的 `_c3`
逐帧比对 **50,172 / 50,176 相同（99.99%）**，其中必然包含多个族的清位动作。

## 5. 对主线的影响

- INT 的 172/172 从「有 4 个悬案」变成 **真正无悬案**；
- 「改写会残留旧位」的风险被排除（族内清空 + 280 清除格 ⊂ 置位格集）；
- 剩余唯一未验证项是**实例级的穷尽反证**（现 23.66%），属采样广度问题，不是规律问题。
