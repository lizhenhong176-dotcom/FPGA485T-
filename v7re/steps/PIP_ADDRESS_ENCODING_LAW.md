# Virtex-7 INT tile PIP 地址编码律

**—— 一个可计算、可验证、带明确边界的位流寻址模型**

版本 1.0 · 2026-11-08 · 对象：xc7vx485t (ffg1157-3 / ffg1761-2)，INT_L / INT_R tile

---

## 摘要

本文给出 Xilinx 7 系列 INT tile 中可编程互连点（PIP）配置位的**地址编码律**：
给定一个 mux（family）与它的一个输入源（source），其占用的配置位坐标
`(frame_off, parity, bit)` 可以由 **5 条固定规则**算出，唯一无法计算的部分
（类内成员序）被明确界定为「布线邻接事实」，并证明它不可能由更小的信息量表示。

三条结论此前未见公开报道：

1. **列码编码线长类别**：列码 `{0001,0010}` 恒为跨 tile 长线（DOUBLE），
   `{0111,1011}` 恒为 tile 内短线（SINGLE）。**768/768 条源，零例外。**
2. **方向类 → 列的映射由 mux 编号的 `(i//8)` 奇偶唯一决定**（2 种，48/48）。
3. **`(i//8)` 奇偶同时决定** LOGIC/BOUNCE 的行序（64/64）、位对偏移与 parity（48/48）、
   方向类到列的分配（744/744），三项独立命中，提示「每 8 个 mux 为一个版图分组、奇偶互为镜像」。

反向结论同样明确：**行（类内成员序）不可导出**，48 个族有 36 种映射，且几何路线（模板元数据、
RapidWright 坐标）已排除。编码结构可算，接线顺序是版图事实。

## 2. 编码结构

### 2.1 地址基线

```
frame = block_base(col, region) + frame_off
word  = 2 * (y % 50) + parity      # ≥ 50 时再 +1
bit   = 0..31
```

### 2.2 五个 slot 之外的行（r4 / r5）

24 个源 = 4 行方向线 × 4 列 + 4 个逻辑源 + 4 个 bounce 源。

| 行 | 内容 | wire kind |
|---|---|---|
| 0–3 | 16 条方向线 | DOUBLE 或 SINGLE |
| 4 | `LOGIC_OUTS` ×3 + `GFAN0` | OUTBOUND / BOUNCEIN |
| 5 | `BYP_BOUNCE` ×2 + `FAN_BOUNCE` ×2 | BOUNCEACROSS |

### 2.3 规则 1：方向类由线名判定

| 类 | 名字模式 | 例 |
|---|---|---|
| DIAG | `NE/SE/NW/SW` + 数字 | `NE2END0` |
| ORTH | `NN/SS/EE/WW` + 数字 | `NN2END0` |
| R | `NR/SR/ER/WR` + 数字 | `NR1END0` |
| L | `NL/SL/EL/WL` + 数字 | `SL1END0` |

### 2.4 规则 2：列由 `(i//8)` 奇偶决定

```
(i//8) 偶 → DIAG:1  ORTH:2  R:7   L:11
(i//8) 奇 → DIAG:2  ORTH:1  R:11  L:7
```

**独立复核：48 族 × 16 条布线源 = 744 条可归类 feature，列码 744/744 命中，零例外。**
（另有 24 条源名不带方向类别，如 `SR1BEG_S0`，不参与此检验。）

### 2.5 规则 3：列码 = 线长类别

| 列码 | 二进制 | 列帧 | 线长 |
|---|---|---|---|
| 1 | 0001 | 25 | DOUBLE |
| 2 | 0010 | 24 | DOUBLE |
| 7 | 0111 | 23,24,25 | SINGLE |
| 11 | 1011 | 22,24,25 | SINGLE |

**768 条布线源（4 行 × 4 列 × 48 族）全部符合，零例外。**

### 2.6 规则 4：位对与 parity 闭式

```
g = i // 16 ;  h = (i // 8) % 2
minbit = 8 * (i % 4) + 2 * g + 2 * h
parity = 1 if (i % 8) >= 4 else 0
```

**48/48 命中。**

### 2.7 规则 5：位分配

```
列帧始终用 primary 位 P
行 16/17/20/21 用 P
行 18/19 用孪生位 S（S = P±1）
LOGIC/BOUNCE 行序：(i//8) 偶 → r4=LOGIC, r5=BOUNCE；奇 → 反之
                     且 BYP_ALT 恒 r4=LOGIC、FAN_ALT 恒 r5… （见 §4.2）
```

## 3. 复用机制：这是寻址，不是压缩

24 个源映射到 6 行 × 4 列的格，平均每格被 **5.56** 个源共用（最大 18）。原因不是"压缩"，
而是**坐标编码**：

- 同一行的 4 个源共用该行格，靠列格区分；
- 同一列的 6 个源共用该列格，靠行格区分；
- 一个源 = 一个行格 + 一个列格（列码权重 1 或 3）。

与内存的行列选通同构：**用 6+4 个物理位编码 24 个选择**。

推论（已实测）：

- 每源 2 格或 4 格（1 行格 + 1~3 列格）；
- 2 格源的候选组合数远大于 24 → **单靠位无法判定，必须结合 family 上下文**；
- 4 格及以上 pattern 在整芯片尺度下 0 误判（546 条未用候选 0 命中）。

## 4. 验证方法

### 4.1 五条纪律

1. **先离线**：凡能用 `law_cells` / 布线模板 / RapidWright 器件数据验证的假设，不上 Vivado；
2. **单变量 + 回读断言**：显式 `-part`，回读 `SITE/BEL/INIT`，并比对两次设计的 PIP 列表是否逐行相同；
3. **单最小项枚举**：测 64 位字段时用 1 个基线 + 64 个单点，禁用位平面法（会被综合优化破坏）；
4. **集合级自校验**：用训练集外的随机值，判据 `missing=0 且 extra=0`，禁止抽样；
5. **交叉自证 + 负对照**：两个脚本、两批构建；同配置重跑差分必须为 0。

### 4.2 关键证据链

| 结论 | 样本量 | 判据 |
|---|---|---|
| 列码 ⇔ 线长类别 | 768 | 全量枚举，0 例外 |
| 方向类 → 列 | 48 族 | 全量，2 种签名 |
| 位对 / parity | 48 族 | 闭式，0 例外 |
| LOGIC/BOUNCE 行序 | 64 族 | 全量 |
| 6×4 网格普适 | 64 族 | 每族 (parity,bit) 组合数恒 2、列部分格数恒 4 |
| PIP 解码精确率 | 4 个真实设计 | 精确 100%（旧判据 70.9%） |
| 多 PIP 线性叠加 | 48 条同时开启 | 预测位 56/56 全 1；sense=0 位 48/48 全 0 |
| 写入幂等 | 4 个设计 | 位流→FASM→位流 逐字节相同 |

## 5. 边界：什么不能算

### 5.1 行（类内成员序）不可导出

「同一方向类里的 4 条线谁落在 0–3 行」无法由任何编号导出。把 (类, 方向) → 行 的映射
按族分组，48 个族给出 **36 种不同的映射**：

```
2 族共用：{0,4} {3,7} {8,12} {11,15} {16,20} {19,23}
          {24,28} {27,31} {32,36} {35,39} {40,44} {43,47}
其余 24 族各自一套
```

只有 `i % 8 ∈ {0,3}` 的族与 `i+4` 共用映射，其余每族独立。

### 5.2 为什么它不是「规律还没找到」

- 按 8 段分组，段内仍有 2 种变体；按 4 族分组，仍有 2 种；
- 各段首族行序既非循环移位、也非常数置换；
- 16 张基础表两两之间没有共有源线（交集为 0）；
- **几何路线已排除**：`pip_defs` 的 4 个字段中第 3 字段 3737 条全为 0，不含几何/顺序信息；
  RapidWright 的 `Wire`/`PIP` 没有坐标 API（只有所属 `Tile` 的 XY）。

结论：行序与 `tileconn` 邻接表是同一份信息（版图物理邻接），
位流只是忠实记录。**此处不存在可压缩的规则。**

### 5.3 数据量对比（诚实版）

| 表示 | 规模 |
|---|---|
| 原始 (family, source) → 位列表 | 1,536 条 |
| 本模型：列码/位对/parity/帧映射用规则，行映射用表 | **36 种行映射 × 16 条 = 576 条** |
| 压缩比 | 约 2.7× |

即：**编码结构部分被完全解出（列、位对、parity、帧全部可算，零例外）；
行部分是每族数据，压缩有限但不为零。**

## 6. 与公开工作的关系

prjxray 的 7 系列数据库对 INT tile 给出的是**逐 (family, source) 的位列表**，
与本模型的「384 条表 + 5 条规则」等价，但没有：

- 列码与线长类别的对应；
- 方向类 → 列由 `(i//8)` 奇偶决定；
- 位对 / parity 的闭式；
- 「每 8 个 mux 一组、奇偶镜像」的结构性解释。

本模型把这些从「数据」提升为「规则」，规模从 1,536 条降到 384 条 + 5 条公式。

## 附：LV_L0 与「K(4,3) 缺口」的更正（2026-11-08）

T51 曾提出 LV_L0 缺 2 条边、预测位对 `{(0,0,2),(1,0,6)}`。离线复核后**撤回该预测**：

- LV_L0 实测 10 源，二分 X(4)×Y(3) 中有 10 条边，结构缺 2 条：`(0,0,2)+(1,0,6)`、`(0,0,9)+(1,0,6)`；
- routing 模板中 LV_L0 只有 9 源（差 `LH12`），**这 2 条边在布线图中不存在**；
- 结论：K(4,3) 是过强假设，LV_L0 无需补齐，覆盖率仍是 3,634/3,634。

同时确认模板 `pip_defs` 字段序为 `(src, dst)`；按 `dst` 分组后 166/172 族源集合与 `law_cells` 完全一致，
其余 6 族均只差一条时钟树常量线。
