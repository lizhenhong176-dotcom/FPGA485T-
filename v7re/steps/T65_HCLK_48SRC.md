# T65：HCLK_CMT 48 源 mux 的编码测量（MMCM 7 + PLL 6）

日期：2026-11-10
背景：`HCLK_CMT` 的 `MUX_CLK_0..13` 共 14 个 mux、每个 48 源、源集合完全相同（T46），
是 INT 之外唯一还没测过编码的复用案例。本轮做了 13 个构建。

## 1. 设计与踩坑

`_hclk48/`：`m0..m6` = `MMCME2_ADV_X0Y6` 的 CLKOUT0..6 → `BUFHCE_X0Y72` → FDRE；
`p0..p5` = `PLLE2_ADV_X0Y6` 的 CLKOUT0..5 → 同 BUFH → 同 FDRE。全部显式 `-part xc7vx485tffg1157-3`。

四次失败（都是真踩到的）：

| 报错 | 原因 | 修法 |
|---|---|---|
| 文件名错乱 | `printf … \| xargs -I{}` 把 `run $t` 当项目 | 只用 echo 标签 |
| `tail: option used in invalid context -- 5` | 远端 coreutils 解析 | `tail -n 5` |
| `BUFH_X0Y0 is not a valid site name` | BUFH 不占独立站点 | 实际站点是 `BUFHCE_X0Y72` |
| `[Place 30-176] Unroutable Placement` | FF 与 MMCM 不在同一时钟区域 | FF 改 `SLICE_X0Y349`（同 `X0Y6` 区域） |
| `[DRC PDRC-29] … frequency 0.000 MHz` | 缺输入时钟约束 | `create_clock -period 10.000 [get_ports clk]` |

最终 **13/13 构建成功**，13 路并发墙钟约 2 分钟。

## 2. MMCM 系列（以 m0 为基准）

## 3. PLL 系列（以 p0 为基准）

PLL 落在另一个 CMT tile（`CMT_TOP_R_UPPER_T_X88Y356` vs MMCM 的 `CMT_TOP_R_LOWER_B_X88Y321`），
所以必须拿 p0 当基准，不能和 m* 比。

每份**恰好 2 格**：

| 设计 | 消失 | 新增 |
|---|---|---|
| p1 | (22144,51,25) (22146,77,6) | (22145,51,25) (22146,77,22) |
| p2 | 同上 | (22144,51,26) (22146,78,6) |
| p3 | 同上 | (22145,51,26) (22146,78,22) |
| p4 | 同上 | (22144,51,27) (22146,79,6) |
| p5 | 同上 | (22145,51,27) (22146,76,22) |

## 4. 读出来的编码结构

PLL 这份是干净的，可以反推：

- **第一级**（帧 22144 / 22145，word 51，bit 25/26/27）：
  `bit = 25 + (n // 2)`、`帧 = 22144 + (n % 2)`
  → 6 个源占 3 个位 × 2 个帧 = 6 个组合，一一对应，**零冲突**。
- **第二级**（帧 22146，word 76..79，bit 6 或 22）：
  `bit = 6 if n 偶 else 22`，word 依次 77,77,78,78,79,76。

第二级不是单调的，看起来像「每 word 两位 = 一个输出组」的分组编码，
与 INT 的「行 × 列」是同一套思路（一级选组、二级选组内成员），但**映射表还没闭合**。

MMCM 7 个源同理落在 (22144/22145, 51) + (22147, 27..30, 9/25)，
两级结构一致，只是第二级换到帧 22147。

## 5. 边界

- 48 源只测到 **13 个**（MMCM 7 + PLL 6）。剩余 35 个（`CK_BUFHCLK*` 12、`CK_IN*` 10、`CCIO*` 4、
  PLL6/7 2、其余）在单区域设计里 Vivado 根本不会选中（T50 已证），要测必须造跨区域/带 BUFG 回环的真实设计。
- 第二级映射未闭合，所以现在还不能对 MUX_CLK_k 做「给定源 → 位坐标」的预测；
  只能反过来做「给定位图 → 读出选中了哪个源」（表驱动）。

## 6. 对主线问题的回答

「时钟 tile 里有没有复用」——**有，而且是全芯片最密的**：

| 家族 | 源数 | 总格 | 每源格数 | 单格最大共用 |
|---|---|---|---|---|
| `CLK_L0/L1`、`CTRL_L0/L1`、`GFAN0/1` | 16 | 8 | 8×2 + 8×4 | **12** |
| `LVB_L0/L12` | 18 | 9 | 全 2 | 6 |
| `LH0/LH12`、`LV_L0/LV_L18` | 10–12 | 7–9 | 全 2 | 4 |
| 对照：INT mux | 21–24 | 8–10 | 2/4 | 8–18 |

即时钟/控制族用 8 个格承载 16 个源（两级编码，T34/T35 已解），
复用强度比 INT 的二维寻址还高。`HCLK_CMT` 的 48 源 mux 是同一思路的更大规模实例。
