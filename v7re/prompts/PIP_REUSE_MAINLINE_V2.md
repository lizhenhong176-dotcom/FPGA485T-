## 二、原始草稿（保留，便于对照优化改了什么）

```text
你是 Xilinx 7 系列比特流逆向的专家。请帮我制定一份「PIP 复用规律」的完整攻坚方案，目标是彻底回答三个问题：(1) 复用到底发生在哪一层；(2) 复用的组织规则是什么，能否写成可执行的生成函数；(3) 要把它做成通用方法，还缺什么测量。

已知事实（均已实测，可作为前提，不要重新假设）：
- 器件 xc7vx485tffg1157-3，配置帧 50,176 帧 × 101 字 × 32 位，第 50 字是帧级 ECC，必须排除。
- 一个 INT tile 有 172 个 family（family = PIP 的目的 wire），3,634 条 (family, source) feature。跨 family 零共享，共享只发生在族内：每个 cell 被 1~18 个源共用，平均 5.56。
- mux 区 64 族（帧 16–25）：每族 24 个源，占据固定 6×4 网格；行帧 = 16+row，列码 bit i → 帧 25-i（0001→25、0010→24、0111→{25,24,23}、1011→{25,24,22}）；每族一对相邻位 (B,B+1) + 一个字 parity + 一个 phase，行 2、3 用另一相位。1,536/1,536 精确命中。

- 剩下唯一不可生成的，是「源名 → 槽位/组」的映射。证据：三族分组边界互不相同，缺位由相邻端线或 bounce 线补位，判断为物理邻接而非位流规律。

请给出：
1. 「复用发生在哪一层」的严格定义与判别方法：它是格级的、位段级的、还是族级的？给出可以用现有数据判定的判据，而不是描述。
2. 针对「源→槽位」这条唯一未闭合的链路，列出 3 种可证伪的假设（例如：槽位 = 器件线序 rank；槽位 = 按 8 方向 × 最近端线枚举；槽位 = 布线图邻接的拓扑排序），并为每种假设写出：预测、最小实验、以及能否用现成数据（routing db 的 tileconn/edges）离线验证。

4. 复用规律在其它 tile 类型（BRAM、DSP、IOI、时钟网络）上的可移植性判断：哪些结构会重现，哪些会变。
5. 最终交付物形态：应该产出什么表/什么函数/什么验证报告，才算是「解决了复用难题」。

约束：不要泛泛而谈方法论；每条结论都要能追溯到具体数据列（law_cells 的 family/src_wire/frame_off/parity/bit）或具体构建；不确定的地方明确标注「未验证」。
```

## 四、用这份提示词时要注意

1. 提示词第 2 条里给了三种备选假设，**不要照抄其中任一条当结论**——要它给出预测 + 最小实验 + 离线验证口径，三者缺一即视为不合格。
2. 第 3 条要求机时估算，若回答没给「每构建约 75 秒」这类可核对依据，说明它在编。
3. 第 4 条是防止把 INT tile 的结论无脑外推到 BRAM/DSP 的关键；回答若没有「哪些会变」就是回避。
4. 全篇要求「可追溯到具体数据列」，出现「一般来说」「通常情况下」这类措辞即视为跑题。

## 五、为什么这样写（设计要点）

- **把已测事实写成前提**：否则模型会重复建议「先做位平面实验」，而我们早已走过并踩过反相/降级的坑。
- **把唯一的缺口精确点名**：`源→槽位`，而不是笼统的「复用规律」——问题越具体，方案越可执行。
- **强制给出可证伪形式**：预测 / 最小实验 / 离线验证口径，三项齐全才叫假设。
- **要求机时估算并给依据**：这一条能筛掉「再跑几百个构建」这种不计成本的建议。
- **交付物要写成表/函数/报告三类**：避免产出「一份分析文档」这种无法验收的东西。
