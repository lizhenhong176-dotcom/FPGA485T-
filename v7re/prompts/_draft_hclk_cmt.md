你是 Xilinx 7 系列（xc7vx485t）比特流逆向的资深工程师。任务：搞清楚 HCLK_CMT 这一类 tile 的 PIP 复用规律，并为它建立可预测、可写入的位映射模型。

## 已知事实（都已在本项目实测确认，不要再验证）
- 器件 xc7vx485tffg1157-3，50,176 帧 × 101 字 × 32 位；第 50 字是帧级 ECC（13 位有效），统计时必须排除。
- 地址公式：frame = 块基址 + frame_off；word = 2*(y%50) + parity（>=50 再 +1）；每配置行 5,246 帧。
- 已完全解决：INT tile 的 172 个家族（3,634 条 feature，1,536 条 mux + 2,098 条 BEG/时钟树），覆盖 100%、0 不符；BUFGCTRL_X0Y0..Y31 的选择位有闭式公式。
- 已建立"受控差分"纪律：两个构建之间必须 PIP 列表逐行相同，差分只允许落在被测配置位上；不满足就不作结论。
- 64 个 mux 家族的复用结构 = 6×4 网格（行帧 16..21、列帧 22..25）；96 个 BEG 家族 = 完全二分图 K(4,5)/K(5,4)，每源固定 2 格；7 个复合码家族 = 3 格 core + 2 个族级附加位。
- 工具：远端 Vivado 2017.2（22 GB 内存 / 单构建 84 s / 32 路并发可行）、RapidWright 2026.1.0（对 HCLK_CMT 返回 getConfigBlock()=null，无配置块信息）、本地 bitstream parser。

## 本次目标
HCLK_CMT 是全器件 PIP 最密的 tile（982 条 PIP、平均 23.4 源/目的、最大 48），必须回答三件事：
1. 它的每条 PIP 用几个配置位？是 1 位、2 位还是多位编码？
2. 多位时，位与位之间是什么关系（one-hot？温度计码？二进制？分组？）
3. 能否给出闭式公式（像 INT 那样），还是必须查表？给出判据。

## 方法要求（必须遵守）
1. 先离线摸底：从 routing 模板统计 HCLK_CMT 的每个目的 wire 有多少源、源的命名规律、是否与 INT 的 8 方向×端线同构。
2. 设计隔离实验时，必须构造"只改配置、不改布线"的对照。优先考虑：
   - 同一物理端口的 I0/I1 选择（像 BUFGCTRL 那样由寄存器位决定）；
   - 同一源的两种等效驱动（DONT_TOUCH + 固定 LOC 的 LUT 输出 vs 直接连）；
   - 成对消元（两个构建各改一个变量，再交叉相减）。
3. 每个结论必须满足：构建回读断言一致（SITE/BEL/part）+ PIP 列表逐行相同。
4. 任何差分如果不能被"已知族 + 被测位"完全解释，必须列出残差并归因，无法归因就判失败，不要硬解释。
5. 禁止抽样结论：位集合必须 missing=0 且 extra=0。

## 交付物
1. HCLK_CMT 的 PIP 源集合清单（每个目的 wire 的源列表 + 数量）。
2. 每条 PIP 的位数结论，按"每目的源数"分组呈现。
3. 位间关系判定（one-hot / 二进制 / 分组），附实测差分表。
4. 能否公式化的结论：能则给公式并用留出法验证；不能则说明为什么，并给出查表所需的条目数。
5. 与 INT / BEG / 复合码三类的结构对照表。
6. 全部负结果照实记录（哪条假设被什么数据证伪）。

## 红线
- 不追求"看起来合理"，只追求可复现。
- 一个结论如果没有第二个独立构建或第二个脚本交叉验证，标注为"未验证"。
- 机时很便宜（32 路并发），但错误的结论很贵——宁可多跑 20 个构建，也不要省一次自校验。
