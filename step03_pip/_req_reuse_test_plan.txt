请把下面这段意图改写成一份可直接交给 AI 执行的提示词：写一份「PIP 复用规律的实验思路 + 测试方案 + 进度」说明。

## 用户处境
用户是 FPGA 比特流逆向项目的主人，主线只有一条：**搞清楚 PIP 复用发生在哪几层、复用的规律是什么**。他能看懂单个结论，但缺少一张「整体图像」：这些结论是靠什么实验一步一步得来的、每一步的判据是什么、现在进行到哪、还剩什么没测。

## 交付物必须包含五部分
1. **实验思路链**：把整条主线画成一条因果链（不是清单），每一步写：这一步要回答的问题 / 用的实验手段（差分、统计、二分图、生成器、反证……） / 输入数据 / 输出结论 / 这一步的证伪条件（什么结果会让这一步作废）。链条至少覆盖：单点差分 → 定位位池 → 列重统计 → 结构判定（二分/乘积） → 两轴归属 → 生成器重建 → 反证（唯一性/篡改/误报） → 迁移检验。
2. **复用规律的正文**：按「在哪一层复用」分层写：位级（cell 被多个 feature 共用）、族级（一个 mux 的多个源共用位池）、跨族（不同家族共用位）、跨 tile/跨器件。每层给出：规律陈述、可执行形式、真实族名实例、数字（分子/分母）、失效条件。
3. **测试与判据表**：每个环节配一条测试，列固定为：测试名 / 判据（分子/分母） / 复算命令 / 产物与时间戳 / 状态（已验证 / 已跑过 / 从未跑过）。
4. **进度**：用分子/分母表达，分母必须标注来源；并单独回答「现在有没有测试在跑、最近一次跑完是什么时候」。
5. **空白与下一步**：明确列出还没测的三块，以及每块补上后能改变哪个结论。

## 硬性纪律
- 三色标注：【硬件事实】/【数据事实】/【推断】。
- 数字只能来自实测或给定清单；没有的写「未测」。
- 禁止「首次」「唯一」「完整」「彻底」这类不可反驳的词。
- 不许把「脚本多、跑过一遍」当进度或当验证。
- 每条规律必须写失效条件：什么观测出现，这条规律就作废。
- 说明「实验思路」时要写清楚为什么用这个方法、它能排除什么别的解释。
