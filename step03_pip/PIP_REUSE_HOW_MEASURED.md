# INT tile 的 PIP 复用规律是怎样被测出来的

> 按 `PROMPT_PIP_REUSE_HOW_MEASURED_V2.md` 产出。器件：`xc7vx485tffg1761-2`（VC707 板）；工具：Vivado 2017.2 + RapidWright。
> 三色标注：【硬件事实】/【数据事实】/【推断】。

---

## ① 一句话总述

**【推断】这条规律是用三件事测出来的：受控差分（只改一个驱动源，两个位流做位级 XOR）→ 结构统计（列重、二分、两轴归属）→ 外部真值（Vivado `get_pips`、线长律、全器件一致性）。**

其中「受控差分」负责把「功能变化」钉到「具体位」，「结构统计」负责把「一堆位」压成「少量规则」，「外部真值」负责排除「规律只在我自己的流水线里成立」。

## ③ 实验设计：怎么「让它选择不同源」

### 步骤 1：锁死所有不该变的东西

- **做法**：显式 `-part`、固定 `LOC` / `BEL`、加 `LOCK_PINS`、每个 LUT 给不同 `INIT` 并加 `DONT_TOUCH`；构建后回读断言 `SITE`/`BEL`/`INIT`。
- **为什么必需**：Vivado 会把 LUT 的 `I0..I5` 自由重排。
- **不这么做会得到什么错结论**：测出来的「源 → 输入脚」映射是**当次分配**的，而不是器件的；同一实验重跑一次索引就变，会把「换源实验」变成测随机数。
- **【数据事实】踩坑记录**：T18 之前没加 `LOCK_PINS`，同一位流两次构建的 `IMUX` 编号不一致。

### 步骤 2：用「胖设计」一次覆盖整个 mux 池

- **做法**：两个 slice（`SLICE_X12Y20` / `SLICE_X13Y20`）各放 4 个 `LUT6`，8 个 LUT 共 **48 个输入脚**，全部由 6 个顶层输入驱动；每个 LUT 用不同 `INIT` 防止被合并；一次 `route_design` 后用 `get_pips -of_objects [get_nets -hier]` 导出每条 net 的全部 PIP。
- **为什么必需**：一个字面意义上的「单输入基座」只能碰到少数输入。
- **不这么做会得到什么错结论**：【数据事实】**T1 原假设「缺的 12 个 IMUX 是 CLBLM 专属」被自己的实验证伪**——胖设计一次 route，**48 个 IMUX 全部出现（48/48）**，此前「未测」的 12 个正好是 M 侧 `C1..C6`、`D1..D6` 全部输入脚。也就是说：那不是「够不着」，是「没碰到」。

### 步骤 3：一次只换一个源，成对构建，位级 XOR

- **做法**：同一骨架、同一 LOC/BEL，只改「驱动该目的 wire 的是哪个源」；两个位流做字节级 XOR，拆成 `(frame, word, bit)`。
- **为什么必需**：这是唯一能把「选了源 A」与「选了源 B」的差异隔离到位的办法。
- **不这么做会得到什么错结论**：如果同时改两个源或同时改 LOC，差分会混进布局差异，你无法判断某个位是「选源位」还是「位置位」。
- **【硬件事实】补充**：**不能靠改 DCP 里的 route 属性来换源**——bitgen 从网表重推布线，属性改动不进入比特流（README 已记），所以必须改网表里的连接关系。

### 步骤 4：先剔掉 `word 50`，再谈规律

- **做法**：差分结果里先删除 `word == 50` 的格。
- **为什么必需**：`word 50` 是每帧的 ECC 字，数据一变它就重算。
- **不这么做会得到什么错结论**：【数据事实】每个源会多出 **4–22 个**「假编码位」（HCLK_CMT 实测：MMCM6 20 格、MMCM4 18 格、PLL5 22 格），你会把 ECC 校验位误当成「这个源有 20 个配置位」，整条列重统计全错。

### 步骤 5：用「单最小项」而不是「位平面」

- **做法**：一次只让一个最小项生效（单 bit 差异），而不是「让某一位平面整片翻转」。
- **为什么必需**：Vivado 会把低复杂度函数降级成小 LUT 或缓冲。
- **不这么做会得到什么错结论**：【数据事实】位平面法会导致**某一位平面整体反相**，于是你测到的「这一列全 1」其实是优化器把函数搬走了，不是编码规律。

### 步骤 6：负对照与同类型不同实例对照

- **负对照**：同参数重跑，差分必须为 0。
- **实例对照（T56）**：拿同一 `tile_type` 的另一个实例做同样的换源实验（`INT_L_X6Y61` vs 已实测的 `INT_L_X6Y11`），判据是**归一化三元组集合逐位相等**。
- **不这么做会得到什么错结论**：无法排除「位地址随 tile 实例变化」——那样规律就只是「每个实例一张表」，谈不上复用规律。

### 步骤 7：把差分变成「格集合」，再谈结构

- 每条 `(family, source)` 得到一个格集合；一族 24 个源的集合放在一起，才看得出「哪些格是所有源共用的」（= 组选择位），哪些是「分码的」（= 列码位）。

## ④ 从差分到规律：四个判据

### 4.1 归一化（绝对帧 → tile 内坐标）

```
frame_off = frame − far_bands[(band, col)].start_frame
band      = band_by_region[y // 50]              # [6,5,0,1,2,3,4]
word      = 2*(y % 50) + parity  (若 ≥50 再 +1，跳过 word 50)
bit       = 位号（0..31）
```

【数据事实】归一化后，同一 `tile_type` 的不同实例得到**同一组** `(frame_off, parity, bit)`（T56：`INT_L_X6Y61` 与 `INT_L_X6Y11` 逐位相等）。

### 4.2 列重（复用的度量）

【数据事实】`A[feature, cell]` 的列重 `w(c) = Σ_f A[f,c]`：

- `Σw = 8,900`（= sense=1 行数，与 `2,818×2 + 816×4` 两条路径一致）；
- 1,598 个不同格；每 feature 2.45 格；每格被 5.57 个 feature 共用；
- 列重只有 8 个取值：`{18:128, 12:12, 6:134, 5:384, 4:909, 3:26, 2:5, 1:4}`，**4–5 档占 1,293/1,602 = 80.7%**。

### 4.3 二分 / 乘积结构（不看名字、不看帧号）

【数据事实】按列重最轻档取「组选择位」（每源恰含 1 个），其余为「码字」：

- **163 / 172 族**通过「组 × 码完全叉积」检验：`(6 组,4 源,4 码位)×64`、`(5,4,4)×96`、`(6,3,3)×2`、`(4,3,3)×1`；
- BEG 侧把源当边、格当端点做 2-着色：**96/96 完全二分**（`K(5,4)` 64 族、`K(4,5)` 32 族）；
- 9 个不通过的都是已知难族（6 个复合族 + 3 个长线族）。

### 4.4 两轴归属（映射到什么物理量）

| 轴 | 判据 | 结果 |
|---|---|---|
| 列码 | 线名里的线长类别 | 【数据事实】**列码 = 线长类别**：`1/2` ↔ `*E2*`(DOUBLE)、`7/11` ↔ `*E1*`(SINGLE)，**744/744 零例外**；列→帧 `1→{25}、2→{24}、7→{23,24,25}、11→{22,24,25}` |
| 行号 | 线名里的方向 | 【数据事实】行 = 方向；斜线行 = 同名主轴行（64/64）；8 个旁路源占 row 4/5，每列恰 1 个 row4 + 1 个 row5（**256/256**） |
| 族参数 | 族序号 | 【数据事实】`minbit = 8*(i%4) + 2*(i//16) + 2*((i//8)%2)`、`parity = 1 if (i%8)≥4`；64 族只有 **16 种配置，每种 4 族** |

生成结果：【数据事实】**3,456 / 3,634 = 95.1%** 的 feature 位集可由名字推出且位级 0 差异（`gen_mux.py` / `gen_slots.py`）。

## ⑤ 验证链（按强度从高到低）

| 序 | 验证 | 判据 | 失败意味着 | 能证伪哪一层 |
|---|---|---|---|---|
| 1 | **外部真值 `get_pips`** | 【数据事实】真值 1,263 条 → 解出 **1,155 = 91.45%**（`col≥128` 的 40 条解出 39） | 位库解码与厂商布线不一致 | 「族级编码律」与「跨 tile 一致」两层 |
| 2 | **全器件一致性 / 线长律** | 【数据事实】12,565 tile、64,686 位、**0 表外位**；线长律 **5,832/5,832** 覆盖 12,937 tile | 规律只在少数 tile 成立 | 同上，且能证伪「单实例巧合」 |
| 3 | **交叉自证（另一批构建 / 另一脚本）** | 【数据事实】S13 解码 181 PIP / 0 ambiguous、token 级 6/6 EXACT；S14 全芯片 75,900 slice 扫描 62 特征 **0 mismatch**；S15 重综合 `SLICE_X47Y51` **0 字差异** | 结论依赖特定构建批次 | 「差分结论」层 |
| 4 | **槽位不变量（干净位流）** | 【数据事实】6 个位流 73,152 槽 + 34 个探针 97,024 槽 + `ref.bit` 60,480 槽 = **231,656 槽位 0 违例** | 「≤1 行 / 码 ∈ {1,2,7,11} / 有码必有行」不成立 | 「编码律」层（且不经 `law_cells`） |
| 5 | **集合级自证** | 【数据事实】预测集 vs 差分集 `missing=0 且 extra=0`：1,536/1,536；全库 3,634/3,634 | 规律只覆盖一部分 | 「覆盖度」层 |
| 6 | **唯一解枚举** | 【数据事实】1,066 / 1,066 个含 mux 配置的 tile **恰 1 解**（0 多解、0 零解） | 不同源配置可能产生同一位流 | 「源级可判」层 |
| 7 | **负对照** | 同参数重跑差分 = 0 | 差分里混进构建噪声 | 全部（这是地基） |

【推断】**「跑过一遍」不算验证**：上面每一条都要求「分子/分母 + 产物文件」，且第 1、2 条的判据完全不经过我自己的生成器。

## ⑥ 边界与未验证项

| 项 | 状态 | 说明 |
|---|---|---|
| `law_cells` 本身 | 单一来源 | 生成与比对都用它；外部真值只覆盖 1,263 条真值 PIP |
| 位级列重、跨族 3 个格 | **仅自洽** | 两/一条求和路径都来自同一张表，无第二条来源 |
| 9 个例外族（6 复合 + 3 长线） | 部分 | 复合族有逐族组模型（96/96 精确），长线族 82 条**无规则** |
| 跨器件 | 未测 | 只有 485T（ffg1761 / ffg1157 同 die） |
| 跨 tile 类型 | 抽样 | 已做 INT_L/INT_R；`HCLK_CMT` 13/48 源；其余 113 类型只有普查 |
| block1（13,454 帧） | 未建模 | 时钟/配置区没有地址表 |
| 尾部 CRC / ECC 地址项 | 未闭合 | 影响「生成可加载位流」 |
| 「类内成员序」旧结论 | **已被推翻** | T51 曾判「源→槽位不可由线名推出」（按 `src_index` 行主序只中 10/1,536、字典序 8/1,536），后由「列码=线类、行=方向 + 16 种配置」推翻，现为 100% 几何重建 |

**三条真实踩过的坑（对应 ③ 的「不这么做会得到什么错结论」之后果）**

1. **检验脚本自己漏了 `+1` 位移** → 一次报出 **22 个「表外位」**，连续两轮把结论引向错误方向（先怀疑长线族，再怀疑位移边界），最后发现是检查器错。
2. **薄基座** → 12 个 IMUX 被误判成「CLBLM 专属」（实际 48/48 全部可达）。
3. **用 `src_index` 行主序猜槽位** → 只命中 10/1,536，差点得出「源→槽位是纯数据」的错误结论。
