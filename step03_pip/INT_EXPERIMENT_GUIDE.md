## 1. 五分钟概览

XC7VX485T 的 `INT_L` / `INT_R` tile 是可编程互连的开关矩阵。一个 INT tile 里有 **600 根 wire、3,737 条 PIP**，其中 **172 个目的 wire 有多于一个候选源**（= 172 个多路选择器，mux）。这 172 个 mux 的 3,629 条信号连接，只由 **1,598 个配置位**承载——平均每个位被 2.27 条连接共用。

**本实验问的是**：这种"多对一"的位复用是随机的，还是有编码规律？
**答案**：有。**3,552/3,634 = 97.7% 的连接可以由"族名 + 源名"按规则生成，逐位 0 差异**；剩 82 条确认是表数据，且已证明它们与其余族是同一编码形式的稀疏实例。

## 2. 术语表（四列：定义 / 本项目取值 / 真实例子 / 常见误解）

| 术语 | 一句话定义 | 本项目取值/形态 | 真实例子 | 常见误解 |
|---|---|---|---|---|
| **tile** | 芯片上规则阵列里的一个方块单元，是配置的最小地理单位 | 485T 共 150,380 个 tile / 115 种类型 | `INT_L_X8Y20` = 左半区第 8 列第 20 行的 INT tile | 以为 tile 有内部行列坐标——工具不提供（§7.5） |
| **site** | tile 内部的可配置元件位置（一个 LUT、一个 FF） | SLICE 里有 4 个 LUT + 8 个 FF | `SLICE_X11Y20` 的 `A6LUT` | 把 site 当成 tile 的一种 |
| **wire** | tile 内部的一段连线（顶点） | INT tile 600 根 | `EE2END0`、`IMUX_L40` | 以为 wire 名字就是引脚名 |
| **PIP** | 两段 wire 之间由配置位控制的可编程连接（边） | INT tile 3,737 条 | `BYP_ALT0 ->> SW2END0` | 把 PIP 当成"开关盒"整体 |
| **mux** | 共用同一个目的 wire 的一组 PIP，组内互斥 | 172 个（扇入>1 的目的 wire） | `IMUX_L40` 有 24 个候选源 | 以为 mux 是独立元件、PIP 是它的子件 |
| **family（族）** | = 一个目的 wire + 它的全部候选源，等价于一个 mux | 172 族/侧 | `IMUX_L40`、`EE2BEG0`、`LH0` | 把"族"当官方术语（本仓库自造，指 `(tile_type, dst_wire)`） |
| **CRAM** | 配置存储器阵列（Configuration RAM），存所有配置位 | 50,176 帧 × 101 word × 32 bit | 器件总配置位 162,168,832 | 以为是普通 SRAM、可按字节寻址 |
| **frame（帧）** | CRAM 的一列，是写入的最小单位 | 每帧 101 word × 32 bit = 3,232 bit | 帧 31,768 = `INT_L_X8Y20` 的基址 | 把帧当成"一个 tile 的配置" |
| **word** | 帧内的一个 32 位槽位；一帧有 101 个 | 0..100；**word 50 是 ECC** | `word = 2*(Y%50)+parity` | 以为 word 是字节、以为 101 个字全是数据 |
| **bit** | word 内的 1 位，最小可寻址单位 | 0..31 | `word 40, bit 6` | 把 bit 号与位流字节偏移混用 |
| **frame_off** | tile 基址到该帧的相对偏移（tile 内坐标） | INT: 0..25；时钟列: 26..29 | mux 行格在 16..21、列码在 22..25 | 把 frame_off 当绝对帧号 |
| **parity** | 同一行占两个 word（偶/奇）的那个 0/1 维度 | 0/1 | `IMUX_L0` 用 parity=0，`IMUX_L4` 用 parity=1 | 漏掉它 → 两族位集合撞车 |
| **FAR** | 比特流里的帧地址寄存器（26 位） | `[25:23]`block `[22]`top `[21:17]`row `[16:7]`col `[6:0]`minor | `frame 31752 → far=0x00420400 → col8 minor0` | 以为 `.bit` 逐帧写 FAR（实测 FAR 只写一次、恒为 0） |
| **band** | 帧地址的分段单位（= FAR 的 block+top+row） | 7 段 × 154 列，每段 5,246 帧 | `band0 = 0..5245` | 与本仓库外的 "bank" 混为一谈 |
| **col** | 帧地址的列字段 | 0..153（逻辑块），7×154 = 1,078 行地址表 | `far_bands[(band,col)].start_frame` | 以为等于 tile 的 grid_x（二者是两套坐标） |
| **region** | 芯片纵向时钟区（7 个） | `region = Y//50`，0..6 | `Y=20 → region 0` | 与 band 混为一谈（band 顺序 ≠ region 顺序：`[6,5,0,1,2,3,4]`） |
| **row** | 本项目中 = band 内的行号 | `row = Y%50`，0..49 | `word_0 = 2*row + 0` | 与 tile 的 grid_y 混用 |
| **码字（code）** | mux 族的 4 个列码位组成的 0..15 值 | 合法集只有 `{1,2,7,11}` | `1071`(二进制 `1011`)=11 | 以为 4 位可以任意取值 |
| **一热编码** | 一组位里恰好一个为 1 的编码方式 | mux 行格：6 行里恰 1 个置位 | 行 3 选中 = 只有 frame 19 的格置位 | 以为可以多个同时置位（会破坏不变量） |
| **完全二分 K(m,n)** | 两组点之间所有边都存在的图 | BEG 96/96 是 K(5,4)/K(4,5) | 20 源 = 5 组 × 4 组，20 条边全在 | 以为稀疏（是边序假设错造成的假象） |
| **双格边编码** | 一条连接 = 两个格（两个端点），源是边 | mux/BEG/长线族都用这个形式 | 源 `SS6END0` = `(11,0,10)` + `(13,0,10)` | 以为一条连接只占 1 位 |
| **sense=1 / sense=0** | 位记录里"必须置 1"与"必须为 0"两类约束 | 每侧 8,900 / 3,264 行 | `law_cells.sense` 列 | **把两类混算 → 得出全部错误结论**（§7.1） |
| **列重** | 一个位被多少条连接共用 | 分布 1..18，4–5 档占 80.7% | 位 `(16,0,6)` 被 6 个源共用 | 以为"平均 5.57"能代表分布 |
| **word 50（ECC）** | 每帧第 50 个字是校验字，不是数据 | 数据一改就重算 | 每对差分里 4–20 个 word50 格随数据变化 | 当成数据位 → 容量算大 1/3 |
| **直通 PIP** | 目的 wire 只有一个源的 PIP（无选择） | 44 条 | `BYP_BOUNCE0 ->> BYP_BOUNCE1` 类 | 当成 mux 的一员 |
| **VCC_WIRE 常量输入** | 源是常量线 `VCC_WIRE` 的输入 | 64 条（在 172 族里） | `BYP_ALT0 ->> VCC_WIRE` | 当成信号连接一起算复用度 |

## 3. 一次完整的实验长什么样（走一个真实 PIP）

以 `INT_R_X37Y199` 的 `SS6END0 ->> SS2BEG0` 为例，从 `.v` 走到"公式能生成它"：

| 步 | 在做的事 | 真实数值 |
|---|---|---|
| 1 | 写 `top.v`，把一根信号从 `SS6END0` 布到 `SS2BEG0`，锁死 `LOC/BEL` | `INT_R_X37Y199` |
| 2 | Vivado 综合→布局→布线→`write_bitstream`，导出 `get_pips` | `.bit` 20,273,538 B；`pips_all.txt` 1,812 行 |
| 3 | 另一版只把该 PIP 去掉，两次位流做 XOR | 差异 = 2 个数据格 |
| 4 | 把绝对帧号换成 tile 内坐标 | `Y=199 → region 3 → band 1`、基址 6,510；`Y%50=49 → word 99` |
| 5 | 读两个格的值 | `(frame_off 11, parity 0, bit 10)` 与 `(13, 0, 10)`，两位都 = 1 |
| 6 | 写进 `law_cells` | `family=SS2BEG0, src=SS6END0, 两格` |
| 7 | 同族 20 个源一起做，看结构 | 20 源 = 5 组 × 4 组，**完全二分 K(5,4)** |
| 8 | 把结构写成公式，重新生成这 20 个源 | 生成器输出与 `law_cells` **逐位 0 差异** |

这一步走通，就说明"这个族的位不是抄出来的，是算出来的"。

## 4. 实验流程（8 步，每步都有"不做会怎样"）

| # | 目的 | 具体做法 | 判据 | 产出 | 不做会怎样 |
|---|---|---|---|---|---|
| 1 | 拿到可信真值 | 造受控设计，导出 `.bit` + `get_pips` | `get_pips` 与 `.bit` 自洽 | `ref.bit`（982 active INT tile）、1,812 条布线 | 没有真值，任何"规律"都无法验证 |
| 2 | 位流 → tile 内坐标 | 解 FAR、算 `frame/word/bit` | 基址反解回 FAR 一致 | 五元组 `(tile, frame_off, parity, word, bit)` | 帧号错位，全表坐标错误 |
| 3 | 验证"存在结构" | 槽位三不变量扫描 | 违例数 = 0 | 231,656 槽位 0 违例 | 直接猜公式，等于赌博 |
| 4 | 定位 mux 位池 | 按列重切行/列两轴 | 行格列重恒 4、列格列重 18/18/6/6 | 6×4 网格、`frame_row=16+r`（384/384） | 无法区分"哪一位选行、哪一位选列" |
| 5 | 归类 172 族 | 按源数/结构分档 | 24 源 64 / 20 源 96 / 其它 12 | 三套结构（网格 / 二分 / 组模型） | 用一套公式套所有族，必然错 |
| 6 | 写生成器 | 只吃名字生成全部位 | 与 `law_cells` 逐位 0 差异 | `gen_mux.py`、`gen_slots.py` | 只能交表，不能称"规律" |
| 7 | 外部反证 | 真值对账 / 线长律 / 整帧重生成 | 差异 0 或已归因 | 91.45% 真值命中、12,565 tile 表外 0、50,176 帧全等 | 无法排除"你只是抄了你自己的表" |
| 8 | 迁移判定 | 换 tile 类型做同样判据 | 结构同形才算可迁移 | HCLK_CMT 同形、时钟区每对 2 数据格 | 结论只能停在"INT 内部" |

## 5. 为什么这么做（每条都写替代方案与"否掉会犯什么错"）

| 为什么 | 替代方案 | 为什么否掉 | 否掉后会犯的错 |
|---|---|---|---|
| 必须自己造受控差分 | 用现成开源位流 + 公开位库 | V7 无公开位库（`segbits_<T>.db` 在导出清单里 `missing`） | 只能抄别人的表，无法判断对错 |
| 必须以"逐位 0 差异"为判据 | 抽样比对 / 肉眼核对 | 抽样无法排除"恰好抽中" | 会把 95% 的规律当成 100% |
| 必须区分三种差分语义（PURE/XOR/FAM） | 一律用 XOR | XOR 会抵消共有置位 | 报"同一族在不同 tile 用不同位"（族不唯一） |
| 必须在**类型级**建表 | 每个 tile 实例各建一张表 | 26,550 个实例若各不同，表规模不可维护 | 以为不可压缩，放弃规律化 |
| 必须先验证不变量再写公式 | 直接拟合公式 | 拟合可以在无结构的数据上"看起来对" | 会得到描述性拟合（换设计即崩） |
| 必须跑干净基线再做注入实验 | 直接测检出 | 干净位流本身有 240 个白名单标记位 | 会把 12.22% 的固有告警算成"检出"（幽灵 mux 假 100%） |

## 6. 覆盖范围：**不是所有 PIP 都被建模**（本节给精确分子分母）

### 6.1 第一层：一个 INT tile 内部的 3,737 条 PIP

| 类别 | 条数 | 占 tile 内 PIP | 有没有编码规律 |
|---|---|---|---|
| 有位记录的信号 PIP（172 个 mux 里） | **3,629** | 97.1% | 有：3,552 条由名字生成（97.7% of 3,634） |
| `VCC_WIRE` 常量输入 | **64** | 1.7% | 无常量线不参与选择，只占位 |
| 直通 PIP（扇入 = 1） | **44** | 1.2% | 无单源无选择 |
| 合计 | **3,737** | 100% | — |

- 复算：`python step03_pip/_q_cover_tile.py`（读 `templates/INT_L.json`）。
- 【数据事实】`law_cells` 每侧记 **3,634** 个 `(family, src)`；模板侧非 VCC 的 mux PIP 是 **3,629**，差 **5** 条是长线族里跨族选源（`LH0←LH12`、`LVB_L0←LVB_L12` 等）在模板与记录表里的拼写差异，【未核实】逐条对照。
- 【数据事实】按连接数算：**3,552/3,737 = 95.0%** 的 tile 内 PIP 可由规则生成；按 `law_cells` 特征数算 **97.7%**。两个分母都要说清楚，不能混。

### 6.2 第二层：类型级（"一张表覆盖 26,550 个实例"的前提）

- 【数据事实】`INT_L` 26,550 个实例、`INT_R` 26,550 个；`type_uniformity.json` 里两侧 `uniform: true`、`mismatching_tiles: []`——**同类型所有实例的 PIP 拓扑逐条相同**。
- 【数据事实】所以"类型覆盖 = 实例全覆盖"成立的前提是：①拓扑只由 tile 类型决定 ②`law_cells` 的键是 `(tile_type, family, src_wire)`，不含坐标。
- 【数据事实】实例差异只出现在**地址**（基址帧）和**哪些族被使用**，不在"位的形状"。

### 6.3 第三层：器件级（这才是"是不是所有 PIP"的真答案）

| 范围 | PIP 条数 | 我做了多少 | 占比 |
|---|---|---|---|
| 全器件（70 个含 PIP 的 tile 类型，共 115 个类型） | **35,126** | — | — |
| `INT_L` + `INT_R` | 7,474 | **7,474** | 21.3% |
| 其余 68 个类型 | 27,652 | 抽样 2 类：`HCLK_CMT`（982）、`HCLK_BRAM`（若干格） | — |
| 器件数 | 1（485T） | 1 | 100% 单器件，**0 个跨器件** |

- 复算：`v7re/steps/T44_ALL_TILE_PIP_SURVEY.md`（35,126 / 16,951 族，平均 2.07 源/族）。
- **直接回答：不是所有 PIP 都被建模。** INT tile 内部 100% 被分类（4 类），其中 95.0% 可按规则生成；**器件级只覆盖 21.3% 的 PIP**，且只在一个器件上。
- 【数据事实】未覆盖的 27,652 条里，`D 类密集多源`（8 个类型，15,518 条，44.2%）才是真正需要编码规律的部分；剩下 A/B/C 类多为单源或稀疏多源，规律价值低。

## 7. 最容易弄错的 6 个概念

1. **`sense=1` 和 `sense=0` 必须分开**——混算会把"必须为 0 的约束位"当成"必须置 1 的编码位"，得到"每源恒 5 格、70 族 4:1 合并"。正确：`2,818×2 + 816×4 = 8,900` 精确闭合。
2. **`word` 是帧内的 32 位槽位，不是字节**——一帧 101 word；`word 50` 是 ECC，公式里必须 `≥50 则 +1` 跳过。
3. **`frame_off` 是 tile 内相对坐标，不是绝对帧号**——绝对帧 = `far_bands[(band,col)].start_frame + frame_off`。
4. **`parity` 是独立的第三维**——`IMUX_L0`（parity 0）与 `IMUX_L4`（parity 1）位模式相同但是不同 word。
5. **tile 没有内部行列坐标**——RapidWright `Tile` API 只给 wire/PIP，`Site.getSitePIPs()` 给的是 LUT 输出选择；所以"6 行物理上排成 6 行"只是【推断】。
6. **"类型覆盖"不等于"器件覆盖"**——两侧 INT 全覆盖 ≠ 全器件；器件级是 7,474/35,126 = 21.3%。
