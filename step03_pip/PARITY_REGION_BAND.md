## 1. parity

| 项 | 内容 |
|---|---|
| 一句话定义 | 同一行两个 32 位字中的高/低字索引（0=低字，1=高字），不是校验位 |
| 物理位置 | 帧地址空间：`word = wof(Yr) + parity`，同一 `(frame, wof, bit)` 的两种取值 |
| 计量单位 | 索引值，取 0 或 1 |
| 485T 数量 | 每行固定 2 个（全器件 50 行 × 7 band × … ⇒ 每帧 100 个数据字）**【实测】** |
| 分界 | 上界是一次 access 的 32 位字（bit 0..31），下界是该行的 64 位组合 |

**为什么一行要两个字**：一行需要承载 64 个可配位，而一个字的宽度是 32 位，所以拆成两个字。
两者合起来才是一行的完整切片：`bit64 = parity*32 + bit(0..31)`。

**它不是校验**的三个证据【实测】：
1. S5 差分（PRECYINIT / AOUTMUX）只落在 `w40`，`w41` 不动 —— 若两字是同内容的冗余，改动应成对出现；
2. S9/S24 的 IMUX 码全部落在 parity=1 上，仍能逐位解出正确的源（6/6 token 一致）；
3. 写回校验 864/864：只改 parity=1 的位即可改变功能。

**真正的校验字是 word 50**：每帧第 50 个字是帧级校验/ECC 类字，且**只在 fabric 块成立**
（CLB/INT/BRAM/DSP）。实测反例【S58/S60】：`io72`/`edge30`/`CMT`/`GTX` 块里 word 50 是真实配置字（BUFR_DIVIDE、GTX 配置都写在 w50 上）。

## 2. clock region（时钟区域）

| 项 | 内容 |
|---|---|
| 一句话定义 | 器件上一块独立的时钟域/tile 配置域，高 50 个 CLB 行、宽半个 die |
| 物理位置 | die 上的二维矩形：纵向 50 行一段，横向分 X0/X1 两列 |
| 计量单位 | region（= 50 CLB 行 × 半片宽） |
| 485T 数量 | **14 个 = 7 行 × 2 列**【实测：`sites.clock_region` 取值为 X0Y0..X0Y6 + X1Y0..X1Y6】 |
| 分界 | 纵向以 50 行为界（`Y//50`），横向以 die 中央 IO 脊为界（不在几何中点） |

旁的佐证【实测】：`MMCME2_ADV` 14 个、`PLLE2_ADV` 14 个 —— 每 region 一套 CMT，数量自洽。

**为什么是 7 行**：485T 的 CLB 名 Y 为 0..349（350 行），每 region 50 行 ⇒ 350/50 = 7。
**这是器件属性，不是 7 系列常数**：同系列 artix7 200T 垂直只有 5 个 region。

## 3. 行带（band）

| 项 | 内容 |
|---|---|
| 一句话定义 | 帧地址空间按 50 行为一组切出的纵向分段，每段 5,180 帧 |
| 物理位置 | 帧地址空间（不是 die 上的物理块） |
| 计量单位 | 帧（frame） |
| 485T 数量 | **7 个 × 5,180 帧 = 36,260 帧**（fabric 段收于 36,688，其后 13,488 帧属 IO/GTX/CFG 侧）**【实测：frame_blocks 1,038 块闭合】** |
| 分界 | 段内以 block（36/28/72/246 帧）为单位，段间有 **66 帧间隙**【实测】 |

band 基址表【实测】：

| band | 0 | 1 | 2 | 3 | 4 | 5 | 6 |
|---|---|---|---|---|---|---|---|
| 起始帧 | 31,748 | 26,502 | 272 | 5,518 | 10,764 | 16,010 | 21,256 |

`band = Y // 50`，`Yr = Y % 50`。

## 4. band 与 clock region：不是同一件事

1. **本质不同**：band 是**帧地址空间**的划分（用于算 frame/word）；clock region 是**物理时钟域**（用于约束时序、决定时钟可跨与否）。
2. **数目不同**：band 只按行切 ⇒ 7 个；clock region 按行 × 列切 ⇒ 14 个。
3. **映射规则**：`band 号 = Y // 50 = clock region 的行号`；但 band 不区分 X0/X1。
4. **不重合之处（重要）**：band 在位流文件中的排列**不是 0..6**，而是
   `b2 → b3 → b4 → b5 → b6 → b1 → b0`（基址 272 → 5,518 → 10,764 → 16,010 → 21,256 → 26,502 → 31,748）。
   这是地址空间的物理布局（band 之间插入 66 帧间隙/VBRK 长线断点），**不是测量误差**。
   artix7 的 `tilegrid.baseaddr` 也呈现同样的非单调性（X0Y3 回绕）【实测：本地 prjxray 数据】。

一句话记：**band 决定你算哪个 frame；clock region 决定这个 frame 里的逻辑能不能用这条时钟。**

## 5. 相关概念一览

| 概念 | 含义 | 与三者的关系 |
|---|---|---|
| bit | 一个 SRAM 配置位 | parity 选字，bit 选位 |
| word | 32 bit，帧内单位 | `word = wof(Yr) + parity` |
| frame | 101 word = 3,232 bit | `frame = block_base + frame_off` |
| tile | 物理最小可配置单元（一列 × 一行） | 它的位分散在 26/28/36 帧的**同一对字**上 |
| site / BEL | tile 内的逻辑单元与内部单元 | 位表以 (site, BEL, 属性) 命名 |
| block | 帧地址块：36（CLB）/28（BRAM/DSP/接口）/72（IO）/246（PCIE） | band 由 block 序列拼成 |
| `wof(Y)` | 行字基值 = `2*(Y%50) + (Y%50 >= 25)` | parity 加在它上面 |
| VBRK / HCLK / HROW | 长线断点、时钟纵轨、时钟横排 | 解释 band 间隙与时钟分布 |

## 7. 三条常见误解

**误解 1：parity 是校验位。**
纠正：parity 是同一行两字的高/低字选择位（0/1），两字是不同的 32 位配置数据。校验字是 **word 50**，且只在 fabric 块。

**误解 2：band 就是 clock region，两者同义。**
纠正：band 是帧地址空间划分（7 个，按 50 行一组），clock region 是物理时钟域（14 个 = 7 行 × 2 列）。数目与用途都不同。

**误解 3：一个 tile 的所有位都在一帧里。**
纠正：一个 tile 的位分散在它所在列的 26（INT）/28（BRAM/DSP）/36（CLB）帧里，每帧只占该行的**两个字**（parity 0/1）；横向看每帧则分给 50 行不同的 tile 加一个校验字。
