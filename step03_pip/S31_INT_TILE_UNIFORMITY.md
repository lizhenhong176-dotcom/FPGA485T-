日期：2026-11-09　设备：xc7vx485tffg1157-3（构建用 part，器件 xc7vx485t）

## 0. 一页结论

**【数据事实】INT tile 的「配置位结构」是上下文无关的**：14 个抽样 tile 跨 6 类位置
（普通 CLB / BRAM 邻接 / IO 夹缝 / 跨 band 边界 / PCIE 邻接 / IO 邻接），
`get_pips` 全部返回 **3,737 条 pip / 216 个族**，族名集合逐字节相同，0 差异。

**【数据事实】"216 vs 172" 是表定义的差异，不是结构差异**：多出的 44 个族全部是
**单源常通抽头**（BYP_BOUNCE0-7、BYP_L0-7、FAN_BOUNCE0-7、FAN_L0-7、GCLK_L_B6..B11_EAST/WEST），
每个恰 1 个源、无选择、无配置位。我们的 172 族表是**可配置族**集合，二者不矛盾。

**【数据事实】配置位覆盖 1,598 / 1,664 = 96.03%**，缺口 66 个 cell 全部落在 offset 0..3，
且呈 stride-4 规律（bits 0,4,8,…,28 各一档）。

**【数据事实】tile 实例基址覆盖 142 / 53,100 INT tile ≈ 0.27%**（含 2 个非 INT 锚点共 144 条）。

## T2 66 个未覆盖 cell 的定性

分布（单侧）：

| offset | 缺失数 | 位位置 |
|---|---|---|
| 0 | 17 | parity 0：0,4,8,12,16,20,24,28,31；parity 1：同 |
| 1 | 17 | parity 0：3,7,11,15,19,23,27,30,31；parity 1：同 |
| 2 | 16 | parity 0/1：0,4,8,12,16,20,24,28 |
| 3 | 16 | parity 0/1：3,7,11,15,19,23,27,31 |

**特征**：stride = 4，且 offset 0/2 用 `4k` 档、offset 1/3 用 `4k+3` 档 —— 与 offset 4..15
的 FAN/GCLK/BYP 控制区**同构**（那些区的档位也按 4 步进）。因此判定：
**这 66 个位置属于 offset 0..3 上的「控制/时钟选择」类，artix7 参考表未收录**，
不是"用不到的 padding"。

> 【推断，待验】它们最可能是 V7 在 `GFAN/GCLK/BYP` 上的额外档位（V7 比 artix7 多 4 条
> 全局时钟缓冲，B6..B11 已见 6 条 GCLK_L）。反证方式：在 V7 上构造 `GCLK_L_B6..B11`
> 与 `GFAN0..7` 的选择实验，看这些位是否翻转。

**每个的最小验证实验**（统一模板）：
1. 设计固定在一个已知基址的 INT tile 邻接 slice（如 `SLICE_X8Y11`，块 31680）；
2. 唯一变量 = 让网从 `GFANk` / `GCLK_L_Bk` 进入（用 `set_property ROUTE` 钉最后一跳）；
3. 差分后只保留 offset 0..3 的位，核对是否命中 T2 列表中的坐标。

# T4b 修正（重要）：25 个 unexplained 的定性 + 方法学缺陷

## 25 条的分布（实测明细）

| tile | 条目 | 观测（均恰 1 位为 1） |
|---|---|---|
| `INT_R_X9Y11` | GFAN1 / NW6BEG1 / SS6BEG0 | (0,0,18) (4,0,19) (5,0,14) |
| `INT_R_X33Y50` | NN6BEG2 / NW6BEG3 / SS6BEG1 / WW4BEG1 | (7,1,7) (7,1,19) (6,0,30) (6,0,16) |
| `INT_R_X33Y78` | 同上 4 个 | 同上 |
| `INT_R_X33Y94` | 上 4 个 + NE6BEG3 | 同上 + (7,1,21) |
| `INT_L_X32Y78` | 同上 4 个 | 同上 |
| `INT_L_X32Y94` | 上 4 个 + NE6BEG3 | 同上 + (7,1,21) |

**与 66 个缺口的重叠 = 0**：缺口全在 offset 0..3（stride-4），这 25 条落在 offset **0/4/5/6/7**，
且每个是「一个必须为 1 的胞为 1、其配对的组/成员胞为 0」= **半码**。
这些胞在表里都**唯一属于某一个家族**（逐条查询 `all_cells.json` 确认，无跨界），
所以不是跨家族共享。

## 决定性发现：命中数不是基址判别器（推翻 S30/T4 的仲裁口径）

把同一块帧当不同 tile 解，得分完全由「该块有多忙」决定，与 tile 身份无关：

| 被解的 tile | 31760 | 31752 | 31716 | 31680 |
|---|---|---|---|---|
| `INT_R_X9Y11` | 1 | 3 | 2 | **12** |
| `INT_L_X8Y11` | 1 | 3 | 2 | **12** |
| `INT_L_X6Y11` | 1 | 3 | 2 | **12** |
| `INT_R_X7Y11` | 1 | 3 | 2 | **12** |

四个不同 tile 在同一块 31680 上都得 12 个 unique。原因：**所有 INT tile 的家族位布局完全相同**
（这正是 T3 的结论），所以「某块被某 tile 写入」的位模式，用**任何**同类型 tile 的家族表都能匹配出
唯一源 —— 匹配成功只证明**布局一致**，不证明**基址正确**。

⇒ 两条必须撤回/降级的说法：

1. **S30 的「命中数最多 + 平局看链」仲裁口径对 INT tile 不成立**，只能用于
   「已知该块属于哪个 tile、要区分 base 与 base±36」这类局部判定。
2. **T4 的 193 unique 不能作为「基址表正确」的证据**，只能作为「offset↔bit 布局一致」的证据。
   25 条 unexplained 也不是「真缺口」，而是**某几步链在此块写入的位与本地家族表不匹配**
   （半码/邻块内容），它们的出现恰恰因为该块并非我们声称的那个 tile 的行范围。

## 修正后的基址判定原则（结构性，非统计性）

列内块序列是确定的：CLB 列 36 帧、接口/BRAM/DSP 列 28 帧，按列类型序列首尾相接。
因此基址应由**列组成 + 块序号**推导（`tilemap` 的 `_build_blocks` 已实现），
而 `tile_blocks` 表里的实测值只作为**校验集**，不与推导冲突时两者一致。

**验收方式改为对照真值**：用 `route_I*.txt`（Vivado ROUTE 真值）的 tile/wire 序列，
检验 walk 是否能**逐 token** 复现 —— 这与基址正确性强相关（S24 已做到 6/6）。

## 下一步（修正后）

1. 用结构性 `_build_blocks` 重算全部 142 个 tile 的基址，与实测表比对，列出不一致项并逐个仲裁（用真值链而非命中数）。
2. 重跑绝对态判读，看 25 条 unexplained 是否消失（预期大部分消失或变为 0）。
3. 若仍有残余，再按「V7 额外源编码」方向做定向差分。

# T4c 结构性基址重算的结果：实测表本身不可靠

## 1. 用 `tilemap` 的结构规则重算 144 条实测基址

| 口径 | 一致 | 不一致 |
|---|---|---|
| 结构性推导（列序 + 相邻 CLB + 28 帧接口块） | **86 / 144** | 58 |

不一致项不是随机分布，而是**系统性取到了邻列的块**：
`INT_L_X14*` 实测 31960（= 西侧 CLBM_L_X12 + 36）而推导给 32024；
`INT_L_X20*` 实测 32168 而推导 32196；`INT_L_X26*` 实测 32368 而推导 32396。

## 2. 更根本的问题：同一列同一带出现**多个基址**

按 (列, band) 分组统计实测值，10 个列出现多基址，其中 8 个是**冲突**：

| 列/带 | 实测票型 | 多数派 |
|---|---|---|
| `INT_L_X8`/0 | {31752:4, 31788:1} | 31752 |
| `INT_R_X15`/0 | {31960:5, 31988:1} | 31960 |
| `INT_R_X21`/0 | {32168:6, 32196:1} | 32168 |
| `INT_R_X27`/0 | {32368:4, 32396:1} | 32368 |
| `INT_L_X32`/1 | {27322:9, 27354:2} | 27322 |
| `INT_R_X33`/1 | {27354:3, 27322:8} | **27322（可疑）** |
| `INT_R_X9`/0 | {31760:1, 31788:1} | 平票 |
| `INT_R_X27`/1 | {27150:1, 27122:1} | 平票 |

**关键矛盾**：band1 的 `INT_L_X32` 与 `INT_R_X33` 不可能同基址（相邻两列各有独立块，
其它列全部相差 28/36）。而多数派把两者都判成 27322 —— 说明**多数票不可靠**：
S13 的「命中数命中即采纳」会把同一个块反复判给多行多列（正是 T4b 证明的混淆）。

## 3. 结论：基址必须靠**全局平铺求解**，不能靠任何局部统计

已知硬约束（全部实测）：
1. 块长只有 36 帧（CLB 列）与 28 帧（接口/BRAM/DSP 列）两种；
2. 同一 band 内各列块首尾相接，band 宽 5,180 帧、带间 pitch 5,246；
3. 相邻 `INT_L`/`INT_R` 列各占独立块，基址差 28 或 36；
4. 已存在的 144 条实测值只是**局部候选**，会与邻列混淆，不能当锚点全信。

可判定的求解方式：把每个 band 视为「按列序分配块长」的**一维平铺问题**，
用 5,180 帧/带 + 首块基址作边界条件求解；再用 `route_I*.txt` 真值链做**唯一验收**
（S24 的 6/6 就是在这个口径下达成的）。

## 4. 因此对 T1/T4 的最终定性

- **结构同质性（T3）成立**：族集合、位布局与位置无关 —— 这部分不受影响，是全篇最硬的结论。
- **基址表（T1 的 0.27% 覆盖）实际质量低于表面数字**：144 条里至少 8 组自相矛盾，
  且矛盾来源已定位（用"命中数"当仲裁依据）。真正可信的基址数量需按全局平铺重算后才知道。
- **25 条 unexplained 与 66 个缺口的性质不同**：前者是基址/块归属错误的症状，
  后者是 artix7 表未收录的控制/时钟位置（形态证据独立：stride-4 与 offset 4..15 同构）。

# T4d 反转：块是「(列, 行槽)」而非「列」，实测表没坏（我的假设坏了）

## 1. 决定性问题：走线链用的是哪些基址

把 S24 那 8 条 6/6 真值链的节点按 (列, Y) 展开，看它们落在实测表的哪些条目上：

```
INT_R_X7Y12 → INT_R_X9Y12 → INT_R_X11Y12 → INT_R_X13Y16 → INT_R_X15Y20
→ INT_R_X17Y24 → INT_R_X19Y28 → INT_R_X21Y32 → INT_R_X23Y36 → INT_R_X25Y40
→ INT_R_X27Y44 → INT_R_X27Y50 → INT_R_X31Y51        (SW6 每跳 2 列 +4 行)
```

`INT_R_X15Y20`、`INT_R_X21Y32`、`INT_R_X27Y44` —— **正是我在 T4c 里标成"冲突/离群"的三条**。

而这三条所在的链与 `route_I*.txt` **逐 token 一致（6/6）**。⇒ **这些基址是对的**，
错的是我的假设：「同一列同一带只有一个块」。

## 2. 真实几何：块沿 SW6 对角线递增

| tile | 基址 | 相对上一跳 | wof(Y) |
|---|---|---|---|
| `INT_R_X15Y20` | 31988 | — | 40 |
| `INT_R_X17Y24` | 32060 | +72 | 48 |
| `INT_R_X19Y28` | 32132 | +72 | 56 |
| `INT_R_X21Y32` | 32196 | +64 | 64 |
| `INT_R_X23Y36` | 32268 | +72 | 73 |
| `INT_R_X25Y40` | 32332 | +64 | 81 |
| `INT_R_X27Y44` | 32396 | +64 | 89 |

基址随 Y 单调递增、步长 64~72 帧 —— 说明**块是 (列, 行槽) 二维的**：
一列在一个带内被切成多个行槽块，块首尾相接沿 Y 推进。

## 3. 因此要撤回/修正的三条

1. **T4c 的"144 条里至少 8 组自相矛盾"作废**：那 8 组不是矛盾，是同一列不同行槽。
   `INT_L_X32`/`INT_R_X33` 的 27322 vs 27354 也同理（不同行槽），不是"相邻列同基址"。
2. **T4b 的 25 条 unexplained 改判**：不是"基址错"，而是**该 (列,行槽) 没有实测样本**，
   只能用邻近外推 → 位位置错一档 → 半码。
3. `tilemap` 的 `_build_blocks`（每列一个块）**模型层级就不对**，应改为 (列, 行槽)。

## 4. 结论：基址只能"测"，不能"推"，但测法要换

- 命中数法（S13）**不可用**（T4b 已证）；
- 每列一槽的递推**不可用**（本节已证）；
- 可用的是：**稀疏探针**——构造只经过目标 tile 的一条网的极小设计，使该 tile 只有一个活跃 family，
  扫候选基址，只有正确基址能让"恰好 1 个 family 匹配、其余全 0"。特异性高，不受"块有多忙"影响。

|---|---|---|---|---|
| `INT_R_X15Y20` | 31988 | (1,1,2) | **31960 (=真值−28)** | (1,1,**2**) 完全相同 |
| `INT_R_X17Y24` | 32060 | (1,1,2) | **32024 (−36)** | (1,1,**2**) |
| `INT_R_X21Y32` | 32196 | (1,1,2) | **32168 (−28)** | (1,1,**2**) |
| `INT_R_X9Y11` | 31760 | (1,4,5) | 31680 | (12,12,36) 更"好" |

⇒ **判据不可用**：真值基址与 ±28/36 的基址给出**完全相同**的判读。

## 2. 原因：整片帧 90% 是空的

`frames 31000..32600`（1600 帧）里：
- 与 `f+28` 完全相同：**1,438 帧（89.9%）**
- 与 `f+36` 完全相同：**1,448 帧（90.5%）**
- 该区间非零帧只有 **90 帧**

绝大多数帧全零，所以"基线位移到空区"与"位移到正确区"在判读上无法区分；
一旦位移恰好落进邻 tile 的内容，反而会冒出更多"匹配"（`INT_R_X9Y11@31680` 得 12 unique）。

## 3. 结论：基址=槽位的问题，只能靠"内容随 Y 移动"的差分解

正确实验设计（**Y 差分**）：同一列、只让网经过 Y1 与 Y2 两个不同行槽的两个设计，
逐帧差分。差出来的帧集合就是该列两个行槽的**帧区段**，两者的起点差 = 行槽步长。
这不需要"块忙不忙"，也不依赖任何匹配判据 —— 是纯几何测量。
