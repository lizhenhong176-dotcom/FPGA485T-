# 实验思路的构建过程与相对已有工作的差别

> 三色标注约定：【硬件事实】= 硅片/工具链给定、不可配置的事实；【数据事实】= 本次实测、给出分子/分母与复算入口；【推断】= 解释性判断，可被实验推翻。无数据处写「未测」。
> 全文数字均给分子/分母与出处；出处为脚本名（`step03_pip/` 或 `v7re/scripts/`）或文档节号。

## 一、一句话结论

【数据事实】在 XC7VX485T 的 `INT_L`/`INT_R` 两类 tile（各 26,550 个实例）上，172 个多源 mux 族的 3,634 条配置位连接只占用 1,598 个不同位格（2.27 条连接/格）；其中 3,552 条（97.7%）可由「族名 + 源名 + 序号」生成、逐位 0 差异（`step03_pip/gen_slots.py`），并与 Vivado 真值一致 1,155/1,263（91.45%）。

## 二、实验思路是怎么长出来的（8 步）

**第 1 步 · 图从哪来**
现象：要做位级研究，先得知道「哪些线之间可以连」。
受控实验：用 RapidWright 导出每类 tile 的 wire 与 PIP 图（`v7re/scripts/step1_topology.py export`，产物 `templates/<TYPE>.json`）。
判据：115 类 tile 的实例签名是否一致。
结论：【数据事实】115/115 类 uniform、150,380 个实例、每 `INT_L` tile 600 wire / 3,737 PIP / 216 个目的 wire（`type_uniformity.json`）。
动因：图只说明「能连」，不说明「哪个位置 1」，所以要造差分。

**第 2 步 · 一次只改一个属性的差分**
现象：改一条连接，位流里到底哪几个位变了？
受控实验：同一 `.v`、只改一个 `LOC`/属性，显式 `-part`，回读断言，两版 `.bit` 逐帧逐字 XOR。
判据：差分必须落在「帧/字/位」三元组且可复现（同参重跑差异 0）。
结论：【数据事实】一个 PIP 的位集合随 tile 的 Y 坐标改变 word：`word = 2*(Y%50)+parity`，且 ≥50 时 +1 跳过校验字（`v7re/scripts/bitwriter.py:41-43`）。这条是后面全部定位的地基。
动因：word 依赖 Y，说明地址不是线性表，得先解地址链。

**第 3 步 · 解地址链**
现象：62,625 个 tile 各自有帧号，逐条存表不可扩展。
受控实验：用 FAR 字段（`[25:23]` block、`[21:17]` row、`[16:7]` column、`[6:0]` minor）与实测帧号对齐。
判据：`frame = far_bands[(band,col)].start_frame + frame_off` 是否能覆盖全部 tile 且 0 不符。
结论：【数据事实】`far_bands` 1,078 行 = 7 band × 154 列即可覆盖 62,625 个 tile；`band` 是 FAR 的 (block, top, row)，`col` 就是 FAR 的 column 字段（`step03_pip/_q_far_segments.py`）。
动因：地址能算了，才能把「所有 PIP 的位」摊到同一张表上比较。

**第 4 步 · 摊开之后看见的反常**
现象：把 3,634 条连接的位摊开，去重后只有 1,598 个位格。
受控实验：统计每个位格被多少条连接引用（列重），并按族、按源分组。
判据：若每条连接独占位，则列重应恒为 1。
结论：【数据事实】列重分布 1→4、2→5、3→26、4→909、5→384、6→134、12→12、18→128（合计 1,602 个族-格对，去重 1,598），4–5 档占 1,293/1,602 = 80.7%（`step03_pip/_q_reuse_structure.py`）。→「复用」不是零散现象，而是编码方式。
动因：既然多位共享，就必须知道共享的结构，否则解码会有歧义。

**第 5 步 · 从列重反推结构（不看族名、不看帧号）**
现象：能不能只用「哪些位一起亮」推出分组？
受控实验：按列重二分（最轻档 = 组选择位，每源恰含 1 个），检验三条判据：每源恰 1 组格 / 各组等大 / 各组码字模式集合相同。
判据：完全叉积（组 × 码，无缺失无重复）。
结论：【数据事实】163/172 族通过，维度为 (6 组,4 源,4 码)×64、(5,4,4)×96、(6,3,3)×2、(4,3,3)×1；9 个例外恰好是已知的复合族与长线族（`step03_pip/_q_grid_is_real.py`）。【推断】6 与 4 分别对应「组轴」「码轴」，但**没有证据**说硅片上排成 6 行 4 列。
动因：结构成立了，下一步要问「能不能反过来生成」。

**第 6 步 · 写生成器，用 0 差异当判据**
现象：如果结构是真的，应该能从名字生成全部位。
受控实验：`gen_mux.py`（族级）与 `gen_slots.py`（槽位级）重建，逐位与 `law_cells` 比对。
判据：0 差异，且不许逐族硬编码。
结论：【数据事实】mux 64/64 逐位 0 差异、16 种配置×4 族；BEG 96/96（含 32 个变体族的列归属规则）；复合 6 族组模型 96/96 → 合计 3,552/3,634 = 97.7%，剩 82 条（6 个长线族）判为逐族表数据（H1/H2 两条候选规则分别只 22/36、25/36 唯一，已证伪）。
动因：生成器只证明「与本表自洽」，还需要外部真值。

**第 7 步 · 四条外部支路**
受控实验：①与 Vivado `get_pips` 真值对账 ②全器件位扫描 ③不变量在真实位流上零违例 ④从 FASM 重生成整片位流。
判据：每条支路独立给一个数，且必须能互相否定。
结论：【数据事实】真值 1,155/1,263 = 91.45%；全器件 12,565 tile / 64,686 位表外 0；不变量 231,656 槽位 0 违例；重生成与 Vivado 产物 50,176 帧全等（仅差时间戳与尾部 CRC）。
动因：INT 内部已闭环，接着问「这套结构是不是只在 INT 成立」。

**第 8 步 · 跨类型试迁移**
受控实验：把同一套判据（位池可定位 / 每源恰 1 组槽位 / 组内码字唯一）套到 `HCLK_CMT` 与 `CLK_HROW`。
结论：【数据事实】`HCLK_CMT` 通过三条判据（1 组槽位 + 2–4 码字），但位池不在 `frame_off 16..25`，而在相邻逻辑列块尾帧 `minor 26..29`；`CLK_HROW` 的 32 个 GCLK 源由局部公式给出（实测 19/32，公式在未参与拟合的 k=2 上独立复现），另 30 个 CK_IN 源不占置位字段（25 个设计零反例）。→ 3/115 类型。

### 三次「判断错了」

| 现象 | 当时结论 | 发现机制 | 更正后 |
|---|---|---|---|
| 列重统计把 sense=0 行也算了进去 | 「70/172 族 4:1 合并、平均 3.35 格」 | 用 `verify_all_pip.py` 复算 172/172 与之冲突 | 只取 sense=1：172/172 族内唯一、2.45 格/连接 |
| `INT_R` 覆盖率只有 63.6% | 「右侧位库不全」 | 归一化族/源名后覆盖率跳到 100% | 是左右侧线名不对称（`IMUX_L40` vs `IMUX40`） |
| 篡改检测器报「幽灵 mux 100% 检出」 | 「2 bit 篡改一定被抓」 | 扣掉 120 个带标记位 tile 的基线后归零 | 幽灵 mux 0/300；换源 18/300 = 6.0% |

## 五、我们不如人的地方（逐条点名影响）

1. **器件只有一颗**（跨器件 0/1，`STATUS.md` §161）→ 影响「97.7% 是 7 系列普遍规律」这一句，只能改口为「485T 上成立」。
2. **类型只有 3/115**（INT 两类 + 两个部分验证）→ 影响「复用是 7 系列 tile 的通用编码方式」，只能改口为「INT 类内成立、另两类结构相似」。
3. **82 条长线族无公式**（82/3,634 = 2.3%）→ 影响「100% 可生成」，只能说 97.7%。
4. **假阴性未知**：与 Vivado 真值一致 91.45%，但真值本身只覆盖 1,263 条 PIP，未覆盖部分不知道错在哪 → 影响「解码正确率」的表述（不能让 91.45% 看起来像上界）。
5. **没有可加载闭环**（ECC 地址项未闭合）→ 影响「能生成可加载位流」，本工作只能声明「位级一致」。
6. **与 prjxray 的信息量差别未被独立证明**：我们没有证明「我们的形式必然包含 prjxray 没有的信息」，只能说「形式不同、且我们给了压缩比」。

## 六、可被推翻的方式

| 什么实验 | 我们会改口成什么 |
|---|---|
| 在另一颗 7 系列器件上跑 `gen_slots.py`，0 差异率 <50% | 「97.7%」降级为「485T 专用规律」，跨器件结论删除 |
| 换一个非 INT 类型做整族重建，0 差异率 <50% | 「结构可迁移」改为「INT 内部结构，跨类型不成立」 |
| 用独立 fuzz（不依赖本表）反推出同一批位，且与我们的族分组不一致 | 「族 = 一个 mux」的分组结论作废，退回逐 PIP 枚举 |
| 真值覆盖扩到 3,000 条 PIP 后一致率掉到 <80% | 「91.45%」改为「小样本偏高」，解码器可靠性结论撤回 |
| 有人给出 vx485t 的公开 segbits 全表，且与我们的生成规则等价 | 「生成规则」的贡献改为「对既有表的压缩重述」 |
| 82 条长线族里找到统一公式 | 「82 条 = 表数据」改为「全族可生成」 |
