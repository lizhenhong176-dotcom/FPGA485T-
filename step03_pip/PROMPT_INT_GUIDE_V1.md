【任务】撰写一份「INT tile 实验完全指南」，目标读者为从未接触过本项目的两类人：新加入的同学、导师组内非本方向（非 FPGA 体系结构/EDA 方向）的老师。读者读完后应能独立回答四个问题：（a）各术语分别是什么意思；（b）实验流程按什么顺序推进；（c）每一步为什么必须这样设计；（d）这套方法到底覆盖了器件中多大比例的 PIP。

【必须包含的四块内容及具体要求】

1. 术语详解（逐个覆盖以下 22 个术语，不得遗漏，顺序可自定但要保证先定义后使用）：
tile / site / wire / PIP / mux / family（族）/ CRAM / frame（帧）/ word / bit / frame_off / parity / FAR / band / col / region / row / 码字 / 一热编码 / 完全二分 / 双格边编码 / sense=1 / 列重 / word 50 ECC / 直通 PIP / VCC_WIRE 常量输入。
每个术语必须写满以下四段，缺一不可：
① 一句话定义（不超过 40 字，面向零基础读者）；
② 本项目中的具体取值或形态（注明对应文件/表/字段名）；
③ 一个带真实数字的例子（数字须可复算，按第 6 条标注复算入口）；
④ 一个常见误解，并明确写出"错在哪"（一句话指出错误假设）。

2. 实验流程：固定 8 步。每步用统一小表或固定字段写清五项：
- 目的（这步要解决什么问题）；
- 具体做法（明确列出读取哪个文件、运行哪个脚本、关键参数是什么）；
- 判据（满足什么条件算通过，给出可核对的数值或状态）；
- 产出（生成什么文件/表/中间结果，命名规则）；
- 如果这步不做会怎样（说明缺失导致的后果或下游影响）。
要求：读者仅凭本节即可从头复现整个流程，不依赖任何未列出的隐含步骤。

3. 为什么这么做：至少给出 4 条硬性设计理由。每条理由必须包含：
- 理由陈述（为什么采用当前设计）；
- 至少一个更简单的替代方案；
- 明确说明为什么不用该替代方案（给出具体代价、错误率、不可行点或数据反例）。

4. 覆盖范围（本节为全文最重要部分，必须给出精确分子/分母）：
- 第一层（tile 内）：一个 INT tile 内共 3,737 条 PIP，按四类划分（有编码的 / VCC 常量 / 直通 / 表数据），逐类给出条数与占比（分子/分母形式）；
- 第二层（类型级）：说明 INT_L / INT_R 各 26,550 个实例共用同一张表，因此"类型覆盖 = 实例全覆盖"这一结论成立的前提条件必须写明（例如同一 family 内表完全一致、无实例级例外）；
- 第三层（器件级）：115 个 tile 类型中含 PIP 的为 70 个、共 35,126 条 PIP；明确给出"本工作完成建模的条数 / 35,126"及其占比。
- 硬性禁止：不得出现"全部覆盖""所有 PIP"等无分母表述；每一句涉及覆盖的陈述都必须带分子/分母。
- 本节开头先给一句直接结论，明确回答"不是所有 PIP 都被建模"这一问题，再展开三层账。
