## 结论摘要（5 行）

- 【数据事实】172 个多源 mux 家族里，3,552/3,634 = 97.7% 的连接可由「族名 + 源名」经公式或规则生成，其余 82/3,634 = 2.3% 只能查表。
- 【数据事实】生成器与独立校验器双向闭合：生成端 0 回落，校验端 172/172 族、不符 0。
- 【推断】主要缺陷不是「还不知道位在哪」，而是四类：97.7% 之外的长线族（拓扑数据）、行轴的物理意义无版图证据、跨 tile 类型只有 3/115、跨器件 0/1。
- 【数据事实】编码侧已定性：合法码集 {1,2,7,11} 的最小汉明距离为 2，单 bit 翻转必落非法值。
- 下一步最小实验：给 6 个长线族 82 条连接补「长线邻接表」并判定能否 ≥80/82 闭合（判据见缺陷账第 1 行）。

1. 【数据事实】生成器闭合：`python step03_pip/gen_slots.py`，2026-11-13 输出 `[mux] 纯定律 64/64，需回落 0`、`[BEG] 纯定律 96/96，需回落 0（其中变体规则 32/32）`、`[复合] 组模型 96/96 源 0 差异`、`[其它] 6 族`、`覆盖 3552/3634（97.7%）`。

## B. 只有行为学证据的（证据类型 + 样本量）

1. 【推断】64 个 24 源族的「6 行 × 4 码」是物理开关矩阵：证据 = 6×4 满填、每行恰 4 源（64/64）、16 个线源恒分 4 组×4 且每组恰含一个长度类（256/256）、行归属 16 种签名×4 族；**无版图观测**。
2. 【推断】「4 列 = 长度类」：证据 = 合法码与线长类别一一对应，且 `getWireIntentCode()` 在 4 组内恒为 2 DOUBLE + 2 SINGLE（每组一致）；线索引在组内离散（237/333/226/348）。
3. 【推断】BEG 96 族是完全二分 K(5,4)/K(4,5)：证据 = 96/96 族 2-着色成功；物理含义（是否为独立开关层）未观测。
4. 【数据事实】E5 全器件抽样：12,565 tile / 64,686 位、表外 0；E8 改 `BUFGCTRL.SEL` 重生成与 Vivado 产物 50,176 帧全等（2026-10-24 实验，脚本无单一入口，需按 `v7re/steps/` 复现）。
5. 【数据事实】跨类型结构同形：CLK_HROW 32 个 GCLK 源公式实测 19/32（k=1..17、24、31）；HCLK_CMT 11 个源（7 MMCM + 4 PLL）测出组槽位 + 码字；30 个 CK_IN 源经 25 个设计的标记普查判为默认通路。

## C. 明确没做到的

1. 【数据事实】6 个长线族 82 条连接无公式：82/3,634 = 2.3%，现以逐族表承载。阻塞原因 = 其源是别的长线的端点线，编码的是长线间邻接（拓扑数据），而 `pip_defs` 的 `delayIndex` 在 INT 全 0。
2. 【数据事实】行轴物理意义无证据：RapidWright `Site.getSitePIPs()` 138 条全是 LUT 输出选择、`Tile` API 无内部行列；Vivado `link_design` 批处理探针挂死 >10 分钟。阻塞原因 = **工具上限**，不是我未做。
3. 【数据事实】跨 tile 类型 3/115、跨器件 0/1：只覆盖 INT_L/INT_R + CLK_HROW 抽样 + HCLK_CMT 抽样。阻塞原因 = 每类型都需重新定位位池（3/115 已做）。
4. 【数据事实】超出 26 帧块（`frame_off` 16..25 + 6..15）与 word 50 的区域未建模；ECC 依赖帧地址未闭合，故尚不能生成任意可加载位流。

## 如果我错了（3 条最易被打穿的断言）

1. 「97.7% 可由名字生成」——若生成器与校验器共用同一张开局表，则这个数字是自证。
   1 天实验：用生成器**只**输出 172 族槽位、不读 `law_cells`，与 `law_cells` 逐条比对；判据 = 差异 ≤82 条（即仅长线族）为通过，否则数字作废。
2. 「4 列 = 长度类」——若长度类只与线名相关而与列码无因果关系，则列轴解释错误。
   1 天实验：取 10 个家族，检查同名线类是否恒落同一列码；判据 = ≥95% 一致为通过，<80% 为否。
3. 「跨类型结构同形」——若 CLK_HROW 的 19/32 只是局部巧合。
   1 天实验：对 `CLK_HROW_TOP_R` 另选一族（`CK_BUFG_CASCO*`，37 源）复跑同口径；判据 = 至少一族 0 差异率 ≥50% 为「同形」成立，否则改口为「INT 专属」。

## 定位句

【推断】在 7 系列 INT tile 内，PIP 选择位的「族—行—码」三层可由族名与源名重建，覆盖 3,552/3,634 条连接（97.7%），其余 82 条编码长线邻接。

### 2026-11-13 晚补充：82 条的编码结构已定性（`STATUS.md §178`）

- 【数据事实】6 个长线族可以写成 **A 轴 × B 轴的双格边编码**（源 = 一个 A 格 + 一个 B 格），与 mux（6×4）、BEG（5×4）同一形式。
- 【数据事实】**48/82 = 58.5% 落在完整乘积网格上**：`LH12` 4×3、`LVB_L0` 6×3、`LVB_L12` 3×6；其余 34 条是稀疏子集（`LH0` 12/20、`LV_L18` 12/20、`LV_L0` 10/12）。
- 【数据事实】三条候选规则（模板顺序、方向/到达边、全局端口序号）全部被证伪；同一源在不同族里 A/B 序号不一致。
- 【数据事实】落表代价从「82 条」压缩到「≤54 个格 + 82 条边」，其中 48 条可按完整网格的坐标表存储。
