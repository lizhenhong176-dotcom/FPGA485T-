# 多源 mux 的配置位是怎么测出来的（给老师看的版本）

> 读者：熟悉 Vivado 流程、但不了解比特流逆向。读完 30 分钟应能复述三件事：数据从哪来、实验怎么控制、凭什么可信。
> 器件：XC7VX485T（探针实测 `xc7vx485tffg1157-3`）；帧结构 50,176 帧 × 101 字。
> 记号：「实测」= 本机跑出来的数字；「推断」= 我们的解释，附可推翻条件。

---
## 一、一页结论
我们做了三件事：**（1）** 把一颗 7 系列 FPGA 的布线开关（PIP）按"终点线"归成 172 个"多选一"开关组（mux）；**（2）** 用受控差分实验测出每个 mux"哪个配置位选哪条源线"；**（3）** 反过来用一张小表重新生成全部开关位，与实测**逐位 0 差异**（`step03_pip/gen_mux.py` + `gen_slots.py`：3,456/3,634 = 95.1%）。

可信度分三级：同源自证（全过）、外部真值（Vivado 真实布线解出 1,155/1,263 = 91.45%，`tamper/ref/pips_all.txt`）、全器件外推（12,565 个 tile、64,686 个置位，**表外位 0**，`v7re/steps/PIP_BIT_REUSE_REPORT.md` §E5）。**未做**：跨器件验证 0/1。

## 二、多源 mux 是什么（结论：它是"器件结构"的事实，不是我们的定义）
一个 `INT_L` tile 里有 600 条连线、3,737 个可编程连接点（PIP，两根线之间一个受配置位控制通断的开关）。每个 PIP 都有一个"终点线"；**把终点线相同的 PIP 归到一组**，就得到一个"多选一"开关组——术语叫 mux，组内互斥（同一时刻只能通一条）。这就是电路事实，不是我们发明的。

216 个终点组里，172 组有不止一个候选源，于是有 172 个 mux；按候选源数量分六档：24 源 64 个、20 源 96 个、18 源 2 个、16 源 6 个、12 源 3 个、10 源 1 个（`templates/INT_L.json` + `step03_pip/_q_mux_fanin2.py`）。

举一个具体例子：`IMUX_L40` 有 **24 条候选源**，但它只占 **10 个配置位**（`law_cells`：`frame_off 16..25`、`parity 0`、`bit = [6,6,7,7,6,6,6,6,6,6]`）。24 条源压在 10 个位上，靠的是"6 个组选择位（一热）+ 4 位列码"——这就是**复用**：一个位被多个源共用。全器件层面：172 个 mux 的 3,634 条连接共用 1,598 个物理位，平均每条连接 2.45 个位（`law_cells`，只统计"必须置 1"的行）。

> 类比：一个总机有 24 个分机，但接线表只有 10 个格子——先把分机分成 6 组（组号占 6 格，一热），再用 4 格写"组内第几个"。类比到此为止，实际是：6 格对应 6 个物理位且**恰好只有一个**为 1，4 格组成一个码，合法码只有 4 个值 `{1,2,7,11}`。

## 三、数据从哪来（结论：两条独立的链，一条给"图"、一条给"码"）
```
【图】谁和谁在同一个 mux 里
Vivado 器件库  data/parts/xilinx/virtex7/…            （一次性）
   └─ RapidWright 2026.1 编译成
      ~/.local/share/RapidWright/data/devices/virtex7/xc7vx485t_db.dat  （一次性，3.6 MB）
        └─ step1_topology.py export                    （一次性，约 1 小时）
           └─ templates/INT_L.json  600 wire / 3,737 PIP                （产物，静态）
              └─ 按终点线聚合 → 216 组 → 172 个多源 mux                （脚本算，可随时重跑）

【码】哪个位选哪条源
Vivado 构建 基线.bit  与  变体.bit                      （每次都做，一次一个变量）
   └─ 位级相减，剔除 ECC 字（word 50）
      └─ 三元组 (frame_off, parity, bit) 集合            （产物 JSON）
         └─ 与【图】按"同一次构建的 .pips 与 .bit"对齐 → 位库表（law_cells）  （join，可复算）
```

为什么要两条链：**图**只告诉我们"这个 mux 有哪些候选源"，不告诉我们"哪个位选它"；**码**只告诉我们"这几位一起变了"，不告诉我们"这几位属于哪个 mux"。两者对齐，才有"某族某源 → 某几位"。

## 四、差分怎么控制（结论：一次只动一个变量，且必须自证动的是那一个）
| 控制措施 | 做法 | 不做会得到的错结论 |
|---|---|---|
| 固定位置 | `set_property LOC SLICE_X11Y20` + `BEL A6LUT` | 位置漂移，差分跨很多帧，无法归因 |
| 锁引脚 | `set_property LOCK_PINS {I0:A1 … I5:A6}` | 引脚被 placer 重排，索引变成"当次布局顺序"→ 同一位置三次测量出三张表（T13 因此报废） |
| 变体同源 | 都从同一个 `routed.dcp` 派生，只改一个 `INIT`/一条 PIP | 重新综合引入布局噪声，把噪声当配置位 |
| 基线与负对照 | 不改的构建重跑一次，差分必须 0 | 环境问题被当成"发现了新位" |
| 反读自证 | 用一个没参与训练的值反读，预测集 vs 实测集必须 `missing=0` 且 `extra=0`（集合级，禁抽样） | 只中几个就宣布成功；T14 就是"挑选性采纳"翻的车 |
| 先声明差分语义 | PURE（参考流已删旧 PIP）/ XOR（旧 PIP 还在）/ FAM（整族加删） | 把 XOR 当 PURE 读 → 误判"形状随 CLB 类型变" |
| 排除 ECC 字 | 差分里 `word == 50` 的位全部剔除 | 每个源凭空多 4–20 个"数据位"，噪声掩埋真规律 |

一次实验的最小命令（简化版，可直接粘）：

```tcl
open_checkpoint /opt/lzh/v7re/work/exp/routed.dcp
set_property LOC SLICE_X11Y20 [get_cells u_lut]
set_property BEL A6LUT [get_cells u_lut]
set_property LOCK_PINS {I0:A1 I1:A2 I2:A3 I3:A4 I4:A5 I5:A6} [get_cells u_lut]
set_property INIT 64'h0000000000000001 [get_cells u_lut]   ;# 唯一变量
route_design -preserve
write_bitstream -force v1.bit
puts "PART=[get_property PART [current_design]] SITE=[get_property LOC [get_cells u_lut]]"
```

```bash
python v7re/scripts/diff_frames.py base.json v1.json --triplet   # 输出 (frame_off, parity, bit)
```

## 五、用了 Vivado 的哪些文件、为什么
| 文件 | 谁产生 | 在这次实验里干什么 | 为什么必须用它 | 不用会怎样 |
|---|---|---|---|---|
| 器件库（`data/parts/xilinx/virtex7/…`） | Vivado 安装 | 硅片结构的唯一源头（有哪些线、哪些 PIP） | 没有它就没有任何名字 | 无法命名线，实验无从开始 |
| `xc7vx485t_db.dat`（3.6 MB） | RapidWright 由器件库生成并缓存 | 让器件结构可被程序遍历 | 能批量、能离线复算，不必开 GUI | 每个实验都要手工点 GUI，无法复现 |
| `.xdc` | 我们写 | `LOC` / `BEL` / `LOCK_PINS` | 固定变量以外的一切 | 见第四节"锁引脚"一行 |
| `.dcp`（routed checkpoint） | 路由后 `write_checkpoint` | 所有变体的同一起点 | 保证"只动一个变量" | 差分里混入布局噪声 |
| `.bit` | `write_bitstream` | 差分原料（两个位流相减） | 配置位的真实取值只在这里 | 没有任何测量对象 |
| `.pips`（`get_pips` 文本） | Vivado Tcl | 真值：这个设计实际点亮了哪些开关 | 用来对账我们解出来的连接 | 只剩"自己验自己"，无法发现系统性错误 |
| `.rpt` / `vivado.log` | Vivado | 回读 `PART`/`SITE`/`BEL`、DRC 证据 | 抓静默回退（默认 part 写错、LOCK_PINS 没生效都不报错） | 整批构建被污染而不自知 |
| `.fasm`（第三方可读网表） | 逆向工具 | **未作为主依据** | 它本身也是逆向产物，且不含"位的位置" | 拿它当"真值"就是循环论证 |

（`get_pips` 的完整用法：`get_pips -of_objects [get_nets -hier]`，导出为 `tamper/ref/pips_all.txt`，1,812 条。）

## 七、老师最可能追问的 8 个问题
1. **差分里的位会不会是优化器噪声？** 不会——变体都从同一个 routed DCP 派生，综合与布局都没重跑；再加上"不改也重跑一次"的负对照（差分必须 0），以及集合级反读（预测集与实测集必须完全相等）。
2. **这套位库对每一颗芯片都成立吗？** 同一 die、同一型号内：26,550 个实例共用一张表，签名一致性检查 `uniform=True`、0 个不匹配（`type_uniformity.json`）。跨型号/跨 die 未测（0/1）。
3. **为什么不用 Vivado 自带的 FASM / route 报告直接读？** route 报告给的是"点亮了哪些开关"，不给"哪个配置位"；FASM 是逆向产物本身，用它当依据等于循环论证。我们的位来自**位流相减**，与它们不同源。
4. **24 个源怎么用 10 个位表示，会不会读错？** 解码不是"投票"而是**精确覆盖枚举**：穷举所有能恰好解释观测的源集合，1,066 个 tile 全部只有一个解（`out/p1_solvability.json`）。
5. **10 个位里为什么合法码只有 4 个？** 4 个列码位只用到 `{1,2,7,11}` 这 4 个值；一位翻转后一定落到非法码，所以单 bit 篡改 99.44% 可检出。
6. **漏检在哪？** 漏检的 8,831 个位（占空位 0.56%）全是"2 位候选的最后一格"——补上它，解码器会多报一条合法但没布线的开关，属于结构性盲区，不是 bug。
7. **误报怎么办？** 干净设计上 12.22% 的 tile 会报，但报警位恒定是两格已知标记位，加白名单后 0 报警（`--fpstats`）。
8. **能推广到别的器件吗？** 未知。目前只做了 2/115 种 tile 类型（按 PIP 数算 21.3%），跨器件 0/1。判据：新器件上 `gen_slots.py` 的 0 差异率 ≥95% 才算可迁移。

## 八、局限与下一步 + 名词小抄
**局限（实测）**：只覆盖 INT 两种类型（2/115）；单器件、跨器件未测（0/1）；82 条长线连接（2.3%）仍无公式只能查表；ECC 与帧地址的耦合未解，写出的位流还不能加载。**下一步**：artix7 同任务对照（0/1，2–3 人日）→ 再补 2–3 种 tile 类型 → 长线族 82 条 → ECC 地址项。

| 词 | 白话 |
|---|---|
| PIP | 两根线之间一个受配置位控制通断的开关 |
| mux | 终点线相同的一组 PIP，互斥（多选一） |
| 位库 | "哪个开关 → 哪几个配置位"的对照表 |
| 三元组 | 定位一个位用 `(帧内偏移, 奇偶, 位号)`，少一个就会认错位 |
| 帧 / 字 | 最小寻址单位：一帧 101 个字，第 50 个字是校验（ECC） |
| 差分 | 两次构建的位流逐位相减，得到"改这一处动了哪些位" |
| 反读自证 | 用没参与训练的值反算，预测集与实测集必须完全一致（不许抽样） |
| 外推检验 | 用真实设计里没用过的 tile 检验同一张表还成不成立 |
