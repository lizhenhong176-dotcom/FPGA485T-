我要一份「给老师看的」单文件 Markdown 说明，主题是：多源 mux（可编程互连里“多选一”的开关组）的配置位是怎么测出来的、差分实验怎么做到只动一个变量、整个过程中用了 Vivado 的哪些文件、为什么非用不可。

读者：我的导师/老师。他熟悉 FPGA 设计与 Vivado 流程（会综合、实现、时序），但不了解比特流逆向，也没有参与本项目。目标：30 分钟内读懂三件事——数据从哪来、实验怎么控制、凭什么说结果可信——并且能向别人复述。

必须讲清的三问：
1) 多源 mux 是怎么来的：一个 INT tile 有 600 条连线、3,737 个可编程连接点（PIP），按“终点线”分组得到 216 组，其中 172 组有多个候选源，这就是 172 个多源 mux；扇入分六档（24/20/18/16/12/10 源）。要给一个具体例子（如 IMUX_L40 有 24 个源、只占 10 个配置位）。
2) 差分实验怎么控制：为什么要固定位置、为什么要锁引脚（LOCK_PINS）、为什么变体要从同一个 routed DCP 派生、为什么要有基线与负对照、为什么要先用未参与训练的值做“反读自证”、为什么要先声明差分语义（PURE/XOR/FAM）。每条都要说“不做会得到什么错结论”。
3) 用了 Vivado 的哪些文件、为什么：必须给一张表，列为「文件 / 谁产生 / 在这次实验里干什么 / 为什么必须用它 / 不用会怎样」。必须覆盖：
   - Vivado 器件库（安装目录 data/parts/xilinx/virtex7 下的器件数据）——硅片结构的唯一源头；
   - RapidWright 由器件库生成并缓存的 xc7vx485t_db.dat（约 3.6 MB，位于 ~/.local/share/RapidWright/data/devices/virtex7/）——让“器件结构”可被程序查询，之后可离线复算；
   - .xdc 约束文件（LOC / BEL / LOCK_PINS）；
   - .dcp（routed checkpoint，变体的唯一起点）；
   - .bit（差分原料，两个位流相减）；
   - .pips（get_pips 导出的真值文本，用来对账我们解出来的连接对不对）；
   - .rpt / vivado.log（回读 SITE/BEL/PART 与 DRC 证据）；
   - （可选）fasm/可读网表为什么没作为主依据。

写作要求：
- 开头先给“一页结论”：我们做了什么、得到什么、可信到什么程度，三句话以内，不铺垫。
- 少术语。每个术语第一次出现时用一句白话解释（例如“PIP：两根线之间一个可用配置位控制通断的开关”）。大量使用类比（总机/接线表、锁死插座、指纹比对），但类比后必须紧跟一句“类比到此为止，实际是……”。
- 数字必须给分子/分母或来源文件，禁止“很多”“几乎全部”这类模糊表述；没有数据的写“未测”。
- 每节首句就是该节结论，后面才是论证。
- 不要写成论文：不写贡献声明、不写 related work、不出现“首次/唯一/完整”这类词。
- 三色标注可选，但凡是“我们的解释”必须写明“推断”，不要与“实测”混在一句里。
- 结尾给一张“名词小抄”（8 行以内）。

格式：单文件 Markdown，7 节固定顺序（一页结论 / 多源 mux 是什么 / 数据从哪来 / 差分怎么控制 / 用了哪些 Vivado 文件 / 结果与可信度 / 局限与下一步 + 名词小抄），总长不超过 130 行，每节表格不超过 8 行，命令用代码块并给出可直接粘贴的简化版。
