我要一份「多源 mux 的配置位是怎么测出来的」的单文件说明（Markdown），用于向同行讲解实验方法并可直接交接。读者有比特流逆向背景，但不了解本项目。

背景：器件 XC7VX485T（本仓库探针实测 part 为 xc7vx485tffg1157-3，VC707 对齐时才用 ffg1761-2），帧结构 50,176 帧 × 101 字。一个 INT tile 有 600 条 wire、3,737 条 PIP，按目的 wire 聚合成 216 个目的，其中 172 个扇入>1 —— 这些就是「多源 mux」，扇入 10/12/16/18/20/24 六档。我要讲的是：这 172 个多源 mux 的「哪个 bit 选哪条源」到底怎么测出来的、怎么证明测对了、Vivado 在其中怎么做到「只动一个变量」。

数据来自两条互相独立的链，必须讲清它们各自给什么、在哪一步对齐：
A) 器件模型链：Vivado 器件库 → RapidWright 2026.1（Java 17，JPype 调用，v7re/routing/env.py:95-100 的 Device.getDevice）→ v7re/scripts/step1_topology.py export（v7re/routing/topology.py:27-54 用 tile.getPIPs / getStartWireName / getEndWireName）→ templates/<TYPE>.json（INT_L: 600 wire_defs / 3,737 pip_defs）→ 按目的 wire 聚合成 172 个 family。这条链只给「谁和谁在同一个 mux 里」= 图，不给码。
B) 位流差分链：固定 LOC/BEL、锁引脚、只改一个变量、Vivado 重建、位级 XOR → 得到「哪几个 bit 变了」= 码。这条链要靠 A 的族名/源名做 join 才能落到具体某个 mux 的某条源上。
C) 第三条独立支路：Vivado get_pips 给出每个设计真实点亮了哪些 PIP，用于对账召回率。

Vivado 精准控制的要求（必须逐条写清做法与为什么）：
- 显式 -part（不许依赖默认 part，默认值历史上写的是 ffg1761-2，会静默污染整批构建）；构建后回读 PART/SITE/BEL 断言一致，否则该构建作废。
- set_property LOC / BEL 固定位置；对 LUT 施加 LOCK_PINS {I0:A1 I1:A2 …}，否则 I0..I5 会被 placer 自由重排，索引变成当次布局的逻辑顺序。
- LOCK_PINS 的管脚名不按 BEL 命名：SLICEM 的四个 6-LUT 管脚一律 A1..A6，写 I0:B1 会 ERROR 12-2497；换 BEL 前先用 get_bel_pins 实测。
- 变体优先由同一个 routed DCP 生成，避免重新综合/布局引入 relocation 噪声。
- 基线配对：未改变的构建重跑一次，差分必须为 0（负对照）。
- 差分语义先声明：PURE（参考流已删 sink PIP）/ XOR（参考流仍含旧 PIP）/ FAM（整族删或加）；语义不明则判读不定论。
- 远端 WSL 跑 Vivado 必须在脚本头写 export LANG=C.UTF-8; export LC_ALL=C.UTF-8; unset LANGUAGE，否则 locale::facet abort（rc=134）。
- 脚本 LF 换行、走 ssh stdin（bash -s），不用 scp 取文件（会挂死）。

怎么定位到「对应位」（必须给出可执行规则）：
- 一律用三元组 (frame_off, parity, bit)，只用 (frame_off, bit) 会漏 parity 造出假共享（IMUX_L0 与 IMUX_L4 就是 parity 不同）。
- 地址律：frame = far_bands[(band, col)].start_frame + frame_off；word = 2*(Y%50)+parity（≥50 再 +1 让开 ECC 字）；bit = raw % 32。
- 必须排除 word == 50（ECC 字随数据重算，混入会凭空多出「数据格」）。
- 位全 0 要分三类：默认源 / 互斥族外 / 未覆盖位，不得混写。
- 未解释差异禁止用「不影响结论」结案：要么给归因实验，要么在结论里显式写「本结论不覆盖这 N 帧 / M 位」。

怎么证明测对了（验证阶梯，必须按强度排序）：
1) 反读自证（集合级）：用未参与训练的随机值反读，预测量与实测量按集合比对，必须 missing=0 且 extra=0，只许集合级比较、不许只看命中数、不许抽样。
2) 负对照：同设计同参数重跑，差分 0。
3) 交叉自证：同一结论必须由另一个脚本、另一批独立构建复核一次；只做同源自证的结论标 unverified。
4) 外部真值：Vivado get_pips 对账（当前 ref.bit：真值 1,263 条 INT PIP 解出 1,155 条 = 91.45%）。
5) 全器件外推：12,565 个 tile / 64,686 个置位里表外位 0。
6) 误报与对抗：干净位流误报、单 bit 穷举、幽灵 PIP、整条 PIP 删除/添加、换源、LUT INIT 真篡改。
7) 跨类型/跨器件：INT_R 命名归一后 172/172；其它 tile 类型 2/115；跨器件 0/1 未测。

已知翻车（必须写进失效条件一节，作为「为什么会测错」的实证）：
- 未锁引脚 + 未回读 → 同一位置三次测量出三张表。
- 表自洽但解码真实设计全错 → LOCK_PINS 缺失，索引是当次布局顺序。
- 把 XOR 差分当 PURE 读 → 误判「形状随 CLB 类型变」。
- 统计漏 parity → 误判「每格被两个 family 共用」。
- 帧级一致但字节差 11 处 → 头部时间戳 + 尾部 CRC。
- 检验器自身有 bug（脚本漏 +1 位移）→ 22 个「表外位」连续两轮误导方向。
- 位平面法被优化器整体反相 → 位平面法作废，改用受控差分。
