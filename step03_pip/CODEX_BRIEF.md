# 请审查：Virtex-7 比特流逆向的现状与下一步计划

你是对抗式审查者。下面是我们已经"立住"的结论、尚未解决的问题、以及可用证据的落点。

## 总目标

XC7VX485T-2FFG1761（VC707）比特流逆向。最终目标：不依赖 Vivado，从 .bit 直接
读/写任意配置位（PIP、LUT INIT、FF 属性等），并能预测"某个逻辑改动会改哪几个 bit"。

器件事实：50,176 帧 × 101 word，每帧 404 字节；word 50 低 13 位 = 帧级 ECC。
帧号 ↔ FAR：31688 → 0x420308（row6, col6, off8）。

## 已立住（含证据与样本量）

1. **帧 ↔ FAR 映射**：由 bitstream 包头逐帧解析，50,148 块确认 + 28 块未解析（开销帧）。
2. **PIP → bit（IMUX 输入多路器）**：
   - 每个 IMUX 的源选择位落在固定窗口：左列 INT_L 为帧 31696–31705（10 帧），每 mux 两个 bit 列（b0 与 b0−1）；
   - 6×4 格编码：row = 帧偏移 0..5（对应 slice 的 6 个输入），col = 帧 6..9 的四位签名；
   - 字段地址：`word = 22 + ((L//4)%2)`，`bit = 1 + 8*(L%4) + (L//8)`（L = IMUX 编号），36/36 拟合；
   - 用 prjxray 7 系列 INT segbits（`prjxray_ref/artix7/segbits_int_l.db` / `segbits_int_r.db`，格式
     `INT_L.<mux>.<src> <word>_<bit> ...`）交叉验证 **864/864 全一致**；
   - 写入验证：用我们自己的编码器改 900 个 Vivado 变体中的 864 个，与 Vivado 的 bit 流逐字节比较，
     **864/864 载荷完全相同**；端到端 18/18 也完全相同。
3. **跨实例 / 跨类型**：INT_L_X6Y11 与 INT_L_X6Y21 归一化后 150/150 相同；INT_L 与 INT_R 归一化后
   792/792 相同（INT_R 帧窗口整体 +108 帧），因此形状表是 tile 类型级常量，只有块地址随行列变。
4. **LUT6 INIT 位映射**（X10Y10 的 A6LUT，基址帧 31748，字 20）：
   `df = 2*(1-((k>>3)&1)) + (k&1)`，`bit = 15 - 4*(k>>4) - ((k>>1)&3)`；
   64 个单比特变体实测 **64/64** 只改这 1 位 + 同帧 word50 的 5~9 个 ECC 位。
5. **帧级 ECC**：每帧 word50 低 13 位，是帧内 100 word 的线性函数；用变体样本拟合出 54 个位置
   （秩 54/54、残差 0），右半 72/72 验证通过。写位时按此补 ECC。

## 未解决（按重要性）

1. **尾部 32 位值（CRC 寄存器）**：载荷后有 `0x30000001` + crc1=0x5F3586D1，尾部还有第二个
   `0x30000001` + crc2=0xE3AD7EA5（后面是 0x20000000 填充）。已穷举否定：
   常见 CRC-32 变体（MPEG-2/ISO-HDLC/C/C2/BZIP2/POSIX/XFER 等）各 6 组参数、字节序/位序/字序/
   帧序翻转、去 ECC 字、清 ECC 位、整文件/从 sync/FDRI 起、全起始偏移扫描、md5/sha1/sha256 前 4 字节。
   更关键：同一位数据在相邻两帧的增量应满足 d1 = M·d0（位置相关线性变换的必要条件），实测
   **0/32 成立** → 它不是对载荷的普通位置相关线性校验。远端无 JTAG（lsusb 为空），无法实测设备是否校验。
2. **块地址函数**：帧窗口随列/行带的偏移规律只有零星样本（INT_R = INT_L + 108；同列不同 region
   有 31688→26442 的跳变）。还没有"给定 (col, row) 预测帧窗口"的闭式函数，也没覆盖 LC/BRAM/DSP tile。
3. **跨类型泛化只有一组**（INT_L vs INT_R），且用的是归一化坐标——绝对地址仍靠经验偏移。
4. **BEL 级只做了 A6LUT INIT**；CE/SR/CLK 选择、FF 的 INIT/SRVAL、CARRY、分布式 RAM 等未做。
5. 远端机器的 `/opt/lzh/step03` 有另一个进程在写（colscan/、blkcol3/ 等新目录），实验环境不完全独占。
