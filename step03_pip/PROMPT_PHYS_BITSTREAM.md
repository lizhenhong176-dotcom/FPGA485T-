# 提示词：FPGA 物理架构分配 + PIP 复用难点 + 物理结构 + 比特流结构

## 1. 角色与任务

你是同时做过 **FPGA 物理实现（floorplan / 布局布线 / 位流生成）** 和 **位流逆向** 的工程师。请围绕 Xilinx Virtex-7（`xc7vx485tffg1761-2`），讲清四件事，并让四者**互相咬合**（不允许各讲一段、彼此不提）：

1. **物理架构分配**：芯片上的资源是怎么划分与排布的（分区、列序列、每类资源的数量与位置规律、时钟/IO/硬核的分布）；
2. **PIP 复用的难点到底在哪**：不是"有共享"这个事实，而是"从位反推 feature"为什么成为难题；
3. **涉及的物理结构**：从配置 SRAM 单元 → pass transistor → mux 树 → switch box → 布线通道 → CRAM 行列组织；
4. **比特流结构**：帧/字/位的组织、地址编码、命令包、CRC/ECC、读回与部分重配置，以及各资源分别落在哪些帧偏移上。

**硬性要求**：第 2 部分必须回答"**难在可判定性，还是难在计算量**"，并给出判定依据，不能只罗列"位被共享了所以有歧义"。

## 2. 背景事实（项目实测，可直接采信，不得篡改）

- 器件 `xc7vx485tffg1761-2`：**150,380 tile**、**86,022 fabric site**、**1,760 package pin**、**14 clock region**。
- 逻辑：`SLICEL 43,200 + SLICEM 32,700 = 75,900` slice；每 slice 4×LUT6 + 8×FF + 2×MUXF7 + 1×MUXF8 + 1×CARRY4。
- 位流：**50,176 block frame × 101 字 × 32 bit**；每 config row 末 2 帧为 OVERHEAD，不属任何用户块。
- 定位：`cell = (block_base + frame_off, word, bit)`，`word = 2*(Y%50) + parity`（`Y%50 ≥ 25` 时 +1），`bit = raw % 32`。
- 帧块大小不等：**CLB 块 36 帧**、**INT 列块 26 帧**、**BRAM/INT_INTERFACE 接口块 28 帧**；缺列处有 28 帧的"夹缝块"。
- 单个 INT tile 位池 **1,664 位**（26 帧 × 2 字 × 32），其中 **1,598 位**被 **3,636 条 PIP feature** 覆盖，**66 位未覆盖**。
- 位池按家族划分：**1,598/1,598 cell 只属一个家族**，0 例跨族共享；族内 **3..18 源/cell（均值 5.57，最大 18）**；每 PIP 占 **1–4 cell**。
- 形状只有 5 类：`(9,20)×96`、`(10,24)×64`、`(8,16)×6`、`(7,12)×4`、`(9,18)×2`（单侧）。
- 已确认**两级 one-hot**：`(9,20)` = 4 组 × 5 成员，位宽 `4+5=9`（而非 `ceil(log2 20)=5`）。
- 全芯片解码 **181 PIP / 181 家族 / 0 ambiguous**；写位回环 **864/864** 一致。
- 已知未解：`CARRY4 CY0` 族、`CE/SR/CLKINV` mux、`(8,16)/(10,24)` 的 4 位编码、BRAM/DSP/IO 的跨族独占性、长线 `LV/LVB` 选择位。

## 3. 命名地基（先讲再展开）

- PIP feature 名：`<tile_type>.<目标 wire>.<源 wire> <frame_off>_<bit>`，`!` 前缀表示该位须为 **0**。
- 本项目记法：`TILE/TILE_TYPE.SRC->>FAM`（源→目标），与上者等价；**家族 = 同一 `tile_type` 下目标 wire 相同的那组互斥 PIP**。
- wire 名：`<方向><长度>BEG<n>/END<n>`，方向 `N/S/E/W` 与 `NE/NW/SE/SW`，长度 `1/2/4/6`；`LV/LVB` 长竖线、`GFAN` 全局扇出、`ER/R` 短线、`LOGIC_OUTS` CLB 输出、`IMUX/BYP/CTRL/CLK` CLB 输入侧 mux 输出。
- tile_type：`INT_L/INT_R`、`CLBLL_L/CLBLM_R`、`BRAM_L/BRAM_R`、`BRAM_INT_INTERFACE_*`、`DSP_L/DSP_R`、`IOB/IOI/IO_INT_INTERFACE_*`、`HCLK_*`、`CLK_HROW_*`、`CMT_TOP_*`、`GTX_*`、`PCIE_*`、`MONITOR_*`、`CFG_CENTER_*`。
- **禁止**把 `BEG→END` 的 tileconn 落点称作 mux（那是固定连接，无配置位）。

## 4. 任务一：物理架构分配

必须给出以下五项，且每项说明"**这个结论怎么从数据/手册算出来**"：

1. **die 分区图**：clock region 网格（14 个）如何切分 die；每 region 的行数/列跨度；region 边界处有什么特殊 tile（`VBRK`、`VFRAME`、`BRKH_*`）。
2. **列序列**：从左到右/从上到下，CLB / INT / BRAM / DSP / IO / 时钟 列的类型排列规律；为什么 `CLBLL` 与 `CLBLM` 交替出现；`SLICEM` 只出现在哪些列、规律是什么（须给出可判定的规则）。
3. **每类资源的数量与分布**：`INT_L/INT_R` 各 26,550、CLB 合计 37,950、`BRAM_L 480 + BRAM_R 550`、`DSP_L 770 + DSP_R 630`、`LIOB18/RIOB18` 各 168、`IOB18S/IOB18M` 各 336 等——说明这些数字如何互相校验（例如 DSP tile × 2 = DSP48E1 site 数）。
4. **时钟网络分配**：`BUFGCTRL` 32、`BUFHCE` 168、`BUFR/BUFIO` 各 56、`BUFMRCE` 28、`MMCM/PLL` 各 14 分别落在哪些 tile、服务哪个 region 范围；`HROW` 如何贯通左右半区。
5. **IO 与硬核分布**：IO bank 如何排列、为什么 die 中央也有 IO（须解释 `LIOI` 出现在 die 中部这一现象）、`GTX_CHANNEL` 56 / `GTX_COMMON` 14 / PCIe 8 个 tile / XADC 3 个 tile 的物理位置。

**验收标准**：读者能凭你的描述，在 tile 表里逐个定位到具体 `tile_type` 与大致坐标；凡无法定位的，写「未测」并给出定位方法。

## 5. 任务二：PIP 复用的难点（核心部分）

必须给出 **≥8 条难点矩阵**，每条固定四列：`难点 / 物理原因 / 数据表现（带数字）/ 后果与验证办法`。

必须覆盖（可增不可减）：

| # | 难点 | 必须回答的问题 |
|---|---|---|
| 1 | 位级共享 | 为什么 N 个源共用 k 位？共享的电路原因是什么（分级 one-hot 而非二进制译码）？
| 2 | 反解多对一 | 为什么"位集 → feature"是多对一映射？在什么条件下才唯一？|
| 3 | 歧义（aliasing） | 何时出现 `|F(o)| > 1`？本项目为什么 0 ambiguous，这个 0 是运气还是必然？|
| 4 | 覆盖不全 | 66 位未覆盖意味着什么？"1,598/1,598 独占"这个分母有什么局限？|
| 5 | 多 PIP 同时激活 | 同一 tile 内多条 PIP 同时置位时，为什么单条查表会失效？需要什么形式的联合求解？|
| 6 | sense 反转 | 位可为 0 表示"选中"时，为什么"置 1 才有效"的直觉会失效？如何从数据区分？|
| 7 | 跨实例/跨 tile_type 迁移 | 位模式能否跨 tile/band/列/slice 实例复用？边界在哪（什么情况下会失效）？|
| 8 | 写入方向更难 | 读只需一致，写还要 ECC/CRC 正确；写错一位的后果是什么？|
| 9 | 基线盲区 | 差分法的固有盲点（ref 已置 1 的位看不见）如何暴露、如何补？|

**必须明确回答**：这门难在**可判定性**（存在多解，需要额外约束才能定解）还是**计算量**（解唯一但搜索空间大）？请分别给出：
- 单 PIP 情形；
- 同 tile 多 PIP 情形；
- 全芯片 181 PIP 情形。
并说明：如果把"家族内位池互斥"这一条当作公理，复杂度会怎么变（这是本项目能解出来的关键假设）。

## 6. 任务三：涉及的物理结构（自下而上）

必须逐层讲清并给出"它如何体现在位流里"：

1. **配置 SRAM 单元**（6T/双端）：一位 = 一个 pass transistor 的栅极电压；
2. **pass transistor 与 mux 树**：N 个源 → N 个开关 → 一个目标 wire；栅极如何被编码（分级 one-hot）；
3. **switch box（INT tile）**：为什么一个 tile 里有 172 个家族、3,636 条 PIP；
4. **布线通道与线段**：`NN/SS/EE/WW` 单方向、`NE/NW/SE/SW` 对角、长度 1/2/4/6 的物理含义（跨几个 tile、几列几行）；
5. **CRAM 的行列组织**：为什么一帧 = 一列的 101 字；为什么帧号沿列递增、每行 50 帧（+2 OVERHEAD）；
6. **由此推出的两条硬约束**：为什么 `word = 2*(Y%50) + parity` 会有"半带 +1"；为什么 CLB 块是 36 帧而 INT 列块是 26 帧。

## 7. 任务四：比特流结构

必须覆盖：

1. **帧/字/位**：`101 字 × 32 bit` 的构成（前 50 字数据 + 第 50 字 ECC 的划分需说明是否成立，若不成立写"未测"）；位序与字节序（哪一端是 bit 0）。
2. **地址**：FAR 的字段构成（block type / row / column / minor），`50,176` 这个数如何由 region × 行 × 列推出。
3. **命令层**：sync word、Type-1/Type-2 包、常用命令（`WCFG`/`FDRI`/`GRESTORE`/`DESYNC`），以及"写一帧"的完整序列。
4. **CRC 与 ECC**：CRC 覆盖范围、ECC 字如何计算、为什么"改位必须同步改 ECC/CRC"。
5. **读回与部分重配置**：读回顺序、`MFWR` 的作用、部分重配置的地址约束。
6. **资源 ↔ 帧偏移**：CLB 的 LUT/FF/IMUX 分别在 off 32–35 / 30–31 / 16–25；INT 的 PIP 在 off 0–15；说明这些偏移是**如何被测量出来**的（差分 fuzz 流程）。

## 8. 四个咬合问题（必须回答）

1. **物理 → 位流**：CRAM 的物理行列组织，如何直接导致"半带 +1"的字规则？（要求用列扫描顺序解释，不许只说"实测如此"）
2. **编码 → 位池密度**：分级 one-hot 编码，如何导致 INT tile 位池 96% 被占、且"cell 只属一个家族"？
3. **复用 → 难度**：如果把这条独占公理去掉（假设跨族共享可能存在），你还能解出 181 PIP 吗？需要什么额外证据才能定解？
4. **写入 → 验证**：为什么"写位回环 864/864"比"读完能对上"更强？它排除了哪一类错误？
