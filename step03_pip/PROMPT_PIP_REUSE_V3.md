# 提示词：PIP 复用规律 — 从位级事实到可判定命题

**目的**：把「PIP 复用规律」从一句模糊描述，变成一组**可复算、可证伪、能指导解码/生成**的陈述。
**适用**：XC7VX485T 比特流逆向项目（本提示词自带全部已测数字，模型不需要外部资料）。
**产出要求**：凡是本项目已测的，只能引用、不许重推；凡是未测的，必须写「未测」并给验证方案。

---

## 1. 已测事实基线（直接引用，不要质疑也不要重算）

### 1.1 器件与布局
- 器件 `xc7vx485tffg1157-3`；150,380 tile；86,022 fabric site；75,900 slice。
- `INT_L/INT_R` 各 **26,550** tile（合计 53,100）；CLB tile 37,950；BRAM 1,030；DSP 1,400；pad 700。
- 帧空间：**50,176 帧 × 101 字**（每帧 100 数据字 + 1 校验字）；`frame_blocks` **1,038 块 / 36,260 帧 = 7 × 5,180**（每 band 精确闭合）。

### 1.2 地址律（已两处独立验证）
```
frame = 块基址 + frame_off
word  = wof(Y) + parity,   wof(y) = 2*(y%50) + (1 if y%50 >= 25 else 0)
bit   = raw % 32
```
Y 取 **tile 名的 Y**（不是 tilegrid 的 grid_y）；块基址**不可由列号推导**（同一列不同行会落不同块）。

### 1.3 INT 位池
- 每侧位空间 26 帧 × 2 字 × 32 位 = **1,664**；已覆盖 **1,598（96.03%）**；洞 **66** 个。
- 洞的结构：off0/off2 取 `bit≡0 (mod 4)`（各 16）、off1/off3 取 `bit≡3 (mod 4)`（各 16 再各加尾部若干位）= 两条正交 stride-4 位线 × 2 parity。
- 家族：**172 个/侧**，全设备 **344 家族 / 24,336 cell**；每 tile 3,737 条 pip / 216 个 `get_pips` 家族（两者口径不同，见 §4）。

### 1.4 家族形状（K=位池宽度，N=源数）
| K | N | a×b | 家族数/侧 | 每源位数 |
|---|---|---|---|---|
| 9 | 20 | 4×5 | 96 | 2 |
| 10 | 24 | 4×6 | 64 | 2 或 4 |
| 8 | 16 | 4×4 | 6 | 2 或 4 |
| 7 | 12 | 3×4 | 4 | 2 |
| 9 | 18 | 3×6 | 2 | 2 |

### 1.5 已闭环的证据（四条独立，任一条都能单独否掉“巧合”）
1. **6/6 输入网** token 级与 Vivado `ROUTE` 完全一致（含 IO 入口段，其间 IO 入口被证明**无配置位**，是 tileconn 固定连线）。
2. **写回 864/864**：按表写位 → 载荷与理论一致、硬件不报错。
3. **181 个 PIP 解码 0 歧义**；反向检验 366 TP / **0 FP** / 0 AMBIG / 6 FN（6 条全为 always ppip，无配置位）。
4. **绝对态判读**：纯 LUT 设计 `e0/e7` 解出 `SLICE_X10Y20/ALUT INIT = 0x9E3779B97F4A7C15`，64/64 位与设计真值一致。

### 1.6 其它已定性的位区
- **DSP**：78 个三态族（`GND` / `VCC` / 走线），**78/78 实测**；三态 = 2 胞编码 + 隐含全零态。
- **BRAM**：60 个三路 mux（`CASCINBOT` / `CASCINTOP` / `IMUX`），三态码字 `C = A & !B`，**60/60 直接观测**；`INIT_xx → 帧 = 46716 + xx`（36 位宽时步长 1）。
- **IO pad**：属性 37 行（PULLTYPE/DRIVE/SLEW/IOSTANDARD）；逻辑字段在 `io72` off0..33 @ pad 行字；**OLOGIC 不是家族**（20 胞核心 + CE/SR 特征位，INIT 只差 1 格）。
- **时钟**：`edge30` off26..29 共 29 格，与“是否有时钟进 fabric”相关。
- **ppip**：2,958 行（always 2,598 / default 128 / hint 232），always = 不占任何配置位的固定连接。

## 2. 术语与命名地基（先用后解释视为不合格）

| 术语 | 定义 | 不要混同于 |
|---|---|---|
| **feature** | prjxray 名 `<TILE_TYPE>.<dest_wire>.<src_wire>` + 位列表 `off_bit`（`!`=须为 0） | 一条“线” |
| **tile** | 配置块的最小物理单元（INT/CLB/BRAM/DSP/IO…） | site |
| **site** | site 内的逻辑资源（SLICE/RAMB18/DSP48E1/IOB…） | BEL |
| **BEL** | site 内的子单元（A6LUT/AFF/…） | 一条 family |
| **PIP** | 布线图的一条有向边（`get_pips` 可列） | **配置位**（位流里的 cell） |
| **family（家族）** | 同一 `tile_type` 下、目标 wire 相同的整组互斥 PIP，其源由同一小组配置位编码区分 | mux 门（电路）／tile_type（目录） |
| **位池 K** | 一个家族占用的 cell 数 | 家族成员数 N |
| **复用** | 见 §3 的四种含义，必须指明是哪一种 | — |

**纪律**：「家族」不是 Xilinx 官方术语（UG470/UG472 里没有）；`BEG→END` 的 tileconn 落点**不是** mux；不要用 “PIP reuse”（EDA 语境指布线资源复用）。

---

## 3. 「复用」必须拆成四层（这是本提示词的核心考点）

严禁把四件事混成一句“位被复用”。逐层给：定义、机制、已测证据、反例边界。

| 层 | 复用对象 | 机制 | 已测证据 | 边界 |
|---|---|---|---|---|
| **L1 位级共享** | 一个 cell 被多个源的编码共同读取 | 家族位池：N 源 share K cell，每源 2/4 位 | 344 家族零例外；189 个 share-bit | 只在 INT/IMUX/AFFMUX/DSP/BRAM 内验证 |
| **L2 位模式跨实例复用** | 同一组相对偏移在别的 tile/列/band/slice 实例上重现 | 地址律 + 相对偏移 | 181 PIP 0 歧义；86 tile 验证 | 块基址必须实测，不可推 |
| **L3 语义复用** | 同一 cell 在不同功能语境下含义不同 | 四类编码（§4） | IO 属性/逻辑/时钟三区已定性 | 时钟树/GTX 未测 |
| **L4 非位复用** | 布线资源被多网分时使用（EDA 称 “PIP reuse”） | 路由器行为，与位流无关 | — | **不是本命题**，出现即须显式排除 |

## 4. 全片只有四类编码形态（必须用这张表反解，不能一把梭）

| 形态 | 对象 | 判据 | 反解方法 | 实测例 |
|---|---|---|---|---|
| **家族（one-hot 网格）** | INT PIP、IMUX、AFFMUX、DSP GND/VCC、BRAM CASCIN | `N=a×b`、`K=a+b`、每源 2/4 位、族内互斥 | C1 掩码过滤 + C2 覆盖 + CSP | `(9,20)` 家族 `4×5` |
| **单位开关** | OLOGIC INIT、FF 的 `ZINI/ZRST`、`BYP/FAN` 旁路、`GCLK` 直通 | 1 位 = 1 特征，**可共现** | 直接读位 | INIT 只差 `(33,1)` |
| **码字** | `PULLTYPE/DRIVE/SLEW/IOSTANDARD`、`ZALMOST_*`、`LUT INIT` | 每值一组固定位，无网格律 | 码表比对 | `ZALMOST_EMPTY = 8191 − EMPTY` |
| **拓扑固定（无位）** | tileconn 落地、IO 数据通路、all-always ppip | 无配置位 | 静态拓扑推断 | IO 入口 0 位 |

> 混用后果：把 LUT INIT 的 64 个源当“互斥家族”要求唯一 → 整个 CLB 层解不出（项目真实踩过）。

## 5. PIP 编码的六条律（本项目的最终结论，可复算）

**律 1（地址）**：`frame = 块基址 + frame_off`；`word = wof(Y) + parity`；`bit = raw % 32`。
**律 2（位池私有 / family-private bit domain）**：同族共享、**跨族零交集**（1,598/1,598 单属）——这是反解能唯一的根本原因。
**律 3（算术）**：`N = a × b`、`K = a + b`（不是 `ceil(log2 N)`）；位宽 = 组位 + 成员位。
**律 4（每源位数）**：恰 2 位（5,640 源）或 4 位（1,632 源，全部出现在 `(10,24)/(8,16)` 形状）；位池内**无恒 0 cell**。
**律 5（极性）**：每源是**部分赋值**，可含“须为 0”位；默认源常为全 0。
**律 6（反解）**：候选 = `{源 : ones ⊆ 观测 且 zeros ∩ 观测 = ∅}`。单 PIP 唯一（181/181）；多 PIP 必须联合 CSP（每族至多 1 源、每观测位被解释）。

每条附：判据、反例边界、复算脚本。

## 6. 必须回答的可判定性问题

1. **单 PIP 反解**：复杂度？为什么实际唯一？（提示：位池私有 + 每源 2 位）
2. **同 tile 多 PIP**：为什么“难在可判定性”而不是算力？（提示：共享源位上会互相掩盖）
3. **全芯片（181 PIP）**：CSP 的规模、实测耗时、解的个数、以及“多个合法解”如何用外部证据剪枝？
4. **END 侧（Vivado `get_pips` 多出 111 家族 / 2,228 条）**：为什么它们**不占配置位**？“列出 ≠ 有位”的判定实验如何设计？（项目已做：改到达线 8 设计，0 表外格）
5. **66 个洞**：是“未用到的位”还是“另一套族的位”？给验证方案。
6. **跨器件**：哪些律是 7 系列通用、哪些是 485T 特有？（要求显式区分，不许混说）

## 7. 已知陷阱（每条都是项目真实踩坑，必须复述并说明为什么）

1. **命中数仲裁不可用**：同一帧块被四个 tile 名下解释都得 12 unique → 匹配成功只证布局一致，不证基址正确。
2. **每列一块递推不可用**：86/144 与实测冲突，且与真值走线链矛盾。
3. **空片歧义**：±28 帧偏移在空片上判读完全相同（89.9% 帧与 `f+28` 同值）。
4. **差分前必须确认 ROUTE 真的不同**：两次未钉引脚 → 配置 0 差异，白跑。
5. **综合会折叠**：六个输入接同一网 → LUT 退化成单变量函数（`INIT=0x0000FFFF0000FFFF`），看起来像解码错。
6. **去重口径**：`(base, word, cells)` 去重后 181 → 140（L/R 同名对是同一个物理 mux），不去重会虚高 29%。
7. **word 50 是帧级校验字**，不是“每帧 ECC”；50,176 帧里只有 157 帧非零。
8. **always ppip 无位**：`BYP_BOUNCE ← BYP_ALT` 这类不占位，别去找它的位。

## 8. 输出格式（八段，缺段视为未完成）

1. **一句话结论** + 复用四层图谱（一张表：层 / 对象 / 机制 / 证据 / 边界）。
2. **六条律**：每条「陈述 + 判据 + 至少一个反例边界 + 复算入口」。
3. **四类编码对照表** + 每类的反解伪代码（含失败模式）。
4. **可判定性分析**：单 PIP / 同 tile 多 PIP / 全芯片三档，区分“信息不足”与“组合爆炸”。
5. **反例与未测清单**：66 洞、END 侧、时钟树、GTX/PCIE、DSP 280 属性位、FIFO 29 属性位。
6. **生成侧**：给定 `(tile, family, src)` 如何算出该写的 cell 与 0/1 值（含“须为 0”位）；给出写后自检口径。
7. **自测 6 题**（含至少 2 题涉及“为什么这个数字不是巧合”）。
8. **误解 ≥8 条**：至少包含「一个源一位」「家族 = 一个 mux 门」「位数 = ceil(log2 N)」「跨族共用省面积」「全 0 = 无选择」「family 是官方术语」「(frame_off,bit) 就够」「跨 tile_type 同名同族」。

## 9. 纪律与验收

- 每个断言前标【硬件事实】/【数据事实】/【推断】；未测就写「未测」，不许编数字、编表号、编论文。
- 禁止“通常/一般/大部分”，必须给分子/分母。
- 引用本项目数字时给出文件名或表名（如 `all_cells.json`、`frame_blocks`、`v7_verified`）。
- **不得把已有结论改成新发现**：六条律、四类编码、6/6 走线、864/864 写回、78/78 DSP、60/60 BRAM 都是已测，**引用即可**；你的增值在于自洽性、边界、可判定性与生成侧。
- 若某段无法给出证据，明确写「无法判定 + 缺什么实验」，不要用篇幅掩盖空洞。
