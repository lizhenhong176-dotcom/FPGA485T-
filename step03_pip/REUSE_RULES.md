## 0. 一句话结论（v2）

> **一个 PIP 的选择位 = 一个家族（family）私有的位池里的一段 0/1 模式；家族内 N 个源共用 K 个 cell，
> 模式互不嵌套；`N = a×b`、`K = a+b`。**
> 复用只发生在**家族内部**，跨家族零共享；"选择"只发生在**段起点（BEG）侧**，终点（END）侧不占位。

## 1. 家族与形状律（核心）

### 1.1 定义

```
family := (tile_type, destination_wire)
```

由 prjxray 的 PIP 命名天然给出：`INT_L_X6Y11/INT_L.NE6BEG0->>SW6END0`，取 `NE6BEG0` 即家族名。

### 1.2 三条定律 【实测】

| # | 定律 | 数字 |
|---|---|---|
| L1 | **位池族内私有**：一个 cell 只属于一个家族 | **1,598 / 1,598**（单侧），0 例跨族 |
| L2 | **形状律**：源数 `N = a×b`，位池 `K = a+b` | **172 族 / 侧**，344 族全量零反例 |
| L3 | **每源位数只有两种**：2 位或 5 位 | 见 §1.4 |

### 1.3 五类形状（单侧；双侧 = ×2）

| (K, N) | 分解 a×b | 家族数 | 典型家族 |
|---|---|---|---|
| (9, 20) | 4×5 | 96 | `EE2BEG0`、`SW6BEG0` 等断线段族 |
| (10, 24) | 4×6 | 64 | `BYP_ALT0`、`FAN_ALT0`（5 位源）|
| (8, 16) | 4×4 | 6 | `GFAN0`、`IMUX_L7`（5 位源）|
| (7, 12) | 3×4 | 4 | `LV_L0`、`LH0`（长线）|
| (9, 18) | 3×6 | 2 | `LVB_L0`（长线旁路）|

> 说明：`(8,16)` 与 `(10,24)` 里每源 5 位；旧文档的"4 位源"是笔误，**已修正为 5 位**。

### 1.4 2 位 vs 5 位的分界 【实测，机制已解（S65）】

| 每源位数 | 家族数 | 源数 | 家族类型 | 显式字段 |
|---|---|---|---|---|
| **2** | 102 | 2,004 | 全部断线段族（EE/NE/NN/NW/SE/SS/SW/WW/EL/ER/NL/SR/WL/WR/NR/SL）+ LV/LVB/LH | **0**（两级都隐式）|
| **5** | 70 | **1,632**（= 64×24 + 6×16）| **IMUX(48) + BYP(8) + FAN(8) + CLK(2) + CTRL(2) + GFAN(2)** | **4**（第二级显式全写）|

**结构解释（S65，172 族零例外）**：每位池都是**两级 mux 树**，两级写法不同——

```
第一级（组选，N/4 组）        第二级（成员选，恒 4）
├─ 只写选中那条 = 1            ├─ 四条全写
└─ 未选中的线一次都不写（隐式）  └─ 选中 1，其余三条明确写 0（显式）
        ↓                              ↓
   1 个 cell                       4 个 cell（1 个 1 + 3 个 0）
```

⇒ 5 位 = **1（隐式组选）+ 4（显式成员选）**；2 位 = 1 + 1（两级都隐式）。
`N = (N/4)×4`；`coords = N/4 + 4`（5 位）或 `a + b`（2 位）。
**判别实验**：70 个显式族按组切分后，各组「4 位码集合」**完全相同（70/70）** ⇒ 两级独立，下层只取决于组内成员编号。

**未解**：为什么第二级必须显式写 0（H1 电平敏感：leaf pass-transistor 未驱动会浮空，需主动关断；H2 共享译码 —— 已被判别实验排除）。H1 仍为【推断】。

### 1.5 反解与生成 【实测】

| 方向 | 规则 | 验证 |
|---|---|---|
| 反解（位→PIP） | 候选 = `{ones ⊆ 观测}` 且 `{zeros ∩ 观测 = ∅}` | 单 PIP **181/181 唯一**，0 歧义 |
| 多 PIP 联解 | 互斥 CSP + 覆盖约束 | 9 条网 → 与 Vivado ROUTE 真值 **6/6 token 级一致** |
| 生成（PIP→位） | 按模式置 1，未提及的位清 0 | 写回 **864/864** 一致 |

## 2. 坐标律（地址部分，v1 保留 + 半带修正）

```
frame = block_base + frame_off
word  = wof(Y) + parity
wof(y) = 2*(y%50) + (1 if y%50 >= 25 else 0)      # ★ v2 新增：半带 +1
bit   = raw % 32
value = sense                                       # 1=置位；0=该位必须为 0
```

* `Y` 取 **tile 名里的 Y**（不是 `tilegrid.grid_y`）。
* 帧块清单：`frame_blocks` 表 **1,038 块 / 36,260 帧 = 7 × 5,180** 精确闭合 【实测】
  （每 band：`111×36 + 35×28 + 2×30 + 2×72`，band1/2 另含 `1×246` PCIE 区）。
* **`block_base` 不可由列号公式推出** 【实测反例】：`grid_x`、`law_tiles.col`、`clb_blocks.grid_col` 三套列号互不相等，
  且同列不同行会跨块。只能用 `frame_blocks` 查表。
* `word 50` 的性质按块类型而定：
  * fabric 块（CLB/INT/BRAM/DSP）→ **帧级校验/ECC**，不参与配置；
  * `io72 / edge30 / CMT / GTX` 块 → **是真实配置字**（S58/S60 实测）。
  * 旧文档"`word 50` 是 ECC"只对 fabric 块成立，且**只有 157 帧真的带 ECC**。

### 2.1 块的类型与尺寸 【实测】

| kind | 帧数 | 数量 | 说明 |
|---|---|---|---|
| `clb` | 36 | 763 | CLB 及其两侧 INT 共用 |
| `gap28` | 28 | 245 | BRAM/DSP/接口列 |
| `io72` | 72 | 14 | IO 列（含 pad 属性、CMT） |
| `edge30` | 30 | 12 | 时钟脊 |
| `pcie` | 246 | 2 | PCIE 区 |
| `x36` | 36 | 2 | 边缘 |

### 2.2 各子系统偏移 【实测】

| 子系统 | 位置 |
|---|---|
| INT 家族位池 | **off 0..25**（IMUX 16..25） |
| CLB LUT INIT | **off 32..35**（64 位）|
| CLB FF 配置 | **off 30..31** |
| BRAM 三路 mux（60 个） | **off 26**（控制帧 = 块基址+26） |
| BRAM/FIFO 属性 | off 26/27 |
| DSP 两路 mux（78 个） | off 26/27 |
| IO pad 属性（`law_iob` 37 行） | io72 **off 38/39** @ 该 pad 行字 |
| 时钟网络（`clk_cells` 94 行） | edge30 + 各列 off 0..25 |
| GTX | **32 帧块 = `band_base − 272`，word 平面全宽 0..100** |

## 3. 差分的三种语义（v1 保留，仍是最大的坑）

| 语义 | 什么时候用 | 判据 |
|---|---|---|
| **PURE** | A/B 两版只差一个属性 | `diff = B − A` 即该属性的位集 |
| **XOR** | 两次差分要相减（如 A∩B 去噪） | 取对称差 |
| **FAM** | 一个家族整体翻转 | 用家族位池求交/并 |

**v2 新增纪律（S61 确立）**：
> 凡"配置位归属"问题，必须用「**同一 LOC、只改一个参数**」的成对实验，并在**第二个 LOC 复跑取交集**。
> 单次差分只给**上界**：交集 = 配置位本体，差集 = 位置相关的布线漂移。
>
> 这条直接推翻了 S52 的 2 条命名（`(1,1,15)`、`(1,1,23)`）并在 S61 里纠正了 1 条误判（`31680`）。

## 4. 复用边界（v2 新增）

| 命题 | 结论 | 证据 |
|---|---|---|
| END 侧是否占位 | **不占**。Vivado 列的 111 个 END 目的家族 / 2,228 条 pip 在 bitstream 里 **0 位** | S35 实测（换 I/O pin 的 8 设计差分，19 个差异格全在 BEG 家族内）|
| always ppip 是否占位 | **不占**。2,598 条 `always` 连接（`BYP_BOUNCE←BYP_ALT`、`FAN_BOUNCE←FAN_ALT`、`GCLK_*_EAST←GCLK_*`、BRAM/DSP 单源族） | S16 反向验证：6 条 FN 全是它们 |
| 跨 tile_type 是否共享 cell | **不共享**（INT 内部已证；跨类型未交叉验证）| — |
| L/R 同名对 | **同一个物理 mux**，只是两侧命名不同；181 条解码 PIP 去重后 = **140** | S33 实测（41 组重复全是 `INT_L_Xn ↔ INT_R_Xn+1`）|

## 6. 四类编码（v2 新增，用于跨 tile_type 统一表述）

| 类 | 形态 | 判据 | 适用 |
|---|---|---|---|
| **A. 家族（one-hot 网格）** | N 源 × K cell，`N=a×b`、`K=a+b`，每源 2/5 位 | 有"组位 + 成员位"结构 | INT / IMUX / BRAM 三路 / DSP 三态 |
| **B. 单位开关** | 1 位 = 1 个开关，可共现 | 无 N 选 1 结构 | OLOGIC INIT、ZINI/ZRST、BYP/FAN 旁路、GCLK 直通、FF 标记 |
| **C. 码字** | 每值一组位，无网格律 | 值↔位模式查表 | PULLTYPE/DRIVE/SLEW、`ZALMOST_*`、LUT INIT、MMCM/PLL 分频 |
| **D. 时钟网络** | 跨 tile 的一簇使能 | 与使用方无关 | `clk_cells` 86 格、edge30 off26..29 |

> 解码器必须**四张表分开**：家族→CSP、单位开关→位读取、码字→码表比对、时钟→网络表。
> 混用会产生成片 UNEXPLAINED（S44 的 `emit.py` CLB 返回空就是 LUT INIT 家族不互斥导致的）。

### 6.0 家族类的两级结构图（S65，跨 tile_type 通用）

```
                    ┌──────────── 第一级：组选（N/4 组，隐式）────────────┐
源 s  ──►  组 g  ──►  该组线写 1；其余组线不写（浮空由上游驱动）           │
                    └──────────────────────┬───────────────────────────────┘
                                           ▼
                    ┌──────────── 第二级：成员选（4 选 1，显式）───────────┐
                    └─ 4 条 leaf 线全写：选中 1，其余 3 条写 0 ─────────────┘
```

| tile_type | 家族示例 | 第一级组数 | 第二级 | coords | 每源 |
|---|---|---|---|---|---|
| INT | `IMUX_L7` | 6 | 4 选 1（显式）| 10 | 5 |
| INT | `GFAN0`/`CLK_L0`/`CTRL_L0` | 4 | 4 选 1（显式）| 8 | 5 |
| INT | `EE2BEG0`/`SW6BEG0` | 4 或 5 | 隐式 | 9 | 2 |
| CLB | `AFFMUX` | 4 | 隐式 | 6 | 2 |
| BRAM | `CASCIN*`（三路）| — | 三态码字 | 2 | 1–2 |
| DSP | `DSP_0_D0`（GND/VCC）| — | 二态 | 2 | 1 |

> 规律：**第二级是否显式写 0，决定每源位数（5 或 2）**——这是"每源几位"的唯一决定因素，
> 与 tile_type、族大小、家族名都无关。

### 6.1 当前各 tile_type 的归类与完成度

| tile_type | 主导编码 | 完成度 |
|---|---|---|
| INT_L / INT_R | A | ✅ 96.03% |
| CLB（slice 内） | A（INIT/AFFMUX）+ B（ZINI/ZRST/CE/SR）+ C | 部分（缺 CARRY4/MUXF 全表）|
| BRAM | A（三路）+ B（FIFO 属性）+ C（INIT） | 大部分 |
| DSP | A（两路 tie-off）+ B（属性位）| 大部分 |
| IOB / IOLOGIC | B + C | 部分 |
| 时钟 | D + C（CMT 属性）| ✅ |
| GTX | 未归类 | 框架完成 |
