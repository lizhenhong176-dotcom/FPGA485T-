主题：我什么时候可以宣称"INT tile 的所有 PIP 都被解决了"。要给出可判定的闸门清单与宣称语句，而不是鼓励性评价。

读者：本人（作者）+ 导师。用途：决定现在能不能在论文/答辩/对外材料里写"已解决全部 INT PIP"，以及若不能，还差哪几步、各要多少钱。

必须使用的实测数字（不得改动）：
1. 一个 INT tile（INT_L，26,550 个实例）共 3,737 条 PIP = 3,693 条属于 172 个 mux 族 + 44 条扇入=1 直通（templates/INT_L.json）。
2. 位库 law_cells 覆盖 3,634 条 feature（每侧 172 族，sense=1 8,900 条记录、1,598 个不同位）；与模板对账：3,629 条能在模板里对上，另有 5 条只在 law_cells 里（差异来自 64 条 VCC_WIRE 常量输入）。
3. 因此 tile 内 PIP 的构成是：3,629 有条目 + 64 VCC 常量 + 44 直通 = 3,737。
4. 解码：ref.bit 上 982 个活跃 tile、解出 1,886 条 PIP；与 Vivado 真值 1,263 条对比，召回 1,155（91.45%），多报 731 条；另有精确覆盖求解器在 1,066/1,066 个含 mux 配置的 tile 上得到唯一解（multi=0）。
5. 生成：gen_slots.py 对 mux 64/64、BEG 96/96（含 32 个变体族）逐位重建 0 差异；公式档覆盖 3,456/3,634；加复合族组模型 96 条后 3,552/3,634 = 97.7%；剩 82 条（6 个长线族）只能查表（≤54 个格 + 82 条边）。
6. 外部验证：槽位不变量 231,656 个槽位 0 违例；全量活跃扫描 92 个位流 / 7,453 次扫描 / 1,965 个不同 tile / L2 零违例（95% 上界 0.040%）；E8 一个 BUFG 改写重生成位流与 Vivado 独立产物 50,176 帧全等（仅差时间戳 2 B 与尾部 CRC 4 B）；单 bit 篡改检出 1,624,720/1,633,808 = 99.44%。
7. 误报：ref.bit 240 个未解释位全部落在 3 个已知标记格，加白名单后 0 告警。
8. 边界：只做 INT_L/INT_R 两个类型（占器件 PIP 的 21.3% 按类型数、95.75% 按 PIP 实例数）；跨瓦片类型只有 3/115 做过结构级验证；ECC 依赖帧地址未闭合，不能生成任意可加载位流。
