# 提示词：彻底讲清「家族（family）」到底是什么 —— 位流逆向里的 mux 分组概念

> 用法：整段复制给任意模型。它自带全部背景与实测数据，**不需要本项目上下文**。
> 目标：让一个没见过本项目的人，也能准确说出「家族」是什么、边界在哪、
> 和 mux / PIP / 位池 / tile_type 分别是什么关系，并能从数据里自己把家族认出来。

---

## 1. 你的角色与任务

你是一位既懂 **FPGA 可编程互连的晶体管级结构**、又做过 **位流逆向 fuzz** 的工程师。
有人在一个 Virtex-7 位流逆向项目里大量使用「家族（family）」这个词，请你：

1. 用**三层递进**说清它是什么：晶体管层 → 结构层 → 数据层；
2. 说清它**不是**什么（与 mux / PIP / tile_type / site / wire 的区别）；
3. 给出**从数据里识别一个家族的可执行步骤**；
4. 解释**家族内部的编码结构**，特别是「为什么 20 个源要占 9 个配置位」这种非最小二进制编码；
5. 列出**常见误解**并逐条纠正；
6. 出 5 道自测题（附答案），检验读者是否真的懂了。

## 2. 背景事实（项目实测，可直接采信为数据）

- 器件：Xilinx Virtex-7 `xc7vx485tffg1761-2`；150,380 个 tile；75,900 个 SLICE。
- 位流：50,176 帧 × 101 字 × 32 位；配置单元定位 `(块基址 + frame_off, word, bit)`。
- 一个 **INT tile** 的配置位池 = **1,664 位**（26 帧 × 2 字 × 32 位）。
- 该位池里 **1,598 位**被 **3,636 条 PIP feature** 覆盖；**66 位**未被任何 feature 覆盖。
- 每条 PIP 的编码占 **1–4 个 cell**。
- 一个「家族」内的多个源**共用同一组 cell**，靠 0/1 组合区分：
  **3..18 个源共享一个 cell，平均 5.57 源/cell，最大 18**。
- **cell → 家族是独占的**：1,598/1,598 个 cell 只属于一个家族，**0 例跨家族共享**。
- 家族内 `(位池大小, 源数量)` 组合只有 **5 类形状**：
  `(9,20)×96`、`(10,24)×64`、`(8,16)×6`、`(7,12)×4`、`(9,18)×2`。
- 统计必须用 `(frame_off, parity, bit)` 三元组作 cell 标识。
- 全芯片一次解码：**181 条 PIP / 181 个家族 / 0 ambiguous**。
- 同一家族内的源编码**两两不同**（172/172 唯一）。

## 3. 命名规范（关键线索，务必解释它）

prjxray 的 segbits 数据库里，一条 PIP 的 feature 名字形如：

```
INT_L.NL1BEG1.NN6END2 07_32 12_33
```

格式是 **`<tile_type>.<destination_wire>.<source_wire>`**，
即「**先写目标 wire，再写源 wire**」，后面跟一串 `frame_offset_bit`（`!` 前缀表示该位须为 0）。

本项目用的另一种写法是 `TILE/TILE_TYPE.SRC->>FAM`（源 → 目标），两者是同一条 PIP 的两种记法。

**「家族」= 同一 `<tile_type>` 下、`<destination_wire>` 相同的那一组 PIP。**
换句话说：**一个目标 wire 背后的整棵 mux 树，就是一个家族。**

## 4. 你要讲清的三层含义

### 第 1 层：晶体管层
一个「目标 wire」由 N 条源 wire 通过 N 个 pass-transistor 驱动；
这些晶体管的栅极接在配置 SRAM 位上。**同一棵 mux 树的栅极是"编码"过的**——
不是每个源一个开关位，而是用 k 个 SRAM 位组成一个编码字，选中其中一个晶体管。

### 第 2 层：结构层
于是「家族」的物理含义是：**一组互斥的候选源 + 驱动它们的那个编码网络**。
它对应网表里的一次「选择」：信号从哪条 wire 来。家族之间互不干扰（各自的编码网络独立）。

### 第 3 层：数据层
在位数据库里，家族表现为：**同一 `(tile_type, destination_wire)` 前缀下的一批 feature 行，
它们共享同一小组 cell**。这就是可以用位池（bit domain）刻画的理由。

## 5. 必须解释清楚的相关概念（逐个给定义 + 与家族的关系）

| 概念 | 定义 | 与家族的关系 |
|---|---|---|
| PIP | 一个可编程开关：把源 wire 驱动到目标 wire | 家族是「目标相同」的 PIP 的集合 |
| mux / mux tree | 多输入选一的电路；多级时是一棵树 | 家族的电路实现 |
| 源 / 目标 wire | 进入 / 离开 mux 的两侧 wire | 源是家族成员，目标是家族名字 |
| 位池 / bit domain | 该家族全部源共用的一组 cell | 家族的数据层刻画 |
| sense（正/负） | 某 cell 该为 1（正）还是该为 0（负）才使该源成立 | 同一 cell 对不同源可有相反 sense |
| 独占 / family-private | 一个 cell 只服务一个家族 | 让家族之间不产生歧义 |
| 别名 / aliasing | 一组位值可匹配多条 feature | 只可能发生在家族内部 |
| tile / tile_type / site | 实例 / 模板 / 模板内的基本单元 | 家族定义在 tile_type 层，运行在 tile 实例层 |
| 编码宽度 vs 源数 | k 位能区分 2^k 个源，但实际 k 远大于 ⌈log₂N⌉ | 提示编码不是最小二进制 |
| 一热 fuzz | 只改一个变量做差分定位位 | 得到家族成员编码的方法 |

## 6. 数学刻画（请写成可判定的条件）

设某 tile 的配置位集合为 `B`，家族 `F` 的源集为 `{s₁..sₙ}`，
每个源对应部分赋值 `a_i : D → {0,1}`，`D ⊆ B` 即该家族的**位池**。

- **家族划分**：`B = ⋃ D`（覆盖）+ `D ∩ D' = ∅`（互斥）——项目实测这两条同时成立。
- **可区分性**：任意 `i ≠ j`，存在 `c ∈ D` 使 `a_i(c) ≠ a_j(c)`。
- **解码**：给定观测 `o : B → {0,1}`，源 `i` 成立 ⟺ `∀c ∈ D, o(c) = a_i(c)`；
  全 0 也可合法（默认源）。

### 图 C：五类形状的编码结构（按「列计数签名」反推）

| 形状（位池, 源数） | 每源位数 | 列计数签名（该位被几个源置 1） | 推得结构 | 家族数（单侧） |
|---|---|---|---|---|
| `(9, 20)` | 2 | `4×5 + 5×4` | 4 组 × 5 成员（两级） | 96 |
| `(9, 18)` | 2 | `6×3 + 3×6` | 3 组 × 6 成员（两级） | 2 |
| `(7, 12)` | 2 | `4×3 + 3×4` | 3 组 × 4 成员（两级） | 4 |
| `(8, 16)` | **2 或 4** | `6×4 + 2×12` | 多级（含直通/旁路源） | 6 |
| `(10, 24)` | **2 或 4** | `6×4 + 2×6 + 2×18` | 多级（含直通/旁路源） | 64 |

**要点**：位宽 = a + b，而源数 = a × b。所以位宽必然大于 `ceil(log2 N)`。
例如 20 个源要 9 位而不是 5 位，因为它是 `4 选 1 + 5 选 1` 的两级结构。

**未解项（必须如实标注）**：`(8,16)` 与 `(10,24)` 里存在**每源 4 位**的编码——
说明有些源**直通了中间级**（多级 mux 的旁路），结构尚未细化；而这两类合计 70 个家族
（单侧），是数量上最大的一类，**不能含糊过去**。

## 7. 重点解释：为什么 20 个源要占 9 个配置位？

`ceil(log2 20) = 5`，但实测是 9。**这个问题的答案在 §6.5 已给出（分级 one-hot），但只对「每源 2 位」的三类成立。**
你要做的是：

1. **复核**：假设 A（分级 mux 树，每级独立编码，位宽相加）是否被 §6.5 的列计数签名支持？
   用「若 A 成立，第 i 个成员列的 1 的个数应等于组数」这一判据去检查 `(9,20)` / `(9,18)` / `(7,12)`。
2. **否定**：假设 C（并行 mux 广播选择 = 一条 select 线驱动多个 mux）若成立，
   会导致**跨家族 cell 共享**；实测 0 例。请说明这条否定是否足以排除 C，还差什么证据。
3. **攻未解项**：`(8,16)` 与 `(10,24)` 存在**每源 4 位**的编码，
   请解释 4 位到底在编码什么（三级 mux？直通旁路？还是两段编码 + 一个额外的约束位？），
   并给出**从列计数签名反推三级结构的做法**（签名 `6×4 + 2×12` 里的 12 该怎么分解成 2 × 6？）。
   这一项占了 70 个家族（单侧），是数量上最大的一类。

## 8. 从数据里识别一个家族（可执行步骤）

1. 取该 `tile_type` 的全部 PIP feature，按 `<destination_wire>` 分组 → 每组即一个候选家族；
2. 对每组取位集并集 → 位池 `D`；统计 `(‖D‖, n)`；
3. 校验互斥：不同组的 `D` 交集是否为空（本项目为 0 例相交）；
4. 校验可区分：组内任意两源的位向量是否两两不同；
5. 用一份真实位流反查：把 `D` 上的观测拼成向量，与组内编码逐一比对，命中的应唯一。
