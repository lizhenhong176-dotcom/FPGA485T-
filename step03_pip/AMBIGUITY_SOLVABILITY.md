## 结论先行（三问的答案）

1. **可解吗**：分三层。①「某个 mux 是否被启用」——**条件可解**（`min-cells 2` 精确率 67.4%、召回 96.0%【数据事实：`v7re/steps/T6B_DISAMBIGUATION.md`】）；②「该 mux 选了哪个源」——**单 feature 独立判定不可解**，位池嵌套导致必然多报；联立全部 mux 后是否唯一 —— **2026-11-08 修订：已证明唯一**（精确覆盖枚举，见 §0 与 STATUS.md §94）；③「整条路径/整个布线唯一还原」——**未证明**，无反例也未证唯一。
2. **做到哪了**：读侧定律 100%（3,634/3,634 feature，两侧归一化后同为 100%【数据事实：`verify_all_pip.py`】）；写侧闭环只闭合到「单 tile 级、9/9 tile 0 差异」，全设计/可加载仍未闭合。
3. **最大阻碍**：**ECC 与帧地址的耦合未闭合**——它挡在「生成任意可加载位流」这一环，没有它，写入侧的每一条结论都只能停在「tile 内自洽」，无法上板验证。数据层缺口（`site_frames` 缺 16,979,200 行）排第二，因为它只影响 CLB 侧覆盖广度，不阻断 INT 侧闭环。

## 一、可解性判定

### 1.1 三层拆解

| 层 | 问什么 | 判定 | 支撑证据 | 性质 |
|---|---|---|---|---|
| (a) mux 启用 | 这个目的 wire 有没有被驱动 | 条件可解 | `min-cells 2`：精确率 67.4% / 召回 96.0%；`min-cells 4`：精确率 100% / 召回 19.7%【数据事实：`T6B_DISAMBIGUATION.md` 四策略实测】 | 采样与策略问题，不是根本不可解 |
| (b) 源选择 | 172 个输入里选了哪一个 | 单 feature 独立判定：**不可解** | 同族内严格子集对 **1,632** 对；2,818 个「2 格 feature」里有 **816 个**被同族另一 feature 严格包含（跨族包含 **0** 例）【数据事实：`step03_pip/_q_subset_pairs.py`，表 `law_cells` sense=1】 | 结构性：位集嵌套，一个观测同时满足两个候选 |
| (c) 整条路径 | 整个设计的布线是否唯一还原 | **未证明** | 无构造性反例，也无唯一性证明【推断】 | — |

### 1.2 「不可解」是下界还是采样不足

- 对 (b)：**不是信息论下界**。位集嵌套只说明「只看这一个 mux 自己的格子不够」；若把同一 tile 内 172 个 mux 的互斥约束（每个 mux 恰好选 0 或 1 个源）联立求解，观测里包含额外信息（那 3 个不属于 2 格 feature 的格子是 0 还是 1）。
- **联立后是否唯一 = 未证明**：没有构造出「两条不同布线 → 逐位相同观测」的对，也没有证明不存在。当前解码器是逐 feature 独立判定（`v7re/scripts/roundtrip.py` 的 `np.logical_and.reduce`），所以必然出现多解——T6B 记录 53 组多解【数据事实：`T6B_DISAMBIGUATION.md`】。
- 可以确证的一条：**位池共享**是真实存在的——1,598 个 cell 被 3,634 个 feature 共用，平均 5.57 个 feature 用一个 cell【数据事实：`law_cells` sense=1 统计】。这意味着「读一个 cell 就知道是哪个 mux 的哪个源」在物理上不成立，必须做全局一致性求解。

### 1.3 这是否等于「匹配复用可解」

- 「复用 172 个 family 编码」的做法本身**可解且已解**：172/172 族、3,634/3,634 feature 精确命中、0 不符（INT_L；INT_R 归一化后同样 100%）【数据事实：`verify_all_pip.py`】。
- 「复用」让**读侧判定**变难的部分是 cell 共享（平均 5.57），不是编码定律本身。两者要分开说，否则会把「定律已成」误读成「解码必稳」。

## 三、最大阻碍

### 3.1 为什么是 ECC

依赖关系（不解决它，下面这些全都做不了）：

1. **生成任意可加载位流**：写进去的每一帧都要重算 word 50，否则加载后器件拒收或行为异常。当前 `ECC(frame) = L(data) ⊕ A(frame_addr)` 只是形式，`A` 的表达式未定【数据事实：`STATUS.md` §32/§34】。
2. **TM2 的端到端验证**：现在测的是「攻击者能重算 ECC 时的可检出性」，只是假设；重算不了就不能上板，攻击链断在最后一环。
3. **全设计重综合对账**：`SLICE_X47Y51` 0 字差异已做到，全芯片差 53 字，其中一部分正是 ECC 项。

### 3.2 为什么不是数据层缺口

`site_frames` 缺 16,979,200 行（B/C/D 三个 BEL 全缺 + 一半 site 的 A 也缺，实测 `bel` 前缀只有 `A`）【数据事实：`v7_model.sqlite.site_frames` 统计】。它影响的是 **CLB 侧宽度**，不阻断 INT 侧闭环；而 INT 侧闭环已经能产出论文级结论（TM2 + 定律 100%）。

### 3.3 三条互斥推进路径

| 路径 | 做什么 | 预期产出 | 最低成本 | 失败会怎样 |
|---|---|---|---|---|
| **P1 联立求解（打歧义）** | 把 172 个 mux 的互斥约束写成整数规划/精确覆盖，用真实位流求解，比较解集是否唯一 | 若唯一 → (b) 层判定升为「可解」；若不唯一 → 得到**构造性反例对**，即论文的「歧义下界」实证 | 2–3 人日（纯本地，`law_cells` + `tamper/ref/ref.bit` 已有） | 若解不唯一且反例只是「同族嵌套」这种平凡情形，论文价值下降，但仍是诚实的下界陈述 |
| **P2 闭合 ECC 地址项（打可加载）** | 用现有 739 个非零帧对 `A(frame_addr)` 做 GF(2) 拟合 + 边界帧 marker 分离 | 可生成可加载位流 → 上板验证 TM2 注入 | 5–7 人日，需要远端 Vivado + 板卡 | 若 `A` 不是线性项（含非线性混合），模型要改，工期翻倍 |
| **P3 补数据层（打广度）** | 先 `VACUUM INTO` 备份 7.6 GB，再按 T23 的四 BEL 逐项实测后补 INIT 到 19,404,800 行 | CLB 侧覆盖 100%，全芯片重综合残差可追 | 4–6 人日，纯本地 | 若四 BEL 顺序不一致，需逐 BEL 单独实测，工期加 2 天 |

**哪条能产出「歧义下界」实证材料：P1**。判据是：必须给出**一对**具体配置（两条不同 feature 集合），它们在**逐位相同**的观测下都合法，并注明这两个集合来自哪张表哪几行；只给「多解组数量」不算下界证明，那只是采样统计。
