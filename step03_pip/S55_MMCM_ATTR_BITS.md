## 2. MULT 字段不是简单二进制

对 MULT 做 3/4/5/6/8 扫描（`r_m3` / `q_mult5` / `r_m6` / `r_m8d1`），相对基线 MULT=4 的变化位分布：

| MULT | 相对 MULT=4 置 0 的位 | 相对 MULT=4 置 1 的位 |
|---|---|---|
| 3 | (12,1) (12,10) (25,10) (25,18) | (12,0) (26,20) |
| 5 | (12,10) (25,10) (25,18) | (12,8) (25,9) (25,17) (26,20) |
| 6 | (12,1) (12,11) (25,9) (25,17) | (12,0) (12,8) (25,16) |
| 8 | (12,1) | (12,8) (25,16) (26,27) (26,30) |

⇒ MULT 由 **≥8 个 cell 跨 3 个 word** 编码，且不是单调二进制（值 3 与 5 共享 `(26,20)`，值 4 与 6 共享 `(12,0)`）。最可能的结构是
「整数部分 × 2 段 + 分数部分」的**分段码**，需要 0..64 全扫描才能定形（下一步）。

DIVCLK 单独变化（`r_m8d1` MULT=8/DIV=1 vs `r_m8d2` MULT=8/DIV=2，二者只差 DIVCLK）：
差值 = **`(26,9)` 置 0**（`r_m8d2` 相对 `r_m8d1` 多出 del `(26,9)`），其余位相同 ⇒ **DIVCLK 的位在 (26,9)**（1→2 时由 0 变 1）。

CLKOUT0_DIVIDE 扫描（8→6 / 8→7 / 8→10）：
- 8→6：+(29,28)(29,31)，−(29,27)(29,30)
- 8→7：+(29,20)(29,28)，−(29,27)
- 8→10：+(29,28)(29,31)
⇒ 同样是分段码而非二进制（(29,30) 只在值 6 出现）。

## 3. 可靠结论（可入库）

| 项 | 结论 | 置信 |
|---|---|---|
| STARTUP_WAIT | `(word 2, bit 30)`，FALSE=0 / TRUE=1 | A |
| CLKFBOUT_PHASE | `(word 26, bit 23)`，0=0 / 90=1（单位与编码待扫） | A（单点） |
| CLKOUT0_PHASE | `(word 29, bit 23)`，0→45 置 1 | A（单点） |
| FINE_PS 使能 | `(word 21, bit 31)` | A |
| BANDWIDTH LOW | `(12,0)=1, (12,9)=0, (12,11)=0` | A |
| CLKOUT1 启用 | `(29,4)(29,9)(29,12)(29,15)` | A |
| DIVCLK 1→2 | `(26,9)` 0→1 | B（一次配对） |
| REF_JITTER 0.010→0.020 | **不编码**（无任何位变化） | A |
| MULT / CLKOUT0_DIVIDE 编码 | 分段码，cell 集已知，映射未定 | C |
