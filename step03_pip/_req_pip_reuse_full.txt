我要一份「PIP 复用规律：数据来源 + 实验思路 + 四层规律 + 测试判据 + 进度 + 空白」的单文件说明（Markdown），用于讲解与交接。

背景：我是 XC7VX485T（VC707）比特流逆向项目的负责人，主线只有一条——搞清楚 PIP（可编程互连点）的复用发生在哪几层、复用的规律是什么。单个结论我都能讲，但缺一张「整体图像」：这些结论分别靠什么实验、按什么顺序得出，每一步的判据是什么，目前到哪一步，还剩哪些没测，以及每一层数据到底从哪来。

数据来源链（必须原样写进交付物，因为这是最容易被质疑的一环）：
1) 器件模型来自 Vivado 安装目录的 7 系列器件库（xc7vx485tffg1761-2）；由 RapidWright 2026.1（Java 17）解析，经 JPype 调用，见 v7re/routing/env.py:95-100 的 Device.getDevice。
2) 由 v7re/scripts/step1_topology.py export 落盘到 out_routing：templates/<TYPE>.json 115 个（v7re/routing/topology.py:27-54 用 tile.getWireName / tile.getPIPs / getStartWireName / getEndWireName / getDelayIndex / isBidirectional / isArcInverted）、tiles.csv.gz 150,380 行、type_uniformity.json（INT_L 26,550 实例 / uniform=True / 0 不匹配）、conns/、manifest.json（sha256）。
3) templates/INT_L.json：600 条 wire_defs、3,737 条 pip_defs，每条 [源 wire, 目的 wire, delayIndex, 是否双向]。
4) 按目的 wire 聚合 3,737 条 → 216 个目的、172 个扇入>1 = 172 个 family。
5) 位流差分（Vivado 构建 + 位级 XOR）测出「哪个 bit 选哪条源」，与 1)–4) 的「图」是两条独立来源；Vivado get_pips 是第三条独立真值支路。

交付物必须包含以下六部分：
一、数据来源表：来源名 / 取什么 / 脚本与行号或文件路径 / 是一手测量还是第三方模型 / 它错了会造成什么后果。
二、实验思路链：因果链而非并列清单，每一步写成「要回答的问题 → 实验手段 → 输入 → 输出结论 → 排除了哪些替代解释 → 证伪条件（出现什么使这一步作废）」。至少覆盖：单点差分 → 定位位池 → 列重统计 → 结构判定（二分/乘积）→ 两轴归属 → 生成器重建 → 反证（唯一性/篡改/误报）→ 迁移检验。
三、复用规律正文：按四层分层——位级 / 族级 / 跨族 / 跨 tile 与跨器件。每层给：规律陈述、可执行形式（公式或判定式）、真实族名实例（不得虚构）、数字（分子/分母）、失效条件（每条规律单独写）。
四、测试与判据表：固定列 = 测试名 / 判据（分子分母）/ 复算命令 / 产物与时间戳 / 状态（已验证 / 已跑过 / 从未跑过）。
五、进度：分子/分母，分母必须写来源；单独回答「现在有没有测试在跑」「最近一次跑完是什么时候」。
六、空白与下一步：还没测的几块，各自补上后能改变哪个结论。

硬性纪律：
- 全文三色标注【硬件事实】/【数据事实】/【推断】，不许混写；没有数据的写「未测」并标注分子/分母与来源。
- 禁止「首次」「唯一」「完整」「彻底」「全面」这类不可反驳的词。
- 不许把「脚本多、跑过一遍」当进度或验证。
- 每条规律、每个实验步骤都必须显式写出失效/证伪条件。
- 涉及第三方器件模型（RapidWright）时必须写明「这是单一来源，错了会整体继承」，并列出当前有哪几条独立支路在查它。
