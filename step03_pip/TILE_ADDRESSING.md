# 一个 tile 的地址是怎么定出来的

> 四级定位 · 四种独立方法 · 五个陷阱 · 交叉验证
> 适用器件：xc7vx485tffg1157-3（实际构建 part）；通用结构对 7 系列成立
> 配套图：`fig_tile_address.png`、`fig_tile_address_methods.png`、`fig_y_and_wof.png`

---

## 1. 四级定位

| 级 | 定义 | 输入 | 是否随位置变 |
|---|---|---|---|
| ① 块基址 | `block_base = frame_blocks[band, grid_col].base` | tile 名（X、Y）、`frame_blocks` 表 | **变**（每列 × 每 band 一个值）|
| ② 块内帧 | `frame = block_base + frame_off` | `frame_off`（家族属性，见 §1.4）| 不变（`frame_off` 全片复用）|
| ③ 字号 | `word = wof(Y) + parity`，`wof(y)=2*(y%50)+(y%50>=25?1:0)` | `Y`、`parity` | **变**（随 `Y%50`）|
| ④ 位号 | `bit = raw % 32` | 家族 cell 定义 | 不变 |

依赖链：`tile 名 → (X, Y) → band=Y//50, Yr=Y%50 → block_base（查表）→ frame；Y → wof → word；家族 → (frame_off, parity, bit)`。

**关键分界**：`frame_off / parity / bit` 是「相对坐标」，与 tile 无关，一次测完全片复用；`block_base / wof(Y)` 是「绝对坐标」，随位置变。这是 172 行表能覆盖 53,100 个 INT tile 的原因。

### 1.1 为什么用 Y 而不是 grid_y

`grid_y = 363 − Y`（`INT_L_X6Y11` 名为 Y=11，grid_y=352，见 `prjxray` 的 V7 `tilegrid.json`）。跨 clock region 比较时 grid_y 带偏移且方向相反，用 Y 才是物理行号。

### 1.2 band 与 Yr

- `band = Y // 50`：485T 垂直 7 个 clock region（350 行 ÷ 50），水平 2 列 → 14 region，与 MMCM 14 / PLL 14 数量自洽。
- `Yr = Y % 50`：region 内第几行，决定 `wof`。
- 7 是**485T 属性**：artix7 200T 垂直只有 5 个 region（`prjxray_ref/artix7/xc7a200t/tilegrid.json` 中 `baseaddr` 高位在 X0Y3 回绕）。

### 1.3 为什么一帧 101 字

```
50 行 × 2 字（parity 0/1）= 100 字
              + 1 校验字（word 50）= 101 字
```

word `0..49` = 行 0..24 的两个字；word `50` = 校验字（fabric 块）；word `51..100` = 行 25..49。

**一个 tile 在一帧里只占两个字**：101 个字是分给同一列 50 个不同行 tile 的，你这行只能用 `(wof, wof+1)`。位流是转置存储——纵向是帧，横向是行。

### 1.4 相对坐标从哪来

`frame_off / parity / bit` 来自 prjxray 的 segbits 行，例：

```
INT_L.IMUX_L7.BYP_BOUNCE3   21_57  !22_57  !23_57  !24_57   25_57
```

`21_57` = frame_off 21、bit64 57；`parity = 57 // 32 = 1`、`bit = 57 % 32 = 25`；`!` 前缀 = 该位必须为 0（`sense=0`）。

> 陷阱：prjxray 把第一个数叫 "word"，实际是**帧偏移**，不是帧内字号。

## 2. 四种独立定位方法

![四种方法](fig_tile_address_methods.png)

### ① 语料帧占用统计

- **输入**：远端 `/opt/lzh` 下 13,749 个 >15 MB 的 `.bit`（其中 7,987 个解析成功）。
- **操作**：大端解析 → 逐帧求「是否被写过」的并集 → 对连续被写的区间切块 → 与 `clb_blocks` 的已知基址对齐 → 反推尺寸签名。
- **输出**：`frame_blocks` 表 **1,038 行 / 36,260 帧 = 7 × 5,180 精确闭合**（clb 763 / gap28 245 / io72 14 / edge30 12 / pcie 2 / x36 2）。
- **失效判据**：若清单外被写帧 > 1%，则块切分错误。实测 84/12,658 = **0.66%**（band 间 66 帧 padding + fabric 之外）。
- **独立性**：只依赖「哪些帧非零」，不需要任何 LOC 或解码结果。

### ② LOC 地面真值

- **输入**：8,004 个有兄弟 `.v/.xdc/.tcl` 的 `.bit`（全库 13,749 个中）。
- **操作**：抽取 4,960 个含 LOC 的 → 4,467 个单 LOC（去重 100 个 tile）→ 判该 tile 所在块的 `INIT[..]` 区（offsets 32..35）是否被写过 → 投票。
- **输出**：`tile_block_gt` **45 行唯一命中**；自洽：同一 X 列跨 band 各命中一块并随 band 平移（X10 → band0 31716 / band3 5486 / band4 10732 / band5 26470 / band6 21224）。
- **失效判据**：若某 tile 的 INIT 区在全部语料中未被写过，则该 tile 无法投票（这也是只有 45/100 唯一的原因）。
- **独立性**：用「设计文件说了它在哪」而不是「位流反解出来像什么」。

### ③ Y 差分实验

- **输入**：两个设计，同列、同 LUT、只改 `Y`（`yA`=`SLICE_X8Y20`，`yB`=`SLICE_X8Y24`）。
- **操作**：Vivado 2017.2 出 `.bit` → 大端解析（自检 `FDRI burst = 50,176 × 101 = 5,067,776`）→ 逐帧逐字异或。
- **输出**：全片仅 4 帧不同（32428–32431）；yA 只动 word **40**、yB 只动 word **48**；块基址不变（32428 − 32 = 32396）。
- **失效判据**：若两版 ROUTE 相同则无差异（实验作废）。S21 曾因此失败：改 IOB 引脚后配置 0 字差异。
- **独立性**：纯几何，不需要任何家族位表。

### ④ 结构推导 + 预算闭合

- **输入**：7 个几何锚点（来自 S13 解码与 S24 走线真值）+ 每 band 的帧预算。
- **操作**：INT 列与相邻 CLB 列共用 36 帧块（`INT_L_Xn` → `grid_col = gx−1`；`INT_R_Xn` → `gx+1`）→ 生成 `tile_blocks` 53,102 行 → 用锚点验算。
- **输出**：7/7 锚点命中（`INT_L_X6Y11`→31680、`INT_R_X7Y12`→31716、`INT_L_X28Y51`→27186、`INT_R_X31Y51`→27286、`INT_L_X10Y11`→31824、`INT_L_X12Y19`→31888、`INT_R_X25Y40`→32332）。
- **失效判据**：若某 band 的「INT 列数 ≠ 块数」且预算不闭合，则规则失效（band0/3/4/6 为 154 列 vs 150 块，靠「少数列共用块」解释，尚未逐列定性）。
- **独立性**：只依赖块清单与列顺序，不依赖位级解码。

## 3. 五个失效模式

| # | 症状 | 为什么看起来正常 | 对策 |
|---|---|---|---|
| 1 | `f` 与 `f+28` 的绝对态判读**完全相同**（1,438/1,600 帧 = 89.9%）| 位模式合法、家族解得出、歧义为 0 | 基址只能靠几何锚点/预算闭合，**不能靠"解得出"** |
| 2 | 同一块当 4 个不同 tile 解，都给出 **12 unique** | 家族偏移是相对坐标，任何同质块都"能解" | 仲裁计数不能证明基址；须外部锚点 |
| 3 | 「每列 +36 帧」线性外推 | 144 条实测里 86 条符合，看着像主规律 | 只 60% 命中；必须查 `frame_blocks`，不能外推 |
| 4 | 夹缝列双映射：`INT_L_X32` 与 `INT_R_X33` 共用 io72 块（27322 / 27354 子窗口）| 两列各自解得出合法结果 | 按块序列走，不按列号 |
| 5 | CMT / GTX 的 `word` 不是 `wof` 平面（MMCM w12/25/26/29；GTX 通道平面 0/22/57/79）| 用 `wof` 也能解出"看着对"的位 | 按块类型分派 word 规则 |

## 4. 手算例

**目标**：`INT_L_X6Y11` 的 `IMUX_L7.BYP_BOUNCE3`（`frame_off=21, parity=1, bit=25`）。

| 步 | 计算 | 值 | 来源 |
|---|---|---|---|
| ① band | `11 // 50` | 0 | tile 名 |
| ② Yr | `11 % 50` | 11 | tile 名 |
| ③ 块基址 | `frame_blocks[band0, grid_col=16]` | **31680** | 表中 base；锚点由 S24 走线真值确认 |
| ④ 帧 | `31680 + 21` | **31701** | `frame_off` |
| ⑤ 字 | `wof(11) = 2×11 = 22`，`+parity 1` | **23** | 半带规则（Yr<25 不跳） |
| ⑥ 位 | `bit 25` | **25** | 家族 cell 定义 |

⇒ **`(31701, 23, 25)`**。S9 的 CSP 在 `s8_v0.bit` 上独立解出该位属于 `IMUX_L7`，与 `BYP_BOUNCE3` 一致。

## 5. 交叉验证矩阵

| 证据链 | 块基址 | 块内帧 | 帧内字 | 字内位 | 不能证明 |
|---|---|---|---|---|---|
| 语料帧占用统计 | 部分（只到块级）| 不能 | 不能 | 不能 | 具体 tile 归属 |
| LOC 地面真值（45）| 能 | 部分（间接）| 不能 | 不能 | 同块内多 tile 的区分 |
| Y 差分实验 | 不能 | 不能 | 能 | 不能 | 块的绝对基址 |
| 7 个几何锚点 | 能 | 不能 | 不能 | 不能 | 未覆盖列的基址 |
| 绝对态判读（636 tile）| 部分 | 能 | 能 | 能 | **基址正确性（空片无法区分）** |

**证明力边界**：
- 「绝对态判读」能证明相对坐标一致，但**永远不能**自证基址——这是空片导致的物理限制，不是方法缺陷。
- 「LOC 地面真值」是最强证据，但只覆盖 45/53,102。
- 「预算闭合」证明块清单完整，不证明每个 tile 落在哪一块。
