# 跨类型一致性：INT_L vs INT_R

## 设计

| | INT_L 批 | INT_R 批 |
|---|---|---|
| 目录 | `/opt/lzh/step03/tilepipe` | `/opt/lzh/step03/tilepipe2` |
| tile | `INT_L_X6Y11` | `INT_R_X9Y11`（多个实例） |
| 设计 | 36（6 BEL × 6 脚） | 36（6 BEL × 6 脚） |
| 观测 | 900 位流 | 900 位流 |
| mux 名 | `IMUX_L0 … IMUX_L46` | `IMUX0 … IMUX44` |

## 结果

按「mux 编号相同 + wire 名相同」配对，归一化（减最小帧、最小 bit）后逐条比较：

```
same = 792, diff = 0
```

**792 对全部一致。**

## 附带的结构一致

| 指标 | INT_L | INT_R |
|---|---|---|
| 每 mux 源数 | 25 | 25 |
| 掩码大小分布 | 0×1 / 2×12 / 4×12 | 0×1 / 2×12 / 4×12 |
| word 取值 | 22 / 23（按 `L//4` 奇偶） | 22 / 23（同规则） |
| 帧窗口 | 31696–31705 | 31804–31813（整体偏移 **+108**） |

## 结论

1. **形状表（哪个 mux + 哪条 wire → 哪几个 cell）在 INT_L 与 INT_R 之间完全相同**，
   与 tile 实例、甚至与 tile 类型都无关。
2. 类型之间的差别只体现在**块地址**：帧窗口整体平移（本例 +108 帧）。
3. 因此可以只维护**一张形状表**（mux 编号 × 25 条 wire → cell 集合），
   再加上一个 **block 地址函数**（由 config row、列、行带决定），就能覆盖整族 INT tile。
