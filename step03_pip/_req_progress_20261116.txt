请为「XC7VX485T（VC707）比特流逆向 —— PIP 复用规律」项目撰写一份**当前进度汇报**的结构化提示词。

汇报对象：导师/评审老师，他关心三件事：现在到哪一步、能不能宣称结论、下一步该做什么。

【必须遵守的写作规则】
1. 三色标注：全文任何一句涉及事实的话，必须能归入【硬件事实】/【数据事实】/【推断】之一；不得混写。
2. 每个数字必须带复算入口（脚本+命令）或明确标出处；给不出复算入口的必须标「不可复算」并降档为【推断】。
3. 禁止把工作量当进度：文件数、脚本数、跑了多少次构建，都不算进度。
4. 禁止出现「首次」「唯一可行」「完整覆盖」「完全解决」这类词；要断言就写成可被一个实验推翻的句子。
5. 进度必须带分母，并写清分母的定义（同一个百分比若有两个分母，两个都要给）。
6. 必须有一节「现在能宣称什么 / 还不能宣称什么」，两边都要给原句。
7. 缺口必须按「影响 × 可修性」排序，不许平铺。
8. 结尾只给三件事，按优先级，每件带判据与预估人日。

【固定结构（六节，不得增减）】
① 一句话结论（≤80 字，含最重要的一个数字）
② 主线与边界（主线是什么、哪些内容被明确排除在外、为什么排除）
③ 分层进度表（层 / 指标 / 数值（带分母）/ 状态（已验证·自洽·未做）/ 证据 / 复算入口）
④ 自上次汇报以来的增量（按「做了什么 → 得到什么数字 → 推翻了什么旧结论」三段式，逐条列）
⑤ 缺口账（按影响×可修性排序的表 + 每行判据）
⑥ 下一步三件事（优先级 + 判据 + 预估人日）与「现在能宣称/不能宣称」两句原句

【本项目的既有关键口径，写作时必须沿用，不得换算成别的口径】
- 位库规模：INT_L/INT_R 各 172 族、3,634 条 feature（连接）、1,598 个物理格、8,900 条置位记录；sense=0 的 3,264 行不可混入。
- 覆盖率两个分母：按 law_cells 特征 3,552/3,634 = 97.7%；按 tile 内 PIP 3,552/3,737 = 95.0%。
- 生成器：mux 64/64 + BEG 96/96（含 32 变体）+ 复合 6 族 96/96 源 = 0 差异；6 个长线族 82 条为表数据。
- 解码不变量：6 个位流 + 34 个探针位流共 231,656 个槽位 0 违例。
- 定位器：单 bit 检出 1,624,720/1,633,808 = 99.4438%；真实设计 982 tile、L1 未解释 240（固定两格标记位）、L2 0。
- 可迁移性：tile 类型 3/115（INT_L、INT_R、HCLK_BRAM 的一路 2 选 1）；器件 1/1。
- 外部真值：12 个新设计、844 个活跃 INT tile、全部唯一解、FP=0，TP 5,940 / FN 1,400（FN 全部为结构上无位的连接：775 直通 + 625 常量），可检出行召回 5,940/5,940 = 100%。
- 单设计精确覆盖对账：TP 1,407 / FP 6 / FN 21 → 精确率 99.58%、召回 98.53%。
- 未闭合项：ECC 与帧地址耦合（`ECC = L(data) ⊕ A(frame_addr)`，A 未定）→ 不能生成任意可加载位流。
