# fuzz 流水线详解（Virtex-7 / xc7vx485t）

编写日期：2026-11-15  
适用器件：`xc7vx485tffg1157-3`  
读者：熟悉 Vivado 与位流概念、但未参与本项目的工程师

> 结论等级约定：`verified` = 同源自证 + 交叉自证都过；`unverified` = 仅同源自证。
> 本文所有数字标出处；无出处的数字视为未测。

---

## 第 0 章　全景

```
① 语料 fuzz      ② 定向 fuzz       ③ 并发执行
   (被动统计)       (单变量成对)       (32 槽并行)
      │                 │                 │
      └──── 假设 ───────┴─────────────────┘
                        │
                ④ 差分判读 (frame, word, bit)
                        │
                ⑤ 归属判定 (双位置交集 / 绝对态 / 负对照)
                        │
                ⑥ 写回验证 (改位 + ECC/CRC)
                        │
                ⑦ 落库 (STATUS / v7_verified / S<n>.md)
```

**两类 fuzz 的结论能力（硬边界）**

| | 语料 fuzz | 定向 fuzz |
|---|---|---|
| 能给出 | **相关性假设**（"出现 X 时 90% 有 Y"） | **因果归属**（"改 X 导致 Y 翻转"） |
| 不能给出 | 因果 | 全语料频率 |
| 禁止做法 | 把相关性写成"某位 = 某功能" | 用少量设计推断"所有 tile 都是这样" |

> 本项目曾把 `(1,0,31)` 与 PLL 的 3.5× 相关性当证据，后被 BUFG 设计的 0 命中推翻（S69）。**相关性只能用来排优先级，不能用来定归属。**

## 第 1 章　语料 fuzz（被动）

**输入**：远端 `/opt/lzh` 下全部 `.bit`（>15 MB 的共 13,749 个，可解析 7,987 个）。

**操作**：numpy 向量化逐文件解析 → 统计每个坐标的出现次数；同目录若有 `.v`，统计关键词（`FDCE`/`CARRY4`/`RAMB`/`MMCM`…）。

```python
# /opt/lzh/step11/scan.py（全量 ~3 min）
arr = np.frombuffer(words, dtype='>u4').reshape(50176, 101)
cnt += (arr != 0)
```

**输出**：`(frame, word, bit)` 频次表；`step11_cnt.npy`（50,176 长数组，每帧被多少 bitstream 写过）。

**判据**：`若 解析成功数 / 总数 < 0.5` → **判定语料集含大量非本器件 bitstream，统计无效**（实测 7,987/13,749 = 58.1%，可用）。

### 这一步会怎样静默撒谎

| 症状 | 为什么看起来正常 | 如何用一次额外请求区分 |
|---|---|---|
| 关键词相关性很高 | 同目录 `.v` 覆盖率高，看着代表性足 | 统计 `.v` 覆盖率：实测只有 **1,234/13,749 = 9.0%**，且其中 91.7% 是本项目自己的探针（含 `DONT_TOUCH`）⇒ 结论只在该子集成立（S68）|
| 某坐标出现 1,284 次 | 频率最高，像"核心配置位" | 用 `wof=2y` 当行字扫一遍：若命中全部集中在 `y=25`，说明读到的是 **word 50 校验字**（S52 首次版即此 bug）|

**止损点**：语料层只出假设，不出结论；任何"某位=某功能"必须在第 5 段重测。

## 第 2 章　定向 fuzz（主动）

**输入**：一个属性 + 一个 site（如 `SLICE_X10Y20` 的 `A6LUT`）。

**操作**：建两份设计——基线（不变）+ 变体（只改一处）；`LOC/BEL/LOCK_PINS` 在 `synth_design` **之后**施加。

```tcl
read_verilog $env(SRC)
synth_design -top top -part xc7vx485tffg1157-3 -flatten_hierarchy none   ;# part 必须显式
set_property CFGBVS GND        [current_design]
set_property CONFIG_VOLTAGE 1.8 [current_design]
set_property LOC  SLICE_X10Y20 [get_cells -hierarchical -filter {IS_PRIMITIVE && NAME !~ "*/*" && (REF_NAME =~ LUT*)}]
set_property LOCK_PINS {I0:A1 I1:A2 I2:A3 I3:A4 I4:A5 I5:A6} [get_cells ...]
set_property SEVERITY Warning [get_drc_checks NSTD-1]
set_property SEVERITY Warning [get_drc_checks UCIO-1]
opt_design; place_design; route_design
write_bitstream -force /opt/lzh/work/${env(JOB)}.bit
```

**输出**：两份 `.bit`（各 20,273,538 字节）。

**判据**：
- `若 "-part" 未出现在脚本` → **判定构建作废**（默认 part 是 `ffg1761-2`，与项目 `ffg1157-3` 不符）；
- `若 基线重跑差分 ≠ 0` → **判定环境不稳**，整批丢弃。

### 这一步会怎样静默撒谎

| 症状 | 为什么看起来正常 | 如何用一次额外请求区分 |
|---|---|---|
| 差分干净、位集漂亮 | 单变量成立，逻辑自洽 | 对比两份 `ROUTE`：S21 首次实验里 A 输入两位只差引脚，但**未钉 `PACKAGE_PIN`** 时 IOB 落在同一 site，配置 0 差异；钉脚后才有 153 帧差异 |
| "改属性导致一堆位变化" | 变化量大，像真实差异 | 查综合日志：`INFO: [Opt 31-389] Phase Constant propagation created 1 cells and removed 2 cells` 表示 LUT 被折叠成常量（yA 实验），此时改的是常量值不是 LUT 真值表 |

**止损点**：`若 SITE/BEL/PART 回读与请求不一致` → 该批作废，不进第 4 段。

## 第 3 章　并发执行

**输入**：一批已定稿的设计 + 构建脚本。

**操作**：远端 44 核 / 98 GB，用 N 个槽并行跑 Vivado。

```bash
# 每个槽独立工作目录，避免 .bit 互相覆盖
for j in $(seq 0 31); do
  ( cd /opt/lzh/work/v$(printf %02d $j) && JOB=v$j SRC=$j.v vivado -mode batch -nojournal -nolog -source build.tcl ) &
done; wait; echo ALLDONE
```

**输出**：N 份 `.bit` + N 份日志。

**判据**：
- `若 grep -c "DONE" != N` → **判定有槽失败**（11 并发时日志截断在 part loading，全部失败）；
- `若 任一份 .bit 大小 != 20,273,538` → **判定该槽无效**。

### 这一步会怎样静默撒谎

| 症状 | 为什么看起来正常 | 如何用一次额外请求区分 |
|---|---|---|
| 脚本打印 `ALLDONE` | 循环正常结束 | `ALLDONE` 只表示 `wait` 返回，不表示每个 vivado 成功；必须 `grep -c "DONE"` 对齐数量 |
| 全批 `rc=127`、耗时 0 s | 看起来"跑过了" | 127 = 命令不存在：实测用 `/usr/bin/time -v` 计时，而 WSL Ubuntu 未装该二进制 ⇒ 去掉它，改用 `date +%s` |
| 峰值 RSS 报 0 | 看着像"没吃内存" | 同上：`/usr/bin/time` 缺失导致所有统计列为 0 |

**止损点**：`若 成功数 < N` → 重跑缺失槽，不得用部分结果做差分。

## 第 4 章　差分判读

**输入**：两份 `.bit`。

**操作**：大端解析 → 取第一段 FDRI burst → 逐帧逐字异或。

```python
p = data.find(b'\xaa\x99\x55\x66') + 4          # 同步字后
w = int.from_bytes(data[p:p+4], 'big')
assert (w >> 29) & 7 == 1 and (w >> 27) & 3 == 2 # type1 WRITE
cnt = w & 0x7FFFFFF                              # 27 位，不能用 0x7fffffff
assert cnt == 5067776                            # 50,176 × 101
```

**输出**：`(frame, word, bit)` 三元组；`word == 50` 单独列表。

**判据**：
- `若 count != 5,067,776` → **判定解析失败**（小端会把同步字读成 `0x665599AA`）；
- `若 差分落在 (f - base) ∉ [0, 36)` → **判定块归属错**；
- `若 word 50 被计入内容位` → **判定统计失败**。

### 这一步会怎样静默撒谎

| 症状 | 为什么看起来正常 | 如何用一次额外请求区分 |
|---|---|---|
| count 解出 1,347,245,056 | 数字很大，像合理帧数 | 掩码写成 `0x7fffffff` 会把包头 `0x5…` 的最高位算进去；改 `0x7FFFFFF` 后应精确等于 5,067,776 |
| 差分只有 3 字节 | 差异极小，像"几乎一致" | 这 3 字节在 ASCII 头（偏移 93–96，时间戳）⇒ FDRI 数据 0 差异，说明两个设计配置完全相同（S21 前身实验），必须回到第 2 段查变量 |

**止损点**：`若 自检 count 不过` → 解析器问题，绝不进第 5 段。

## 第 5 章　归属判定

**输入**：第 4 段的位集 + 家族表 `all_cells.json`。

**操作**：
1. **双位置**：同一功能在 `SLICE_X10Y20` 与 `SLICE_X6Y11` 各建一版，取位集**交集**；
2. **绝对态判读**：不看差分，直接读一块 tile 的位，匹配 `ones ⊆ 观测 且 zeros ∩ 观测 = ∅`；
3. **负对照**：同设计重跑，差分必须为 0。

**输出**：属性 → 坐标的归属表。

**判据**：
- `若 交集 == ∅` → **判定归属不成立**（该位随 LOC 变化，是列共享位）；
- `若 unique 解数 > 1` → **判定 AMBIGUOUS**，需 CSP 或补约束；
- `若 负对照 ≠ 0` → **判定环境噪声**。

### 这一步会怎样静默撒谎

| 症状 | 为什么看起来正常 | 如何用一次额外请求区分 |
|---|---|---|
| 单 LOC 结果"很干净" | 只有几个位，看着就是该属性 | 换第二个 LOC 后多出 4 个局部位（S61 的 `31680/w22/b23` 等）⇒ 那是 slice 局部位不是网络位 |
| 多解时取"命中数最多" | 统计上最优 | 用同一块数据当 4 个不同 tile 解，都得 12 unique（S31 T4b）⇒ 命中数不能仲裁，必须靠链/拓扑一致性 |

**关键数字**（`verified`）：绝对态判读 **636 个有配置位的 tile / 1,196 次家族判读 / 0 歧义 / 0 未解释位**；走线复原 **9 网 6/6 token 级一致**；反向检验 **TP 366 / FP 0 / AMBIG 0 / FN 6**（6 个 FN 全是不占位的 always ppip）。出处：S40/S24/S16。

**止损点**：`若 两位置交集为空` → 该批只出"某功能会点亮哪些位"，不出"某位属于某功能"。

## 第 6 章　写回验证

**输入**：第 5 段的坐标 + 一个"已知答案"的设计。

**操作**：直接改 `.bit` 载荷位，重算 CRC/ECC，再回读（或至少证明载荷与重综合结果一致）。

**输出**：写回成功率。

**判据**：
- `若 回读载荷 != 期望` → **判定写位实现有误**；
- `若 硬件拒绝` → 先查 CRC/ECC，**不得直接判"位无效"**。

### 这一步会怎样静默撒谎

| 症状 | 为什么看起来正常 | 如何用一次额外请求区分 |
|---|---|---|
| 864/864 全过 | 全绿，像已验证 | 864 只证明"未被硬件拒绝"，**不能区分 CRC 与 ECC 的作用域**（已从此前的"含 ECC 验证"降级）|
| 帧级 0 差异就收工 | 帧级一致很强 | 字节级仍可能有头部时间戳与尾部 CRC 差异；必须两级分开报告 |

**止损点**：`若 只有帧级一致、无字节级对账` → 标 `unverified`。

## 第 7 章　落库

**输入**：上述全部输出。

**操作**：追加 `STATUS.md` 实验节、写 `v7_law.sqlite.v7_verified`、写 `step03_pip/S<n>_*.md`。

```python
open('STATUS.md','a',encoding='utf-8').write(section)   # 追加，禁止全文回写
con.execute("insert into v7_verified(...) values (...)")
```

**输出**：可复算记录。

**判据**：
- `若 报告缺【实测】/【推断】/【未测】标注` → **判定未完成**；
- `若 结论缺结论等级（verified/unverified）` → **判定未完成**；
- `若 STATUS.md 行数比写入前变化 != 新增行数` → **判定截断**（历史事故：1773 行被写成 811 行）。

### 这一步会怎样静默撒谎

| 症状 | 为什么看起来正常 | 如何用一次额外请求区分 |
|---|---|---|
| 文档里写着"已验证" | 读起来是结论 | 检查是否有交叉自证（另一脚本 / 另一批构建）⇒ 只有同源时只能写 `unverified` |
| 数字都记得住 | 前后自洽 | 抽查一个数字回表：`select count(*) from law_cells` 应为 **24,328**，`v7_verified` 当前 245 行 |

**止损点**：`若 任一结论无法给出最小可证伪实验` → 该结论降级为"观察"。

## 第 8 章　失败传播图

```
① 语料 ──相关性假设──▶ ⑤ 归属（只影响优先级，不污染数据）
   └─若把相关性当因果──▶ ⑦ 结论【污染结论，止损点：⑤】
② 定向 ──part/变量错误──▶ ④ 差分【污染数据】
   └─若变量实际两个──▶ ⑤ 归属【污染结论，止损点：④ 的 ROUTE 对账】
③ 并发 ──槽失败/空 .bit──▶ ④ 差分【污染数据】
   └─若只 grep ALLDONE──▶ ④⑤⑦ 全污染【止损点：③ 的 DONE 计数】
④ 差分 ──端序/掩码/word50──▶ ⑤ 归属【污染数据】
   └─若块归属错──▶ ⑦ 结论【止损点：④ 的自检 count】
⑤ 归属 ──单 LOC/命中数仲裁──▶ ⑥ 写回（写到错位）【污染数据+结论】
   └─【止损点：⑤ 的交集为空 / 多解】
⑥ 写回 ──只改载荷不改校验──▶ ⑦ 结论（"位无效"误判）【污染结论】
   └─【止损点：⑥ 的 CRC/ECC 对账】
⑦ 落库 ──无等级/无出处──▶ 后人复用【污染长期结论】
   └─【止损点：⑦ 的三项判据】
```

**一句话**：数据污染在 ④ 之前都还能救（重跑），结论污染一旦进 ⑦ 就会变成"历史事实"。

## 第 9 章　吞吐与成本

| 量 | 值 | 出处 / 复算 |
|---|---|---|
| 单设计墙钟（32 并发下）| **214 s** | 32 设计 214 s 全批收尾（S16）|
| 单实例峰值内存 | **3.0 GB** | 同上 |
| 单位设计成本 | `32 × 214 / 32 = 214 s`（核·秒/设计）| 由上式 |
| 并发上限 | **32 稳定；11 有时全失败** | S52 第三批（11 失败改 4 并发 11/11 成功）|
| 全语料扫描（7,987 可解析）| **≈ 3 min** | `step11/scan.py` numpy 向量化 |
| 全语料扫描（13,749 个，16 进程）| 【未测】按上式折算 ≈ 5 min | `step18/holescan_all.py`（未单独计时）|

**规模感**：一套 150 个设计的属性普查 ≈ 17 分钟；66 格全归属（约 40 个设计 + 语料）≈ 半天。

## 附：命令姿势（远端默认 shell 是 `cmd.exe`）

```bash
# 推文件（管道会被 cmd 重切 ⇒ 用 tee，且不能带引号/竖线）
ssh fpga 'C:\Windows\System32\wsl.exe -d Ubuntu -u root -- tee /opt/lzh/work/x.py' < x.py

# 跑脚本：先落地再执行
ssh fpga 'C:\Windows\System32\wsl.exe -d Ubuntu -u root -- bash /opt/lzh/work/r.sh'

# 取产物：cat 输出；二进制用 python base64 取出，切勿 | head（cmd 无 head）
```

**硬规则**：脚本 LF 换行；脚本头 `export LANG=C.UTF-8 LC_ALL=C.UTF-8; unset LANGUAGE`；长任务用后台 job 保持 WSL 不退。
