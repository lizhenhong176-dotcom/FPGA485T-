# PROMPT · fuzz 流水线详解 (V1)

> 生成方式：`optimize-user-prompt`(user-prompt-professional) → `iterate-prompt`(iterate，6 条加固)。
> 用途：产出「可复现 + 每步带判据 + 每步带静默失败检测」的流水线文档。

---

请为我的 Virtex-7 (xc7vx485t) 位流逆向项目撰写一份《fuzz 流水线详解》技术文档，面向熟悉 FPGA 位流与 Vivado 工具链但未参与本项目的工程师，使其读后能复现整条流水线并理解每步设计取舍。

## 一、七段流水线逐章展开（真实执行顺序）

1. **语料 fuzz（被动）**：扫描远端 `/opt/lzh` 下 13,749 个 >15 MB 的 `.bit`（7,987 个可解析），同目录有 `.v` 则做关键词相关性统计。
2. **定向 fuzz（主动）**：Vivado 2017.2 建「基线 + 单变量变体」成对设计，`LOC/BEL/LOCK_PINS` 在 synth 之后施加，part 显式 `xc7vx485tffg1157-3`。
3. **并发执行**：44 核 / 98 GB；32 并发可跑（32 设计 214 s，单实例峰值 RSS 3.0 GB）；4 并发最稳；11 并发全部失败（日志截断于 part loading）。
4. **差分判读**：大端解析，自检 `FDRI type2 count = 5,067,776`；逐帧逐字异或输出 `(frame, word, bit)`；word 50 单独计数。
5. **归属判定**：同功能在两个不同 LOC 各建一版取交集；绝对态判读（非差分）；负对照 = 同设计重跑差分必须为 0。
6. **写回验证**：改位到 `.bit`（含 ECC/CRC），回读硬件或证明载荷一致；864/864。
7. **落库**：`STATUS.md`、`v7_law.sqlite.v7_verified`、`step03_pip/S<n>_*.md`；结论标【实测】/【推断】/【未测】。

## 二、每章固定格式

「输入 → 操作 → 输出 → 判据」；**判据必须写成可执行断言**（给出具体命令或表达式，如 `assert count == 5067776`、`若 len(hits)==0`），不允许只写"应一致"。

## 三、每章必须含「这一步会怎样静默撒谎」

至少 2 条静默失败模式，每条按 **「症状 → 为什么看起来正常 → 如何用一次额外请求区分」** 三段式给出。

## 四、必须区分两类 fuzz 的结论能力

**语料 fuzz 只能产生"相关性假设"，不能产生"因果归属"**；只有定向 fuzz 能做因果归属。把语料相关性当因果结论的，必须标为禁止做法。

## 五、命令/脚本骨架

ssh + wsl + vivado 调用姿势；**远端默认 shell 是 cmd.exe，管道与引号会被重切**，须给出规避写法。

## 六、失败传播图

一张「七段流水线的失败传播图」，标明某一步出错会污染后续哪几步；每条传播关系说明**污染的是数据还是结论**，并给出**止损点**（在哪一步就该丢弃本批）。

## 七、出处

每个数字标出处（报告编号 / 脚本路径 / 表名）。

## 八、吞吐与成本

三个可复算的数：**单设计墙钟**、**单位设计成本**（并发数 × 时长 / 设计数）、**全语料扫描总时长**。
