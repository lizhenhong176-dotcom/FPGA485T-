# PIP 复用在哪一层、复用规律是什么

> 定位：**项目主线正文档（PIP 复用分析）** —— 复用发生在哪几层 + 七条规律。主线边界见 `STATUS.md §97`。

按 `step03_pip/PROMPT_REUSE_MAINLINE_V2.md` 产出。器件 `xc7vx485tffg1761-2`，INT tile。
标注：【硬件事实】/【数据事实】（附表名或脚本）/【推断】。所有统计一律取 `sense=1`。

## 结论先行

1. **复用在四层，只有一层是真共享**：cell 被多个 feature 共用（平均 5.57 次）是真共享；family 与 family 之间几乎不共享（1,598 个 cell 只有 3 个跨族，0.19%）；tile 与 tile 之间**共用的是地址模板，不是位**；器件层只有线名差异。
2. **规律的主干是一条正交划分**：16 个位对 × 2 个 parity × 2 个 phase = **64 个家族地址空间**，与 64 个 mux 族一一对应（`combo_check: max_per_combo=1`）；同一对位上的两个族靠 phase 互斥，这正是「复用」的几何本质【数据事实：`v7re/steps/T3_PIP_REUSE_LAW.md:46-65`】。
3. **族内是唯一编码**：172/172 族内没有任何两个源的 cell 集合相同；每源占 2 或 4 格（2,818 个 2 格 + 816 个 4 格 = 3,634 feature）。
4. **172 族的构成已闭合**：64 mux（帧 16–25，6×4 网格）+ 64 BEG2/1（帧 6–15，5×4 网格）+ 32 BEG6/4（帧 2–7，K(4,5) 二分图）+ 6 时钟/控制（帧 0–1，组模型）+ 6 长线族 = **172**。
5. **复用的本质**：位池被正交切成 64 个互斥的家族地址空间，家族内部再对 24 个源做唯一编码 —— 是「地址空间的正交划分」，不是「位的任意混用」。反例判据：只要找到「两个非长线族共享同一个 cell」的实例，这句话就假；实测跨族共享的 3 例全部落在长线族（`LH0`/`LV_L0`/`LV_L18`）之间【数据事实：`step03_pip/_q_reuse_mainline.py`】。

## 一、复用发生在哪一层

### 1.1 五层的计数与共享度量

| 层 | 对象 | 数量（INT_L 单侧） | 是否共享 | 共享度量 |
|---|---|---|---|---|
| 位池 cell | `(frame_off, parity, bit)` | **1,598** | 是，且是唯一真共享层 | 1,595 个 cell 只服务 1 个族，2 个服务 2 个族，1 个服务 3 个族 |
| 特征 feature | 一个源在一个族里的置位集合 | **3,634** | 否 | 每 feature 2 格（2,818 个，77.5%）或 4 格（816 个，22.5%），均值 **2.45** |
| 家族 family | 共用同一目的 wire 的一组 PIP（组内互斥） | **172** | 否 | 族内每源 pattern **172/172 互不相同** |
| tile | 26,550 个 INT_L 实例 | 26,550（INT_R 同） | 共用地址模板，不共用位 | `uniform=1`：所有 INT tile 同一张 3,737 PIP 的网 |
| 器件 | 150,380 tile / 115 类型 | 150,380 | 只在线名命名上分左右 | INT_L 77 列（偶 0..152）、INT_R 77 列（奇 1..153） |

**cell 被 feature 共用的分布**（这是「复用」的主战场）【数据事实：`law_cells` sense=1】：

```
每 cell 被几个 feature 共用：2→2 个, 3→28 个, 4→910 个, 5→384 个, 6→134 个, 12→12 个, 18→128 个
合计 1,598 个 cell / 8,900 条 sense=1 行 → 平均 5.57
```

即：一个 cell 平均被 **5.57** 个 feature 用到（3,634 feature 抢 1,598 个格子），这是「读一位能不能唯一确定一个 PIP」之所以不成立的物理原因。

### 1.2 必须区分的两类行（口径硬规则）

`law_cells` 每侧 12,164 行 = `sense=1` **8,900**（必须置 1）+ `sense=0` **3,264**（必须为 0 的约束位）。**所有统计只取 sense=1**。混算会得到下面这组假象，已全部作废【数据事实：本会话 2026-11-07 复算；`STATUS.md` §65】：

| 混算得到的假象 | sense=1 真值 |
|---|---|
| 每源恒 5 格 | 2 或 4 格，均值 2.45 |
| 平均 3.35 格/feature | **2.45**（8,900/3,634） |
| 每 cell 被 7.61 个 feature 共用 | **5.57**（8,900/1,598） |
| 172 条只有 102 唯一、70 族 4:1 合并 | **172/172 唯一，0 族合并** |
| cell 共用度 `[…,24,24,24,24]` | `IMUX_L40` 的 `[4,4,4,4,4,4,6,6,18,18]` |

### 1.3 文字版层次图（谁复用谁）

```
位池 1,598 cell ── 被 3,634 feature 共用（均 5.57）… 真共享
   │
   ├─ 每个 cell = (frame_off, parity, bit) 三元组
   │
feature 3,634 ── 每个 feature 2 或 4 格；族内互不重复（172/172）
   │
   ├─ 同族内：一个源 = 一组格；换个源 = 换一组格（互斥）
   │
family 172 ── 每个族占用一组互斥的 cell；族间几乎不共享（3/1,598）
   │
   ├─ 跨族共享只出现在长线族 LH0 / LV_L0 / LV_L18 的 3 个格上
   │
tile 53,100 个 INT ── 位位置模板全同（uniform=1），位值各不相同
   │
器件 150,380 tile ── 左右侧仅线名不同（IMUX_L40 ↔ IMUX40）
```

方向读法：**向下的箭头是「被复用」，横向是「互斥」**。真共享只在最上面一层（cell 被多 feature 用），family 与 tile 层都是「同一模板 + 不同取值」。

## 二、复用的规律

### 规律 1｜族内唯一性

- **陈述**：同一 family 内，任意两个源的 cell 集合不相等。
- **可执行形式**：`∀f, ∀s1≠s2 ∈ srcs(f): cells(f,s1) ≠ cells(f,s2)`
- **证据**：**172/172** 族成立，0 反例【数据事实：`T3_PIP_REUSE_LAW.md:143-145`；`verify_all_pip.py`】
- **实例**：`EE2BEG0` — `EE2END0={(9,0,6),(15,0,6)}`、`EE4END0={(9,0,7),(15,0,6)}`、`EL1END0={(11,0,6),(15,0,6)}`，20 个源两两不同。
- **失效条件**：换 tile 类型（CLB/DSP/BRAM 的位布局未做同口径统计）；若某族源数 > 位池能容纳的唯一组合数（如上侧 9 格 20 源，C(9,2)=36 ≥ 20 才成立），唯一性必然失败。

### 规律 2｜形状分类（7 类）

- **陈述**：172 族可按 (置位格数, 源个数) 分成 7 类，且分类与帧窗一一对应。
- **可执行形式**：`shape(f) = (|∪cells|, |srcs|)`，然后 `Counter(shape(f) for f in 172)`
- **证据**【数据事实：`_q_reuse_mainline.py`】：

| 形状 | 族数 | 占比 | 帧窗 | 对应族 |
|---|---|---|---|---|
| (10, 24) | 64 | 64/172 = 37.2% | 16–25 | 48 个 `IMUX*` + 8 个 `BYP_ALT*` + 8 个 `FAN_ALT*` |
| (9, 20) | 96 | 96/172 = 55.8% | 6–15（64 族）+ 2–7（32 族） | `*BEG*` |
| (8, 16) | 6 | 6/172 = 3.5% | 0–1 | `CLK_L0/1`、`CTRL_L0/1`、`GFAN0/1` |
| (9, 18) | 2 | 1.2% | 0–1 | `LVB_L0`、`LVB_L12` |
| (9, 12) | 2 | 1.2% | 0–1 | `LH0`、`LV_L18` |
| (7, 12) | 1 | 0.6% | 0–1 | `LH12` |
| (7, 10) | 1 | 0.6% | 0–1 | `LV_L0` |

- **失效条件**：换器件（V7 其他型号的 INT 行数/列数不同，族数未必 172 —— **未测**）；INT_R 需先做线名归一化，否则 96 个 `*BEG*` 会与 INT_L 的名字对不上（实测 INT_R 未归一化时覆盖仅 2,312/3,634 = 63.6%）。

### 规律 3｜网格生成律（160 族的地址是生成的，不是数据）

- **陈述**：mux 区与 BEG 区的地址由「源在网格里的 (row, colcode)」加「族的 (位对, parity, phase)」直接算出。
- **可执行形式**【数据事实：`T3_PIP_REUSE_LAW.md:21-56`；代码 `v7re/scripts/bitwriter.py`】：

```
frame_row = 16 + row                      # row ∈ 0..5（mux 区 6×4 网格）
frame_col = { 25 - i | colcode 的第 i 位为 1 }   # 0001→{25} 0010→{24} 0111→{25,24,23} 1011→{25,24,22}
列帧恒用 primary 位 P；行帧 row∈{0,1,4,5} 用 P，row∈{2,3} 用配对位 S=B^1
16 位对 × 2 parity × 2 phase = 64  ←→  64 个 mux 族，一一对应
```

- **证据**：`combo_check: families=64, distinct_combos=64, max_per_combo=1`；`--verify` **1,536/1,536** 槽位全对。BEG 区同构：帧 6–15 的 64 族用 **5×4** 网格、同一套 (位对, parity, phase) 编址【`T3:129-139`】。
- **实例（同一对位 6/7、同 parity 0、靠 phase 区分）**：`BYP_ALT0`（primary=7，行帧 0,1,4,5→bit7，2,3→bit6，列帧 bit7）与 `IMUX_L40`（primary=6，互为镜像）——**两者源集合相同、cell 集合互斥**，这就是「复用」的几何本质【`T3:58-65`】。
- **失效条件**：帧 0–7 的 44 个族（时钟/控制 + `*6BEG*/4BEG*`）**不符合** 5×4/6×4 判定；`*6BEG/4BEG*` 按 (frame,bit) 字典序切两轴会被切错，必须按二分集切。

### 规律 4｜BEG6/4 区是 4×5 完全二分图

- **陈述**：帧 2–7 的 32 个族，每个源 = 一条边，格 = 节点，构成 K(4,5)。
- **可执行形式**：`每源 2 格 → 边集；统计节点数/边数/度序列`，判 `9 节点 / 20 边 / 度 4 与 5`
- **证据**：32/32 族一致；节点 9、边 20（4×5 用满）、三角形 0、直径 2、二分【数据事实：`T3:167-182`】
- **实例**：`EE4BEG0` — `EE2END0=(3,8)+(3,9)`（同帧两位）、`SS2END0=(3,8)+(5,11)`（跨帧跨位）。
- **失效条件**：同上，用「按帧切轴」的判据会把同帧两格的源切错，误判为非网格。

### 规律 5｜时钟/控制 6 族是「组模型」，比对必须先过滤 sense=1

- **陈述**：`CLK_L0/1`、`CTRL_L0/1`、`GFAN0/1` 每族 16 源、8 个格，结构是 `core(3 格) + drops(2 源各去 1 格) + extras(2 源各加 1 格)`。
- **可执行形式**：`model(src) = core − drop(src) + extra(src)`，逐源与 `law_cells` 的 sense=1 集合比对
- **证据**：24 组 **96/96 精确命中、不符 0、恒定 cell 0**；若不过滤 sense=1，会得到「需要并 4 个恒定 cell」的假结论【数据事实：`v7re/steps/T35_COMPOSITE_GROUP_MODEL.md` §6】
- **实例**：`CLK_L0` 组 0 的 core = `{(0,0,25),(0,0,26),(1,0,24)}`；`GCLK_L_B1` 的 sense=1 集合 = `{(0,0,26),(1,0,24)}`（= core 去掉 `(0,0,25)`）。
- **失效条件**：`LV_L0` 在 `composite_groups.json` 里是**空列表**（组模型不适用），其 10 条 feature 由 `beg_families.json` 覆盖；把它算进「96 条」会重复计数。

### 规律 6｜跨族共享被封在 3 个格（0.19%）

- **陈述**：1,598 个 cell 里只有 3 个同时服务两个及以上的族，且全部落在长线族之间。
- **可执行形式**：`cell → set(family)`，取 `len>1`
- **证据**【数据事实：`_q_reuse_mainline.py`】：

```
(1,0,6) → LH0, LV_L0, LV_L18   （3 族共用）
(0,0,2) → LH0, LV_L0
(0,0,9) → LV_L0, LV_L18
跨族 cell = 3/1,598 = 0.19%
```

- **实例**：长线族（`LH0` 9 格/12 源、`LH12` 7 格/12 源、`LV_L0` 7 格/10 源、`LV_L18` 9 格/12 源、`LVB_L0`/`LVB_L12` 9 格/18 源）彼此之间共享 3 格，其余 169 族严格独占。
- **失效条件**：换器件或换 tile 类型（BRAM/DSP 的 `pbits` 组织未做同口径统计 —— **未测**）。

### 规律 7｜可加性与两侧同构

- **陈述**：172 族 = 160 个网格族（64 mux + 64 BEG2/1 + 32 BEG6/4）+ 12 个非网格族（6 时钟/控制 + 6 长线），3,634 条 feature 全部可由这套定律解释；INT_L 与 INT_R 同构。
- **可执行形式**：`verify_all_pip.py --tile-type {INT_L,INT_R} [--normalize]` → 要求 `未覆盖=0 && 不符=0`
- **证据**：

```
INT_L           : 覆盖 3634/3634 = 100.0%  命中 3634/3634 = 100.0%  mux 1536/1536  beg 2098/2098  未覆盖 0
INT_R（归一化）: 覆盖 3634/3634 = 100.0%  命中 3634/3634 = 100.0%  未覆盖 0  家族 172/172
INT_R（未归一化，历史）: 覆盖 2312/3634 = 63.6%
```

- **同构的代价**：左右侧线名不对称（`IMUX_L40`↔`IMUX40`、`CLK_L0`↔`CLK0`、`GCLK_L_B0`↔`GCLK_B0_EAST`），必须归一化（去 `_L/_R`、数字前插 `_L`、`_EAST↔_WEST`），否则会误判成「右侧定律缺失」。
- **失效条件**：未归一化就跑 INT_R 会得到 63.6% 的假缺口；`VCC_WIRE` 常量输入（59 个族的模板扇入 25 而 law 记 24）若计入比对会多报 59 条不符。
