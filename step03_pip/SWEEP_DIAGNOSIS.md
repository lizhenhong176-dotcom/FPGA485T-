# 抽样回归失败点定位（S_8_161）

## 观察

`S_8_161` 的路由链（22 条 PIP）大部分是**长线/六方向线**家族：

```
NN6BEG0/LOGIC_OUTS_L12   LV_L0/NN6END0   LV_L18/LV_L0 ×4
NW6BEG1/LV_L9   NN6BEG1/NW6END1   NN6BEG1/NN6END1 ×8
NE6BEG1/NN6END1  NL1BEG0/NE6END1  NR1BEG0/NL1END0  IMUX_L8/NR1END0
```

观测到 21 帧、42 位，只有 4 位命中预测（都在帧 31680 的 LV_L0/NN6END0）。

## 结论（推翻上一轮的“band 映射错”）

1. **band 公式没错**：同一链里 `INT_L_X6Y10` 的 `NN6BEG0` 预测到 31683 附近，实测确实在 31680–31685，方向正确。
2. 真正的问题是：**长线家族（LV/LH/NN6/NW6/NE6…）的配置位不在本 tile 的 CLB 列块里**。
   - LV 位的落点在 **块列 4 / 块行 1**（帧 142–147），而 tile 是 X6 → 差了 2 列、6 个行带；
   - 另有部分落在块行 2（帧 5389–5475）。
3. 表里这些家族确实有（`pip_law._ALL` 共 228 个 sink 名，含 `LV_L0`、`LV_L18`、`NN6BEG1`），
   但表里的 `(offset, bit)` 是在 **Y11/Y21 的 CLB 列块**上测的，长线家族的块归属与之不同 —— 所以按
   `block_start(col) + offset` 预测必然打偏。

## 修正后的模型

```
地址 = f(家族, 块归属规则) + 形状项
```

- **CLB 列块规则**（IMUX / *_BEGn / FAN / VCC 等）：`block = (row 由 Y 决定, col 由 X 决定)`，offset ∈ 16..25 —— 已由 150/150、792/792 验证。
- **长线规则**（LV/LH/NNn/NWn/NEn…）：需要单独确定 block 的列/行归属。目前只确认了两点：
  - LV 位出现在**块列 4、块行 1**；
  - 长线可能有**多份副本**（同一设计里同一 PIP 同时在 31680 与 142 出现）。

## 下一步（最小实验）

1. 做一个**只含一条长线**的对照：net 从 `SLICE_X6Y10` 出发，只经 `NN6BEG1/NN6END1` 走到相邻 INT tile，不碰 LV/IMUX；
2. 逐 PIP 删除（不是全删），得到每个长线家族的**单独位集**；
3. 用这些位集反解长线家族的 block 列/行规则。

在此之前，`pip_law` 只对「CLB 列族」有效，`PIP_LAW.md` 需要写明这个适用范围。
