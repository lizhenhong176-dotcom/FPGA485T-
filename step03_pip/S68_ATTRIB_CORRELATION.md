# S68 · 8 个「点亮但无表」格子的归属尝试（源文件相关性统计）

日期：2026-11-11　脚本：`/opt/lzh/step18/attrib.py`　产物：`/opt/lzh/step18/attrib.json`

## 0. 方法

对 13,749 个 .bit 逐个判读 10 个目标坐标，再读同目录的 `.v/.sv`，统计关键词出现率；与「所有带源文件的设计」的基准率对比，看哪个 RTL 特征与置位强相关。

**重要限制【实测】**：13,749 个 bitstream 里**只有 1,234 个（9.0%）能找到同目录 .v**，且这些绝大多数是本项目的探针设计（`DONT_TOUCH` 基准率 **91.7%**）。因此相关性只在这个子集内成立，不能外推到"真实用户设计"。

## 1. 基准率（1,234 个带源文件的设计）

## 3. 判读（分四组）

1. **进位链组**：`(1,1,19)`（28×，样本 16）、`(0,0,20)`、`(0,1,20)` ⇒ **CARRY4 相关**。这是 S5 遗留的"CARRY4 CY0 家族未解"的补丁方向——`(1,1,19)` 只有 16 个设计点亮，正好符合"只有真的例化了 CARRY4 才写"。
2. **分布式 RAM/SRL 组**：`(0,1,8)`、`(1,0,27)` ⇒ 与 `LUT6_2` + `RAM64/128/256` + `SRLC32` 完全共现（样本小，2 和 1）。
3. **时钟组**：`(1,0,31)`（192 个）、`(0,1,31)`（40 个）⇒ 与 PLL/BUFG/BUFH 弱相关（2–3×），可能是"时钟网络进入该列"的使能。
4. **`(1,1,30)` 无解**：1,284 个设计点亮它，却与任何 RTL 特征**负相关**（BUFH 0.1%、MMCM 0.1%，远低于基准 17%/19%）。最可能是**本项目探针设计（单 LUT + 单 FF、DONT_TOUCH）的固定配置痕迹**，不是功能位。

## 4. 结论与下一步

- **可归属**：`(1,1,19)`+`(0,0,20)`+`(0,1,20)` → CARRY4；`(0,1,8)`+`(1,0,27)` → 分布式 RAM/SRL；`(1,0,31)`+`(0,1,31)` → 时钟网络。共 **7 个**。
- **不可归属**：`(1,1,30)`（1,284 次、无特征相关）——怀疑是探针设计共性，需用"非探针语料"复核。
- **方法学限制（必须记住）**：源文件覆盖率仅 9.0%，且高度偏斜到本项目探针。要得到可信归属，正确做法是**自己造定向设计**（CARRY4 ×3、分布式 RAM ×2、PLL/BUFG ×2，各在两处 LOC 做双位置交集），而不是继续在语料里找 .v。
