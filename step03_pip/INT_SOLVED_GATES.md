# 什么时候可以说"INT tile 的所有 PIP 都解决了"

> 器件：XC7VX485T-2FFG1761｜类型：INT_L / INT_R（各 26,550 实例）
> 标注：**【硬件事实】**器件结构｜**【数据事实】**本项目实测可复算｜**【推断】**解释性
> 复算入口见 §7；所有数字后括注来源

---

## §1 一句话答案

【数据事实】**现在就能说的**：在 INT_L/INT_R 上，3,629 条信号 PIP 的位坐标已实测到位、解码在 1,066 个实例上得到唯一解、3,552/3,634 条特征可由规则生成（97.7%）、其余 82 条查表可实现、全部外部扫描零反例。
【数据事实】**现在还不能说的**：①"tile 内 3,737 条 PIP 全部有交代"（差 64 条 VCC + 44 条直通未定性）；②"全部 PIP 由公式生成"（82 条是表）。这两条各需 0.5–1 人日与 2–3 人日。

⇒ **再补 2 个人日（G1+G2），就可以在"限定 INT_L/INT_R 类型"的前提下宣称"全部 PIP 已解决"。**

## §2 "解决"的四层定义（与关系，四层是"与"不是"或"）

| 层 | 判据 | 分母 | 达标线 |
|---|---|---|---|
| **L1 位坐标完备** | tile 内每一条 PIP 都知道它的配置位在哪，或能证明它没有配置位 | **3,737**（tile 内全部 PIP） | 3,737/3,737 有交代 |
| **L2 解码唯一** | 给定位流，能反推出唯一一组被配置的 PIP | 被扫到的活跃实例 | 全部唯一 + 与真值一致 |
| **L3 生成可复现** | 给任意 PIP 集合，能算出对应位流且位级相等 | 3,634 条 feature | 0 差异 |
| **L4 外部验证** | 独立来源（Vivado 真值 / 不变量 / 篡改实验）不产生反例 | 扫描到的实例与位 | 0 反例、误报可控 |

【数据事实】四层缺一不可：只满足 L1 是"有字典"，只满足 L3 是"会写不会读"，只满足 L4 是"抽样没出错"。用一层的成绩去掩盖另一层的缺口，是这类工作最常被审稿人打回的地方。

【数据事实】`law_cells` 3,634 与模板 3,629 的差是 5 条只在库里的长线 PIP（`LH0←LH12` 等）；模板多出的 108 条正是 64 VCC + 44 直通（`_q_cover_pairs.py`）。

## §4 五个闸门（按性价比排序）

### G1 把 108 条"特殊 PIP"定性 —— 关闭 L1

- **判据**：64 条 VCC 常量与 44 条直通，逐条给出"无配置位"的结构证据，或给出其位坐标。
- **现状**：未定性；只在文档里说"VCC 常量输入、直通"（【推断】级）。
- **缺口**：需要证明 `VCC_WIRE` 为目的 wire 的 PIP 在 `pip_defs` 里没有对应的可配置位（例如其 `delayIndex`/`inverted` 形态与其它 PIP 不同），以及 44 条扇入=1 的 PIP 只是布线拓扑、不占 CRAM。
- **成本**：**0.5–1 人日**，纯本地（读模板 + 跑一次 `law_cells` 反查）。
- **解锁**：可以说"tile 内 3,737 条 PIP 全部有交代"。
- **不做会变成什么错话**：一旦写"覆盖全部 PIP"，审稿人只要问一句"那 108 条在哪"，前面的 3,629 也会被怀疑是挑着报的。

### G2 用精确覆盖解码器重做真值对账 —— 关闭 L2/L4 的精度缺口

- **判据**：用 `p1_solvability.py` 的精确覆盖求解结果（而不是"每条 PIP 独立判全格置位"）作为解码输出，与 `pips_all.txt` 真值对比：召回与精确率都要给出。
- **现状**：召回 91.45%，多报 731 条——多报的来源是"两个 2 格长线候选的最后一格被别的 PIP 顺手点亮"，属解码判据问题，不是位表错误。
- **缺口**：把逐 PIP 判定换成集合覆盖后重跑一次对账。
- **成本**：**1–2 人日**，纯本地。
- **解锁**：可以同时说"解码唯一"与"与真值一致率高"；否则这两句在审稿人眼里互相矛盾（一个说唯一，一个说多报 731）。
- **不做会变成什么错话**："解码唯一"与"多报 731"并列出现，会被当成自我矛盾，而不是两个不同层面的现象。

### G3 82 条长线：闭合公式，或明确查表

- **判据**：要么给出可复算公式（判据：82/82 逐位 0 差异），要么在全文把口径写成"公式 97.7% + 查表 2.3%，合计 100% 可实现"。
- **现状**：已是"≤54 个格 + 82 条边"的表；两种候选规则（模板顺序、方向配对）已证伪。
- **成本**：闭合公式 **2–3 人日**（不确定能否成）；只改口径 **0.2 人日**。
- **解锁**：可以说"全部 PIP 由公式生成"（强宣称）或"全部可生成，其中 97.7% 有闭式"（稳宣称）。
- **不做会变成什么错话**：写"100% 公式化"，被问 82 条时无法回答。

### G4 跨瓦片类型补 1 类完整重建 —— 关闭"只在 INT 上成立"的质疑

- **判据**：对 `CLK_HROW_CK_MUX_OUT_*`（62 源）或另一类 48 源族，给出全源槽位重建 0 差异。
- **现状**：3/115 类型做过结构级（含 HCLK_CMT 11/11、CLK_HROW GCLK 19/32 公式）。
- **成本**：**2–3 人日**，需远端 Vivado（62 个受控位流）。
- **解锁**：可以说"该规律不限于 INT"。
- **不做会变成什么错话**：写"适用于 7 系列"，被问"其它类型呢"只能答"未测"。

### G5 把覆盖率的两个分母写进正文 —— 关闭表述风险

- **判据**：论文同时出现"类型 2/115"与"PIP 实例 95.75%"两个数字，并解释它们为何不矛盾。
- **成本**：**0.2 人日**（纯写作）。
- **不做会变成什么错话**：只写 95.75%，被问"你不是只做了两个类型吗"，会像在挑数字。

## §5 三种可直接使用的宣称原句

**① 现在就能用（不改任何数据）**
> 在 INT_L/INT_R 两个瓦片类型上，我们实测了 3,629 条信号 PIP 的位坐标，在 1,066 个实例上验证解码唯一，并以规则重建了 3,552/3,634 条特征的位模式（97.7%，剩余 82 条查表可实现），独立扫描约 2.3 万个实例零违例。

**② 补完 G1 后（+ 0.5–1 人日）**
> INT 瓦片内 3,737 条 PIP 全部有交代：3,629 条位坐标实测，64 条为 VCC 常量输入、44 条为固定直通，二者不占配置位。

**③ 补完 G1+G2 后（+ 2 人日，限定类型）**
> INT_L/INT_R 瓦片的 PIP 已解决：位坐标完备（3,737/3,737 有交代）、解码唯一并与 Vivado 真值一致、生成位流与独立构建逐位相等（50,176 帧全等）。

## §6 三种禁止使用的说法

| 禁止说法 | 为什么被打回（原话质疑） |
|---|---|
| "覆盖了 INT tile 的全部 PIP" | "3,737 里有 108 条（VCC/直通）你怎么处理？"——未定性时这句不成立 |
| "解码 100% 正确 / 全部可解" | "你多报了 731 条 PIP，怎么解释？"——多报属判据问题，但与"唯一"并列时会被当成矛盾 |
| "可生成任意位流" | "帧级校验字依赖帧地址，你的生成器能写出可加载位流吗？"——ECC 未闭合 |

（另：不要写"适用于 7 系列"，只能写"在同一器件另一类型上结构同形"。）

## §8 如果只能再做一件事

**用精确覆盖解码器对 `ref.bit` 重做一次真值对账，并在同一份脚本里把 64 条 VCC 与 44 条直通的"无位"证据一并打印出来。**
