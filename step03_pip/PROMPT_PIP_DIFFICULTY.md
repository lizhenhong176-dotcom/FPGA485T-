# 提示词：PIP 逆向的难题到底是什么

> 生成流程：`optimize-user-prompt`(user-prompt-professional) → `iterate-prompt`(iterate，8 条加固)
> 用途：让模型系统回答「PIP 逆向难在哪」，强制把难点分类（结构性不可观测 / 组合爆炸 / 数据缺失 / 证据不足 / 纯工程量），
> 并为每个环节给出「可判定的充分条件」，防止把苦劳清单伪装成技术难点。
> 配套数据：`all_cells.json`、`s13_pips.json`、`REUSE_RULES.md`、`S13_INT_GLOBAL.md`、`S10_INT_WALK.md`、`PIP_FAMILY_METHOD.md`

---

你是 FPGA 位流逆向的资深工程师与审稿人。请针对 xc7vx485tffg1157-3 项目，系统回答「PIP 逆向的难题到底是什么」，并把每个难点严格归入以下五类之一：结构性不可观测 / 组合爆炸 / 数据缺失 / 证据不足 / 纯工程量；禁止混类、禁止把工程量包装成原理困难或反之。

【术语统一（硬性）】以下术语初次出现时必须给出英文原词，之后全文一致使用；禁止混用「家族/族/组」等近义替换：
- family（家族；本文统一写作 family，不写「族」「组」）
- PIP（可编程互连点，Programmable Interconnect Point）
- tileconn（tile 连接表）
- IMUX（输入多路选择器）
- CRAM（配置存储器，Configuration RAM）

【背景事实（本项目实测，引用时必须与下列数字一致；给不出的写「未测」）】
- 位流：50,176 帧 × 101 字 × 32 位；CLB tile 占 36 帧，INT tile 占 28 帧（26 数据 + 2 overhead），单个 INT tile 位池 1,664 位。
- family（同一 tile_type 下目标 wire 相同的一组互斥 PIP）：INT_L/INT_R 共 172 family / 1,598 cell / 3,636 feature；同 family 3..18 个源共享 3..10 个 cell（均值 5.57 源/cell，最大 18）；cell→family 1,598/1,598 独占。
- 编码是分级 one-hot：20 源 → 4 组 × 5 成员 → 位宽 4+5=9（不是 ceil(log2 20)=5）；五类形状：(9,20) 96 family、(10,24) 64 family、(8,16) 6 family、(7,12) 4 family、(9,18) 2 family（单侧）。
- 编码位落在 tile 自帧的 offset 16..25（640 位全用）；行内字 = 2*(Y%50) + (Y%50>=25 ? 1 : 0) + parity。
- 从位流解码出 181 条 PIP、181 个 family、0 ambiguous；9 条网（6 输入 + 3 输出）求解共用 94..98/181。
- 走线：tileconn 提供类型级 (dx,dy) 与 wire_pairs；SW6 步进位置相关（-18,+4)/(-18,+5)/(-9,+4) 等多变体；IO 入口段在 INT_INTERFACE / 28 帧接口块，tileconn 中无 INT_INTERFACE 对。
- 已验证：6 条输入网与 Vivado ROUTE 真值 token 级 6/6 一致（含 IO 入口）；重综合位级对账单元配置 0 差异。

【必须回答的 8 个问题（每个环节均须给出「可判定的充分条件」）】
1. PIP 逆向的完整链条是什么？拆成可独立失败的环节：位池抽取 → family 归因 → 位集→源反解 → tileconn 落地 → 路径搜索 → 多网互斥 → IO 入口 → 引脚/端口命名。每个环节须写明输入、输出、失败症状，并额外给出该环节的「可判定的充分条件」：即在什么可观测的观测下该环节的输出是唯一的；缺这个充分条件即视为该环节未答完。
2. 每个环节的难点是什么？逐环节说明：难点是什么、为什么难、属于五类中的哪一类、失败时的可观测症状（缺症状视为空话）、以及该环节的「可判定的充分条件」是否满足（满足/未满足 + 观测说明）。
3. 哪些是「原理上不可判定」的？给出论证：必须明确区分两类并各给判别方法：
   - 真不可判定：存在两个不同配置产生完全相同的位（位级不可区分）；
   - 等价类：同一网络语义可由多条等价路径实现（语义等价但位不同）。
   必须举出至少 2 个你判断为不可判定的具体情形，逐一说明属于上述哪一类、判别方法是什么、为什么。
4. 哪些是「可判定但计算量大」的？给出规模估算：单个 tile 的搜索空间、全芯片 181 PIP 的约束规模、多网互斥的组合数上界，以及本项目实际耗时（解码 13.5 s / 求解 1.7 s）。
5. 数据缺失类难点有哪些？至少覆盖：IO 入口段（tileconn 缺 INT_INTERFACE 对）、跨时钟区域长线（LV/LVB）、位置相关步进变体、分支/环回（SW6 多变体）、clk/ce/rst 等控制网、BRAM/DSP/IO family 未测。每条须写明缺什么、影响哪一环、绕行办法、是否已绕行，并标注该缺失属于「外部资料缺失」还是「硬件结构不可达」（两者后果不同：前者可补资料/实验，后者原理上无法观测）。
6. 歧义与「错解但自洽」如何区分？给出判据：位集→源的四种结局（SOLVED / AMBIGUOUS / UNEXPLAINED / CONFLICT）各自的定义与检测方法；并说明为什么「0 ambiguous」不等于「不会错解」。
7. 五个「难点强度」实验：每个实验须能证明该难点真实存在（而非理论担忧），写明输入、执行方式（到步骤级）、判定阈值、所需工具（Vivado 版本 / Python / prjxray），以及「预期结果 A（难点存在）/ 预期结果 B（难点不存在）」，要求可二选一判定。至少包含：同 tile 双源位同置的非法帧、跨带长线取样、IO 入口缺失验证、多网互斥压力测试、跨 family 独占性抽检（BRAM/DSP/IO）。
8. 难题排序：按「阻塞下游的程度 × 解决成本」给出优先级表，并明确回答：当前项目已解决哪些（每个已解决项须附证据及该证据的边界，例如「0 ambiguous」只覆盖单 PIP 激活，不覆盖多网互斥或长线）、未解决哪些、下一个该攻哪个。

【已解决项的强制要求】凡声称「已解决」的难点，必须写明：用什么证据证明解决 + 该证据的覆盖边界（明确该证据不能证明什么）。

【输出结构（严格 9 段）】
⓪ 自检清单（8 项勾选，逐项打勾并简述依据）：五类标签齐全 / 每环节有失败症状 / 每环节有可判定充分条件 / 不可判定至少 2 例且分真不可判定与等价类 / 计算量给数字 / 数据缺失标外部或硬件 / 实验有 A/B 判定 / 反常识≥3 条 / 已解决项有证据边界。
① 一页结论（PIP 逆向的 3 个真难点，各一句话）
② 链条分解表（环节 / 输入 / 输出 / 失败症状 / 难度类别 / 可判定充分条件）
③ 逐环节难点详解（每环节 ≤120 字，必须写「属于哪类问题」并标注充分条件是否满足）
④ 不可判定性论证（≥2 个具体情形 + 论证；逐一标注真不可判定 / 等价类及判别方法）
⑤ 计算量估算表（环节 / 搜索空间 / 本项目实测耗时）
⑥ 数据缺失清单（缺什么 / 影响哪一环 / 绕行办法 / 是否已绕行 / 外部资料缺失 vs 硬件结构不可达）
⑦ 五个难点强度实验（可执行到步骤级，每个实验含预期结果 A / 预期结果 B 二选一判定）
⑧ 反常识检验（≥3 个「看起来难其实不难」的点，逐条说明为什么不难）
⑨ 难题优先级表 + 已解决（附证据与边界）/未解决/下一步

【纪律】
- 区分【硬件事实】【数据事实】【推断】；推断必须写明依据。
- 禁止用「通常/一般/业界共识」代替数字与机制。
- 每一条难点必须配「失败时的可观测症状」，否则视为空话。
- 每个环节必须给出「可判定的充分条件」，缺失即视为该环节未答完。
- 引用本项目数字时必须与上面给的数字一致；给不出的写「未测」。
- 术语初次出现给英文原词，之后一致使用，禁止混用「家族/族/组」。
