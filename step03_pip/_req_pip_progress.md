在上面这版提示词基础上迭代，必须满足这些硬要求（每条都要落进正文，不要只写在抬头）：

1) 三色标注：每个结论行必须标【硬件事实】/【数据事实】/【推断】之一；缺证据的一律写【未测】，禁止用「显然」「应该」补齐。
2) 复算命令：每条进度必须给出一条可直接执行的复算命令（脚本路径 + 参数）或一句可直接跑的 SQL；给不出就说明为什么给不出。
3) 进度的四态：已完成 / 部分完成（写清缺什么）/ 未开始 / 已作废，四态只能选一个，不许用「基本完成」这类模糊说法。
4) 已作废结论必须单列成表，三列 = 旧结论 / 作废依据（脚本或数据）/ 新结论；特别点名三类已知自纠：sense=1 与 sense=0 混算导致的口径假象、INT_L/INT_R 线名不对称导致的覆盖率误报、检测器未减基线导致的假检出。
5) 新颖性纪律：prjxray/artix7 移植来的位形状不得表述为自研发现，必须写清哪部分是移植、哪部分是本地新增（地址律、生成式压缩、闭环、可解性判定）。
6) 禁止「首次」「唯一」「完全」这类不可证声明；要写「在本器件、本模型口径下」并给出适用范围。
7) 新旧数字并存：同一指标若历史上有两版数字，必须同时给新旧与切换原因（例如覆盖率的 128 列 vs 154 列、tile 数 44,100 vs 53,100）。
8) 输出结构固定为六节，顺序不可调：一页结论（不超过 200 字）→ 进度表 → 已作废表 → 缺口账 → 风险与边界 → 下一步优先级；进度表列固定为：层 / 指标 / 数值 / 状态 / 证据（表或脚本）/ 复算命令。
9) 不许把「文件很多」「跑了很多实验」当工作量证据；只认可复算的数字。
10) 写盘纪律：如果产出超过 200 行，必须先写文件再摘要，不得在对话里整篇重排长文档。
