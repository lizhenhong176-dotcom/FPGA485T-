# S37 —— 用 7,987 个既有 bitstream 反推帧块结构（不跑 Vivado）

## 1. 数据规模
远端 `find /opt/lzh -name '*.bit'`：8,014 个 >15 MB 的完整 bitstream（含 27 个非 50,176×101 的变体）；**7,987 个成功解析**（大端、`FDRI burst=5,067,776` 自检）。总体积约 160 GB，扫描脚本 `/opt/lzh/step11/scan.py`（numpy 向量化，全量 ~3 分钟）。

产物：
- `E:\v7work\step11_cnt.npy`：长度 50,176 的 uint32，记录**每个帧被多少个 bitstream 写过非零内容**（word 0..49，排除 w50）。
- `E:\v7work\step11_cnt50.npy`：同上但只统计 word 50（帧校验字）。
- `E:\v7work\step11_summary.tsv`：7,987 行，每文件 `路径 / 非零帧数 / 首帧 / 末帧`。

## 3. 帧块清单封板（新表 `frame_blocks`）
用 `clb_blocks`（763 条实测 CLB 块）+ 块间 gap 反推，得到**每 band 恰好 5,180 帧**的完整块序列：

| band | 块数 | 尺寸签名 | 合计 |
|---|---|---|---|
| 0/3/4/6 | 150 | 111×36 + 35×28 + 2×30 + 2×72 | 5,180 |
| 1/2 | 144 | 105×36 + 35×28 + 1×30 + 2×72 + 1×246 | 5,180 |
| 5 | 149 | 110×36 + 35×28 + 1×30 + 2×72 + 1×36 | 5,180 |

全 die 汇总：**1,038 块 / 36,260 帧 = 7 × 5,180**（精确闭合，无残差）。
块类型统计：`clb` 763、`gap28` 245、`io72` 14、`edge30` 12、`pcie` 2、`x36` 2。

**占用验证**（有用例/无用例）：
| 类型 | 被动过 / 总数 |
|---|---|
| clb | **720 / 763** |
| gap28 | 236 / 245 |
| io72 | 14 / 14 |
| edge30 | 12 / 12 |
| pcie | 2 / 2 |
| x36 | 2 / 2 |

12,658 个非零帧里只有 **84 个**落在清单之外（0.66%），全部位于 band 之间的 66 帧 padding 或 fabric 之外，属预期。

## 4. tile → 块基址 的地面真值（新表 `tile_block_gt`）
4,467 个 bitstream 的兄弟文件里带**唯一** `SLICE_XnYm` 约束 ⇒ 100 个不重复 tile。用“该块 offsets 32..35（LUT INIT 区）是否被写过”投票：

- **45 个 tile 唯一命中**（每 tile 只有 1 个候选块得分），55 个无票（设计没用 LUT INIT 或落在 gap 块）。
- 一致性检验通过：**同一 X 列在不同 band 各命中一个块**，且块基址随 band 平移（X10 → band0 31716 / band3 5486 / band4 10732 / band5 26470 / band6 21224）。
- 相邻列验证：X8 → 31680、X10 → 31716，相差 36 帧 ⇒ 相邻 CLB 列各占一个独立 36 帧块。

## 5. 结论与价值
1. **帧块结构不再需要 Vivado 探测**：块清单、块尺寸、块类型、每 band 帧预算全部由既有 bitstream 反推并闭合到 36,260 帧。
2. **占用统计**给出“哪些块是任何设计都没碰过的”（43 个 CLB 块、9 个 gap28 块）——这些块上的 tile 目前**无任何实测证据**，是后续探针的优先目标。
3. **tile→块** 仍需逐列锚定：本轮拿到 45 个锚点，证明“一个 CLB 列 = 一个 36 帧块”的模型成立；要把 53,100 个 INT tile 全部填上，还需按列扩锚（每个 fabric 列 1 次即可）。
