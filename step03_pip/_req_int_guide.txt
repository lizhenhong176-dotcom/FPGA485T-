【任务】写一份「INT tile 实验完全指南」，读者是完全没接触过本项目的人（新同学 / 导师组的非本方向老师）。他要能看懂：术语是什么意思、实验流程怎么走、为什么每一步要这么做、以及最关键的一句——**这套东西到底覆盖了多少 PIP**。

【必须包含四块】
1. 术语详解：把「tile / site / wire / PIP / mux / family（族）/ CRAM / frame（帧）/ word / bit / frame_off / parity / FAR / band / col / region / row / 码字 / 一热编码 / 完全二分 / 双格边编码 / sense=1 / 列重 / word 50 ECC / 直通 PIP / VCC_WIRE 常量输入」逐个讲清。每个术语必须写四段：①一句话定义 ②在本项目里的具体取值或形态 ③一个真实数字例子 ④一个常见误解（错在哪）。
2. 实验流程：8 步，每步写「目的 / 具体做法（吃哪个文件、跑哪个脚本）/ 判据（什么算过）/ 产出 / 如果这步不做会怎样」。流程必须能让人照着复现。
3. 为什么这么做：至少 4 条硬理由，每条回答「有没有更简单的替代方案、为什么不用」。
4. **覆盖范围（本节最重要，必须给精确分子分母）**：
   - 第一层：一个 INT tile 内 3,737 条 PIP 如何分四类（有编码的 / VCC 常量 / 直通 / 表数据），每类给条数与占比；
   - 第二层：类型级覆盖（INT_L / INT_R 各 26,550 个实例共用同一张表，所以"类型覆盖 = 实例全覆盖"这句话要说清前提）；
   - 第三层：器件级覆盖（115 个 tile 类型里含 PIP 的 70 个、35,126 条 PIP，我只做了多少条、占比多少）。
   - 禁止写「全部覆盖」「所有 PIP」这类没有分母的句子；每句带分子/分母。

【写作纪律（硬规则）】
- 三色标注：【硬件事实】/【数据事实】/【推断】不得混写；拿不到数据写「未测」。
- 每个数字后面标注复算入口（脚本名或 SQL）或标「未测」。
- 术语必须先定义再使用，不得先用后定义。
- 覆盖范围一节必须回答「不是所有 PIP 都被建模」这个直接问题，先给结论句再给三层账。
- 排版：表格优先；每节 ≤80 行；总长 220–300 行。
- 面向读者写，不写内部黑话代号（如"§161"）作为唯一说明。
