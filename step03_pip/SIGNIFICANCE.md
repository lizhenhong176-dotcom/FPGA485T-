# 我现在做的这件事有什么意义（分层 + 反例 + 不能宣称的部分）

## 一、10 秒版与 30 秒版
**10 秒版**：这颗芯片没有公开的多路选择器位库，我们自己测了出来，并写成一张能反过来生成位流的常数表。

**30 秒版**：XC7VX485T 的布线小块（`INT_L` tile）里有 172 个"多选一"，3,634 条连接只占 1,598 个配置位。我们用受控差分实验测出"哪几个位决定选哪条线"，归纳成"地址 + 复用 + 编码"三件事；一张约 6×10² 个数的表重建 3,456/3,634 条连接（95.1%，`gen_slots.py`），与 Vivado 真实布线对账召回 1,155/1,263（91.45%，`tamper/ref/pips_all.txt`）。

**给三类读者各一句**

| 读者 | 一句话 |
|---|---|
| 不懂硬件的朋友 | 原本要靠人一个个试几周的位，现在能按表推出来。 |
| 做 FPGA 但不做逆向的同学 | 换一颗芯片、换一种 tile，这套差分流程照样能搬。 |
| 做安全的同行 | 单 bit 篡改 99.44% 能检出；整条 LUT 功能改动结构上检不出。 |

## 二、技术意义：填上"没有公开位库"这个空缺
【数据事实】prjxray 的 485T 导出里，`segbits_<类型>.db` 与 `mask_<类型>.db` 明确标注为 missing（`E:\v7work\db\prjxray\xc7vx485t\manifest.json`）——即这颗芯片的开关位库没有公开来源。

【数据事实】我们把 `INT_L`/`INT_R` 每个 tile 的 172 个多选一整理成三件事：**地址**（位在 `帧内偏移/奇偶/位号` 的哪个位置）、**复用**（一个位被哪几条连接共用）、**编码**（合法码只有 `{1,2,7,11}`）。据此一张约 6×10² 个数的常数表重建 **3,456/3,634 = 95.1%** 的连接，与实测逐位 0 差异（`gen_slots.py`）。

**如果没人做这件事**：这颗芯片上任何"读位流 / 改位流 / 查连线路由"的工作，都只能靠反复试错或依赖第三方闭源数据库。

**这条意义的反例**：若换一种 tile 类型做同样实验，0 差异率 **<50%**，则"规律"降级为"该类型的事实"。

## 三、方法意义：一套能带走的实验协议
【数据事实】位级差分协议包含五个必须项：固定位置 + 锁引脚、基线与负对照（不改也重跑，差值必须 0）、集合级反读自证（预测集与实测集必须完全相等，禁抽样）、先声明差分语义（PURE / XOR / FAM）、剔除校验字（每帧第 50 个字随数据重算）。

【推断】这套协议不依赖这颗芯片，也不依赖 INT 类型；它只要求"能生成两个位流 + 能读回连接清单"。我们自己的三次翻车（未锁引脚出三张表、把 XOR 当 PURE、漏 parity 导致两族共用）都是协议里的某一条被跳过造成的，反向说明这五条的必要性。

**如果没人做这件事**：每个团队都要重新踩一遍同样的坑，且踩坑后往往把错误当成发现（我们有两份报告因此作废）。

**这条意义的反例**：若在别的 tile 类型上，跳过"锁引脚"仍能得到稳定的单变量差分，则这条协议的必要性被削弱。

## 四、数据与工程意义：位是共用的，所以能压成表
【数据事实】3,634 条连接共用 **1,598** 个位；总位引用 8,900 次。于是 8,900 ÷ 3,634 = **每条连接平均 2.45 个位**，3,634 ÷ 1,598 = **每个位平均被 2.27 条连接共用**（`law_cells`，只计"必须为 1"的行）。

【数据事实】位库从 8,900 条逐条记录压成约 600 个数（约 2.27 倍）。**压掉的是存储形式，不是信息量**——解码时仍然必须做"组合判定"，因为一个位同时属于好几条连接。

【推断】"一个位不是私有位"直接决定两件下游事：①能不能生成位流（生成器必须保证所有被共用位一致，否则写出非法组合）；②篡改能不能被检出（共用位被改会同时破坏多条连接，反而更容易暴露）。

**如果没人做这件事**：位库只能以逐条列表存在，无法回答"改这个位会动到哪些连接"，也无法判断"哪些改动必然被发现"。

**这条意义的反例**：若统计出"绝大多数位只被 1 条连接使用"（即共用度接近 1），则压缩与组合解码的结论都不成立。

## 五、验证与安全意义（旁支）：能检出什么、检不出什么
【数据事实】单 bit 篡改检出 **1,624,720/1,633,808 = 99.44%**；漏检的 8,831 个（占空位 0.56%）全部是"2 位候选的最后一格"（`exhaustive_ref_154col.json`）。

【数据事实】整条 LUT 功能篡改**结构上完全检不出**：改 24 个 LUT 的 INIT 后重新生成位流，与原设计差 1,092 个位，但落在我们建模区的 **0** 个，945/945 个 tile 的连线集合完全相同、检测器 0 报警（`tamper/ref/tamper_init.bit`）。

【推断】所以"比特流一致性检测"的能力边界很清楚：它能抓**编码违规**（非法码、槽位冲突、未解释位），抓不到**语义合法但功能被换**的改动。这条边界是可写进论文的结论，但它属于旁支，不是主线。

**如果没人做这件事**：容易得出相反的错误结论——"能解位流就等于能验一致性"，而这在功能篡改面前是不成立的。

**这条意义的反例**：若存在某种功能篡改必然破坏编码合法性（例如所有 INIT 位都受某个不变量约束），则"检不出"这一结论失效。

## 六、不能宣称的部分
**不能宣称**：不是"首个 7 系列比特流逆向"。**要补什么才敢宣称**：无——已有公开工作覆盖同方向，这个说法本身不该用。

**不能宣称**：这套规律是"通用的"。**要补什么才敢宣称**：目前只做 2/115 种 tile 类型、单器件、跨器件 0/1（未测）；需在新器件与新类型上 0 差异率 ≥95%。

**不能宣称**：配方已闭合。**要补什么才敢宣称**：82 条长线连接（2.3%）没有公式只能查表，需给出可执行形式。

**不能宣称**：能生成可加载位流。**要补什么才敢宣称**：校验字与帧地址耦合未解（`ECC = L(data) ⊕ A(frame_addr)`，`A` 未定），需闭合后做上板验证。

## 七、下一步最值钱的一件事
**做 artix7 同任务对照**（在 prjxray 已覆盖的 artix7 同类 tile 上，跑同一套生成器）。

**为什么它比另外两件更值钱**：另外两件是"补 ECC 地址项"（5–7 人日，需硬件，只补闭环不补新颖性）和"补数据层 16,979,200 行"（4–6 人日，只影响覆盖不影响结论）。而这一件是三者中**能同时回答两个关键质疑**的那一个：①"你和 prjxray 是不是同一件事"（同任务对照直接给出可比数字）；②"你的规律能不能外推"（换个器件看 0 差异率）。它完全本地、不需要硬件。

**可执行判据**：2–3 人日；观察量 = 同一套生成器在 artix7 同类 tile 上的 0 差异率；**≥95% 算站住，50%–95% 算部分可迁移（需写明边界），<50% 算规律不外推**（此时把主张降级为"485T 上的一组事实"）。
