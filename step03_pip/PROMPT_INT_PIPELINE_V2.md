【任务】以数据流水线视角，完整说明「INT tile 的位复用规律是如何一步步被处理出来的」：从原始 20 MB 位流字节开始，经过九个阶段的连续变换，最终得到 600 个可复算数字。输出必须能让读者按阶段复现处理链路，而不是只看到结论。

【必须包含】
1. 九阶段流水线说明。每个阶段固定写六段，缺一不可：
   ① 输入：写清文件名/表名/字段名，并给出行数或记录数；
   ② 处理：写清所用算法和关键操作，并附不超过 15 行伪代码；
   ③ 输出：写清新表名/新字段名，并给出一条真实样例记录；
   ④ 判据：写清“什么算这一步通过”，判据必须是可检查的条件；
   ⑤ 真实数字：给出该阶段的实际统计值，并标注复算入口；
   ⑥ 失败分支：写清“这一步如果判错/跳过，错误会以什么具体形态出现”，例如某族位集合与另一族完全相同、列重全相等、二分失败、表结构异常、字段值异常或无法复算的具体现象，不能只写“结果不正确”。
2. 一条真实数据在九个阶段的形态变化表：选定同一根连接，逐阶段说明它在每个阶段的数据形态、所在表/字段、关键值变化。
3. 数据量演进表，必须覆盖以下链路并逐步给出压缩比：
   `20,273,538 B → 50,176 帧 × 101 word × 32 bit → 162,168,832 位 → 3,634 条连接 → 1,598 个格 → 8,900 条置位记录 → 600 个数字`
   表中每步写清：输入量、输出量、压缩比、复算入口（脚本名/表名）。
4. 表结构演进表：逐阶段列出表名 / 行数 / 关键列 / 由哪一步产生，至少覆盖 `law_tiles`、`far_bands`、`frame_map`、`law_cells`、`site_frames` 等表；行数必须与第 3 节数据量演进表一致，关键列需标明主键或连接键。
5. 关键判定算法必须写清可执行规则：
   - 列重怎么算：写清统计对象、统计口径、计算公式；
   - 二分怎么判（2-着色）：写清判定条件、冲突处理、通过/失败标准；
   - 码字怎么读：写清读取位置、位序、字段映射；
   - `frame_row=16+r` 怎么从数据中读出而不是假设：写清来源表/字段、推导步骤、校验方式。
6. 第 5 阶段（结构判定）必须给出三套判据的完整写法，每套均写清判定对象、计算公式、通过标准，并各配一个真实反例（写明反例所在表/字段、具体数值、为何失败）：
   - 一热槽位：每行置位数 ≤ 1；
   - 码字合法性：码字 ∈ {1,2,7,11}；
   - 完全性：K(m,n) 边数 = m×n。
7. 「压缩的代价」一节：写清 600 个数字能重建 8,900 条记录所依赖的 3 条前提，并逐条说明缺一条会导致什么具体重建失败（错误表结构、错误字段值、错误连接数、错误置位分布或无法复算的具体现象）。
8. 结尾「一张图能讲完的版本」：用文字流程图（不超过 12 行）把九阶段串起来，每行标明阶段名、输入→输出、关键判据。

【写作纪律（硬规则）】
- 全文使用三色标注：【硬件事实】/【数据事实】/【推断】；无数据支撑处写「未测」。
- 每个数字必须标注复算入口（脚本名/表名）；给不出复算入口时，必须降档标注并说明降档原因。
