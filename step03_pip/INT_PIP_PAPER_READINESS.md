# INT tile PIP 逆向：可发表性评估（按 `PROMPT_INT_PIP_PAPER_V2.md` 跑一次）

> 评估范围：仅 INT tile（INT_L / INT_R 各 26,550 实例）的 PIP 选择位规律、生成器、地址可复算。
> 数据来源：只取 `_req_int_pip_paper.txt` 给出的清单；清单外一律标「未测」。
> 标注：**【数据事实】**= 可复算数字；**【推断】**= 我的判断，附可推翻条件。

## ② 可发表性打分（0–5）

| 维度 | 分 | 扣分点 | 提高 1 分的最小补充证据 |
|---|---:|---|---|

## ③ 新颖性主张与公开工作逐条对照

先明确公开工作的形态：

- **【数据事实】** Project X-Ray / F4PGA 的 `segbits` 是**逐 PIP 枚举表**：每行一条 PIP 的置位/清位列表（`!` 前缀表示须为 0）。这是「查表」形态。
- **【数据事实】** 我自己的 prjxray 导出 `v7work/db/prjxray/xc7vx485t/manifest.json` 的 `missing` 里写着 `segbits_<T>.db (needs fuzz results)`：**vx485t 没有公开 segbits**。
- **【数据事实】** 存在一篇同主题论文 *Determining Confidence in FPGA Bitstream Reverse Engineering Results*（Williams, Collier），标题即指向「如何判断逆向结果可信」。（注：我只从检索结果拿到题名与作者，**未读正文**，不转述其结论。）
- 参考：[Project X-Ray 文档](https://github.com/f4pga/prjxray/blob/c9f02d8576042325425824647ab5555b1bc77833/docs/introduction.rst)、[segbits 格式](https://mithro-prjxray.readthedocs.io/en/latest/dev_database/common/segbits.html)、[该论文条目](https://par.nsf.gov/biblio/10536733-determining-confidence-fpga-bitstream-reverse-engineering-results)。

对照我的可主张点：

| # | 我的主张 | 与公开工作的关系 | 判定 |
|---|---|---|---|
| A1 | 172 族的位集可由「每族常数 + 16 条配置 + 4 行长线表 + 4 桶方向表」生成，对 3,456/3,634 = 95.1% 做到位级 0 差异 | segbits 是逐 PIP 枚举，无生成器 | **可能构成贡献**（形态差异）；可推翻：若有人已用生成式描述 7 系列 mux |
| A2 | 压缩比：3,634 条 feature 只落在 1,598 个位上（2.45 格/feature）；一对一编码需 3,634 位，实省 2.27× | segbits 不统计压缩比 | **可主张为工程贡献**，非科学发现 |
| A3 | 七种列重谱型覆盖 172/172；乘积结构 163/172 | 与 mux 结构本身等价 | **换形式**，单独不能主张 |
| A4 | 地址链 band→col→frame→word→bit 可复算 | FAR 语义在 prjxray 已有 | **换形式** |
| A5 | 独立验证：位流差分 1,536/1,536、线长律 5,832/5,832、解码 91.45% 真值一致 | Williams & Collier 已在做「可信度」问题 | **有贡献但需与他们对比**；不对比就是重复劳动 |
| A6 | 485T 无公开 segbits，本工作填了这个空 | 事实成立，但「填空白」是数据集价值，不是方法价值 | **可作为定位**，不能当主贡献 |

**【推断】最站得住的主张是 A1 + A5 的组合**：不是「我知道位在哪」，而是「我用一百来个常数把 95.1% 的位重算出来了，且 91.45% 与第三方真值一致」。

## ④ 审稿人最可能的三条杀招与应答

**杀招 1（事实类）**：「这套位库与 prjxray artix7 segbits 同构，你只是把它搬到了 485T 并换了个表述。」

- 应答【数据事实】：485T 无公开 segbits（manifest 的 missing 明写 needs fuzz results），因此「搬」这件事本身需要重新测。
- 应答【推断】：贡献不在位的位置，而在「用生成器替代枚举表后仍 0 差异」。
- **可推翻条件**：若审稿人给出 485T 的公开 segbits 全表，则本工作的数据贡献归零，只剩工程贡献。

**杀招 2（泛化类）**：「单器件、单 tile 类型（INT_L/INT_R），凭什么说这套规则有意义？」

- 应答【数据事实】：INT_L/INT_R 各 26,550 实例、两套规则完全对称；另有 96/96 BEG 与 64/64 mux 的 0 差异。
- 应答【推断】：对称性说明这是 fabric 层的结构而非个体巧合。
- **可推翻条件**：若在其他 tile 类型（如 CLK_HROW、HCLK_CMT）上同样方法给出 <50% 的 0 差异率，则「通用方法」不成立——目前 HCLK_CMT 只测了 13/48 源（未测全景）。

**杀招 3（循环论证类）**：「你的 0 差异是拿自己流水线产出的 `law_cells` 去验证自己生成的位集，属于自证。」

- 应答【数据事实】：至少有三条独立来源——① Vivado `get_pips` 真值（1,155/1,263 = 91.45%）；② 位流差分（1,536/1,536）；③ 线长律（5,832/5,832，来自 tileconn，不来自 law_cells）。
- 应答【推断】：三条来源都不经过 law_cells 的生成路径。
- **可推翻条件**：若真值一致率随设计规模上升而下降（即小设计上好、大设计上崩），则「独立验证」只覆盖了简单情形。

**摘要要点（按原文顺序，非逐字抄录长篇）**

1. 逆向工程（RE）在工程实践中普遍存在，对「发现数字硬件中的恶意功能」尤其相关。
2. 本文讨论 **FPGA 的 bitstream / firmware RE**：位流决定器件 fabric 的配置。
3. 「完整掌握物理 fabric + 完整掌握某个位流的解释」在原理上足以确定被烧写的 FPGA 的完整配置。
4. 但现实挑战是：关于 fabric 的信息、以及位流解释的信息，**通常是不完整的**。
5. 这些不确定性**限制了对 RE 结果正确性的置信度**。
6. 本文**识别（identifies）**FPGA 位流 RE 中的**代表性不确定性来源**。

**它做了什么 / 没做什么**

| 维度 | Williams & Collier 2023 | 本工作（INT PIP 线） |
|---|---|---|
| 论文性质 | 立场/框架短文（5 页会议）：给不确定性**分类** | 数据 + 规则 + 生成器 + 验证 |
| 是否给位级结果 | **没有**（摘要层面无任何位数/编码律/一致率） | 3,634 feature、1,598 位、95.1% 公式重建 |
| 是否给公开数据/工具 | **没有**（closed access、无 OA PDF） | 生成器 `gen_mux.py`/`gen_slots.py` + 位表 |
| 是否做真值比对 | **摘要未提**（正文未读，不做判断） | 91.45% 与 Vivado `.pips` 一致 |
| 与我的关系 | **上游**：定义「为什么 RE 结果不可全信」 | **下游**：给一个把不确定性压到可量化的实例 |

**【推断】不构成撞车，反而提供了引用锚点**：他们列不确定性来源，我的三档账（公式 95.1% / 表 20.3%→现 96 条 / 未解 82 条）+ 三条独立验证，正好是把其中若干来源**量化并消解**的一个样本。可推翻条件：若正文（未读）实际上已给出某种位级置信度计算方法，则我的 A5 主张需要重新定位为「实现与测量」，而非「方法」。

**写作上可直接用的一句定位（不含「首次」）**

> Williams 与 Collier 指出位流逆向的置信度受 fabric 信息与位流解释不完整的限制；本文给出 INT tile 区间内一个可量化的实例：172 个 mux 家族中 95.1% 的 feature 位集可由常数表与族序号生成并达到位级零差异，另 2.7% 靠组模型、2.3% 仍未解——剩余不确定性被显式列出，而非隐藏。
