## 二、实验思路链

格式：**要回答的问题 → 实验手段 → 输入（来源）→ 输出结论 → 排除了哪些替代解释 → 证伪条件 → 当前状态**

### 2.1 单点差分：改一个属性，位流里到底动哪几个 bit？
- 【数据事实】手段：固定 `LOC/BEL/LOCK_PINS` + 显式 `-part`，只改一个属性，Vivado 重建两次，位级 XOR 求差；同参重跑作负对照（差值必须 0）。
- 输入：来源「位流差分」（表一第 7 行）。
- 输出：每条 PIP 的置位格集合（如 `IMUX_L7 ← BYP_BOUNCE3` @ frame 31701 / word 23 / bit 25）。
- 排除：①优化器合并/删逻辑（用 `DONT_TOUCH`，但**不阻止常量传播**，故必须靠「只改一处」的受控设计）；②位平面法产生的假象（某位平面整体反相，已弃用）；③抽样误差（集合级 `missing=0 extra=0`，禁抽样）。
- 证伪：同参重跑差值 ≠ 0；或差分里出现无法归因的格 → 该次实验作废。
- 状态：**已验证**（集合自证 + 负对照全部通过）。

### 2.2 定位位池：这些格在 tile 的哪个位置？
- 【数据事实】手段：用 `law_tiles` 的 `(col, y)` 算 `band`、`start_frame`，再用 `word = 2*(y%50)+parity`（≥50 则 +1 跳过 word 50 的 ECC）把绝对帧号折算成 tile 内坐标 `(frame_off, word, bit)`。
- 输入：来源「帧地址表」「`frame_map`」（表一第 9、10 行）。
- 输出：mux 家族位池＝`frame_off 16..25` × 2 word × 32 bit = 1,664 位；BEG 家族在 `frame_off 6..15`。
- 排除：①绝对帧号漂移（跨 region 的列基址错开，已用 FAR 直解复核）；②word 50 混入（ECC 字，必须排除，否则差分里凭空多出「数据格」）。
- 证伪：归一化后同一家族在不同 tile 上落在不同 `(frame_off, word, bit)`。
- 状态：**已验证**（`ref.bit` 与 5 个探针位流全部自洽）。

### 2.3 列重统计：一个物理格被几个源共用？
- 【数据事实】手段：把「族 × 格」写成 0/1 矩阵 `A`，列重 `w(c)=Σ_f A[f,c]`；`Σw = 8,900`（= 全部置位记录数）。
- 输入：来源「位流差分」（`law_cells`，`sense=1`）。
- 输出：`w` 只有 8 个取值——`18→128`(8.0%)、`12→12`、`6→134`、`5→384`(24.0%)、`4→909`(56.9%)、`3→26`、`2→5`、`1→4`（按「族-格」对计 1,602 条，去重物理格 1,598 个，差 4 来自 3 个跨族格被多计）。**4–5 档占 1,293/1,602 = 80.7%**。
- 排除：「平均 5.57」被误当成常态——它只是一阶矩，实际是双峰（4/5 与 18）。
- 证伪：`Σw` 与 `law_cells` 行数不符，或列重出现非上述 8 个值之外的新值（说明有未被纳入的写入路径）。
- 状态：**已验证**。

### 2.4 结构判定：列重把格分成几类？
- 【数据事实】手段：按列重二分——最轻档格每源恰含 1 个（组选择位），其余为码字；再看是否「组 × 码」完全叉积。
- 输入：2.3 的 `A` 矩阵。
- 输出：**163/172 族**通过完全叉积检验，维度 `(6 组,4 源,4 码位)×64`、`(5,4,4)×96`、`(6,3,3)×2`、`(4,3,3)×1`；9 个例外全落在已知难族（6 个复合族 + 3 个长线族）。
- 排除：①「行/列」是我给的名字而非硅片事实——换叫「组轴/码轴」结论不变，唯一约束是 6 必配组轴、4 必配码轴；②先验直觉分类（分类依据是列重，不是命名）。
- 证伪：出现某族既满足完全叉积又与列重分类矛盾；或 6/4 两轴可互换却仍自洽。
- 状态：**已跑过 163/172**（分母＝172 族，来源 `law_cells` 两侧各 172）。

### 2.5 两轴归属：组轴和码轴分别由名字里的什么决定？
- 【数据事实】手段：对每组做线类/方向标记，检验 `组=f(方向)`、`码=f(线类)`。
- 输入：各族源线名（`law_cells.src_wire`）+ 2.4 的分组。
- 输出：mux 24 源族（64 个）——**组轴＝方向令牌**（每族 6 组，铺满 row 0..5）、**码轴＝线类**（`axis`/`diag` 占码对 {1,2}，`rlineL`/`rlineR` 占码对 {7,11}，对内标签逐族互换）；BEG 20 源族（96 个）——**组轴＝方向令牌 96/96**、**码轴＝几何类别 64/96 纯净**。
- 排除：①按线类直接分组（0/64，证明行不是由线类决定）；②按名字字典序/基名归类（已排除）；③布线邻接决定顺序（`law_cells` 键不含坐标，同类型 26,550 个 tile 共用一张表 → 不可能是几何决定的）。
- 证伪：某族的组不仅由方向决定（如两向混入同一组且无法用规则解释）。
- 状态：**已验证**（mux 6 轴 64/64、BEG 组轴 96/96）。

### 2.6 生成器重建：能不能只吃名字就把位集算出来？
- 【数据事实】手段：写 `gen_mux.py`（cell 级）与 `gen_slots.py`（槽位级），判据是无例外的 0 差异。
- 输入：2.5 的轴规则 + 族序号（`frame_row = 16+r`、`parity`、`primary` 逐族 3 个数字）。
- 输出：mux **64/64 族 0 差异**（3,072 条记录）；BEG **96/96**（其中 32 个变体族靠 4 个常数表 + 1 个方向位）；合计 **3,456/3,634 = 95.1%**。
- 排除：①「最小 bit 优先」确定 primary（错，会让 32 个 parity=1 的族判不符）；②「一类一码」（错，实际是码对 + 对内互换）。
- 证伪：任一族生成结果与 `law_cells` 差一位即作废。
- 状态：**已验证**（2026-11-11 更新：复合族组模型接入后 **3,552/3,634 = 97.7%**，其中定律 3,456 + 复合组模型 96；剩 82 条＝6 个长线族，已定性为逐族表数据，见 STATUS §161）。

### 2.7 反证：这套码字是真的唯一，还是只是我的解码器这么认为？
- 【数据事实】手段：①精确覆盖枚举（`p1_solvability.py`）——候选池限制为「全部格都在观测置位内的 feature」，穷尽所有能精确解释观测的子集；②篡改注入（单 bit 穷举、幽灵 PIP、整条删除、换源、word50、LUT INIT 真篡改）；③干净位流误报统计。
- 输入：2.6 的生成结果 + `tamper/ref/ref.bit` + `tamper/ref/tamper_init.bit`。
- 输出：**1,066 个含 mux 配置的 tile 全部唯一解**（0 多解）；单 bit 穷举 1,624,720/1,633,808 = **99.4438%** 可检出；幽灵 mux **0/300**、整条 PIP 添加 0/300、word50 0/300 检出；真实 LUT INIT 篡改（1,092 bit 全在建模区外）**0 检出**；干净位流误报 120/982 tile（12.22%）、240 个未解释位（白名单后 0）。
- 排除：①旧解码器的 `min-cells` 伪歧义（T6B 的「53 组多解」是解码器判据产物，不是信息论下界）；②检测器自身的基线 bug（曾漏减基线导致幽灵 mux 误报 100%，已修）；③被清掉的共享格造成「检出即定位到邻居」的错觉（定位精度须单独统计）。
- 证伪：出现「同一份位流、两种不同配置都合法」的实例 → 唯一性结论倒塌。
- 状态：**已验证**（可解性）；**已跑过**（篡改与误报，样本 300/982）。

### 2.8 迁移检验：这张表是这一个 tile 的，还是整个类型/整个器件的？
- 【数据事实】手段：①类型一致性（26,550 实例签名比对）；②跨 tile 真值（Vivado `get_pips` vs 解码）；③线长律外推（对 12,937 个 tile 检验线长→码位映射）；④跨类型（`INT_R` 命名归一化后重跑）。
- 输入：表一第 5、8 行 + 2.6 的规则。
- 输出：`INT_L`/`INT_R` 各 **172/172**、mux 1,536/1,536、beg 2,098/2,098；真值召回 **1,155/1,263 = 91.45%**；线长律 **5,832/5,832**；跨类型测试 2/115 类型。
- 排除：①`INT_R` 的 63.6% 缺口是**命名不对称**（`IMUX_L40` vs `IMUX40`、`GCLK_L_B0` vs `GCLK_B0_EAST`），归一化后消失；②「只覆盖一个 tile 的巧合」——26,550 实例共用一张表，若为巧合则应大量不匹配。
- 证伪：任一其他 tile 类型（如 `CLBLL_L`、`HCLK_CMT`）上同一套规则 0 差异率 <50%。
- 状态：跨 tile/跨类型 **已验证**（仅 INT 两种类型）；跨器件 **从未跑过**（0/1）。

## 三、复用规律（按四层）

### 3.1 位级：一个配置格平均承载几条 PIP？

【数据事实】**规律陈述**：复用发生在「格」这一级——1,598 个物理格承载 3,634 条 (family, src) 连接，8,900 条置位记录；每条连接平均 **2.45** 格，每个格平均被 **5.57** 族共用。

**可执行形式**：`Σ_c w(c) = 8,900`；`cells/feature = 8,900 / 3,634 = 2.449`；`features/cell = 8,900 / 1,598 = 5.570`。

**真实实例**：`IMUX_L40`（24 源）只占 **10** 个格（`frame_off 16..25`、`parity 0`、`bit = [6,6,7,7,6,6,6,6,6,6]`），24 条连接落在 10 个格上；`EE2BEG0`（20 源）占 **8** 个格（`frame_off 6..13`）。

**数字**：2,818 条 2 格连接 + 816 条 4 格连接 = 3,634（分子/分母 = 8,900/3,634；分母来源 `law_cells` `sense=1` 行数，单侧）。

**失效条件**：若某族出现「连接数 < 格数」或「格被 24 个以上族共用」，说明位池里混入了不属于该族的格（例如把 ECC 字或旁路标记位算进来）。

### 3.2 族级：一个 mux 家族的码字怎么排？

【数据事实】**规律陈述**：mux 家族 = 6 组 × 4 码 = 24 源，占 `frame_off 16..25` 的 10 个格；组选择位在 `frame_row = 16 + r`（r = 组号 0..5），列码位在 `frame 25−i`（i = 码位 0..3），合法码只有 `{1,2,7,11}`；BEG 家族 = 5 组 × 4 码 = 20 源，完全二分 `K(5,4)`，位池在 `frame_off 6..15`。

**可执行形式**：`rows = [r for r in (0,1,4,5) if M[16+r, w, b]] + [r for r in (2,3) if M[16+r, w, b^1]]`；`code = Σ_i M[25−i, w, b] << i`；不变量＝`len(rows) ≤ 1`、`rows ⇒ code ∈ {1,2,7,11}`、`code ≠ 0 ⇒ rows`。

**真实实例**：`BYP_ALT0`（`pair=6, parity=0, primary="S"`，`SW2END0→(row 0, code 1)`、`FAN_BOUNCE7→(row 5, code 11)`）；`EE2BEG0` 的 5 组＝`{EE2,EE4,L8,L12}`、`{SE2,SE6,EL1,L4}`、`{SS2,SS6,ER1,L0}`、`{NE2,NE6,NL1,L22}`、`{NN2,NN6,NR1,L18}`。

**数字**：槽位不变量在 231,656 个非平凡槽位上 **0 违例**（73,152 + 97,024 + 60,480，三个位流批次）；`frame_row = 16+r` **384/384 行格**；合法码 4 值、`(r, bit)` 192 组合各出现 2 次；BEG 二分 **96/96**（`K(5,4)` 64 族 + `K(4,5)` 32 族）。

**失效条件**：①出现第 5 个合法码（说明列码位不止 4 位）；②同族两个源共用全部格（说明组选择位不全）；③`len(rows) ≥ 2`（说明同一槽位被两条源同时占用，位的物理含义被误解）。

### 3.3 跨族：不同家族之间有没有共用格？

【数据事实】**规律陈述**：172 个家族基本不共享格——1,598 个格中只有 **3 个**被 2–3 个家族共用，且这 3 个在各自族里列重仅 1–2（长线族的边缘位，不是编码位）。

**可执行形式**：对格 `c` 统计 `|{f : A[f,c]=1}|`，分布应为 `{1: 1,595, 2: 2, 3: 1}`。

**真实实例**：`(1,0,6)` 同时出现在 `LH0` / `LV_L0` / `LV_L18`；`(0,0,2)` 在 `LH0` / `LV_L0`；`(0,0,9)` 在 `LV_L0` / `LV_L18`。

**数字**：3/1,598（分母＝去重物理格数，来源 `law_cells` 单侧）。

**失效条件**：若跨族共享格出现在高列重（≥4）的编码位上，则「族内独立编码」前提破裂，生成器必须在族之间联立求解。

### 3.4 跨 tile：同类型的 26,550 个实例是不是同一张表？

【数据事实】**规律陈述**：`INT_L` 26,550 个实例、`INT_R` 26,550 个实例共用**一张** 172 族表；地址由 `(col, y)` 决定，编码与实例无关。

**可执行形式**：`(tile_type, family, src_wire) → {(frame_off, parity, bit)}`，键不含坐标。

**真实实例**：`tamper/ref/ref.bit` 用了 982 个 active INT tile、解出 1,886 条 PIP；真值 `pips_all.txt` 里 1,263 条 INT PIP，解出 1,155 条（91.45%）。

**数字**：`INT_L` / `INT_R` 各 172/172、mux 1,536/1,536、beg 2,098/2,098；线长律 5,832/5,832 覆盖 12,937 个 tile（占 150,380 的 8.6%）。

**失效条件**：若某个实例的位池与表不符（例如列基址错开未处理），则该实例解码全错——这只能靠真值支路发现，不能靠自洽发现。

### 3.5 跨器件：换一颗芯片还成立吗？

【推断】**规律陈述**：**未测 0/1**。已知结构高度规整（7 类谱型覆盖 172/172），但另一颗 7 系列芯片（不同 die、不同型号）是否同构，没有实验。

**可测的做法**：①同家族（`xc7vx485t` 换封装/速度等级）——预期地址链常数变、编码不变；②同代不同 die（如 `xc7k325t`）——需重建 RapidWright 模板 + 重跑 2.1–2.6。

**判据**：在新器件上，`gen_slots.py` 的 0 差异率 ≥95% 视为编码律可迁移；<50% 视为不可迁移。

**失效条件**：只要出现一个家族的组/码维度不是 6×4 或 5×4，跨器件「同一套编码律」的说法即作废。
