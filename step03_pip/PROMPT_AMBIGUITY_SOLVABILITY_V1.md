请撰写一份可直接保存为中文技术评估文档的提示词，用于指导生成「可解性评估 + 现状盘点 + 最大阻碍定位」报告。该提示词面向 XC7VX485T 比特流逆向项目的实际场景：项目已从比特流中反推出 INT tile 互连 mux 的编码定律，现在需要判断「位流中读取的比特能否唯一反推出实际布了哪条 PIP」这一匹配问题是否可解、当前进展到哪一步、主要卡点在哪里。生成的提示词必须要求最终文档只回答以下三件事，并严格按顺序组织：

一、可解性判定。要求将「可解」拆分为至少三层分别判定：(a) 某个 mux 是否被启用，即该目的 wire 是否被驱动；(b) 该 mux 选择了哪一个源 wire；(c) 整条路径或整个设计的布线是否唯一还原。对每一层都必须给出：判定结论（仅限「可解 / 不可解 / 条件可解」三者之一）、支撑证据、以及若判定为「不可解」必须明确区分是信息论下界还是采样不足；凡无法提供构造性证据的，一律写「未证明」，禁止使用「理论上」等空泛表述。

二、现状盘点。要求用表格列出已经闭合的能力及每项能力的量化指标（包括命中率、覆盖率、样本量、复算命令），并明确标注每个数字来自哪张表或哪个脚本；凡结论仅由单侧 tile、单器件或单个真实设计支撑的，必须显式标注「泛化未验证」。

三、最大阻碍定位。要求从所有已知缺口中只选出「一个」最关键阻碍，说明其为何比其他缺口更关键，并给出依赖关系：不解决它，后续哪几件事都无法开展；同时给出三条互斥的推进路径，每条路径必须包含：做什么、预期产出、所需最低成本、失败后的后果。不得列出超过三条路径；不得把「需要更多数据」本身当作阻碍。

写作纪律要求：每条事实必须标注【硬件事实】/【数据事实】/【推断】三类之一，三类不得混写；【数据事实】必须附带表名或脚本路径；无实测支撑的内容写「未测」，禁止编造数字或使用模糊量化词；涉及「两个不同配置产生同一观测」的论断，必须给出可构造的一对配置（明确哪两条、哪些位相同、哪些位不同），无法给出则写「未构造」；文档开头用不超过 5 行结论先行给出三问答案，正文再展开。
