# 多源 mux 的配置位测量：我们的做法与自疑点（请您判断方法是否有问题）

## 一、三句话结论与本次请求
**做了什么**：把 7 系列 FPGA 里"多选一"的互连开关组（mux）按终点线归成 172 个，再用受控差分实验测出"哪个配置位选哪条源"，最后反过来用一张小常数表重建全部开关位。
**结论**：一张表（约 6×10² 个数）重建 3,456/3,634 条连接（95.1%）与实测逐位 0 差异（`gen_slots.py`）；与 Vivado 真实布线对账召回 1,155/1,263（91.45%，`tamper/ref/pips_all.txt`）。
**本次请求**：请您只判断一件事——**这套实验做法本身站不站得住**，尤其是第四节的差分控制与第五节的证据强度，是不是足以支撑"规律"这个词。

## 二、实验对象与要测的那个问题
一个 `INT_L` tile 有 600 条连线、3,737 个可编程连接点（PIP：两根线之间一个受配置位控制通断的开关）。把终点线相同的 PIP 归一组，得到 216 个"终点组"，其中 **172 组有多个候选源**——这 172 个就是多源 mux（`templates/INT_L.json`）。候选源数量分六档：24/20/18/16/12/10 源，分别 64/96/2/6/3/1 个（`law_cells`）。

要测的问题是：**给定一个 mux，哪几个配置位的取值决定"选哪条源"**。
例：`IMUX_L40` 有 24 条候选源，只占 **10 个配置位**（`law_cells`：`frame_off 16..25`、`parity 0`、`bit = [6,6,7,7,6,6,6,6,6,6]`）——24 条源压进 10 个位，靠"6 个组选择位（一热）+ 4 位列码，合法码只有 `{1,2,7,11}`"。这就是"复用"：全器件 3,634 条连接共用 1,598 个物理位，平均 2.45 个位/连接（`law_cells`，只计"必须为 1"的行；3,634 + 59 常量 + 44 直通 = 3,737）。

## 三、数据从哪来（两条链，缺一不可）
```
【图】谁和谁同属一个 mux
Vivado 器件库 data/parts/xilinx/virtex7/…                    （一次性）
  └─ RapidWright 编译 → xc7vx485t_db.dat（3.6 MB，缓存）      （一次性）
     └─ step1_topology.py export → templates/INT_L.json       （一次性）
        └─ 按终点线聚合 → 216 组 → 172 个多源 mux             （脚本，可随时重跑）

【码】哪个位选哪条源
同一个 routed.dcp 派生的 基线.bit / 变体.bit                  （每次一个变量）
  └─ 逐位相减、剔除 word 50（ECC 字）→ 三元组 (frame_off, parity, bit)
     └─ 与同一次构建的 .pips 对齐 → 位库表
```

关键点：**图只给候选源，码只给"这几位一起变了"**；两者用"同一次构建"的产物对齐，才有"某族某源 → 某几位"。

| 文件 | 谁产生 | 为什么非用不可 | 不用会怎样 |
|---|---|---|---|
| Vivado 器件库（`data/parts/xilinx/virtex7/…`） | Vivado 安装 | 硅片结构的唯一源头 | 无法命名任何线 |
| `xc7vx485t_db.dat`（3.6 MB） | RapidWright 由器件库生成并缓存 | 让结构可被程序遍历、可离线复算 | 只能手工点 GUI，无法复现 |
| `.xdc` | 我们写 | `LOC`/`BEL`/`LOCK_PINS` 固定除变量外的一切 | 引脚被 placer 重排（我们曾因此三次出三张表） |
| `.dcp`（routed） | 路由后 `write_checkpoint` | 所有变体的同一起点 | 差分混入布局噪声 |
| `.bit` | `write_bitstream` | 配置位的真实取值只在这里 | 没有测量对象 |
| `.pips`（`get_pips` 文本） | Vivado Tcl | 真值对账 | 只剩自己验自己 |
| `.rpt` / `vivado.log` | Vivado | 回读 `PART`/`SITE`/`BEL`、DRC | 默认 part 写错、LOCK 未生效都不报错 |
| `.fasm` | 第三方 | **未作主依据** | 它本身是逆向产物，用它当真是循环论证 |

## 四、一次差分实验的完整控制（七条）
| 控制 | 做法 | 不做会误判成什么 |
|---|---|---|
| 固定位置 | `LOC` + `BEL A6LUT` | 位置漂移，位差跨多帧，无法归因 |
| 锁引脚 | `LOCK_PINS {I0:A1 … I5:A6}` | 索引变成当次布局顺序 → 三次测量三张表 |
| 变体同源 | 同一 `routed.dcp`，只改一个属性 | 把综合/布局噪声当成配置位 |
| 基线与负对照 | 不改的构建重跑一次，差值必须 0 | 环境抖动被当成"发现新位" |
| 反读自证 | 未参与训练的值反读，预测集 vs 实测集必须 `missing=0` 且 `extra=0`（集合级，禁抽样） | 中几个就宣布成功 |
| 先声明差分语义 | PURE / XOR / FAM 三选一 | 把 XOR 当 PURE → 误判"形状随 CLB 类型变" |
| 剔除 ECC 字 | 位差里 `word == 50` 全部剔除 | 每个源凭空多 4–20 个"数据位" |

```tcl
open_checkpoint routed.dcp
set_property LOC SLICE_X11Y20 [get_cells u_lut]
set_property LOCK_PINS {I0:A1 I1:A2 I2:A3 I3:A4 I4:A5 I5:A6} [get_cells u_lut]
set_property INIT 64'h0000000000000001 [get_cells u_lut]
route_design -preserve ; write_bitstream -force v1.bit
puts "PART=[get_property PART [current_design]] SITE=[get_property LOC [get_cells u_lut]]"
```

## 六、我自己怀疑的六处（每条：怀疑 / 错了会表现成什么样 / 最小实验）
1. **怀疑**：一张表覆盖 26,550 个实例，可能只是"同一 die、同一型号"的产物，不是规律。**错了会表现**：换型号后 `mismatching_tiles` 从 0 变成非 0（`type_uniformity.json` 目前 115/115 全 uniform）。**最小实验**：换 `ffg1157-3` 版跑 1 个 tile 的 20 个源。
2. **怀疑**：95.1% 里有一部分来自"生成器和验证共用同一张开局表"，不是独立验证。**错了会表现**：改用真值 `.pips` 反推族再重建，0 差异率从 95.1% 掉到 80% 以下。**最小实验**：只用 `pips_all.txt` 反推，不看 `law_cells`。
3. **怀疑**：91.45% 的召回率不足以说"位库可用"。**错了会表现**：108 条漏解集中在 7 个 tile，若它们全是"列 ≥128"或"源数 24"的特例，则覆盖率有偏。**最小实验**：按列号与源数对漏解分层统计。
4. **怀疑**：`route_design -preserve` 未必真"不动布线"。**错了会表现**：位差里出现布线位（应只在 INIT 区）。**最小实验**：同一 DCP 连跑两次 `-preserve` 不改属性，差分必须 0。
5. **怀疑**：6 组 × 4 码可能只是众多合法划分中的一种（我们按列重切，存在事后拟合空间）。**错了会表现**：换一个列重阈值也得到完美乘积结构，且同样"163/172 通过"。**最小实验**：随机划分对照，看是否只有当前划分给出 163/172。
6. **怀疑**：12.22% 误报被白名单"解释掉"属于事后拟合。**错了会表现**：换一个新设计，白名单外的位也会出现（`--fpstats`：120/982 tile 报警，白名单后 0）。**最小实验**：第二个不参与标定的真实设计测误报。

**等价性风险（必须点明）**：prjxray 的 segbits 同样是"逐 PIP 枚举"的产物。我们与它的差别如果只在**形式**（常数表 + 生成式 vs 逐条列表），而不是**信息量**（我们有真值召回、全器件 0 表外位、端到端帧级复现），那么"生成式"这一主张就应降级为工程整理，而不是发现。

## 七、请您判断的 6 个问题
1. 从同一个 routed DCP 派生、只改一个 `INIT`，是否足以排除综合与布局层面的噪声？（对应第四节）
2. 用 1,155/1,263 = 91.45% 的真值召回，支撑"位库可用"是否过强？需要多高才够？（对应第五节）
3. 12.22% 的误报用两格已知标记位白名单消掉，是否构成事后拟合？应当如何处理才算诚实？（对应第六节第 6 条）
4. 95.1% 的 0 差异中，多大比例要靠"同一张开局表"才成立？要什么独立输入才能称为独立验证？（对应第六节第 2 条）
5. 只做 2/115 种 tile 类型、单器件，这批证据应当被叫作"规律"还是只能叫"该器件上的一组事实"？（对应第五节末行）
6. 与 prjxray 的差别是形式还是信息量？如果只是形式，它还够不够作为研究贡献？（对应第六节末段）

## 八、如果这套做法有问题，最可能是什么问题
| # | 最可能的错法 | 判别实验（做法 → 观察量 → 阈值） |
|---|---|---|
| 1 | **把结构当规律**：只在 INT 上成立，却被说成通用 | 换一种含 mux 的 tile 类型（如 `HCLK_CMT`，42 族）→ 20 个源的 0 差异率 → **<50% 判否** |
| 2 | **把同源验证当独立验证** | 只用 `pips_all.txt` 反推族与槽位，不看 `law_cells` → 重建 0 差异率 → **<80% 判"未独立验证"** |
| 3 | **事后拟合**：白名单、列重阈值、开集划分都可调 | 第二个未参与标定的真实设计 → 不新增白名单项时的误报 tile 率 → **>5% 判不可用** |
