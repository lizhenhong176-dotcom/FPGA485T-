# REVIEW REQUEST V5 — frame_map import (post v4-review fixes)

## What changed since V4

All four gaps from `CODEX_FRAME_MAP_VERDICT_V4.md` are addressed:

**Gap 1 (auditable expected-run table / reproducible generator)**
- New artifact `data/expected_runs.csv`: the EXACT per-run table with
  1,183 entries (`run_id,start_frame_index,length,row,block_addr,block_type`),
  generated by `data/DumpExpectedRuns.java` (checked in) directly from the
  RapidWright 2026.1.0 `ConfigArray` enumeration of xc7vx485t (device data
  `xc7vx485t_db.dat`, md5-checked by RapidWright).
- Reproducibility of the chain is documented in `data/FRAME_INDEX_MAP.md`:
  a fresh `DumpFrameIndex` run re-emits `frame_index_far.csv` byte-identical
  (sha256 `77A4655FB8C3...`), and `DumpExpectedRuns` enumerates the same
  ConfigArray.
- `import_frame_map.py` (v5) check 15 now compares EVERY run's
  (start_frame_index, length, block_addr, row, block_type) against this
  exact table — not just aggregates.
- New negative test **T5** proves the exact table catches what aggregates
  cannot: a whole-run RELOCATION to a valid unused 0x80-aligned region of
  the same FAR block type (shift block_addr and all fars consistently —
  passes alignment, continuity, region uniqueness, FAR uniqueness, run
  count, length multiset, per-row counts) is rejected ONLY by the
  expected-run match. See `v5_selftest_log.txt`.

**Gap 2/3 (fingerprint coverage)**
- `db_fingerprint()` v5 returns a 7-field fingerprint:
  (a) row counts of ALL tables; (b) hash of the COMPLETE sqlite_master
  object dump (type/name/tbl_name/rootpage/sql — every table, index, view,
  trigger); (c) sha256 over all 50,176 frame_map rows; (d) journal mode;
  (e) WAL/SHM sidecar presence+size; (f) sha256 of the ENTIRE main DB file
  (639,430,656 bytes — covers the byte representation of every table's
  contents, including the 5.49M-row site_pins, and all schema objects);
  (g) file size. T1/T2 compare full equality before/after.

**Gap 3 (5.19 partition)**
- 5.19 now explicitly asserts the 14 row intervals are adjacent AND
  partition exactly [0, 50175] (starts[0]==0, ends[-1]==50175,
  starts[k]==ends[k-1]+1), not implied by global index/count checks.

**Gap 4 (migration executable from bundle)**
- New negative test **T6**: builds a disposable OLD v1-schema DB
  (unconstrained, no row_number/block_addr), runs the checked-in
  `data/migrate_frame_map_checks.sql` on it, then re-imports with
  `data/import_frame_map_v5.py`; verifies post-migration empty table,
  re-import commits 50,176 rows, row_number/block_addr columns present,
  CHECK constraints present in migrated DDL. All inside a temp dir.
- Migration SQL header updated with bundle-relative usage
  (`python data/import_frame_map_v5.py ...`).
