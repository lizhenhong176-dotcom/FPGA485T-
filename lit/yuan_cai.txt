                         摘 要




                       摘       要

  随着现场可编程逻辑门阵列（Field Programmable Gate Array, FPGA）逐步应用
于军事、基础设施等重要领域中，其面临的安全威胁日益严峻。特别是在大国对抗
中，FPGA 作为各类武器装备的核心器件，一旦被硬件木马等手段攻击，将导致十
分严重的后果。而目前针对硬件木马的防护手段主要集中于电路设计的较高层级，
如网表级或代码级。然而，在不破坏芯片的前提下获取电路设计源代码是难以实现
的，但提取比特流文件则相对容易。因此，有研究者提出了完整的比特流逆向框架，
实现了从比特流文件到网表文件再到代码文件的逆向，但其目前支持的芯片型号
较少，且不支持硬核资源的逆向。针对上述情况，本文在现有比特流逆向框架下，
提出了基于命令行和 Tcl 的映射关系数据库测量方法和针对硬核资源的代码逆向
方法，前者主要应用于 Altera FPGA 芯片的网表逆向过程，提高映射关系数据库的
测量效率和数据完整度；后者主要应用于 Xilinx FPGA 芯片的代码逆向过程，为可
扩展的代码逆向框架增加了逆向硬核资源的功能。本文的主要研究工作如下：
 （1）提出了基于命令行和 Tcl 的映射关系数据库测量方法。首先阐述了当前
FPGA 网表逆向技术的三个基础，包括配置文件、网表文件和映射关系数据库等，
和现有的映射关系数据库测量方法以及 Quartus II 软件内的可执行命令行程序和
Tcl 脚本的使用方式。然后提出了改进的数据库测量方法，该方法针对现有数据库
测量方法主要由人工操作，用时较长、效率较低的缺点，采用可执行命令行程序和
Tcl 脚本相结合的方式，来自动化运行整个测量过程，提高了数据库测量效率与数
据完整度。最后采用了在网表逆向平台中，依次载入根据本文方法和现有方法所测
量出的映射关系数据库，并逆向 ISCAS’85 基准组合电路集和 ISCAS’89 基准时序
电路集中部分电路的方法，验证了按照本文方法测量出的数据库数据的正确性。
 （2）提出了针对硬核资源的代码逆向方法。首先介绍了现有的可扩展的代码逆
向框架，以及包括分布式 RAM 和移位寄存器 SRL 在内的硬核资源的底层硬件结
构。然后讨论并选择了以原语的方式逆向硬核资源，并分种类详细阐述了该逆向方
法的流程。最后，使用扩展了硬核资源逆向功能的代码逆向平台，对 Xilinx 官方提
供的硬核资源示例程序进行了逆向，验证了该逆向方法的正确性与实用性，拓宽了
代码逆向平台的应用范围。另外，还简单介绍了代码逆向技术的一项应用，即实现
FPGA 网表与 ASIC 网表的相互转换。

关键词：FPGA，逆向工程，比特流文件，硬核资源，硬件安全

                                     ABSTRACT

     As Field Programmable Gate Array (FPGA) is gradually applied in military,
infrastructure and other important fields, it is facing increasingly serious security threats.
Especially in the great power confrontation, FPGA as the core device of all kinds of
weapons and equipment, once attacked by hardware Trojan and other means, will lead to
very serious consequences. At present, the protection measures against hardware Trojan
mainly focus on the higher level of circuit design, such as netlist level or code level.
However, it is difficult to obtain circuit design source code without destroying the chip,
but it is relatively easy to extract bitstream files. Therefore, some researchers have
proposed a complete bitstream reverse framework, which can reverse from bitstream files
to netlist files and then to code files. However, it currently supports fewer chip models
and does not support reverse of core resources. In view of the above situation, this thesis
proposes a mapping relational database measurement method based on command line and
Tcl and a code reverse method for hardcore resources under the existing bitstream reverse
framework. The former is mainly applied to the netlist reverse process of Altera FPGA
chip to improve the measurement efficiency and data integrity of mapping relational
database. The latter is mainly applied to the code reverse process of Xilinx FPGA chip,
which adds the function of reverse core resource to the extensible code reverse framework.
The main research work of this thesis is as follows:
     (1) A mapping relational database measurement method based on command line and
Tcl is proposed. Firstly, it introduces the three cornerstones of the reverse technology of
FPGA netlist, including configuration file, netlist file and mapping relational database,
and the existing measurement method of mapping relational database as well as the use
of executable command line program and Tcl script in Quartus II software. In view of the
existing database measurement method is mainly composed by manual operation, and has
the shortcomings of low efficiency and time-sonsuming, the modified measurement
method is proposed to run the whole measurement process automation using command
line executable programs and combination of Tcl script, and to improve the efficiency of
database measurement and data integrity. Finally, by loading the mapping relational
database measured by the proposed method and the existing method into the reverse
platform of netlist, and reversing the ISCAS '85 benchmark of combined circuit set and

ISCAS' 89 benchmark of sequential circuit set, the correctness of the database measured
by the proposed method is verified.
     (2) A code reverse method of the hardcore resources is proposed. The existing
extensible code reverse framework and the underlying hardware architecture of hardcore
resources including distributed RAM and shift register SRL are introduced. Then we
discuss and choose to reverse hardcore in a primitive way, and expatiate the process of
reverse method in detail. Finally, the hardcore code example provided by Xilinx is
reversed by the code reverse platform which extends the hardcore reverse function. The
correctness and practicability of the reverse method are verified and the application scope
of the code reverse platform is broadened. In addition, an application of code reverse
technology is briefly introduced, that is, the conversion between FPGA and ASIC netlist.

1.1 研究背景与研究意义
   很长一段时间以来，硬件系统都被认为是可以信赖的，一直作为计算机的最底
层资源，运行软件层指令。因此，与硬件相关的安全研究主要是加密算法的硬件实
现[1]和硬件版权保护问题，其中前者指使用硬件来提高加密应用的计算性能和效率。
但研究人员一直没有注意到硬件本身的安全问题。
   随着片上网络（System On Chip, SOC）平台设计复杂性的增加和芯片制造成
本的增加，集成电路（Integrated circuit, IC）供应链逐渐扩展到全球。在这种趋势
下，诸如第三方软/硬 IP 核等硬件电路第三方资源被普遍应用在电路设计与制造过
程中。这些第三方资源在很大程度上提高了设计效率，降低了设计成本，并缩短了
上市时间。然而，这样的应用也带来了极大的安全问题，例如在芯片代工过程中植
入硬件木马，或者在 IP 核内制造设计缺陷或恶意逻辑等[2]。
   于是，为了解决上述问题，研究者提出了硬件安全的概念。硬件安全最初单指
硬件木马的设计、分类、检测和隔离，而芯片代工过程是硬件木马发生率最高的环
节。因此，大部分硬件木马检测方法集中芯片制造阶段，强调对现有测试方法的增
强[3,4]。另外，由于第三方 IP 核也极有可能是恶意逻辑载体，所以在设计阶段对硬
件进行保护也同等重要，因此研究人员发展出了硬件设计保护方法[5,6]。
   除了硬件木马检测，硬件安全的概念已经从测试解决方案扩展到形式化验证
方法。形式化验证方法不仅在软件安全领域被广泛使用，在硬件安全领域也被证明
是有效的[7,8]。该方法有助于在攻击者能够访问原始设计时为硬件设计提供高级安
全保证，同时可以解除其他硬件木马检测方法中对黄金模型的需求。
   近年来，硬件安全研究已经从单纯的硬件木马检测转向了可信赖硬件的开发。
一个最突出的例子是开发物理不可克隆功能 [9] （Physical-Unclonable Functions,
PUFs），即利用芯片生产过程中的各种变化形成指纹，代表芯片的唯一身份。另外，
研究人员还在开发除 MOSFET 外的新型晶体管，如自旋转移扭矩（Spin-Transfer
Torque, STT）器件和忆阻器[10]等，利用其特殊性能保障硬件安全。
   综上所述，硬件安全问题虽然日益严重，但研究人员已经开发了大量有效的应
对方法。而在国防安全领域，硬件安全问题作为现代战争第五战场的关键，对现代
化战争的胜负起了决定性作用。因此，如何通过使用上述方法，分析武器装备硬件
中存在的安全漏洞和硬件木马等问题，成为亟待研究的课题。鉴于当前绝大部分硬
件安全分析防护手段都应用在电路设计的较高层级，并且需要分析的硬件设备都

是组装并调试好的成品，无法直接从其硬件系统中得到网表文件或者代码文件，而
只能通过某些方法得到其比特流配置文件，研究如何从比特流信息中得到网表信
息和代码信息则成了解决问题的关键。
   基于上述原因，本文将分别以 Altera 和 Xilinx 公司生产的 FPGA 为目标，研
究 FPGA 大规模比特流逆向关键技术，实现对网表逆向时所必须使用的数据库的

向的效率、准确度和覆盖范围。


1.2 国内外研究现状
1.2.1 逆向工程研究现状
   逆向工程是一把双刃剑，根据使用者意图的不同，其意义也完全相反。从积极
意义上来说，逆向工程可以用在国防安全领域，对涉密硬件设备的逻辑漏洞和恶意
逻辑进行检测分析，确保自身安全。而从消极意义上来说，逆向工程可以在对方不
知情的情况下，获得硬件设计相关内容，偷窃他人劳动成果，侵犯他人知识产权。
作为科研人员，应当为实现积极意义而进行相关研究，不能有消极的想法。对逆向
工程而言，包括了 ASIC 和 FPGA 逆向两大类。

1.2.1.1 ASIC 逆向工程

   目前主流的 ASIC 逆向方法共有四大类。第一类是通过暴力破坏的方式将芯片
全部打开，观察其内部组成结构和位置排列等信息；第二类是将芯片所存储的电路
参数、连线、功耗等信息综合起来，统一分析；第三类是通过收集包括芯片生产全
过程的信息，来判断其组成；第四类是通过专业手段剥离芯片封装，再通过专业设
备观察其底层硬件使用情况，从而得到电路图[11]。
   S. E. Quadir 等人在文献[12]中，仔细阐述了 ASIC 逆向总体流程：外包装去
除、切片、显影和电路还原。流程的第三步切片会对芯片造成不可逆的破坏，需要
使用特殊装置进行操作，且其操作方法十分复杂，需要耗费大量时间。而利用 X 射
线断层显像技术则可以在芯片保持完整的情况下，扫描其内部所有层次结构，并且
得到其图像[13]。
   对网表进行逆向的含义是将 ASIC 电路的门级网表，还原为对应硬件描述。早
在 1985 年，M. Ohlrich 等人就可以通过子图同构算法高效还原电路结构，所使用
的器件基本不变[14]。到了 1997 年，S.T. Eckmann 等人完成了将部分网表转换为功
能等效的 RTL 代码的工作[15]。并且以此为指引，G. H. Chisholm 等人于 1999 年实
现了用 RTL 代码来表述完整网表的功能，具体方法为将一个复杂网表拆分成多个

                          2
                          第一章 绪论


简单网表，然后根据前文方法得到简单网表的 RTL 代码，再将他们结合起来[16]。
紧接着，M. C. Hansen 等人便实现了用 RTL 代码表述 ISCAS’85 基准电路的网表
文件的功能[17]。
    在接下来的几年时间中，研究人员不断对硬件安全问题进行研究。DARPA 公
布了一项名为 IRIS 的计划，旨在解决硬件安全问题，主要方法为重新配置网表结
构，并将其运用在安全验证中。受此影响，网表逆向算法大量出现。
    2012 年，W. Li 等人提出了组件模式比对方法。具体操作为：首先提取组件库
中组件，针对其特性生成对应模式图，然后总结出待逆网表的模式图，再将两者进
行仔细比对，以此来匹配待逆网表所使用的组件及其连接关系[18]。
    2013 年，P. Subramanyan 等人提出了一个算法，用来将诸如加法器和寄存器
等功能简单的逻辑模块从待逆网表中提取出来，并将其转换为 RTL 代码[19]，之后
在文献[20]中，他们减少了算法复杂度，并且处理能力达到百万门级。同年，W. Li
等人提出了用字级结构替代组件模式图的方法，该方法精简了 RTL 语言表述，加
深了数据通路运行轨迹[21]。
    网表逆向的形式不止是将网表逆向为 RTL 代码这一种，也包含有限状态机
（Finite State Machine, FSM）模式。K. S. McElvain 的研究结果表明，直接将 FSM
自动化地从底层电路中总结出来是可行的[22]。之后，L. Yuan 等人将该算法进行了
优化，成功从底层电路逻辑资源中提取出了 FSM，虽然其与原电路 FSM 的布局布
线结构不同，但他们在功能上是等效的，并且该方法功耗更低，占用面积更小 23。
2008 年，Y. Shi 等人创造性的使用了两级 FSM 分离技术，成功去掉了电路中多余
的状态寄存器，使得算法更为高效[24]。
    在此基础上，T. Meade 等人设计了一个网表逆向工具，并将其命名为 REFSM，
其功能为从 FSM 中提取状态转移函数。该工具集成了 3-SAT 运算器，无论电路网
表是简单还是复杂，都能进行逆向[25]。之后，他们成功升级了该工具，并重命名为
REILC，为该工具添加了根据结构判断寄存器具体种类的功能[26]。将以上两个工具
结合在一起，就可以实现一个综合的网表逆向工具集[27]。

1.2.1.2 FPGA 逆向工程

    FPGA 逆向工程可按照流程划分为两个阶段，分别是网表逆向和代码逆向。对
于网表逆向而言，有一个 Xilinx 官方工具为其提供了新的解决思路，该工具就是
重配置工具 JBits[28]。该工具最大的功能，就是可以无视源代码，直接对芯片的底
层硬件资源和布局布线信息进行修改。其实现方式为：在映射关系数据库的辅助下，
直接修改配置文件中的比特位，其对应的资源也会发生改变。该数据库并未向用户

                    电子科技大学硕士学位论文


开放，并且早已不再更新，但却可以使用在网表逆向过程中，只要研究人员继续测
量该数据库即可。另外，还有一个名为 JRoute[29]的工具与其类似，存放了 FPGA 的
底层连线资源。
   基于上述方案，2006 年，D. Ziener 等人首次实现了配置文件元件分离[30]。该
方法是在他们经过大量实验，搞清了 Xilinx Virtex-II 和 Virtex-II Pro FPGA 配置文
件格式后提出，可以从配置文件中分离出 LUT 的数据。
   而网表逆向的第一个实用工具名为 Debit[31]。该工具的使用原理反映了 XDL
网表文件和比特流文件之间存在某种映射关系。作为逆向配置文件的第一次尝试，
虽然无法进行完整正确的逆向，但是它的出现为后续研究指明了方向。
   之后，J. Note 等人在文献[32]中详细分析了 Xilinx FPGA 配置文件的格式，然
后大胆提出了一些关于网表逆向的假设，阐述了配置文件中比特位与底层逻辑资
源可配置项的映射关系，构建出了基本的映射关系数据库。
   FAT[33]以图形化界面的方式，提供了对 FPGA 底层电路设计的分析方法。通过
使用该工具，也可以一点一点测量出映射数据库，但是效率极低，只能在某些小型
的器件上使用。
   同样基于文献[32]中的假设，F. Benz 等人仔细分析了 XDLRC 文件，并使用分
析结果构造出了网表逆向工具 BIL。该工具实现了对可编程元件资源和可编程连线
资源逆向的初步尝试，并取得了一定效果，可以逆向出一部分电路信息[34]。在文献
[35]中，J. Yoon 等人进一步完善了该工具，提升了逆向覆盖范围。
   2013 年，Z. Ding 等人引入了 PK/PUK 算法，将其与配置文件结合起来，以一
种不同的角度构建了映射数据库，进一步提高了逆向准确性，并新增了以图形化方
式来描述网表的功能[36]。
   IceStorm[37]是专门用于分析逆向 Lattice FPGA 芯片的工具，该工具完整存储了
Lattice ice40 的配置文件结构，并且可以绕过 EDA 工具，直接对比特流进行操作。
   2017 年，江珊等人在研究针对最小项伪装电路的攻击方法时，使用了逆向技
术。在该方法中，逆向的主要方式为物理破解[38]。
   2020 年，S. Choi 等人提出了一种从比特流信息中快速提取查找表逻辑函数的
方法[39]。该方法改进了之前需要对 n 输入 LUT 进行详尽的 2N 处理的不足，将处
理减少到了 2N，提高了逆向效率。
   到了 2021 年，为了有效检测硬件木马，C. Mingi 等人基于 BIL 工具提出了一
个从配置文件到 LUT 级网表文件的逆向过程，提升了该工具的性能与覆盖范围，
并取得了成功[40]。同时，等人使用 Rapidsmith 方法构建了映射数据库，然后比较
逆向网表与标准网表，来确认电路中是否有硬件木马[41]。

  目前，研究人员的关注点主要都集中到了 Xilinx FPGA 上，分析其逆向方法的
论文数量也较多。而 Altera 和其他厂商的 FPGA 相关研究就相对较少，目前有 Marek

文本语法的转换，只是将一种记录信息的语法转换为了用户能够直接阅读的语法，

而在文献[43]中，D. Cheremisinov 等人构造出了一个针对代码逆向的智能工具，可
以实现将配置文件逆向为 EDIF 或 VHDL 文件的功能。


1.3 论文的研究内容与结构安排
  本文主要对两项工作进行了研究，分别是提出了基于命令行和 Tcl 的映射关系
数据库测量方法和针对硬核资源的代码逆向方法。前者主要应用于 Altera FPGA 芯
片的网表逆向过程，采用可执行命令行程序和 Tcl 脚本相结合的方式，自动化运行
整个测量过程；后者主要应用于 Xilinx FPGA 芯片的代码逆向过程，为可扩展的代
码逆向框架增加了逆向硬核资源的功能。
  本文的章节结构安排如下：
  第一章，介绍了课题的研究背景与研究意义，介绍了 FPGA 和 ASIC 逆向工程
的国内外研究现状，并说明了本文的主要工作。
  第二章，介绍了 FPGA 的基本概念，包括 FPGA 的编程技术、体系结构和开
发流程等，并介绍了 FPGA 的硬核资源和 Tcl 脚本的基础知识。
  第三章，在介绍了 FPGA 网表逆向三个基础后，详细阐述了网表逆向的一项
关键技术，即基于命令行和 Tcl 的映射关系数据库测量方法，并通过其与现有方法
的对比实验，验证了该方法的可行性及有效性。
  第四章，在介绍了现有的可扩展的代码逆向框架后，详细阐述了针对硬核资源
的代码逆向过程，并将其加入到了代码逆向框架中，然后使用实验证明了该代码逆
向方法的准确性。另外，还简单介绍了一种代码逆向的应用，即 FPGA 网表与 ASIC
网表的转换方法。
  第五章，是对全文研究内容的一个总结，提出了目前尚且存在的不足之处，并
对今后的研究工作进行了展望。

              第二章 相关研究及技术介绍

2.1 FPGA 介绍
   和以往的集成电路元件，如 GAL、PAL、CPLD 等比较，FPGA 集成元件数量
更多，即 FPGA 中门的排列布局更加紧密，从而克服了以往集成电路元件中门的
数量不能满足日益增长的设计需要的问题；同样，FPGA 可以看作是一种用户可自
定义的电路，其灵活性远胜于 ASIC。目前，IC 设计验证的主要方式就是使用硬件
编程语言编写设计文件（包括但不局限于 Verilog 和 VHDL），然后将设计好的 RTL
文件加载到 EDA 工具中，经过分析综合和布局布线后得到配置文件，最后将配置
文件下载到 FPGA 板卡上进行使用。伴随我国电子制造业的发展，FPGA 以其自身
所具备的可重复编程、节省研究经费、缩短研发周期等优点，被广泛应用在更多的
复杂电路系统设计中[44-46]。


2.2 FPGA 编程技术
   现如今，主流 FPGA 编程技术分为三类，分别是反熔丝编程技术、SRAM 编
程技术以及 Flash 编程技术[47]。了解主流编程技术，可以对 FPGA 逆向的起点即为
何选择从配置文件开始进行逆向有一定的认识。
   其中，通过反熔丝编程技术所得到的电路，无法重新进行编程，即该种编程技
术只允许编程一次。采用反熔丝编程技术的 FPGA 主要由阵列开关结构组合而成，
其电路实现过程就是按照设计文件，逐一设置反熔丝阵列，从而将设计功能载入到
FPGA 中。这种技术虽然不能重复使用，但外部环境很难对其进行干扰，同时耗电
量也较小，使得单个芯片的可利用率大大提高。
   三种编程技术中应用得最为普遍的是 SRAM 编程技术，其原因在于该技术支
持设计文件覆盖重写操作，即可对其进行重复编程，并且编程速度快，实现效果好。
但是，在采用这种技术后，一旦将 FPGA 断电，SRAM 无法保存配置数据，需要
在下一次启动 FPGA 时将配置数据重新下载到 SRAM 单元中。本文的研究对象就
是使用该编程技术的 Altera FPGA 和 Xilinx FPGA。
   Flash 编程技术属于新兴科技，同样具备可多次编程的优点。但是，其与使用
SRAM 的方式相比，不同点在于采用该技术进行电路设计的 FPGA 可以无视断电
的影响，将配置数据长时间保存在其内部核心中，美中不足的是其需要使用较长的
时间来进行编程操作。使用 Flash 编程技术的 FPGA 通过 SRAM 和 EEPROM 进行

存储和读取操作，其中 SRAM 主要负责实现底层逻辑功能，而 EEPROM 具有非易
失性，被用作 SRAM 的载体。所以，Flash 编程技术的优点在于可以进行多次编程，
以及掉电后配置数据不会丢失，不需要再次下载设计文件。而该技术的缺点在于成
本较高，难以进行批量使用。

2.4 FPGA 开发流程
   FPGA 的开发流程就是利用 EDA 工具对 FPGA 芯片进行开发的全过程。每个
FPGA 厂商都有其专用的 EDA 工具，如 Altera 公司的 Quartus II 软件和 Xilinx 公
司的 ISE 和 Vivado 软件，其主要作用为辅助用户更好地完成 FPGA 开发工作。通
常情况下，典型的 FPGA 设计流程如图 2-4 所示，可将其粗略地分为四个阶段，第
一是电路规划阶段，主要完成电路规划及芯片定型工作，第二是文件载入阶段，第
三是综合分析阶段，主要包括综合优化、布局布线等，最后是板级验证阶段。
   第一步是电路规划阶段，即电路功能设计阶段。在开始系统设计之前，先要对
方案进行论证，然后适配符合方案的 FPGA 芯片型号。开发人员一般需要针对具
体任务要求，如设计功能复杂度和需要达到的各项指标，对运行速度和芯片功耗等
进行取舍，设计出能满足要求的各方面性能更加均衡的设计方案和适配的芯片型
号。大多数开发人员会选择自顶向下的设计方式，把庞大复杂的系统设计分割为多
个相互独立的简单模块，在简单模块设计完成后再将其通过各种互连资源组合到
一起，以实现原有设计功能。

RTL 代码，它能够在硬件上实现；而其他无法使用的语句会被 EDA 工具直接舍弃，
并有可能提示报错。

   最后一步是 FPGA 板级测试，具体操作为将上一步生成的配置文件通过下载
器下载到 FPGA 板卡中，通过输入测试向量来观察对应输出是否正确，来辨别此
次开发是否获得了成功。作为成熟的产品，逻辑分析仪效果极好，操作简单，十分
适合用作板级测试，但考虑到其价格十分昂贵，各厂商都针对性的开发出了适合自
家产品的逻辑分析仪，并且能够在线使用，如 Xilinx ISE 软件中的 ChipScope 工具
和 Altera Quartus II 软件中的 SignalTap II 工具等，所耗资源少，实用性高。
   开发人员进行开发的过程中，需要不断对设计进行仿真验证，至少需要三次。
第一个是功能仿真，也被称为前仿真，其作用是判断当前 RTL 代码是否符合规范，
其描述电路是否可以实现；第二个是综合后仿真，顾名思义是在综合优化后运行，
查看当前生成电路功能是否正确；第三个是时序仿真，简称后仿真，可以对布局布
线后的电路进行时延分析，得到精确的运行结果。三个仿真配合使用，可以更加有
效的确保设计流程的准确性，并在出现问题时及时发现，避免无效劳动。
   了解 FPGA 正向开发整体流程，可以对逆向工作起到很大的启发作用。逆向
工程本身就是对正向开发的反向推演，正向开发的步骤或关键节点都可以对应到
逆向工作中。例如，根据生成文件的两个关键节点，将逆向过程分为了两步，即从
配置文件逆向到网表文件和从网表文件逆向到代码文件。


2.5 FPGA 硬核资源
   随着 FPGA 芯片集成度的大幅提高，针对 FPGA 的设计功能也越来越复杂，
规模也越来越大。在开发人员开始一项新的设计时，一般情况下不会完全从零开始
重新设计整个电路，通常情况下会采用这种解决方法：对数字电路中使用率较高、
通用性较强的部分，进行重复使用，而集中精力与资源去完成全新的电路设计。这
部分重复使用的电路，就被称为知识产权核（Intelligent Property core, IP core），具
体来说就是开发人员可以直接使用的部分 RTL 代码。开发人员可以通过使用特定
IP 核来实现预期逻辑功能，能够极大地提升开发效率，加快开发进度，让开发人
员可以腾出手来解决其他问题。
   按照获取方式的不同，IP 核可分为软核、固核和硬核三类。其中，软核指纯粹
的 RTL 代码语句段，即用硬件语言描述的功能模块，需要对其进行相应的编译流
程；固核是已经经历过综合过程的模块，难以对其细节和参数等进行修改，但是具

2.6 Tcl 脚本语言简介
  脚本，指的是用纯文本的方式，完成对设计流程的各种设置并运行整个设计流
程，同时输出相应的报告。在 EDA 行业中，大部分开发人员都会使用脚本语言来
简化开发流程，提高开发效率。对于 EDA 来说，其“自动化”的最直接体现，就
在于可以使用脚本语言，来全自动地完成整个设计过程。使用脚本语言的优点在于：
  ⚫   节约内存资源，提高开发效率。
  ⚫   将设计分为多个步骤完成，可以灵活安排设计过程。
  ⚫   可嵌入性高，能轻易加载到包括 makefile 在内的设计流程中。
  ⚫   便于执行分布式计算。
  工具命令语言（Tool Command Language, Tcl）就是一种被广泛使用的脚本语
言，对大部分软件而言，Tcl 自身所拥有的通用编程能力已经足够满足需求。Tcl 的
命令解释器作为一个 C 语言函数库，负责解释并运行所有命令，并且能够轻易得
与各种软件融合，运行在各种计算机平台上。Tcl 的命令可以由用户输入，也可以


                               14
               第二章 相关研究及技术介绍


从包括按键和选项的接口中读取，Tcl 解释器在接受命令后，会将其分解为内建函
数，再执行相应的功能，已成为 EDA 行业的一项工业标准。Tcl 的编程功能全面，
可嵌入性强，可拓展性高，用户可以自由的创建新的附加命令来扩展其内建函数，
也可以在 Tcl 社区中进行搜索和下载。另外，Tcl 语法简单易懂，语言清晰明了，
可以很快学习掌握，便于初学者学习。
  Tk 是 Tcl 最实用的扩展之一，它是一个专用于 GUI 开发的应用软件工具集。
Tk 丰富了 Tcl 内建函数的功能，加入了用户界面构造命令，可以替代 C 语言成为
图形用户界面构建的专用工具。Tcl/Tk 工具集在设计层次上高于 C/C++或 java 语
言，可以让开发人员省略很多底层细节，大大减少代码数量，实现快速开发。另外，
Tcl/Tk 工具集可以在程序运行的同时，生成和使用新的脚本，而无需再次编译和重
启软件，使得开发人员可以及时修改程序错误。虽然作为解释语言，Tcl 的运行速
度较其他编程语言稍慢一些，但可以采用内部优化的方式，再加上日渐提升的芯片
性能，足以抵消绝大部分的差距。
  Tcl 的另一个优势在于是它是开源软件，可以免费使用，因此能够降低开发成
本。Tcl 社区中也有很多套件及用户上传的扩展程序，允许所有人免费下载、查看、
修改以及再发布。

3.1 FPGA 网表逆向基础概述
  FPGA 比特流逆向整体流程为：从 FPGA 芯片中提取出含有电路所有配置信息
的配置文件（又被称为比特流文件），然后通过逆向平台将其逆向为网表文件，再
逆向为 RTL 代码文件，两次逆向都会输出对应的逆向文件和报告。其中，配置文
件由 EDA 工具在编译完成后生成，以二进制代码的形式记载了当前设计的所有参
数、配置和底层逻辑资源的布局布线信息；网表文件则是根据 EDA 工具的不同，
以不同的语法详细记录 FPGA 的基本参数、可配置项使用情况和内部可编程互连
信息。为了实现从配置文件到网表文件的转换，需要构建一个映射关系数据库，专
门存储配置文件二进制比特位与网表文件底层硬件资源使用情况的映射，并且通
过网表逆向平台，实现网表逆向过程。图 3-1 展示了 FPGA 比特流逆向的完整流
程。

  配置文件作为 FPGA 网表逆向平台的输入，是网表逆向工作的源头。配置文

3.1.3 映射关系数据库
   映射关系数据库作为 FPGA 网表逆向平台的参考输入，是网表逆向工作的关
键和重中之重。映射关系数据库专门存储配置文件二进制比特位与网表文件底层
硬件资源使用情况的映射，具体的说，是将底层逻辑元件模块的可配置项信息和硬
件互连资源中的可编程连接开关信息与其在配置文件中对应的二级制比特位和其
配置值组成一对映射，存储在数据库中，供网表逆向平台调用查询。而这些对应的
二进制比特位，被称为支配位，这些配置值也被称为支配值。每条数据的支配位可
能不止一位，多个支配位组合在一起就被称为支配位集合。



                              20
                  第三章 FPGA 网表逆向关键技术解析


  映射关系数据库由三种数据库组成，分别是逻辑元件数据库、可配置连线开关
数据库和偏移量数据库。其中，逻辑元件数据库存储了每个实例模块的可配置项与
其支配位和支配值的映射关系。可配置项指组成 LE 或 IOE 的所有底层硬件资源，
包括 LUT、FF、MUX 等逻辑元件和输入输出端口、进位链、控制端口、时钟端口
等端口信息。在上一小节分析的 ADL 网表文件中，inst 语句段下的所有内容都由
一个实例的可配置项信息组成，其结构为“可配置项：对应参数”，当未使用该可
配置项时，对应参数为#OFF。
  而 ADL 网表文件中的另外一种内容，即 net 语句段记录了一个可编程互连线
网络的信息，包括一个输出端口和其连接的数个输入端口，以及它们之间的可配置
连线开关资源。在 Altera FPGA 内部，其互连网络资源围绕 LAB 和 IOE 横向和纵
向排列，整体结构呈“井”字型。数据可以在横向通路和纵向通路的交叉连接处进
行交换，而该交叉处是一个可编程开关，负责控制数据交换状态，被称为可配置连
线开关。可配置连线开关数据库则存储了上述可编程互连线资源与其支配位和支
配值的映射关系。
  另外，每一款 FPGA 芯片内的 LAB 数量从数百到几万门不等，而每个 LAB 内
的可配置项也至少有几十种。若是把每一个 LAB 中的每一个可配置项全都测量完
毕，不仅需要耗费大量的时间，更会使得逻辑元件数据库内的数据量过于庞大，不
利于网表逆向平台调用查询，对逆向效率影响极大。但是值得注意的是，在同一系
列的 FPGA 芯片内部，同类别的硬件模块具有相同的布局结构，除了位置不同外
其他所有构造细节全都相同。而且经过实验，可以得到在相对位置不变的情况下，
两个模块内所有同类可配置项的支配位地址相差固定的位数，即模块 X 和模块 Y
在位置固定后，每一种可配置项所对应的支配位地址的差值相同，本文将这个差值
称为偏移量，而存放这些偏移量值的数据库称为偏移量数据库。
  表 3-1 展示了一张映射关系数据库表的结构。每张数据库表的内容可大致分为
三项，包括硬件资源在 FPGA 芯片中的位置信息、硬件资源的可配置项种类及其
参数和该可配置项的支配位及支配值。

3.3 基于命令行和 Tcl 的映射关系数据库测量方法
  上述映射关系数据库测量方法提供了一个基本的映射关系数据库测量思路。
在这个思路下，研究人员不仅建立起了一个基本可用的涵盖了 FPGA 所有内部基
础结构类型的映射关系数据库，并且利用这个映射关系数据库对一些简单的 FPGA
案例进行了逆向，得到了正确的逆向网表文件。
  但是，上述映射关系数据库测量方法实用性不高，原因在于其每一步测量步骤
都是通过手动方式进行，包括基准电路的生成、分析综合基准电路得到配置文件、
在 Chip Planner 中修改具体设计及生成修改后的配置文件、配置文件对比和数据库
使用等，操作复杂，涉及软件平台较多，并且需要耗费大量时间在等待软件运行及
修改设计操作上。针对上述问题，同时考虑到该测量过程有大量简单机械的重复操
作，本文使用可执行命令行程序和 Tcl 脚本来自动化完成涉及 Quartus II 软件的所
有操作，并结合 java 程序完成其他步骤，以实现自动化运行的映射关系数据库测
量方法，使大规模芯片的映射关系数据库完整测量成为了可能。
  基于命令行和 Tcl 的映射关系数据库测量方法流程如图 3-7 所示。
  第一步，建立基准电路。后续所有电路修改操作都是在基准电路的基础上进行，
并且修改后的电路也是通过与基准电路进行比较来得到电路参数与支配位的映射，
可以说基准电路是整个测量方法的基础。
  第二步，修改电路设计。使用 Tcl 脚本对基准电路进行针对性的修改，包括改
变可配置项、元件位置和互连关系等，但一次只能改变一项，以保证能够通过比较
得出该项所对应的支配位和支配值。
  第三步，生成配置文件。该操作需要使用可执行命令行程序编译整个工程，得
到电路的配置文件，支配位和支配值就是从配置文件中得到。
  第四步，获取当前电路参数。由于可配置项是用户指定的修改，所以不用特意
去获取此时的可配置项信息。但每次布局布线时，各元件间的连接关系不能由用户
指定，所以这个步骤所获取的主要是电路中的互连信息，即可配置连线开关信息。
  第五步，关联可配置项数值。将第三步和第四步得到的电路参数和配置文件结
合起来，形成一对映射，并存储到对应数据库中。但可配置连线开关信息是成组出
现的，无法通过一次对比就将所有的信息区分开来，需要通过其他方式来确定其每
一条信息的映射关系。本文提出了一个可配置连线开关支配位确定算法，可以解决
上述问题。

3.3.2.2 电路设计修改

   在得到了可以新建并修改工程的 Tcl 脚本后，后续步骤只需针对性的修改其对
应部分的语句以实现相应功能即可。在测量逻辑元件和偏移量数据库时，应修改电
路中 LE 内的各项参数或 LE 的布局布线位置，而测量可配置连线开关数据库时，
应修改两个 LE 的位置及其输入输出端口以使用不同的连接通路。
   Altera FPGA 主要由两种底层硬件模块构成，分别为 I/O 单元（I/O Element,
IOE）和逻辑阵列模块（Logic Array Block, LAB），对同一系列的芯片而言，同种硬
件模块的元件组成细节基本相同。其中，每个 LAB 除了进位链和各种本地互连资
源外，主要由 16 个逻辑单元（Logic Element, LE）组成。图 3-9 展示了 Cyclone IV
E 系列芯片的 LAB 内基础单元 LE 的具体结构。




              图 3-9 Cyclone IV E 系列芯片中 LE 的具体结构

   每个 LE 可大致分为组合逻辑部分和时序逻辑部分。组合逻辑部分的核心是一
个四输入 LUT，其输出表达式也是可配置项，由四位输入通过简单的逻辑运算实
现不同的功能，如用“A&B#!A&C”表示二选一数据选择器的功能；时序逻辑部分
以一个可编程寄存器 FF 为框架构成。另外，两部分各包含了两个数据选择器，分
别用 A/B/C/DMUX 表示，也是需要测量的可配置项。
   根据以上结构，用 Tcl 脚本进行电路修改，以测量不同的可配置项。在 Tcl 脚
本中，可以对电路进行修改的语句都包含在 chip_planner 包中，该包在使用前需要
使用 load_package 语句加载。然后，使用 add_new_cell 和 remove_old_cell 语句可
以在网表中的指定位置创建或删除一个指定类型的元件，包括 LUT 和 FF。在没有
特别指定属性值的情况下，新创建的元件类型默认为 LCELL，并被放置在设计层
次的最顶层。使用 make_input/output_port 和 remove_input/output_port 语句可以为
指定位置的元件增加或删除一个输入或输出端口，在对应端口被使用后，包括四个
数据选择器在内的其他逻辑元件便会被使用，可以根据此时的状态来判断该逻辑
元件的配置值。另外 connect_chain 和 remove_chain 语句可以连接或移除指定端口
的进位链，用于测量进位链相关逻辑元件的配置值。而修改连线可以使用
make_ape_connection 和 remove_ape_connection 语句，它可以在源端口和目的端口
之间建立或删除网表连接，同时更改元件位置和网表连接就可以对可配置连线开
关进行测量。

3.3.2.3 配置文件生成

所以本文直接使用单独的命令行程序来运行整个编译流程，其代码示例如图 3-10

3.3.2.5 可配置项数值关联

   在得到配置文件信息和电路参数信息后，就需要将其关联起来，加载到数据库
中。具体操作为首先对比基准电路配置文件和修改后电路配置文件，找到并记录其
中不同的配置位及其配置值，然后提取此时改变的电路参数，如可配置项的打开或
关闭等，将该参数与记录的配置位（即支配位）和配置值（即支配值）作为一对映
射保存到对应的数据库内。
   对逻辑元件数据库而言，由于每次只会修改一类可配置项中的一个，比如修改
LUT 内表达式、打开或关闭 AMUX 等，所以配置文件中不同的配置位就是该可配
置项的支配位，不同的配置值就是支配值，不存在无法判断的情况。
   对偏移量数据库而言，也不存在上述无法判断的情况。但同样的，在第 4、7、
11、14、18、22 和 25 行的 LAB 内的可配置项支配位偏移量出现了不相同的情况。
造成该现象的原因为可配置项对应支配位的副地址在该行内发生了变化，所以两
者间会有 251_1 位的偏差。为简化映射关系数据库结构，本文选择将该偏移量的
修正工作置入到网表逆向程序中，当逆向到上述行内的 LAB 时，对存在偏差的部
分可配置项进行修正，即加上该偏差值，其余情况下则直接使用数据库中保存的偏
移量值。
   而对可配置连线开关数据库而言，根据输入输出端口距离的不同，所经过的可
配置连线数量也不同，所以每次修改电路后得到的可配置连线及其配置位和配置
值都是成组出现的，在没有其他信息的情况下无法区分出每一条可配置连线所对
应的那一位或几位配置位。因此，本文提出一种可配置连线开关支配位确定算法，
具体步骤如下：
   第一步，在可配置连线数据库中构造两张新的数据库表，并将其命名为 PIP 和
Buffer，表 3-4 和表 3-5 展示了该表的结构。其中，PIP 表用于存储比对成功的单个
的可配置连线开关，及其支配位和支配值，而 Buffer 表是一个存放中间结果的表，
记录的是每次修改电路后得到的且经过比较后尚且无法确定具体映射关系的一组
可配置连线数据信息。当后续能够判断出某一个可配置连线开关与其支配位的映
射后，则将其从 Buffer 表中移除，并放入到 PIP 表中。
   第二步，获取改变电路连接关系后，新发现的可配置连线开关数据组，并将其
中的每一条连线开关信息都与 PIP 表中 Configurable_connection_switch 列的数据
进行比较，若存在相同数据，则从数据组中将其删除，并进入第三步。若不存在相
同数据，则直接进入第三步。
   第三步，将 Buffer 表中 Configurable_connection_switch_buffer 列的数据依次与
剩余的可配置连线开关数据组信息进行比对，当发现有部分重合的数据时，则将重

了三个部分。若这三个部分中的某一个或几个只包含了一条可配置连线开关数据
信息，则将其存储到 PIP 表中，而其他部分则重新存入 Buffer 表中，等待下一组
信息到来时继续比较。

3.3.3 数据支配位优化
   对可配置连线开关数据库而言，在正常情况下，一个可配置连线开关对应的支

方法中，对比配置文件的操作实际上默认了配置值为 0 是未使用该位的意思。而
实际上，为节省配置文件资源，降低配置文件大小，会对在同一时间不可能同时使
用的多个可配置连线开关进行复用支配位的操作。具体来说，在不复用支配位的情
况下，使用 1-2 位支配位才能代表一个可配置连线开关，而复用支配位后，用 3 位
支配位就能代表至多八个可配置连线开关，可以大大压缩配置文件的占用空间，节

3.5 本章小结
  本章主要分析了 FPGA 网表逆向的关键技术——基于命令行和 Tcl 的映射关
系数据库测量方法。首先，介绍了网表逆向的所需的三个要素，即配置文件、网表
文件和映射关系数据库等，这是进行网表逆向不可或缺的基础。然后，介绍了现有
的映射关系数据库测量方法，该方法是以手动测量的方式进行，效率较低。接下来，
介绍了新的基于命令行和 Tcl 的映射关系数据库测量方法，详细介绍了在 Quartus
II 软件内命令行和 Tcl 脚本的用法及数据库的完整测量过程。最后，则是通过对比
试验的方式，验证了本文提出的测量方法的可行性及有效性，和对测量效率及数据
完整度的提升。

  在网表逆向流程结束后，接下来就是对网表文件进行代码逆向，得到 RTL 代

  配置文件是以二进制代码的形式记录了电路的各项参数数据，这种代码形式
只能被机器识别，肉眼无法辨认。当层级上升到网表文件后，由于其是在布局布线
后生成，所以需要以更直观的方式展示出底层逻辑资源的使用情况，因此其内容包
含了具体的电路元件与互连线的名称位置信息。但是，鉴于网表文件也不是面向用
户开发的文件，因此其代码语言风格可读性不高，只能作为分析使用。而用户可以
直接编写使用的 RTL 代码文件处于更高层级，该文件使用硬件描述语言，可用专
业的术语针对性的描述电路功能，虽然不包含芯片资源信息，但其可读性高，可移
植性好，因此 RTL 代码文件是开发人员进行电路设计的首选。

询每个元件的配置信息，确定其具体功能，然后复现出等价的 RTL 代码，加入到
逆向代码文件中。
  第四步，信号声明补充。将第三步中倒推出的所有元件的互连信息补充完整，

  第五步，结束语句添加。在上述流程全部运行完毕后，将结束语句加入到逆向
代码文件的最后。
  由于第三步是整个逆向框架的核心，下面将仔细分析该步流程。
  一般情况下，RTL 代码中的绝大多数语句可以按照功能的不同，分为连续赋
值语句和过程赋值语句两类。具体何时该逆向为何种语句，则需要跟 FPGA 芯片
的底层元件资源使用情况结合起来考虑。而对于每个元件而言，其具体实现的功能
主要受到两个因素的制约，一个是其自身所能实现的逻辑功能，一个是其所连接的
输入输出信号。受到这两个因素的影响，元件所实现的功能可能会相差甚远。所以，
要想保证逆向准确率，必须做到对每一个元件功能的精确表述。这就要求该框架掌
握整个芯片的资源使用情况，包括元件和互连线。因此，选择从输出模块开始，沿
着信号流的方向反向向前倒推的方式进行全局搜索，可以保证对底层资源的完整
还原。这是由于从互连网络的角度来看，每个网络可能会有多个输入，但必定只有
一个输出，若是从输入模块往后推导，不仅可能造成遗漏，从网表文件中提取信息
也更为复杂。
  在倒推过程中，需要对搜索到的元件实施两个必要过程。第一，根据元件自身
逻辑功能和其输入信号，推导出元件在当前设计中的具体功能，再根据具体功能选
择逆向语句并将其总结提炼为 RTL 代码。第二，将当前元件的上一级元件放入倒
推队列中，并继续向上搜寻，直到倒推出所有输入模块为止，此时可以确定所有元
件都已搜索完毕。
  另外，在倒推过程中，如何查找上一级元件还需要有相应的先验知识。因为对
不同家族不同系列，甚至同系列不同型号的 FPGA 而言，其底层元件的布局和数
量也有可能不同，更有甚者连元件种类也会存在差别。例如在 Spartan-3 芯片中，

4.2.1 分布式 RAM 结构
  SLICEM 中的 LUT 可以通过编程以 RAM 形式使用，这个 RAM 分布在整个

FPGA 中，因此被形象化地称作“分布式 RAM（Distributed RAM）”
Kbit 的块 RAM（Block RAM）。这种类型的 RAM 可以在数据通路的任何位置提供
适量的数据缓冲。分布式 RAM 的还有一个别名为 LUT RAM。分布式 RAM 运行
速度快，占用空间小，经常用在如 FIFO 等小型实例中。
  分布式 RAM 对于许多需要相对较小的嵌入式 RAM 块的高性能应用程序（如
FIFOs 或小寄存器实例）来说是至关重要的。分布式 RAM 同步写和异步读。但是，
如果应用程序需要，可以使用与每个 LUT 关联的寄存器来实现同步读取功能。每
个 16x1 位 RAM 可级联用于更深层和/或更宽的内存应用程序，通过专门的逻辑资
源产生最小的时间惩罚。
  分布式 RAM 包含两种内存类型，分别是单端口 RAM 和双端口 RAM，如图
4-5 所示。每个 SLICEM Slice 中的 LUT 都可以编程为一个独立的 16x1 位单端口
RAM（Single-port RAM）。单端口 RAM 的写入操作是同步的，读取操作时异步的，


                             46
                 第四章 FPGA 代码逆向关键技术解析


使用与该 RAM 相关联的触发器则可以实现同步读操作。将两个单端口 RAM 通过
一定的方式级联起来就可以得到一个 16x1 位双端口 RAM（dual-port RAM），其中
一个单端口 RAM 按照正常工作模式运行即可，另一个单端口 RAM 只提供读取功
能，并且是异步的，同样也可以通过触发器实现同步读操作。双端口的意义在于，
在数据同时写入两个单端口 RAM 后，第二个单端口 RAM 可以在第一个单端口
RAM 正常工作的同时，向外界输出其存储的值。输入端口 D 上的任何写操作和输
出端口 SPO 上的任何读操作都可以与第二个只读端口 DPO 上的读操作同时发生，
或者也可以独立发生。

  “双端口”选项将两个 LUT 结合在一起，使用户可以从两个独立的数据线访问
内存。相同的数据被同时写入两个 16x1 内存，但它们有独立的读地址线和输出。
要实现双端口功能，需要级联同时用于读写操作的 G-LUT 地址线和 F-LUT 写地址
线,以及通过 DIF_MUX 元件级联 G-LUT 和 F-LUT 的数据输入端口 DI。
  INIT 属性可用于在 FPGA 配置期间预加载内存数据。RAM 的默认初始值为全
零。如果 WE 始终保持低电平，则该实例可以认为是一个 ROM。ROM 功能也可
以在 SLICEL 中实现。
  一个 SLICEM LUT 可以存储 16 比特信息，而多个 SLICEM 通过可编程互连
网络连线组合起来就可以存储更多信息。每个 CLB 可包含最多 64 位（如 16x4、
32x2、64x1）的单端口 RAM 或 32 位（如 16x2、32x1）的双端口 RAM。

  SLICEM 的 LUT 还可以被配置为移位寄存器（Shift Register LUT, SRL16），它
的原理为将 LUT 配置为一个 16 位的小型移位寄存器，以此来替代传统的使用触

4.3 针对硬核资源的代码逆向过程

4.3.1 代码逆向方式选择
   在 Xilinx FPGA 使用中，用户可以使用三种方式来配置一个硬核，分别是使用
EDA 工具自带的 Xilinx CORE Generator 系统、使用标准 VHDL/Verilog 语言和使
用 Xilinx 原语。下面将详细分析三种使用方式，以确定逆向所使用的方式。
   （1） 使用 EDA 工具自带的 Xilinx CORE Generator 系统




                图 4-8 Xilinx 内核生成器的图形用户界面


   Xilinx 内核生成器（Xilinx CORE Generator）系统可以通过访问高度参数化的、
面向 Xilinx FPGA 的 IP 核来缩短设计时间，囊括了从基础的单元电路模块到高端



                            49
                     电子科技大学硕士学位论文


的超大型集成电路的所有种类电路。生成器通过图形用户界面，可以方便快捷地选
择所需要的使用的 IP，并个性化定制其各项参数，如图 4-8 所示。
   在界面设置完成并点击生成 IP 核后，会输出四个重要文件，分别是*.V、*.VEO、
*.XCO 和*.EDN。其中，*.V 文件将定制参数传递给 IP 核的通用仿真模型，用以
支持 IP 核的功能仿真；*.VEO 文件是该 IP 核的 Verilog 语句模板，包含了元件的
声明及例化，用以实例化该 IP 核；*.XCO 文件内记录了当前项目的所有约束以及
其各项变量值；*.EDN 文件是该 IP 核的网表文件，在后期进行布局布线时需要用
到。因此，*.XCO 文件囊括了所有 IP 核生成所必须的基础要素，并在生成 IP 核时
自动调整对应后台代码，以实现用户预定义的各项功能。所以在分析编译整个工程
时，不能缺少该文件，否则会缺少对应的 IP 核详细配置数据，无法匹配生成对应
电路，造成编译失败。
   另外，某些 IP 核需要设置初始值，如分布式 RAM 和 SRL16。在默认不输入
的情况下，其初始值为全 0。若需要指定其他非零值，则需要通过内存初始化文件
（*.MIF）输入，该文件由一行二进制数据组成，保存用于初始化 IP 核和仿真模型
中内存的实际二进制数据。或者也可以创建一个系数文件（*.COE），它的主要功
能为定义 IP 核的初始值，还能定义内核生成器系统的其他所有控制参数。但在 IP
核生成期间，COE 文件还是会被转换为 MIF 文件。
   对于正向设计来说，通过软件自带工具生成 IP 核的方式，可以使得用户从编
程细节中解脱出来，将注意力集中到其他方向，大幅提升设计效率。但是，从逆向
工程的角度来说，却有几点缺陷。第一，需要的生成的文件太多，增加了逆向复杂
度。若采用该方法逆向，不仅需要在网表辨析后添加对应 IP 核的注释，还要根据
该注释手动或者通过脚本生成其他几个内核生成器所必须的文件，如*.COE 或
*.XCO 文件。这一步骤会花费额外的人力和时间。第二，逆向后的文件太多，不便
于使用者直接观察 RTL 级代码，或将这些文件用于诸如硬件木马分析或逻辑漏洞
挖掘等后续功能。因此，本文不采用这种方法逆向。
   （2） 使用标准 VHDL/Verilog 语言
   EDA 工具内支持的 IP 核都可以用标准 VHDL 或 Verilog 代码进行初始化，并
用于综合和仿真。根据用于创建设计的特定逻辑综合工具的不同，使用 VHDL 或
Verilog 语言编写的基于综合的设计可以推断出或直接实例化 IP 核。其中，在不使
用原语的情况下，代码无法直接实例化 IP 核，只能依靠综合工具来推断。大多数
VHDL 和 Verilog 逻辑综合工具，如 Xilinx 综合工具（Xilinx Synthesis Tool, XST）
和 Synplicity Synplify 等，可以基于硬件描述推断 IP 核的使用。以 SRL16 组件为
例，由于 SRL16 没有同步或异步的置位或置零功能，并且不能同时访问移位寄存

如硬件木马分析或逻辑漏洞挖掘等各项功能。但是，这种方法针对规模较小、功能

  （3） 使用 Xilinx 原语
  原语（Primitive），是各大 FPGA 厂商在 EDA 工具中集成的、根据自身芯片结

和 SRL 等多种简单或复杂的基础元件系统。该方式可以不使用其他附加工具，只
用编写代码即可直接例化，但要保证所用原语的名称、语句结构和使用方式等没有
出错，否则无法成功例化。

4.3.2 代码逆向过程
  根据 4.1 节介绍的可扩展的代码逆向框架，由于其现阶段并不具备逆向硬核的
能力，所以需要补充硬核对应的配置文件到代码逆向框架中。不同于以往只是硬件
最底层资源的简单配置文件，想要以原语的方式来描述硬核，就不能再将每个底层
逻辑元件分开单独考虑，需要将所有使用到的元件整合起来，作为一个整体，或者
说以黑盒的形式来逆向。硬核的配置文件生成总体流程如图 4-11 所示。
  第一步，获取布局布线信息。由于配置文件的具体内容是从网表信息到代码语
句的一对一映射，即只通过该映射就可以实现从网表文件到代码文件的准确转换，
而映射的建立需要了解正向情况下代码语句所生成的底层布局布线信息，并以此
为基础与网表信息对应起来。不同的代码会使用不同的布局布线，然后生成不同的
网表文件。所以配置文件的生成首先需要得到正向代码所对应的布局布线信息。

  第二步，生成正向网表文件。根据第一步的分析，正向网表文件也是配置文件
生成过程中不可缺少的一部分。XDL 文件内容除了注释信息外，主要分为三个部
分，包括工程信息 design、实例信息 inst 和互连信息 net。工程信息指工程名、所
用芯片型号和引脚分配等基本信息，实例信息按照芯片结构中的 IOB、SLICEL 和
SLICEM 等结构划分，详细记录了模块内部元件的使用情况，互连信息则记录了每
个模块从输出到输入的所经过的所有可编程互连线。
  第三步，确定待逆向代码具体参数。配置文件不关心工程信息和互连信息，只
需要根据实例信息确定具体实现了哪种功能，因为代码文件是以实现功能为目的，

而不需要指定具体的连接。根据 4.2 节的介绍，可以确定分布式 RAM 和移位寄存

型，然后是该实例的布局位置。第二行开始到最后都是该实例的元件配置字段，以

   第四步，载入配置文件。综合第三步得到的所有映射信息，可以生成硬核的配

无法判断，还需要其他信息的进一步补充。
  接着通过确定移位寄存器 SRL 的输入输出端口来确定具体使用的原语。在查
阅数据手册和实际生成电路后观察发现，移位寄存器的 4 位地址输入 A[3:0]直接
连接到了 GLUT 的地址输入 G[4:1]上，用于选择需要输出的数据，同时将此信息
传输到输出端口 Q，但不传输到端口 Q15，如图 4-19(a)所示。Q15 端口在移位寄
存器中十分特殊，在 FPGA 芯片编辑器中被称为 MC15，它总是输出最后一位（第
15 位）的数据值，可专门用于级联时向下一片移位寄存器传递数据。两个输出端
口 Q/Q15 可直接向外连接，从任意一个端口向上搜索都能找到移位寄存器结构，
并且再被另一个端口搜索到时不会重复逆向。由于此时 Q15 端口打开，并连接到
了其他元件，所以判断该移位寄存器的原语包含级联功能，因此原语中应包含字母
“C”。而由于所有原语的长度都为 16 位，当长度大于 16 位时，就需要将多个原语
通过级联的方式连接在一起，构成一个更长的移位寄存器，其具体连接方式为：在
同一个 SLICEM 中的情况下，上一级移位寄存器的最高位信息通过 Q15 端口向外
输出，然后经过 DIF_MUX 传输到下一级的输入端口 DI；在跨越多个 SLICEM 的
情况下，上一级移位寄存器的最高位信息通过 Q15 端口向外输出后，经过
SHIFTOUT 和 SHIFTIN 线的连接进入下一级 SLICEM，再通过 DIG_MUX 传输到
下一级的输入端口 DI。
  实际上，在使用移位寄存器 SRL 硬核时，还有一个动态长度调节功能，这意
味着在正向设计的过程中，不用强行将移位寄存器的长度设置为 16 的倍数。该功
能通过地址输入动态地改变移位寄存器的长度，例如设置地址为 7（0111）选择 Q7
作为输出，就可以模拟 8 位移位寄存器。但此时必须使用 Q 端口作为移位寄存器
的输出，而不能使用 Q15 端口。在布局布线时，由于片内资源的限制，长度不足
16 位的移位寄存器都会被实例化为 16 位，因此在逆向时，只能识别到这是一个
SRL16 硬核，而不能正确判断其具体长度。但在这种情况下地址输入是固定不变
的，且逆向时也能正确识别这些地址输入，所以逆向后从功能上来看与正向设计也
是一致的。
  第一级移位寄存器的数据输入 DI 则是从 BY 端口接入 SLICEM 后，通过
DIG_MUX 接入到 F/GLUT。而使能端口 WE 和时钟端口 CLK 则同时直接接入到
了使能模块 WSGEN，如图 4-19(b)。WE 端口默认为高电平有效，因此在原语不包
含时钟使能功能的情况下，该端口会直接接入高电平；而此时该端口接入了其他信
号，说明该移位寄存器的原语包含时钟使能功能，因此原语中应包含字母“E”。至
于触发方式的选择，为观察 XDL 文件中 CLKINV 字段后的配置信息确定其触发方

式，配置信息为 CLK 时为上升沿触发，否则为下降沿触发。同样，为统一标准，
并减少配置文件复杂度，逆向原语只选择上升沿触发的几种原语类别，当碰到下降

4.4 逆向结果验证
   本章的前几节详细描述了基于可扩展的代码逆向框架的 FPGA 硬核逆向方法，
本节将通过实验验证该方法的逆向时间与功能等效性。

4.4.1 实验工具和流程
   代码逆向实验所使用的 FPGA 芯片型号为 Xilinx Spartan-3 XC3S200-5FT256，
EDA 工具版本为 ISE Design Suite 14.7，代码逆向软件开发平台为 Eclipse Java 2019-
06，EDA 工具和软件开发平台都运行在一台操作系统为 Windows 10 企业版 LTSC
64 位的 PC 主机上，其主要参数为：处理器 i3-3240 CPU，主频 3.40GHz，运行内
存 8.00GB。实验选择的设计主要来自于 Xilinx 公司的官方例程，可以在 ISE 软件
中和 Xilinx 官方网站进行下载和使用。
   代码逆向验证实验流程如下：
   1) 将源代码文件载入到 EDA 工具中，并进行分析综合和布局布线，得到正向
网表文件；
   2) 将正向网表文件作为输入加载到代码逆向软件中，并运行程序，得到逆向
代码文件与逆向时间；
   3) 将源代码文件与逆向代码文件进行等效性验证，得到代码逆向等效结果。
   对 FPGA 进行等效性验证的方法不多，大致有以下两种方式可以选择。第一
种是形式化验证，它是以纯粹的数学方式来模拟计算当前工程的关键节点信息与
其实现的匹配程度。另一种是模拟验证，它是将通过多种方式生成的测试向量输入
到目标设计中，然后将其实现与参考设计的实现相对比，得出其匹配程度。虽然形
式化验证更加的便捷高效直观，且有现成的商业化工具可以使用（如 Synopsys 公
司的 Formality 一致性检测工具），但由于这些工具无法分析 Xilinx 原语，所以在
设计中包含原语时，只能采用模拟验证的方式。但模拟验证需要通过各种方式生成
复杂的测试向量，而硬核电路又广泛采用了时序逻辑，输入翻转状态存在数量庞大
的可能性，基本不可能实现完全覆盖。因此，若要使得验证结果更具说服力，就需


                              63
                     电子科技大学硕士学位论文


要提升测试向量的针对性，本文采用方式为，根据所使用硬核资源的深度、宽度或
数据长度等，获取特定数量的随机值，然后使用这些随机值设计出测试向量并将其
随机载入到硬核存储元件中，再按照随机地址读取这些数据作为输出。使用该方式
测试逆向电路和源电路，然后对比两者输出，如果相同，则认为等效性验证通过，
逆向文件和原始文件匹配度高。

4.5 FPGA/ASIC 网表转化机理
 （1）FPGA 网表转化为 ASIC 网表
  根据本章前几节的分析，将 FPGA 的网表文件逆向到 RTL 代码文件是可以实
现的，并且也确实完成了该逆向工作。因此，要想将 FPGA 网表转化为 ASIC 网
表，首先需要将 FPGA 网表通过代码逆向平台逆向为 RTL 代码文件，然后将逆向
的 RTL 代码文件载入到 ASIC 专用 EDA 工具中进行逻辑综合，就能得到 ASIC 门
级网表。该过程较为简单，本文不再赘述。
 （2）ASIC 网表转化为 FPGA 网表
  参考 FPGA 网表转化为 ASIC 网表的方法，将 ASIC 网表转化为 FPGA 网表也
可以按照上述步骤实施。因此，应首先完成 ASIC 网表的逆向工作。
  ASIC 门级网表的结构如图 4-20 所示，图中类似内容作了省略，并用省略号代
替。从图中可以看出，其实 ASIC 门级网表的语法结构和书写内容与 Verilog 代码

                    电子科技大学硕士学位论文


基本相同，都包括了输入输出端口声明、信号变量声明和对应元件的例化等。唯一
的区别在于，门级网表大量采用了结构描述方式，将所有的功能电路细分为了一个
一个的门逻辑，再通过门电路的各种组合构成基础模块如加法器等，再继续向上一
层级组合，直到构成能够实现设计功能的复杂电路为止。而一般情况下使用的
Verilog 代码主要使用行为描述方式，通过代码编程的方式来抽象描述出一个实际
电路。
   而仔细观察可以发现，门级网表在元件例化语句里所调用的模块与通常 FPGA
里所使用的有一些区别，具体在于其名称后增加了一个后缀，如在 ASIC 网表中所

文件。

5.1 全文总结
  本文主要完成了两个工作，分别是提出了基于命令行和 Tcl 的映射关系数据库
测量方法和针对硬核资源的代码逆向方法。前者主要应用于 Altera FPGA 芯片的网
表逆向过程，采用可执行命令行程序和 Tcl 脚本相结合的方式，自动化运行整个测
量过程；后者主要应用于 Xilinx FPGA 芯片的代码逆向过程，为可扩展的代码逆向
框架增加了逆向硬核资源的功能。全文的主要工作总结如下：
 （1）介绍了 FPGA 的相关基础知识，总结了有关 IC 的逆向工程的研究现状，
并简单介绍了 FPGA 硬核资源和 Tcl 脚本语言的基本概念。
 （2）提出了基于命令行和 Tcl 的映射关系数据库测量方法。首先介绍了现有
FPGA 网表逆向技术的三个必备要素，包括配置文件、网表文件和映射关系数据库
等。然后简单介绍了现有的映射关系数据库测量方法以及 Quartus II 软件内的可执
行命令行程序和 Tcl 脚本的使用方式。最后提出了改进的数据库测量方法，该方法
针对现有数据库测量方法主要由人工操作，用时较长、效率较低的缺点，采用可执
行命令行程序和 Tcl 脚本相结合的方式，来自动化运行整个测量过程，提高了数据
库测量效率与数据完整度。
 （3）通过在网表逆向平台中分别载入按照本文方法和现有方法测量出的映射
关系数据库，并逆向 ISCAS’85 基准组合电路集和 ISCAS’89 基准时序电路集中部
分设计的方式，验证了按照本文方法测量出的数据库数据的正确性。
 （4）提出了针对硬核资源的代码逆向方法。首先介绍了现有的可扩展的代码逆
向框架，以及包括分布式 RAM 和移位寄存器 SRL 在内的硬核资源的底层硬件结
构。然后讨论并选择了以原语的方式逆向硬核资源，并分种类详细阐述了该逆向方
法的流程。最后，介绍了代码逆向技术的一项应用，即实现 FPGA 网表与 ASIC 网
表的相互转换。
 （5）使用扩展了硬核资源逆向功能的代码逆向平台，对 Xilinx 官方提供的硬
核资源示例程序进行了逆向，验证了该逆向方法的正确性与实用性，拓宽了代码逆
向平台的应用范围。


5.2 后续工作展望
  FPGA 逆向工程是一项复杂的系统性工程，对它的研究任重而道远。



                      69
             电子科技大学硕士学位论文


  随着制造精度的提高，FPGA 芯片上可编程资源密度越来越高，特别是可编程
连线开关；硬核资源的种类也在不断增加，使得 FPGA 能够实现的功能也更加丰
富。所以对于网表逆向平台而言，重中之重仍然是在映射关系数据库的测量上，而
代码逆向平台则应把注意力集中到硬核资源上。虽然本文提出了一种测量映射关
系数据库的自动化方法，并拓展了代码逆向平台的硬核资源逆向功能，但是仍然存
在一些不足之处，列举如下：
 （1）映射关系数据库数据完整度仍然没有获得较大提升，主要问题在于可配置
连线开关无法全部遍历，需要找到一个可靠的方法来将其完整度提高到 100%。
 （2）映射关系数据库中记录的数据映射是基于未压缩的配置文件的，当从芯片
中提取到压缩过的配置文件时，便无法进行逆向，因此还需要实现对配置文件的解
压缩操作。
 （3）虽然硬核资源的逆向选择了使用原语，但原语的通用性稍低，不仅无法在
不同厂商直接通用，甚至连同一厂商的不同系列芯片都可能不通用，在遇到新的硬
核资源时就需要重新编写代码逆向程序，因此需要找到一种提高基于原语逆向技
术可移植性的方法来进行逆向。
